# 战场画面台账 —— 只减不增（tools/battle_scene_audit.py 判据⑤ 守）
#
# 【这张表记的是什么】战场中带（去掉上下各 15% 的 UI 带）的高频像素占比，
#   也就是「信息密度 / 视觉噪声」。由来是用户 2026-09-30「你知道什么叫 UI **全方面差距**吗」。
#
# ★★★ 2026-10-02 建表的同时更正了一轮错数字。原来记在
#   `docs/plans/ref/20260930-Botworld逐帧参考.md` §8 的「我们 12.5% / 参考 3.2% / 4.0 倍」
#   **全部作废**，判据⑤ 原来的硬阈值 8.0% 也作废。两条原因都是实测：
#
#   ① **尺子自己有 bug**：`_edge_mid_pct` 归一的是**宽边**不是短边（与它自己的 docstring 相反），
#      1280×720 被压到 0.42 倍 ⇒ 2px 尺度的细节完全看不见。合成梯子（1280×720）：
#
#        | 合成图       | 宽归540(旧) | 短边归540(现) | 原生不缩 |
#        |--------------|------------|--------------|---------|
#        | 纯色         |    0.00    |     0.00     |   0.00  |
#        | **2px 格纹** |  **0.00**  |    88.88     |  74.98  |  ← 旧尺子【瞎】
#        | 4px 格纹     |   97.24    |    55.51     |  43.71  |  ← 旧尺子【饱和】
#        | 白噪声       |   73.89    |    91.40     |  96.53  |
#
#      ⇒ 旧尺子量出的「逐像素抖动对噪声贡献 0%」那条结论，**是尺子看不见、不是它不存在**。
#      换分辨率的敏感度也是短边归一最小（4.8pp vs 9.4pp），所以取它。
#
#   ② 拿**同一批参考帧**（51 张 Botworld @1280×720，就是当初那批）用修好的尺子重量：
#
#        | | 旧记录 | 修正后实测 |
#        |---|---|---|
#        | 参考（中位） | 3.2% | **10.55%**（四分位 10.35~10.87 · 全距 10.22~11.80） |
#        | 我们（中位） | 12.5% | **18.74%**（五个拍摄时刻 18.54~19.61，极差 1.07pp） |
#        | 倍数 | 4.0× | **1.78×** |
#
#      ⇒ 旧阈值 **8.0% 比参考自己（10.55%）还低** —— 那是一条「参考来了也得红」的判据。
#
# 【拍摄口径必须钉死，否则前后两次量的不是同一件事】
#   SHIP=1 SELFSHOT=4 WINDOW=1 bash godot-quiet.sh --resolution 1280x720 \
#     --position 5000,5000 res://scenes/RealtimeBattle3D.tscn --quit-after 3000
#   ⚠ 分辨率不能换：同一场战斗 540×960 量出 13.58%、1920×1080 量出 18.40%。
#
# 【目标】参考全距上沿 **11.80%**。现在 18.74%，还差 6.9pp。
#   这条是**棘轮不是硬阈值**：差距是真的，但一步到位不现实。
#   容差 +1.5pp（实测拍摄时刻极差 1.07pp，容差要大于它，否则判的是拍摄抖动不是画面）。
#
# 冻结于 2026-10-02
战场中带高频密度	18.74
