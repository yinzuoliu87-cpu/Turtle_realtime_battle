> 这是本项目**工程侧**规范的唯一权威。游戏**数据/机制**的事实源另见 [docs/README.md §1](README.md)（那三份 + 代码）。
>
> **核心原则（大厂做本品类的共识）：规范不是写在文档里的约定，是写成机器能判的门禁。**
> 没有门禁的规范 = 愿望。本项目吃过这个亏：2026-07-19 把主文件从 23329 拆到 22149(−1180)，
> 因为**没有强制**，功能增生又把它涨回 25272 —— 抽层不持续就白抽。所以每条规范下面都必须挂一个**会红的门禁**。

## 二、Definition of Done（一条改动"做完了"的判据）

一个提交只有**全部满足**才算 done，缺一条都不许报"做完了"：

1. `bash run-tests.sh` **全绿**（自证测试 + 冒烟 + 三方对账 + 上面所有审计器）。
2. 若**玩家可感知**：版本号 +1（四处）、`CHANGELOG` 记账、给提交打 `git tag`（开发工具类不升）。
3. **prove-fail 过**：新加的检查必须演示过"改坏→会红"，否则它可能是空检查。
4. **CI 亲验**：push 后用 Actions API 看 conclusion=success（本地绿 ≠ CI 绿）。
5. 落地后同步对应权威文档（数据→28龟权威 / 系统→系统机制权威 / 状态→路线图）+ 跨会话 memory。

## 三、架构方向（长期·棘轮驱动还债）

- **目标**：主战斗文件从 25272 行的上帝对象，逐模块拆到每个系统独立、单文件 <3000 行。
- **机制**：`arch_budget` 台账把主文件冻结在当前行数——**想往里加代码必须先拆出去**（否则门禁红）。
  每拆一刀 → 行数下降 → 把 `arch_budget.json` 里的数字改到新值（改小才过）= 单调下降、可审计的还债账。
- **安全拆分靠两张网**：① 纯代码搬迁行为不变 → `verify_battle_determinism` 指纹逐字节不变即证等价；② 冒烟不崩。
- **拆分候选与依赖数据**：见 [design/主文件拆分方案-20260719.md](design/主文件拆分方案-20260719.md)。
- **哪些不能 blind 自动拆**：合并两条伤害路径 / 类型化单位 / 会改手感的时序——headless 门禁盖不住手感/像素/28龟平衡，**必须用户 F5 盯着改**。

## 四、这份文档自己的规矩

- 它只管**工程流程/结构**；游戏内容数值一律不进这里（去权威文档）。
- 每条规范的第 2 列必须指向一个**真实存在、会红**的门禁或明确标 ⚠ 约定。谁把 ⚠ 落成 ✅（补上门禁），就把状态改过来。
- 与 `CLAUDE.md` 的分工：`CLAUDE.md` = 逐条**踩过的地雷 + 工作方式**（叙事）；本文 = **规范清单 + 强制映射**（表）。冲突时以本文的门禁为准。
