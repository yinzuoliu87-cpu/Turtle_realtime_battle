# 【持续回复】治疗气泡逐帧 — `heal-hot-bubbles.png`

烘制脚本：`tools/bake_heal_hot.py`
规格：cell 40×40 texel，**共 6 帧**，游戏里按 `HHOT_YARDS = 71` 码摆、`HHOT_FPS = 9`
⇒ 40 × 1.775 = 71，**正好 1:1**，不糊。6 帧 ÷ 9fps = 0.67 秒一轮气泡。

## 为什么要有这张图

用户 2026-09-14 看 044 深海项链：「特效有做么，就是这 **6 秒的持续回复**特效」。

查过代码不是猜的：摊付的结算在 `RealtimeBattle3DScene.gd` 的 `_tick_unit` 里只有两行 ——
`if _t < eq_hot_until: _heal(rate * delta)`，**纯数字零演出**。
`_heal_body_glow` 是触发那一下的一次性脉动（约 0.8 秒），之后 5 秒多只有血条在悄悄涨。

★接在**共享字段 `eq_hot_until`** 上而不是接在 044 上 —— 044 深海项链 / 045 珍珠耳环 /
037 蜡烛都走这个字段，做成「演出是状态的函数」则三件自动都有。

## 量出来的三条

- **上缘在 0↔6 之间反复**：0 / 6 / 3 / 0 / 5 / 0 —— 这就是"气泡在往上升、到顶破掉"。
  烘制脚本里有断言卡住「六帧最高点不许全一样」，全一样就说明它是一张贴纸。
- **均亮几乎不动**：191.3 / 191.3 / 189.6 / 190.4 / 194.2 / 189.1，波动 **2.6%**。
  这是**故意的** —— 持续态一旦整体明暗在跳，就会读成"要结束了"或"在闪"（淡出病）。
  变化全在**形状**（气泡位置 + 哪几颗破了），不在亮度。
- **峰亮六帧恒为 242**：亮边色 `RIM(168,255,196)` 一直在场，没有一帧是暗的。

覆盖量极差 121 px（39%），烘制脚本断言要求 < 55%，留了余量。

## 半透明是刻意的

气泡体 `BODY` alpha 150（约 0.59）、亮边 236、高光 210。
**亮的边负责被看见，半透的体负责不挡住龟** —— 全不透就把龟涂没了。

## 已知取舍

- 气泡是**空心环**不是实心球：实心球正是被点名过的禁区形状（"无含义圆环与白球"那一类里的球）。
  空心 + 亮边读成气泡，而且能透出龟。
- 循环闭合靠 `(y0 - f*STEP) % CELL`，`STEP = CELL/FRAMES` ⇒ 六帧正好走完一个周期，
  第 5 帧接回第 0 帧不跳。
