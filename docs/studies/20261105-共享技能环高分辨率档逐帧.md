# 共享技能环 · 高分辨率档（128 / 256）逐帧

> 2026-11-05 · 方案书 `docs/plans/20261104b-特效对标商业做法.md`「11-05 审核片逐段审」第一条系统性问题
> 素材：`assets/sprites/vfx/skill-ring-10f-128.png`、`assets/sprites/vfx/skill-ring-10f-256.png`（生成：`tools/assetgen/build_skill_ring_hi.py`）
> 运行时选档：`scripts/scenes/battle/ring_sheets.gd`（半径 < 96 码用 64 档，< 192 码用 128 档，其余用 256 档）

## 为什么要这两档

11-05 审核片逐段审：竹刺阵、糖衣炮弹、墨水炸弹、碎晶爆破、财宝风暴、万千触须、火炮齐射这些大范围技能，脚下的环边缘一格一格的台阶。
原因是 187 处地面环共用一张 64 像素的帧表（`skill-ring-10f.png`），半径 300 码时一个贴图像素约 9.6 码，在 1280 宽画面上约 10 个屏幕像素一格，比龟立绘（约 2~3 屏幕像素一格）粗三四倍。
11-04 加的敌我描边用的是同一张图，又把台阶描了一圈。

## 做法与自检

- 同一组 Blender 渲帧（`tools/assetgen/blender_ring.py --px 1024`），BOX 面积平均缩到格边长，锁 ring 板（4 档纯灰，alpha < 24 切掉），淡出烤进帧 alpha（第 6~9 帧 200 / 150 / 95 / 45）。
- **先复刻 64 档再出高档**：同一流水出的 64 档和仓库里现有那张，10 帧不透明像素数逐帧完全相同（160 / 212 / 288 / 352 / 388 / 440 / 480 / 492 / 496 / 448），证明流水对了，再信 128 / 256。
- 三档像素化取整不同，末帧外径占半格的比例差 1% 以内（64：0.972，128：0.965，256：0.963）。300 码的环差 1% 就是 3 码，所以每档用自己实测的末帧外径换算 pixel_size（`RingSheets.LAST_R_PX`），门禁 `verify_skill_ring_curve` ③ 量末帧直径 = 2r×WS，四个半径（40 / 60 / 105 / 300）全过。
- 新增判据：一格在世界里不超过 8 码。变异成只用 64 档时，这条在 300 码那个环上红（9.6 码），还原后绿。

## 结论

- 三档几何一致：外径从 0.30 匀速长到 0.96~0.97，环带先厚后薄，峰值在第 5 帧，第 6~9 帧边扩边淡，和 64 档一样。
- 高档只是边缘更细更圆：64 档环带最细 2.4 像素，放大到大半径就是粗台阶；256 档同一帧环带 7.6 像素，放到 300 码约 2.4 码一格，和场上其它像素画密度一致。
- 运行时一个环从生到灭只用一档、pixel_size 恒定只切帧（不在档之间缩放），像素网格不会被打烂。
