# 035 黄铜齿轮 · 逐帧研究（2026-09-13）

台子：`VFXLAB_CASE=p2eq_035`（**本轮新建**）。
录法：`VFXLAB=1 … --audio-driver Dummy`，**共 16 帧**（5.70–13.60 s，全部逐帧看过）。
拍点压在 **t≈6.0 与 t≈12.0** 两次到账的前后。

## 文案就是规格

> 每 `GEAR_IV`(6) 秒获得 **1/2/3** 枚深海币。

## 一、这一件**没有任何战斗演出**

它的全部可见性只有两样：
1. 到账瞬间携带者头顶的 **「+3💠」飘字**；
2. **装备格徽章**上的本局累计产币数（`PANEL_COUNT`，读数的正规出口）。

逐帧看下来：舞台上从头到尾三只龟站着不动，**什么都没有**；
真正在变的是**左上角携带者卡片里那个齿轮图标右下角的数字**——
6.05 s 那帧它是 **3**，12.05 s 那帧变成 **6**。

★这不是缺陷：memory `fb-vfx-defect-families` 明写「读数一律进装备图标框 `PANEL_CHARGE` / `PANEL_COUNT`，
别自造头顶条」，它走的就是那条正规出口。

## 二、修了一处「同一个数存两份」

```gdscript
if float(stt["gear_t"]) >= GEAR_IV:
    stt["gear_t"] = float(stt["gear_t"]) - 6.0      # ← 写死的 6.0
```

常量就叫 `GEAR_IV`，而扣周期那一行写死 `6.0`。改 `GEAR_IV` 只有一半跟着变。已改成读常量。
门禁专门有一条守它：**连喂两个周期必须进两次账**——把 `GEAR_IV` 改成 9 就当场红。

## 三、门禁 · 判据直接量产品真正写的那个钱包

不数我插的标记，直接读 `GameState.meta_deepsea_coins`：
① 差 0.2 秒不到账 ② 满周期进 1/2/3 枚（吃星级）③ 连喂两周期进两次账
④ **右队（敌方）携带者不产币**（深海币是玩家侧 meta 货币）。反向验证 3 条全红在各自判据上。
