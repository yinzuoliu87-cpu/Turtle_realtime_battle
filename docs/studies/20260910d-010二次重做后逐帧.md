## 顺手抓到的：`_wait_sim` 会随机多等一步

逐帧数第一版重做的帧 4–16，斩击 5 帧占了 **13 个 25ms 拍点**（应该只有 10 个）。
没有靠眼睛下结论，写了探针打数值：

```
[PSTEP] 斩击第0帧 要等0.05000 实等0.06667 (步数=4.00)   ← 第一次施放
[PSTEP] 斩击第1帧 要等0.05000 实等0.05000 (步数=3.00)   ← 第二次施放
```

根因：`_t` 是一步一步加出来的（每步 `SIM_DT = 1/60`），而 1/60 在浮点里不精确 ——
3 步加起来是 `0.049999999999999996`，而 `t_end = _t + 0.05` 里的 0.05 是 `0.050000000000000003`。
差几个 ulp，于是 `while _t < t_end` **多等一步**，那一段演出就慢 33%；而它慢不慢**取决于当时 `_t` 的浮点相位**，
所以同一段演出两次施放长度不一样。**几乎所有演出都在用 `_wait_sim`，不止 010。**

已修（`_t + secs - 1e-6`）并焊进 `verify_interactive_determinism`：
`_wait_sim(k×SIM_DT)` 必须正好等 k 步，10 次不同步数/不同相位全量一遍。
反向验证：把 EPS 拿掉 ⇒ 10 次里有 2 次变成 k+1 步，门禁当场红。
