## ★★为什么是「一排直立的火簇」而不是「一张弯月贴图」

像素风**不许自由旋转**，而波的弧每帧角度都在变 —— 一张弯月贴图必须跟着转。
**但火焰永远朝上**（浮力），所以把波拆成沿弧摆放的**直立火簇**：
贴片一次都不用转，波变长就**多摆几个（整数个）**，也就不需要连续缩放。

形状是被像素风的硬约束逼出来的，同时物理上正确 —— 这正是 021 那次被否（「不要用什么规则图案敷衍我」）之后定下的做法。

## 实战镜头逐帧（1:1 连续录，台子 `staff_023`，共 **9** 帧）

录 6.10~7.70 s 每 0.2 s 一帧（蓄力 → 波推出去 → 扫过敌人 → 出画）。

| 帧 | 时刻 | 画面 |
|---|---|---|
| 0 | 6.10s | **还没有火** —— 蓄力中，场上只有携带者与三个假人 |
| 1 | 6.30s | 波出现：携带者右侧脚下**一小簇立着的火**，2~3 个火簇，贴地 |
| 2 | 6.50s | 火簇变多、整体右移；已经能看出它是一小段**弧**而不是一团 |
| 3 | 6.70s | 弧成形并右推，正好从中间那只假人**身上/身后扫过**；弧上下两端开始张开 |
| 4 | 6.90s | 弧完全脱离队列，立在假人右侧；火簇全部竖直，**没有一个是斜的** |
| 5 | 7.10s | 弧继续外推、变长；簇数肉眼可数地增加（不是把一张图拉大） |
| 6 | 7.30s | 弧到画面右侧，长度已跨过大半个画面高度 |
| 7 | 7.50s | 弧接近最远处，簇数十几个，两端向外张 |
| 8 | 7.70s | 波仍在推进、已压到画面边缘；左边携带者那里在放别的装备的效果 |
**读得出的是**：波**从携带者脚下推出去**、**弧越走越长**、**火簇一根都不歪**。

★**这一段实拍里看不出「扫到谁谁烧」** —— 灼烧是飘字，在这个缩放下读不出来；
  伤害那一条由门禁第 ⑤ 组直调 `_fire_coral_wave_hit()` 验（扇形内吃、扇形外不吃、波前没到不吃）。
  **画面上没看见的事，就不写进逐帧表。**

## 门禁与反向验证

`tests/verify_fire_coral_wave.gd`（**22 条**）量真实产出的 `Sprite3D` 与**抽出来的结算函数**，
不断言我自己插的标记。反向验证七条，**七条全红在各自判据上**：

| 变异 | 红在 |
|---|---|
| M1 退回连续缩放 | ② scale 全是 1（违规 7/7） |
| M2 退回 LINEAR | ② texture_filter 必须显式 NEAREST |
| M3 贴片跟着弧转 | ② 贴片不许自由旋转（违规 6/7） |
| M4 扇形判定拆掉 | ⑤ 扇形外的不吃（实得 90 层） |
| M5 波前带拆掉 | ⑤ 波前还没到的不吃 |
| M6 灼烧不吃星级 | ⑤ 层数 60 ≠ 90 ／ 1 星 40 |
| M7 火簇沉到地下 | ⑥ 火底齐地 |

### ★★M4 一开始没红 —— 是我的样本选错位置

第一版把「扇形外」那个敌人放在 (600,800)：偏角 76° 没错，**但它离原点 412 码而波前在 300 码**，
**波前带那一条也把它挡了** ⇒ 两个条件搅在一起，把扇形判定整条拆掉这条断言照样绿。
挪到**同一半径 300 码**、偏角 76° 之后，M4 当场红。

> 判据要**刚好卡住那个形状**；样本也要**只被那一条挡住**，否则测的不是你以为的那条。
