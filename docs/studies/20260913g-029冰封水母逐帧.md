# 029 冰封水母 · 逐帧研究（2026-09-13）

台子：`VFXLAB_CASE=staff_029`（台子早就有，但**配错了**，见下）。
录法：`VFXLAB=1 … --position 5000,5000 --audio-driver Dummy`，**共 20 帧**（1.00–3.40 s，全部逐帧看过）。

## 文案就是规格

> 该法器法力条集满时为自身获得 **100/160/250 点护盾**并砸地，朝**最近的敌人**推出一条冰道
> （长 `FISSURE_REACH`＝500 码、中线两侧各 `FISSURE_HALF_W`＝90 码），**冰道推进到谁才结算谁**：
> 受到 **25/40/60 魔法伤害**，被竖直击飞约 `FISSURE_KNOCK_SEC`＝0.6 秒并**冰封 1/1.8/2.5 秒**。

## 一、台子本身就是错的（第三次栽同一个坑）

| 配错的 | 后果 |
|---|---|
| `mana_kick: 100` | 未激活法器羁绊时满值是 **`MANA_FULL_BY_TIER[0]` = 200**，只灌半条 ⇒ **整段拍下来什么都不会发生** |
| 7 个拍点跨 15 秒 | 整套演出是【前摇 0.3 s + 冰道推进 0.9 s】共 **1.2 秒** —— **采样比效果本身还粗**，冰道推进的过程一帧都拍不到 |

023 → 026 → 029，这是第三次。已改成 `mana_kick: 200` + 1.00~2.60 s 每 0.1 秒一帧。

## 二、结算层：两层延时都埋在 tween 里

| 层 | 原样 | 后果 |
|---|---|---|
| 砸地前摇 | `_eq_ice_fissure` 的 `tween_interval(0.3)` | 冰道根本不推出去 |
| 逐目标结算 | `_ice_fissure_go` 里**每个敌人各一条** `tween_interval(d)` | 整条冰道**一个人都不结算**：伤害 / 击飞 / 冰封全不落 |

★第二层尤其要紧：那个 `d = (沿线距离 ÷ 冰道长) × 0.9 秒` **就是文案写的「冰道推进到谁才结算谁」**——
**这条节拍本身是规格的一部分**，不是演出细节。所以门禁里专门有一条量它：
推到「前摇 + 冰道走一半」时，**近的必须已结算而远的必须还没**。两个同时掉血就不是一条在推进的冰道。

两层现在都走共享原语 `EquipTickSystem.schedule`（024/025/026/028 同一个）。节拍一个数没动，
只把 0.3 / 0.9 抽成了 `FISSURE_WINDUP` / `FISSURE_SWEEP_SEC`（门禁要拿它推 sim）。

门禁 `tests/verify_ice_fissure.gd` 共 **21 条**，反向验证 **6 条变异全部红在各自那条判据上**。

## 三、演出层：删掉了一个「手抄的副本」

`_eq_ice_fissure` 在 `_grant_shield` 之后又调了一次**自绘的** `_shield_bubble`。而
`_grant_shield` 里早就有【通用护盾罩】`_vfx.shield_shell`（2026-09-11 用户否掉地上金圈之后才做的）。
两个叠着放 ⇒ 通用罩被自绘的球盖住。而那个球还同时违反两条硬约束：

- 贴图是 `VfxTex._make_fire_glow_tex()` **程序生成的光球**（实拍是一个把龟整个吞掉的不透明米色实心球）
- 靠 `tween_property(spr, "pixel_size", …)` **连续缩放像素贴图**（被否过的那个糊）

它**只有一个调用者**，所以连函数带调用一起删掉（主文件 8811 → **8793**）。
memory `fb-hand-rolled-copies-drift`：共享原语到位之后，单件的手抄副本就是永远落后一次的那一份。
门禁专门有一条守它：上盾那一下必须**恰好 1 个通用护盾罩、0 个第二层自绘演出**。

## 五、已知缺口（没动，登记在案）

- 冰刺/冰砖/霜面这三样都是**真像素素材**，这一件的演出本身没有程序生成球。
- 击飞的金色粒子 `_impact_particles`（20 处共用）在冰系上读着偏暖，**没动**（共享原语）。
- **数值 / 文案 / 触发条件一个字未改。**
