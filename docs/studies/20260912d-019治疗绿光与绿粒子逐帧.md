## 用户原话（钉住，不许漂）

看 019 的窗口之后：

> 「**应该要身上冒绿光和绿粒子，但不要复用**」

被否的是「治疗只有脚下一圈淡绿地环 + 一个飘字」——
**治疗这个动作在画面上读不出来**（和 015 的反伤同类：文案写了、画面读不出）。

然后我立刻犯了第二个错，他当场又否：

> 「**我只让你对019做这次的绿光和绿粒子，你不对把其他的也全用了吧**」

我把它挂到了 `battle_damage._heal_flush()` —— 那是 `_heal` 全仓 **80 个调用点**的中央收口，
等于全游戏所有治疗（装备 / 技能 / 羁绊 / 食物 / 温泉蛋 / 不沉之锚…）一起换了演出。
**范围由需求定，不由我推广。** 已收回到只有 019（携带者自己 + 被奶的那只友军）。

> 这条和 memory `fb-fix-the-shared-primitive-not-one-instance` 不矛盾：

## 「不要复用」怎么落实的

| | 014 汲取生命 | 019 治疗 |
|---|---|---|
| 形状 | **四芒星**（尖） | **圆药滴**（圆） |
| 含义 | 「夺」 | 「给」 |
| 调色板 | `life` 正绿 (104,244,112) | `heal` 海葵绿 (36,178,112) |
| 实体填充率 | **0.40**（尖芒之间全是空） | **0.81** |

门禁判据落在**形状**上而不是文件名——文件名不同是随手就能满足的，
填充率 0.60 这条线正好把两者分开（实测 0.40 / 0.81）。

## 光束做废过一版：读成「城市天际线」

第一版是「5 条竖直的舌分三层（外暗→中主色→内亮）」。烤出来 1:1 一看：
**方顶、等宽、白色占 32.7%** ⇒ 读成柱状图 / 城市天际线，不是光。

那是**形状的错，不是参数的错**。现版改成：

- **脚下一条亮带**（只有两三个像素高）—— 它是「光从这里冒出来」的因
- **11 根细光丝**，1~3 px 宽、正弦微弯、越往上越细越暗，高度逐帧起伏

> 细而弯 ⇒ 读成「冒出来的光」；粗而直 ⇒ 读成「立着的物体」。

---

## 第二个做废的版本：加色把薄荷青直接冲成白

第二版素材用 `jade` 板（主色 110,200,148，亮度 **167**）。1:1 实拍一看 ——
**从龟头上戳出来的一排白针**，连是不是绿的都看不出来。

根因不是形状，是**加色（additive）**：加色是「往背景上加」，源越亮越快冲到 255。

⇒ 另立 `heal` 板，**亮度阶梯故意比别的板暗一档**：

| 板档 | 色 | 亮度 |
|---|---|---|
| 档 0 | (168, 255, 214) | 231（只用在极少的尖上） |
| 档 1 | (92, 226, 160) | 186 |
| 档 **2** | **(36, 178, 112)** | **136 主色** |
| 档 3 | (22, 122, 78) | 93 |
| 档 4 | (12, 74, 50) | 56 |
| 档 5 | (6, 40, 28) | 30 |

门禁把这条焊死：**加色层主色亮度 ≤ 160**。jade 主色 167 会被它判红。

## 实战镜头逐帧（1:1 连续录，共 **8** 帧）

台子 `p2eq_019`，探针与录制**同一个进程**（触发时刻每次跑都会浮动，跨进程对不上）。
实测触发在 7.02 / 14.03 / 21.05 秒，下表是第一次触发前后每 0.1 秒一帧。

| 帧 | 时刻 | 画面 |
|---|---|---|
| 0 | 6.90s | 无。中间是携带者（45% 血），左上是血最低的友军 |
| 1 | 7.00s | **触发** —— 携带者与左上友军**同时**从脚下亮起绿光，下半身被照绿 |
| 2 | 7.10s | 光丝往上窜，两只都在亮；圆药滴开始从脚边冒出来 |
| 3 | 7.20s | 光最盛的一帧；携带者身上的绿覆到龟壳下缘 |
| 4 | 7.30s | 药滴升到龟身中段，仍满亮（先 hold 再淡） |

## 门禁与反向验证

`tests/verify_heal_burst.gd`（17 条）量的全是真实产出：从 `_world` 捞新建 Sprite3D、
读贴图真实像素、读 `pixel_size`、读材质混合模式、手推它自己的 tween。

七条变异**逐条红在各自判据上**：

| 变异 | 红在 |
|---|---|
| M1 光束贴图整体提亮 1.7× | ② 加色层主色亮度 190 > 160 |
| M2 去掉加色混合 | ② 光束必须用加色 |
| M3 光束尺寸缩一半 | ③ pixel_size 0.0213 ≠ 0.0426 |
| M4 退回一出生就淡 | ⑥ 满亮段 alpha 从 1.00 掉到 0.00 |
| M5 药滴不往上飘 | ⑥ 只涨了 0.03 m（要 ≥ 0.50） |
| **M6 范围复发·挂回 `_heal_flush`** | ⑤ 普通治疗冒出了 1 个光束（应 0） |
| M7 复用 014 的汲取粒子 | ③ 药滴 pixel_size 对不上（12px 格） |

### 反向验证自己踩的三个坑，写在这里

1. **变异锚点不唯一**：`mat.blend_mode = BLEND_MODE_ADD` 在 `battle_vfx.gd` 里出现 **2 次**
   （护盾罩 + 治疗光束）。分母断言拦下了，改用上下文块锁死。
2. **变异没复现那个形状**：M1 第一版是「把素材重索引回 jade」—— **不红**。
   因为烤出来的源色已经是 `heal` 的暗绿，重索引到 jade 时最近邻落在 jade 的暗档
   （58,150,104，亮度 117），照样 ≤160。原来的毛病是 **Blender 源色本身就是 jade 的亮档**
   ⇒ 改成直接提亮贴图才复现得了。
3. **★★我又写了一条恒真式**：⑥「药滴往上飘」第一版的阈值写成
   `>= HEAL_DROP_RISE * 0.5 * WS` —— 把 `HEAL_DROP_RISE` 从 46 码改成 2 码，
   **阈值跟着变小，门禁照样绿**。判据的阈值不许拿被测常量自己算。
   现在是绝对值 **0.50 m**（≈12 屏幕像素 ≈ 1/4 个龟高）。

另有一条是**判据自己的锚点错了、被测对象是对的**：起点 `y0` 我取在推 tween 之后，
那时药滴已经飞了 77% 的路，于是「涨了多少」量出来只有 0.19 m 而判据要 0.55 m，
门禁报红而产品没问题。锚点提到推之前就对了。
