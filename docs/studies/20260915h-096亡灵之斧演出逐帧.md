## 为什么有这套图

用户 2026-09-15 看完九段形态视频:「6/9亡灵斧你这是在敷衍我啊，完全没按标准来」。
被否的是三样代码现算的图形: 程序细环(环) / ImmediateMesh 绿线(吸取) / 6 根 BoxMesh 小方块(复活)。
他同一段对别的形态说的尺子: 演出读得出机制 · 范围 = 判定 · 每个效果有自己的画面 · 生效有反馈。
分段表见 `docs/plans/20260915g-096九形态重做.md`「E」。

## 怎么看的

- 每张先看 Blender 大图(每帧缩到 320 格拼一排), 再看像素版(小表按 4~8 倍最近邻放大; 320/384 格的按 1:1), 再进 VFXLAB 实拍(`p2eq_096_undead`, zoom 2.2)。
- 下表数字由脚本逐帧量出: 不透明像素数 / 包围盒 / 色数 / 高光像素(亮度 ≥ 200)/ 最高亮度。
- 贴地的三张(领域 / 内收 / 倒计时)在游戏里铺在地面平面上, 画布边 = 世界里的外径(领域 = 2 × 300 码)。

## 量出来的几条

- **领域是持续态**: 八帧不透明像素 27901~28360(波动 1.6%)、最高亮度恒 244, 变化全在旋臂 / 骨纹 / 火舌 / 魂点的**位置**, 不在亮度 —— 不会读成「在闪 / 要结束了」。
- **一次性表的高光档**: 内收 / 吸到了 / 崩散 / 复活 四张前 5 帧的最高亮度都在全表最高的 85% 以上, 暗下来的只有末 2~3 帧(门禁 `verify_axe_undead_holo_vfx` ⓪ 用同一个量, 并用「人为逐帧压暗」反证它会红)。
- **倒计时读得出进度**: 点亮的魂烛数 = ⌊(帧 + 1) ÷ 2⌋, 第 15 帧 8 支全亮; 高光像素 0 → 16 → 31 → 47 → 200 → 371 → 392 基本单调上升, 越接近复活越亮。
- **领域外缘 = 判定圆**: 第 0 帧中线最左 / 最右不透明像素在第 0 / 319 列(门禁 ⓪ 量 ≤ 2 格), 游戏里 pixel_size = 600 码 × WS ÷ 320。
