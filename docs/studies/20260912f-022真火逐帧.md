## 前三版漏量的四条（这一轮补的）

同一把尺子，扣背景（火 = 比无火帧亮 28 以上 且 R−B>30）：

| 量 | 参考实测 | 第 3 版做出来的 |
|---|---|---|
| 填充率（火占包围盒） | **0.44** | 0.37，而且是并排细杆不是团块 |
| 亮度 内/外（离边 3px vs 0px） | **1.26 —— 芯亮边暗** | **反的**：白在尖、暗红在根 |
| 单段宽（横扫描线游程，按面积加权） | **38.2 px / 火高 149 = 0.256** ⇒ 80 格里 **20.5 texel** | 细得多 |
| 火星（脱离本体的碎块） | 连通块 38 个，**82% 是 ≤12px 的碎星** | **0 个** |

### 量宽度这条我又走了一次弯路

第一次量的是**中位段宽**：9 px / 149 = 0.060 ⇒ 4.8 texel。照它做出来是一把**细面条**。
错在：中位数量的是**细舔**，而火的**面积**压倒性地在宽段上（75 分位 22 px、90 分位 46 px）。
换成**面积加权**（Σw²/Σw）才得到 38.2 px = 20.5 texel —— 火是**胖圆瓣**，不是细舔。

> ⇒ 量「典型尺寸」时先问：我要的是**个数**上的典型，还是**面积**上的典型。

## 为什么用 Cycles 体积发光

**「芯为什么亮」不是画上去的渐变，是视线穿过的火焰体积更厚。**

所以几何不是平面片而是**元球（metaball）堆出来的三维团**，材质是 `Principled Volume`：
亮度 = ∫ 发光 × 路径长。外缘薄 ⇒ 暗橙；舌片中轴厚 ⇒ 亮橙；两片交叠处最厚 ⇒ 近白。
**梯度是渲出来的，不是我调出来的** —— 门禁里那条「分档 ≥3」因此不是恒真式。

用元球而不是扫掠管，是因为**靠近的球自动融成一团、远的自然断开成独立舌尖**，
轮廓的疙瘩是**融出来的**，不是我画的规则图案（021 那次用户否的正是「规则图案」）。

### 两个踩过的坑

**① 元球取样必须密于半径。** 初稿每条流线放 22 颗（间距 0.086 > 半径 0.048）⇒
它们根本不融，烤出来是**一串珠子**。间距 ≈ 0.5 × 半径 才连成一条，改成 64 颗。

**② `continue` 插在 `elements.new()` 之后 = 留下一颗默认半径的元球。**
给「白热芯」加高度裁剪时，我把 `if ... continue` 写在了 `e = mb.elements.new()` **之后**，
于是元球被建出来却没赋半径 —— **Blender 的默认 `radius` 是 2.0**，在 `[-1,1]` 的画布里
一颗就把整幅图填满。实拍是一整块米色方块。
（同族：CLAUDE.md §3.7「脚本批量改代码」那一节讲的就是插入位置。）

## 亮度：压了三轮才不被泛光洗白

台子有泛光，亮色会被抬上去。三轮实拍对账：

| 主色 | 亮度 | 实拍读成 |
|---|---|---|
| `(255,196,130)` 占 61% | 205 | **奶白**，完全不是火 |
| `(255,196,130)` 占 54% | 205 | 还是**奶油色** |
| **`(240,150,74)` 占 75%** | **168** | **橙色的火** ✓ |

中间那一轮我一度以为是「体太亮」，算下来体本来就落在主火色上 ——
**真凶是芯铺得太大**（`CORE_SCALE 0.60` ⇒ 亮档占 54%），把整团抬了上去。
收窄到 0.32 之后亮档只剩 3%，主火色 75%。

> memory [[fb-vfx-defect-families]]「加色下亮色必洗白，源色必须更暗」——
> 这次连栽两轮才想起来照它做。

## 素材本身（8 帧，80×80 一格）

| 量 | 实得 |
|---|---|
| 色数 | 4（`240,150,74` 75% / `196,96,40` 13% / `128,52,22` 8% / `255,196,130` 3%） |
| 半透明像素 | **0**（硬边） |
| 填充率 | 0.57 |
| 宽/高 | 0.83 |
| 帧间差 | 最小 583 px；末帧→首帧 887 ≤ 平均 780 × 1.8 ⇒ **循环无缝** |

三层结构照实测的「内/外 1.26」搬：**外幔**（最暗最红，只有它单独存在的那一圈 ⇒ 深色描边）
→ **火体**（主火色）→ **白热芯**（橙白，只在中下部，因为实测亮度剖面最亮在中上部而不是舌尖）。

8 帧全部由 `sin(2π·frame/8 + 相位)` 驱动 ⇒ 第 8 帧天然接回第 1 帧。

## 实战镜头逐帧（1:1 连续录，台子 `p2eq_022`，共 **9** 帧）

录 9.40~13.40 s 每 0.5 s 一帧（真火 5 秒的整段 + 撤掉那一刻）。

| 帧 | 时刻 | 画面 |
|---|---|---|
| 0 | 9.40s | **真火挂上**：目标整个被火吞住；四周还有命中那一下的红色火星在散 |
| 1 | 9.90s | 火在翻腾（8 帧循环的下一相位），最高那根舌尖朝右倾 |
| 2 | 10.40s | 中央那根舌最高，顶过目标的龟壳上沿；左右两根分开，露出背景黑场 |
| 3 | 10.90s | 舌片分成两股，中间的缝里看得见目标的青色前肢 —— **火是透的，不是一块板** |
| 4 | 11.40s | 火底最宽的一带压着地面，目标脚下整个被盖住 |
| 5 | 11.90s | 整体收窄一档；火体中部看得见亮芯那一档的浅色纹路 |
| 6 | 12.40s | 又涨回来；左侧舌片探出目标轮廓之外（火宽 > 目标宽，与参考一致） |
| 7 | 12.90s | 另一件装备的黄色抛物线从旁边飞过；真火不受影响，继续烧 |
| 8 | 13.40s | 火**撤掉**（`true_fire_until` 到点）；目标恢复常态，旁边是另一件装备的护盾球 |

**读得出的是**：这只龟**正在真火里**、**烧了多久**、**什么时候结束**。
这正是 022 的效果本身 —— 一个 5 秒的 buff，不是一次命中。

## 门禁与反向验证

`tests/verify_true_fire.gd`（**24 条**）量三件事：挂上了没 / 是不是持续循环 / 到点撤没撤，
外加素材本身的分档、填充率、宽高比、循环无缝，以及**走产品自己的那条 tick**。

### 接线为什么不在 `_fuel_bottle_hit` 里

第一版我把 4 行接线写进了 `RealtimeBattle3DScene.gd`，`arch_budget` 当场红
（**8879 > 台账冻结的 8875**，主文件欠债只减不增）。改成在 `battle_render._tick_true_fire()`
逐帧扫 `_units`：**谁身上 `true_fire_until` 还没过，谁就自动烧起来**。

这不只是为了绕过台账，它本来就更对：演出是**状态的函数**，
以后任何写 `true_fire_until` 的路径都自动带火，不用再接一次线
（memory [[fb-zero-caller-is-a-whole-class]]：「写了没人读」是一整类，不是偶发）。

而且门禁第 ⑨ 组因此能**走真入口**：只写状态、调产品自己的 tick、看火起不起来 ——
只断言 `true_fire_aura` 建得出 Sprite 是守不住「还有没有人调它」的
（memory [[fb-verify-must-run-the-real-path]]）。

反向验证八条，**八条全红在各自判据上**：

| 变异 | 红在 |
|---|---|
| M1 火缩到 60 码（不再吞掉目标） | ④ 火高 0.72 龟高 |
| M2 循环改成放一遍就销（退回「闪一下的爆点」） | ② 循环播放 / ③ 到期自销 |
| M3 到期不读单位的钟（另起第二条计时） | ② 到期读的是 `true_fire_until` |
| M4 贴图改 LINEAR | ④ 像素画用 NEAREST |
| M5 素材退回「实心橙板」（第 1 版的病） | ⑤ 分档只有 1 档 / ⑥ 填充率 0.88 |
| M6 掏空 `_tick_true_fire`（接线断掉） | ⑨ 只写状态后火**没起来**（follow_vfx 1 → 1） |
| M7 退回 `TRUEFIRE_H = 1.30`（火沉到脚下 0.4 m） | ④ 火底齐脚 −0.404 m ／ 露出只剩 1.42 龟高 |
| M8 抬到 `TRUEFIRE_H = 2.4`（火整个飘在半空） | ④ 火底齐脚 +0.696 m |

变异脚本本身也踩了两个坑，记在这里：
`TEXTURE_FILTER_NEAREST` 全文件有 **5 处**（别的特效也设），单行锚点直接命中失败 ⇒
改成**按函数块定位**；heredoc 里的 `\n` 会变成真换行（memory 里已有这条，我又踩了一次）。

## 还没解决的（登记，不假装没有）

- **填充率 0.57 vs 参考 0.44**、**宽/高 0.83 vs 参考 1.0~1.3**：我们的火比参考**更实、更窄**。
  元球融合天然比真实火焰连得更死；要更透只能把球打散，那又会退回「串珠」。**没动。**
- **火星（实测参考 82% 的连通块是碎星）现在被 alpha 阈值吃掉了**：
  `pixelize_sheet` 切 `alpha<24`，1~2 texel 的火星在 320→80 的 BOX 缩放后大多低于阈值。
  素材里剩下的碎星寥寥。要留住得改缩放策略，会波及所有素材，**没动**。
- **参考的内/外亮度 1.26 我们没有直接复核**：我们的梯度是靠三层（外幔/体/芯）分出来的，
  量化到 4 色之后再量「离边 3px vs 0px」已经不是同一个量。门禁改用**分档数**当替代判据，
  这条差异写在这里不装看不见。
- **022 另有三条没动的问题**（用户只点名了「真火的特效」）：
  ① 伤害埋在 tween 链末尾（CLAUDE.md §3.5 明令禁止的形状）
  ② 碎裂特效用 `TEXTURE_FILTER_LINEAR` + `VfxTex._make_fire_glow_tex()` 程序生成光球 + 两个圆环叠一起
  ③ `ember-flask.png` 图标 64×64 / 94 色，不合像素画规格（在台账上）
- **数值 / 文案 / 触发条件一个字未改。**

## 追记（v0.19.367）：火根埋在地里 40 厘米，而门禁绿着

用户问了一句「**这个特效的最低高度是多少**」。量出来是 **−0.404 m** —— 火底在脚下 40 厘米。
他跟着说「**火焰的最低点应该和单位的脚差不多吧**」。对。

### 根因

`TRUEFIRE_H` 是**贴图中心**的高度，不是底边。半格 = 80 texel ÷ 2 × 0.0426 = **1.704 m**，
而我拍了 **1.30** ⇒ 底边 1.30 − 1.704 = −0.404 m。改成 1.704 之后火底 **+0.000 m**。

探针读的是**真实 Sprite3D 的 AABB**（`centered=true`、`offset=(0,0)`、`pixel_size=0.0426`、
局部 AABB `pos.y=-1.704 size.y=3.408`），不是我算的 —— 算术对不对是另一回事，量到才算数。

### ★★连带查出一条门禁假绿

④ 原来量的是 `cell × pixel_size` = **3.41 m，恒定**。这个数跟贴图在世界里的位置无关 ——
**贴图整个沉到地下它也一样绿**。而实际就出了这事：沉下去 0.40 m 之后，
**露出地面的火只有 1.33~1.42 龟高**，已经低于参考实测的 1.5~1.7，判据却全程绿。

现在两步：从真实 AABB 取底/顶（底被地面切掉的不算），再用**贴图里真的画到的行**
把方片顶往下切 —— AABB 是整个贴图方片，拿它报「火多高」同样是虚的。
修后实测：**火 0.00 ~ 3.24 m，露出 1.62 龟高**。

> memory [[fb-judge-must-fit-the-shape]]：判据没问对问题，比代码写错更难发现。

### 顺带修的：开窗工具自己的两条假绿

`tools/vfxlab_show.py` 正是为「别对着主菜单讲特效」建的，这次它自己骗了我：

1. **开窗后没置顶** ⇒ 截出来整幅是 **VS Code**，游戏窗口被压在下面只露出左上角一条标题栏。
   `SetForegroundWindow` 被 Windows 前台锁挡住（返回 false、窗口纹丝不动），
   有效的是 `SetWindowPos(HWND_TOPMOST)`。
2. **判据「暗像素（亮度<70）> 70%」两边都是 95%** —— VS Code 深色主题 `#1f1f1f` 亮度 31 也算暗。
   换成**近纯黑（亮度 ≤10）≥ 70%**：被挡住 19.4% / 真台子 93%。
3. 我在这条上**又栽一次**：标定用的是**亮度**，实现却写成「三通道都 ≤10」。
   台子背景 `(2,4,11)` 亮度 3.8 但最大通道 11 ⇒ 把真台子判成 0.4%，当场误红。
   （memory [[fb-verify-check-can-fail]]：新尺子先拿已知答案的样本量一遍。）
