# 027 电棍 · 逐帧研究（2026-09-13）

台子：`VFXLAB_CASE=p2eq_027`（**本轮新补 —— 这一件原来没有台子也没有门禁，从没被逐件体检过**）。
录法：`VFXLAB=1 … --position 5000,5000 --audio-driver Dummy`，1.00–7.75 s **每 0.25 s 一帧共 28 帧，全部逐帧看过**。
配置：★3 携带者 `basic`、两个 5 万血不还手的假人、`attacker: true`（它靠**普攻命中**触发，不开永远不触发）。

## 文案就是规格

> 每 3 秒充能就绪，下一次普攻命中时对该目标追加 **30/40/50 魔法伤害**并使其**眩晕 2.5/2.5/3 秒**，
> 每次消耗 1 层电击（装备时拥有 **3/4/5 层**，**层数为 0 时停止、装备不消失**；层数每场战斗重置）。

## 一、结算层：查下来是健康的

| 查什么 | 结论 |
|---|---|
| 结算在不在 tween 上 | **不在**。它挂在 `_eq_on_basic_attack` 里**同步**结算 —— 024/025/026 那条「延时挂 tween、无头下推不动」的病，027 没有 |
| 层数从哪来 | `equip_stats_apply.gd:213` 按星级给 3/4/5，不是我喂的 |
| 眩晕是不是真的眩晕 | `battle._freeze()` 内部就是 `_damage._stun(u, sec, "_freeze")`，和文案的「眩晕」对得上 |
| 伤害口径 | 走 `_resolve_dmg(…, magic=true)`，魔抗 500 实测只吃 5（软目标 60）⇒ 确是魔法伤害 |
| 实得 60 而文案 50 | **产品本来的行为**：携带者 `id="basic"` 走【小龟·不屈】按目标稀有度增伤 +20%。不是 027 的 bug，所以门禁判据落在**对该被动不敏感**的形状上 |

门禁 `tests/verify_baton.gd` 共 **23 条**，反向验证 **12 条变异全部红在各自那条判据上**。

## 二、演出层：这里有真缺陷，已修

### 2.1 它借的是一张「对称放射星爆」，不是电

就绪火花 `_baton_spark` 与命中爆闪 `_chain_zap` 两处都 load 同一张 `electric-zap.png`。
把那张表拆开量：**五帧全是中心一颗白球 + 均匀放射线的星爆**，没有任何电弧特征。
而 027 从文案到装备名从头到尾写的是「电棍 / 电击 / 眩晕」。

### 2.2 ★更要命的是它有**黑帧**，而就绪火花抽的是 `randi() % 5`

逐帧量 `electric-zap.png` 的不透明像素：

| electric-zap 的帧 | 不透明 px | 亮像素(≥200) | 亮占比 |
|---|---|---|---|
| frame0 | 2157 | 1226 | 0.57 |
| frame1 | 2537 | 1961 | 0.77 |
| frame2 | 2092 | 1598 | 0.76 |
| frame3 | 1235 | 543 | 0.44 |
| **frame4** | 1037 | **0** | **0.00** ← 整帧没有一个亮像素 |

frame4 均色 R18 G25 B34。抽到它等于**什么都没画**。
⇒ 就绪态的火花里**每五次有一次是全黑的**，在黑场里读成一团污渍 ——
3.25 s 那一帧我亲眼看到的那团灰就是它。

### 2.3 为什么不改那张图，而是新出两张

`electric-zap.png` 还被**赛博侵入 / 雷电龟 / 026 连锁闪电**共 5 处在用，改它会连坐；
且素材不复用是铁律（新内容一律新素材）。所以新烘两张，`tools/bake_baton_arc.py`：

- `baton-arc.png` 24×24 × 8 帧 —— 就绪态棍身上噼啪跳的短弧
- `baton-strike.png` 56×56 × 8 帧 —— 命中态劈在目标身上的落雷（0-1 起弧 / 2-4 最盛 / 5-7 余辉，是**一次放电的过程**不是八个随机样子）

形状来自**中点位移折线 + 分叉**（电弧的真实形态），不是规则图案。四色、零半透明像素、硬边。

### 2.4 ★★配色绕了三版，记下来省得再绕

| 版本 | 做法 | 实测结果 |
|---|---|---|
| v1 | 暗色只往 +x/+y 方向铺 2px | 暗留在折线**中间**、亮被挤到边上，和真电弧**反着** |
| v2 | 中蓝八向膨胀 1 格当辉光 | 3px 中蓝把 1px 的芯压死，渲成一条蓝虫；**更要命的是载体小龟本身就是亮青 (0,240,207)**，亮蓝弧贴在亮青身上等于没画（实测 3.50 s 那帧电弧均色 R87 G167 B178，和龟皮几乎同一族） |
| **v3** | **深蓝描边 (16,38,92) + 亮芯** | 描边把弧从任何底色上切出来，芯保持最亮 —— 这就是像素画的通用解，也是我自己从 948 张 mod 图标里量出来的那条（描边闭合度） |

### 2.5 ★判据也跟着换了一次 —— 换的是**形状**不是阈值

第一版门禁量「不透明像素的平均亮度 ≥ 150」。加了深蓝描边（正解）之后平均亮度掉到 124 ——
**判据要把好素材判红了**。真正要卡的从来不是「平均多亮」，是「这一帧在黑场里**有没有看得见的东西**」。
改成量**亮像素占不透明像素的比例 ≥ 0.15**：

- 旧 electric-zap frame4 = **0.00** ⇒ 当场红
- 本轮两张 = 0.20 ~ 0.40 ⇒ 绿，且**深蓝描边不再被误伤**

## 四、演出贴不贴合判定

027 是**单体**判定（只打被普攻命中的那一个）。落雷因此只建 **1 道**、且**挂在被打中的那个单位身上**跟着它走，
不是打在场地坐标上。这两条各一条断言，变异（挂到旁边那只 / 不建）**各自当场红**。

尺寸按**整数倍**缩放（像素风硬约束，1 texel = 0.0426 m）：
跳弧 24 texel = 1.02 m ≈ 0.51 个龟高（就绪态本来就该是小火花，不该盖住龟）；
落雷 56 texel = 2.39 m ≈ 1.2 个龟高（单体判定，演出就只罩住被打的那一个）。
