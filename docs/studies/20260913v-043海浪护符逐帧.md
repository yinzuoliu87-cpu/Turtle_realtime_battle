# 043 海浪护符 · 逐帧研究（2026-09-13）

台子：`VFXLAB_CASE=staff_043`（已有，本轮订正 `mana_kick`）。
录法：`VFXLAB=1 … --audio-driver Dummy`，共 **16 帧**（2.30–5.30 s，全部逐帧看过）。

## 文案就是规格

> 法力满时从身后 `WAVE_BACK`(400) 码涌起浪墙横扫全场，**敌我双方都会被扫到**：
> 友军 +40/95/120 护盾并**永久** +2/3/5 双抗；敌人受 60/110/200 魔法伤害并**永久** −2/3/5 双抗。
> 负面被动：该法器的法力条上限提升 50/25/0%。

## 一、★★台子 `mana_kick` 给 100 —— 同一个坑的**第六次**

未激活法器羁绊时法力条满值是 `MANA_FULL_BY_TIER[0] = **200**`，不是 100。
023 / 026 / 029 / 030 / 031 已经各栽过一次，043 是第六次。

⇒ 这一轮把它**做成门禁**了：新增 `tests/verify_vfxlab_case_config.gd`，
判据是「配了 `mana_kick` 的 case 一律灌得满（档 0 满值 × 该件自己的倍率）；
故意只灌半条的要显式写 `mana_partial: true`」。
全表扫下来**一次订正了 9 个 case**（syn_staff / staff_023 / staff_043 /
staff_088 / staff_089 / staff_090 / p2eq_088 / p2eq_089 / p2eq_090）。

★这条门禁反向验证过：把 043 退回 100 ⇒ 当场红「staff_043(灌 100 < 满 200)」。

★注意 043 自己带满值倍率（`MANA_FULL_PCT = [50, 25, 0]`），所以判据不能只比常量，
必须把**该件的倍率**算进去 —— ★1 的满值其实是 300。门禁里有一条分母断言专门钉这一点。

## 二、★真缺陷：命中水花是「程序圆环 + 4 颗程序光点」

`_water_splash` = `_skill_ring`（一圈程序生成的椭圆环）+ 4 颗 `VfxTex._make_glow_texture()`
上飘光点。实拍在每个被扫到的单位脚下留下**两个蓝圈**，读不出"被浪打到"。

重做成真正的水花（新素材 `wave-splash.png`，6 帧 × 24×16 texel：王冠状水冠 + 往外崩的水滴）。
烘制脚本 [tools/bake_wave_splash.py](../../tools/bake_wave_splash.py)。

★★这里我自己栽了一次并被抓到：**图烘完了却忘了接线**（`wave-splash.png` 零调用者，`_water_splash` 还在跑老的程序圆环），而我已经把这一节写成了「已重做」。
—— 正是 [[fb-zero-caller-is-a-whole-class]] 那一类。已补接线：主场景的 `_water_splash` 整只删掉，换成 `battle_vfx.wave_splash()`，两个调用点（友军/敌人各一）都改过去。

## 三、浪墙本身是健康的

`_spawn_tidal_wave` 用的是真素材 `tidal-wave-anim.png`，沿 `perp` 铺 4~16 片浪头、
沿 `dir` 推进，方向靠 `flip_h` 不靠旋转 —— 与像素风三条约束一致。
结算走 `_pending_shots`（sim 钟），**没有一处埋在 tween 上**。
