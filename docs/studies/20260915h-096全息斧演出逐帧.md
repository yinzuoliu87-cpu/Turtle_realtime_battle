# 096 小木斧 · 全息斧 造物演出逐帧 —— 8 张帧表

烘制: `tools/blender_axe_holo.py`(Blender 5.2 EEVEE, 正交相机 ortho_scale 2, 同色同层的面合批成一个网格, 发射着色器直接用 `holo` 调色板八色)
→ `tools/pixelize_sheet.py --palette holo`。
素材: `eq096-holo-field.png`(384 格 × 8)、`eq096-holo-deploy.png`(384 × 8)、`eq096-holo-pulse.png`(384 × 8)、`eq096-holo-bit.png`(12 × 8)、
`eq096-holo-shield.png`(64 × 8)、`eq096-holo-boost.png`(48 × 8)、`eq096-holo-haste.png`(40 × 8)、`eq096-holo-guard.png`(64 × 8)。
本篇把 8 张按「法阵 → 展开 → 脉冲 → 数据块 → 护盾 → 治疗反馈 → 加速圈 → 护罩」连续编号, **共 64 帧**。

## 为什么有这套图

用户 2026-09-15 看完九段形态视频:「8/9也是，完全没达标」。
被否的是: 两圈程序细环 + 一根 BoxMesh 竖条当「插地的斧头」(法阵) / 把网格透明度闪一下(每 0.5 秒一跳) / 普攻给友军护盾零演出。
他同一段对别的形态说的尺子: 演出读得出机制 · 范围 = 判定 · 每个效果有自己的画面 · 生效有反馈。
分段表见 `docs/plans/20260915g-096九形态重做.md`「E」。

## 怎么看的

- 每张先看 Blender 大图, 再看像素版(小表 4~8 倍最近邻放大, 384 格按 1:1), 再进 VFXLAB 实拍(`p2eq_096_holo`, zoom 1.0)。
- 下表数字由脚本逐帧量出: 不透明像素数 / 包围盒 / 色数 / 高光像素(亮度 ≥ 200)/ 最高亮度。
- 贴地的四张(法阵 / 展开 / 脉冲 / 加速圈)画布边 = 世界里的外径(法阵 = 2 × 600 码)。

## 量出来的几条

- **法阵是持续态**: 八帧高光像素 6531~6545(波动 0.2%)、最高亮度恒 249, 转的是扫描线 / 追光 / 字符 / 虚线的位置。
- **展开倒放 = 收拢**: 展开第 7 帧外缘贴满画布、第 0 帧只剩插点; 游戏里到期前 0.4 秒从第 7 帧倒放, 到期前最后一步落在第 0 帧(门禁 `verify_axe_undead_holo_vfx` ⑤ 逐模拟步量)。
- **脉冲与跳同长**: 8 帧 ÷ 16fps = 0.5 秒 = `HOLO_AURA_TICK`, 第 6 帧碰边一亮、第 7 帧收尾, 下一跳从第 0 帧起。
- **一次性表的高光档**: 展开 / 脉冲 / 护盾 / 治疗反馈 前 5 帧最高亮度都在全表最高的 85% 以上(门禁 ⓪ 同一个量 + 人为逐帧压暗的反证)。
- **已知小瑕疵**: 数据块 12 格太小, 顶边有 1~2 颗像素落到「治疗亮绿」档(色数 7~8, 调色板里没有更近的青白); 实拍里是一点高光, 读不出绿。
