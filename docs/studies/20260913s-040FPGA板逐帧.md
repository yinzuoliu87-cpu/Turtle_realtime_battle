## 文案就是规格

> 每 `FPGA_IV`(6) 秒随机抽 `FPGA_PICKS`(1/2/4) 个 2-bit 状态（可重复）：
> `00` = 回复 5% 最大生命 **并** 累计 +12 双抗；`01` = 累计 +15 攻击力与 +7% 生命偷取；
> `10` = `FPGA_BUFF_SEC`(3.5) 秒内增伤 +15%；`11` = 3.5 秒内受伤减免 25%。
> 登场还给【对方】随机 1/2/3 个敌人各一把古灵精怪枪。

## 一、★台子配错读成「这件装备没效果」

第一版台子配的是 `"ui": true`。实拍下来**整段只有脚下一个淡青圈**，
我差点写下「040 除了一个圈什么都没有」。

查证：`ui: true` 的语义是**整层 UI `visible = false`，只把队伍面板搬到独立层** ——
而二进制码走的是 `_float_text`（飘字），飘字挂在那一整层上，于是被一起关掉了。
改配 `"bars": true`（整层 UI 都留着）之后，四个码**一直都在**。

⇒ 这正是 memory [[fb-clean-vfx-stage-not-squint]] 那条「把『我没配对环境』报成『效果有问题』」。
**判据：读数走飘字或血条的件，一律配 `bars`，不是 `ui`。**

## 二、★真缺陷：★3 抽四个码，实拍连成一串读不出是四个

`xoff = (k − (n−1)/2) × 34.0` —— 这个偏移是**世界码**，而飘字是**屏幕空间的固定字号**。
34 码 ≈ 17 屏幕像素（zoom 1），比两个字符还窄 ⇒ 实拍是 `1111 0000` 一整串。

已改成 **80 码**（≈40 屏幕像素），四个码分得开。

## 五、门禁

`tests/verify_equip_040_045.gd` 第 ① 节共 6 条（反向验证 3 条 Z1/Z2/Z3 全部红在各自判据）：

- ★分母把 `FPGA_IV / FPGA_PICKS / FPGA_00_RESIST / FPGA_01_ATK / FPGA_BUFF_SEC / FPGA_00_HEAL_PCT` 六个常量全钉住

- `10/11` 是**限时**的：抽到之后推过 3.5 秒，增伤/减伤都必须归零

★期望值写死在门禁自己的 `EXP_PICKS := [1, 2, 4]`，**不读被测常量**（读常量是恒真式）。
