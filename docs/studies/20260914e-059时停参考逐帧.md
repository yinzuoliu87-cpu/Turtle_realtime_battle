## 量的是什么（先说口径）

三个量，都对 160×90 的缩图算，避免被压缩噪点带偏：

| 量 | 怎么算 | 用来回答 |
|---|---|---|
| **运动量** | 与**前一帧**的逐像素 RGB 绝对差的均值 | 这一帧动没动 |
| **饱和** | HSV 的 S 通道均值 | 颜色浓不浓 |
| **亮度** | HSV 的 V 通道均值 | 亮不亮 |

**★先对齐口径再下结论**（memory `fb-pixel-1to1-video-reference`）：
"定格"和"镜头没切"是两回事。切镜头会让运动量冲到 40~90，
所以判"定格"只能看**同一镜头内部**的运动量，不能拿跨镜头那一帧当数据。
下表里凡是「切镜头」的帧都单独标了出来。

## ★★量出来的三条（这份研究的全部产出）

### ① 定格 = 真的一帧都不动

| | 运动量区间 |
|---|---|
| **定格段**（f044~f057 / f071~f085 / f126~f148） | **0.00 ~ 0.81** |
| 动态段（同片其余部分） | **1.25 ~ 90.47** |

差了 **5 ~ 100 倍**。参考里没有"大致静止、个别东西还在飘"这种状态 ——
背景、配角、影子、飘落物，**全部是 0**。

**这条直接变成了产品的门禁判据**（`tests/verify_timestop_freeze.gd`）：
时停期间 `battle._world` 下除了携带者自己与时停自身的演出，**一个节点都不许变**。
修之前产品实测是 **56 个节点照常在动**（背景鱼群 Δpos 1.4112 → 1.4188，
和时停前**一模一样**），修完 **0 个**。

### ② 定格是**长镜头**，不是一闪

三段定格分别 **1.4 秒 / 1.5 秒 / 2.3 秒**（14 / 15 / 23 帧）。
最长那段（f126~f148）是全片结尾，**2.3 秒一动不动**。
⇒ 我们 4/7/20 秒的定格时长在"读得出来"这一点上是够的，问题从来不是时长。

### ③ 入停是**一记过曝白闪**，一帧内完成

f121 → f122 那一下：

| | f121 | f122 | 变化 |
|---|---|---|---|
| 亮度 | 131.9 | **180.9** | **+37.2%** |
| 饱和 | 85.9 | **71.7** | **−14.1**（被闪白冲淡） |
| 运动量 | 36.55 | **79.72** | 全片第二高 |

然后 **3 帧（0.3 秒）**落到冷暗（亮度 181 → 135 → 97 → 76），f126 起彻底定格。
出停那一下同理：f091 亮度 **+153.3%**，是全片运动量最高的一帧（90.47）。

⇒ **进出都要有一记强冲击，不是渐变**。产品现有的「反色闪」
（`_ts_visual_start`：0.05 秒冲到 0.92、0.13 秒回落）时长同量级，形式对得上。

## 已知取舍 / 没照搬的

- **没有照搬"整屏去色"**：参考里定格镜头偏冷暗，但那几帧本来就是**夜间外景**，
  换镜头造成的亮度落差（−52% / −57% / −59%）里分不出多少是"时停的色调"、多少是"镜头本身"。
  拿分不清的东西当依据去调产品的灰度 shader，就是 memory
  `fb-color-criteria-need-clean-background` 记的那个坑（基线不为零别调阈值）。
  ⇒ 只取**能干净分离**的那三条。
- **没有动那个钟**：用户原话「那个时钟还可以」。
- 参考是 2D 动画的**分镜**语言（靠切镜头强调定格），我们是**一台连续的 3D 相机**，
  切不了镜头 ⇒ 「定格」这件事在我们这里只能靠"世界真的不动"来表达，
  这也是为什么①那条比在参考里更要紧。
