## 3. 需求 ↔ 代码的出入

- 召唤物属性现在只写在文案里，而且是手写进句子的；做角色页必须读代码常量（同 `minion_codex.gd` 的教训：手抄必漂）。
- 每个召唤调用点已强制带中文名（门禁 `verify_summon_label`），但没有「召唤物 → 图鉴条目」的登记表，新加召唤物不会自动进图鉴。

## 4. 方案（思路）

**一、图鉴第一栏改名「角色」，分组列出**：龟（28）→ 战场单位 → 召唤物（按来源：龟技能 / 装备 / 羁绊）。龟仍排在最前。

**二、每个单位一页，统一结构**：
1. 形象（待机动图）+ 名字 + 来源（哪只龟 / 哪件装备 / 哪个羁绊，点了跳过去）。
2. 定位：近战 / 远程、射程、攻击间隔、移速、存在多久（持续时间 / 死后会不会再召）。
3. 属性表，按来源五种写法：
   - 按星级：★1 / ★2 / ★3 三列；
   - 按主人比例：「生命值 = 主人最大生命值的 X%」；
   - 按羁绊档（百夫长）：(2) / (5) / (8) / (10) 四列，下面一行写「每件不同长矛每颗星使生命值与攻击力 +3%」；
   - 按阵亡 / 被复制单位：「继承阵亡单位最大生命值与攻击力的 X%」，比例按羁绊档列。
   - 按龟的等级 / 合体数 / 成长（机甲、随从、小木斧化身）：写公式，例「生命 =（100 + 2 × 等级）× 炮数」，下面给几个常见取值。
4. 技能与行为：普攻 → 技能 → 被动，和龟页同一种结构、同一种写法。
   - **登场效果算被动**（用户 11-27「这个应该作为角色的被动吧」）：例百夫长【从天而降】= 落地击飞全场敌人 1.5 秒、150% 攻击力魔法伤害。
   - **什么时候召唤**（第 8 秒 / 生命值低于 60%、每个战场一次）是召唤它的羁绊 / 装备 / 龟的规则，写在那一边，角色页只在「来源」里一句带过。

**三、羁绊 / 装备文案的新写法**：句子里只写「召唤谁、什么时候、它会做什么、每档多了什么本事」，不写召唤物的生命 / 攻击 / 护甲数字；名字做成可点的链接，点了跳到它的角色页。例：

- 长矛 (2)：每件 +5% 龟能回复速率，召唤百夫长
- 长矛 (5)：每件 +10% 龟能回复速率，百夫长攻击贯穿直线，放下盾时横扫周围敌人
- （数字都在百夫长那一页）

**四、单一数据源**：新建 `scripts/gamedata/summon_codex.gd` 登记表（单位 id、名字、形象、来源、属性来源类型、引用哪个代码常量），角色页只读它；门禁扫全部 `_spawn_summon(` 调用点，每一种都必须在登记表里，漏一个就红。
