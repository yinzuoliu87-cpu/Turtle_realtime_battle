## 3. 需求 ↔ 代码的出入

- 用户说「它也是 AI 游戏」—— 两边的「AI」不是一回事：它是**玩家运行时**用 AI 生成内容；我们是**开发时**用 AI（我）写代码、出图。用户要学的是**开发方式**，所以重点是它的「原子项 + 参数化模板」这套生产结构，而不是把运行时 AI 搬进游戏（那会碰服务器裁判的确定性与公平，另立需求）。
- 它的平衡问题没解决，我们反而有它没有的东西：确定性模拟 + 裁判机 + 机器人对局，可以把「每个新组合先自动跑几百局」做成门禁。

- A3 **数值预算**：给每个原子定「强度预算」，新组合自动跑机器人对局，胜率出带就红（扩现有 balance 门禁）。
- A4 **美术**：「AI 出稿 → 手工 / 规则调优 → 用户认」写成固定流水（现有 PixelLab + `pixel_art_audit` 的延伸）。
- A5 **音效**：给原子配声音模板（起手 / 飞行 / 命中），批量生成 + 统一响度。

### 8.3 S2 / S3 拆包实证（2026-11-04，Demo 0.x Steam 5294350）

方法：Demo 是 Unity（il2cpp + Addressables）。`tools/oneoff/blackbox_unpack_study.py` 只读统计三个包，不导出素材。另实玩 3.5 分钟录屏（`.out/blackbox/s2_play.mp4`，不进仓库）。

**① 音效（音效包 103 条 + 背景乐 4 条）**
- 玩家技能**没有一条专属音效**：名字带元素词（火 / 冰 / 雷 / 毒…）的 0 条。所有 AI 生成的技能共用 `player_shoot` / `sfx_shoot` 出手 + `hit8` 命中 + 3 条 `etfx_explosion_*` 爆炸（来自商用特效包 Epic Toon FX），其余如 `grenade_pin_foley_003`、`magnetcrossbow_single_001`、`warper_001` 是商用音效库原名。
- 只有**首领技能**是专做的，且一律「前摇 pre + 命中 hit」两段：激光 / 锯 / 斩 / 旋斩 各一对；频繁命中的（激光、能量球）命中音做 **5 个随机变体**防耳疲劳。
- 等待类做「开始 / 循环 / 结束」三段：AI 生成（`generatestart / generateloop / generateend`，另有 29.6 秒长版）、融合、孵化；奖励按稀有度分 `normal / rare` 两条。
- ⇒ 对 A5 的修正：它不是「每个原子配起手 / 飞行 / 命中三段」，而是**玩家技能共用一小套 + 首领技能两段 + 命中多变体 + 等待三段 + 稀有度分档**。

**② 特效（成品 455 个 · 粒子系统 3870 · 材质 2044 · 贴图 632）**
- 玩家技能按「形态 × 元素」**逐格手做**：激光 / 追踪 / 爆炸 / 增益 / 环 / 子弹 × 火 / 冰 / 电 / 毒 / 常青 / 神圣 / 光，每格一套成品（拼音命名 `fx_playerskill_boom_fire_01_body`，中国特效师手做），每套再分**主体 body + 辅助 fuzhu** 两层；一个成品中位 6 个粒子系统、最多 19 个。
- 共用的只有底层：2044 个材质里 2023 个用同一个自研万能着色器（`VFX_Uber`，开关式功能：软粒子 / 遮罩 / 溶解 / 扭曲 / 边缘光 / 顶点贴图）；贴图几乎全是**灰度**的形状 / 噪声 / 遮罩（一张噪声被 663 个材质用到）；颜色全靠材质 `_Color` 的 **HDR 染色**（火 (19.5, 3.4, 0)、冰 (0, 7, 19.5)）—— 中心过曝成白、边缘透出元素色，这就是 S1 看到的「白芯 + 元素色外晕」的实现。
- 配色实测（量尺已标定：火爆炸量成橙红、冰爆炸量成蓝 100%）：

| 冰 | 蓝 76% | 21% | 8.5 |

- ⇒ **A2′ 配色规范（有数据版）**：① 每种伤害 / 效果类型一个固定色相家族；② 约 1/5 的层是白芯；③ 同色相的两类靠亮度拉开（不新造颜色）；④ 持续 / 阴险类（毒、诅咒）压暗、不发光；⑤ 前摇比命中暗；⑥ 主体给形状、辅助层给高光。我们是像素画 Sprite3D、没有 HDR 泛光 ⇒ 「HDR 亮度」对应成「调色板里最亮那两格的占比」。每件特效仍各画各的逐帧素材（不碰素材铁律）。

**③ 技能数据 —— AI「搓技能」的真身（技能描述语言 179 份）**
- 每个技能是一份 JSON：`meta`（名字 / 描述 / **实现说明**：模型用中文写出「`entry` 生成火弹、`on_hit_unit` 挂灼烧…」）+ `cast`（出手 6 种：点按 / 按住 / 开关 / 蓄力 / 弹药）+ `entities`（实体 4 种：飞弹 225 / 激光 / 连锁 / 召唤）+ `triggers`（触发 9 种：入场 / 命中单位 / 定时 / 生成时 / 距离 / 撞墙 / 蓄力松开 / 受伤 / 击杀）→ `action`（动作 4 种：生成 / 改属性 / 上状态 / 改实体）；实体身上挂**积木 31 种**（寿命 / 形状 / 速度 / 最大命中 / 撞击伤害 / 高度 / 追踪 / 之字 / 回旋 / 弹墙 / 连线…）。
- 外观 = `visual {category, theme, param{intensity}}` + 实体的 `element` 标签 ⇒ 引擎按「外观类别 × 元素」去 ② 那张手做表里挑成品，`intensity` 只调大小亮度。**AI 只写积木 JSON，不画特效、不写代码**。
- 例「灼烧弹」：点按 → 入场时朝光标生成 1 个火元素飞弹（圆 0.35、速度 18、火伤 0.485、命中 1 次即消失、寿命 2 秒、外观 energy_ball 强度 0.5）→ 命中单位时对它上「灼烧」。
- ⇒ 对 A1 的意义：它的「原子」= 4 实体 × 9 触发 × 4 动作 × 31 积木，一张表就能描述 179 个技能（含首领技能）。我们 28 龟 + 59 装备若照此抽，先数清我们的触发 / 动作 / 积木各有几种（A1 框架方案第一步）。

### 8.4 A1 框架方案（只写方案，本周不迁结算；2026-11-04）

**对照（数据来自 §8.3 ③ 与本仓 grep 粗数，不是逐行解析）**

| | 黑箱 | 我们 |
|---|---|---|
| 内容量 | 179 个技能（含首领） | 28 龟技能入口 `_sk_*` 85 个（`scripts/systems/skills/` 66 文件 1.16 万行）+ 59 件装备（`scripts/systems/equip/` 82 文件 2.2 万行） |
| 触发 | 9 种（入场 / 命中单位 / 定时 / 生成时 / 距离 / 撞墙 / 蓄力松开 / 受伤 / 击杀） | 约 15 种钩子：命中 / 普攻 / 受伤 / 阵亡 / 击杀 / 登场 / 法力满 / 受魔法伤 / 闪避 / 被治疗 / 上盾 / 反弹 / 挂持续伤害 / 落地 / 定时（`_tick_eq_intervals`） |
| 动作 | 4 种（生成 / 改属性 / 上状态 / 改实体） | 共用函数早就有：直接伤害 `_apply_damage_from` 173 处 / 51 文件、治疗 64 / 29、护盾 72 / 38、击退 51 / 23、增减益 40 / 19、召唤 38 / 15、眩晕 31 / 16、给龟能 18 / 9 |
| 组合方式 | 数据（JSON 积木），引擎一个解释器跑 | **每个文件手写「哪个触发 → 哪个动作 → 什么参数」**；参数散在代码常量里 |
| 外观 | 「类别 × 元素」查手做成品表 | 每件各自一套演出代码（`*_vfx.gd` 等 25 文件 2.5 万行） |

**结论**：我们缺的不是「原子动作」（已经是共用函数），缺的是**接线那一层的数据化**。A1 = 加一层「效果描述 + 一个解释器」，动作仍调现有函数，外观仍是每件自己的手画素材（按 id 挂，和黑箱的手做表同构，不碰素材铁律）。

**框架（下一版起做，这一版不动）**
1. 效果描述（`scripts/gamedata/`，纯数据）：`{trigger, cond, target, action, params, vfx_id}`；`target` 用现有选人函数（最近 / 最远 / 直线首敌 / 扇形 / 全体）。
2. 解释器（在 `_sim_step` 调用链上 ⇒ 按 CLAUDE.md §6 留主文件或 `scripts/systems/equip/` 新文件，走 `DetMath`）：现有钩子处调一次 `EffectRunner.fire(trigger, u, ctx)`，查表执行。
3. 迁移顺序：先迁 2~3 件「定时 + 单次伤害 / 护盾」的最简单装备当样板（例：048 黄铜手铳、049 连发弩这类周期件），复杂的（召唤、多段演出、跨路状态）最后。
4. **判据现成**：`verify_rules_fingerprint`（5 局裁判真入口 + 静态表摘要）—— 迁移前后对局结果逐字相同 ⇒ 证明「只换了组织方式、没改结果」，`RULES_VER` 不用升；不同就是迁错了。这是黑箱没有的东西（它平衡问题自认没解决）。
5. 新装备写成数据后，A3 预算门禁（`tools/equip_budget_audit.py`）可以从「只管属性」扩到「效果也算预算」。

**为什么本周不迁**：离周日 0.22.8 太近，迁移碰结算路径；框架先写在这里，0.22.9 起按上面顺序做（用户点头后）。
