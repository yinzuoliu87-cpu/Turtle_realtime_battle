## 2. 调查

全部结论来自真实对局探针 `tests/_probe_timestop_lanes.gd`（`_` 前缀 ⇒ 自动发现不收它，不进门禁），
跑法见文件头注。**不是读代码推理出来的** —— 读代码只产出了怀疑，证据是跑出来的。

### 2.1 三战场实测（★3，`TURTLE_SEED=20260916`，det 模式 1 帧 = 1/60 游戏秒）

| 战场 | 场上带 059 的单位 | 本路时长 | 蓄力帧 | 定格帧 |
|---|---|---|---|---|
| 上路 | 1 | 28.5 s | 64 | **1216** |
| 下路 | 1（`PROBE_MODE=both` 特意装的对照组） | 52.8 s | **0** | **0** |
| 终极 | 1（随幸存者快照带进来） | 36.9 s | **0** | **0** |

多种子复现：`7 / 11 / 23 / 41 / 20260916` 结论一致。

**分母纪律**：最早一轮 `PROBE_MODE=split` 的下路统计是「0 蓄力 0 定格」，但那一路
**本来就没人带 059**（分母 = 0），不构成 bug 证据。补了 `both` 对照组（下路真有一个 ★3 携带者）
才算数 —— 这一条写在探针的打印里，避免下次再拿它当证据。

### 2.2 四条独立缺陷

| 编号 | 缺陷 | 证据 |
|---|---|---|
| **A** | `_ts_fired` 永不重置 | `timestop_system.gd` 全仓只有三处出现：`:27` 声明 / `:78` 判断 / `:92` 置 true。换路清场 `dual_lane_flow.gd:937-945` 不碰它 ⇒ 下路与终极永不触发 |
| **B** | 蓄力中换路整场被吞 | 换路清了 `_ts_charge_casters`，没清 `_ts_charging` / `_ts_charge_t`。走真入口 `_dl_lane_over()` 实测：换路瞬间 `charging=true / charge_t=1.00 / casters=0` → 下路白蓄 70 帧 → `_ts_fire()` 见 casters 空直接 `return` → **定格 0 帧**，而 `_ts_fired` 仍是 true |
| **C** | 演出叠加层被永久隐藏 | `_ts_overlay` / `_ts_flash_overlay` 的 `visible=false` 只写在 `dual_lane_flow.gd:941-942`，**全仓无一处写回 true**；`_ts_ensure_overlay()` 见对象还在直接 return。探针实测下路与终极两层均「存在=true 可见=false」 |
| **D** | iOS 上从来没有空间扭曲 | `timestop_system.gd:181` 移动端分支（2026-07-11 为修「整屏黑」写的不读屏版）里 `warp` / `warp_r` / `zoom_blur` 三个 uniform **声明了但 fragment 一次都没用**。量过：桌面版各用 1 次，移动版各 0 次 |

C 目前被 A 遮住：因为下路根本不触发，所以「没画面」还观察不到。**修好 A 之后 C 才会暴露** ——
两条必须一起修，只修 A 会换来「定格了但一个画面都没有」。

### 2.3 时停时长（回答「确定时停时间正确吗」）

| 星级 | 设定 `TS_DUR` | 实测跨度 | 差 | 其中顿帧 hit-stop |
|---|---|---|---|---|
| ★1 | 4.00 s | 245 帧 = 4.0833 s | +0.0833 s（+2.08%） | 4 帧 |
| ★2 | 7.00 s | 425 帧 = 7.0833 s | +0.0833 s（+1.19%） | （同族，未单独量） |
| ★3 | 20.00 s | 1212 帧 = 20.2000 s | +0.2000 s（+1.00%） | 12 帧 |

**账是平的**：★1 = 240(设定) + 4(顿帧) + 1；★3 = 1200 + 12。
根因在 `RealtimeBattle3DScene.gd:2283-2286` 的 `if frozen: … elif in_ts: _ts_remaining -= dt` ——
**二选一**，所以顿帧的每一帧时停倒计时不走，而 `_ts_active` 还在 ⇒ 定格被拉长，
幅度与本次定格期间打了多少下成正比（1~2%，方向是**变长**）。

⇒ **时长本身没写错**，TS_DUR 设对了也正确递减。这 1~2% 是 hit-stop 结构的副作用，
**不在本次改动范围**（数值/手感不擅自改，见 §5 未决点 U2）。

### 2.4 文案现状

`data/phase2-equipment.json` `p2eq_059`：`effectDesc1` 写「持续 4/7/20 秒」+「**一场战斗一次**」，
`effectBrief` 写「全场定格 4/7/20 秒，**一场一次**」。秒数与常量一致（占位符 `{C:TimestopSystem.TS_START_T}` 也活着）。
但**语义改成每战场一次后这两句就错了**，必须同步改 —— 文案就是规格（memory `fb-effect-text-is-the-spec`）。

## 3. 与现状的出入

- 用户的直觉「严重 bug」成立，但**不是时长问题**：时长是对的，坏的是「后两个战场根本不触发」。
- 我最早报给用户的「下路完全没时停」那句**证据不成立**（分母 0），已在 §2.1 更正。
- 「空间扭曲不见了」在 iPhone 上 = D；**桌面端没有回归**（最近一次改动 `c6a1efe4` 第五版重做，warp 一直在）。
- C 是一条**尚未被任何人看到**的缺陷 —— 它被 A 挡着。不一起修就会在修完 A 的那一刻变成新 bug。
- 「一场战斗一次」的旧语义与 `TS_START_T` 用**全局 `_t`** 比较是配套的；改成每战场一次就踩上
  CLAUDE.md §3.4（`_t` 跨路累加、永不重置）—— 下路一开场 `_t` 已经 40 秒 > 10 ⇒ **第一帧就放**。
  所以 A 不是「把 `_ts_fired` 清掉」那么简单，必须同时引入本路 t0。

## 4. 方案

### 4.1 A —— 每个战场各一次（含本路 t0）

`timestop_system.gd`：

1. ~~新增 `var _ts_lane_t0`~~ **实现时改用现成的 `battle._sd_t0`**（= 本战场开打时刻，
   `_dl_start_fight` 每路重置；`star_system.gd:659` 已经在用同一个东西）。
   同一个概念存两份必然漂（memory `fb-hand-rolled-copies-drift`），所以不另存。
2. `_ts_update_trigger()` 的触发判据由 `battle._t < TS_START_T` 改为
   `battle._t - battle._sd_t0 < TS_START_T`。
3. 新增 `func reset_for_lane() -> void`：把 `_ts_fired` / `_ts_charging` / `_ts_charge_t` /
   `_ts_charge_casters` / `_ts_maxstar` 归位。
4. `dual_lane_flow.gd` 换路清场处调 `reset_for_lane()` —— **不在 `dual_lane_flow` 里逐个字段手改**，
   否则下次加字段又会漏一个（B 就是这么来的）。

### 4.2 B —— 蓄力状态跟着一起清

由 4.1 的 `reset_for_lane()` 一并覆盖（`_ts_charging` / `_ts_charge_t` 归位）。
另外 `_ts_fire()` 里 `casters.is_empty()` 的静默 return 改为**同时把 `_ts_fired` 放回 false**：
没放出来就不该记账成"这一路用掉了"。

### 4.3 C —— 演出层恢复可见

`_ts_visual_start()` 里无条件 `_ts_overlay.visible = true` / `_ts_flash_overlay.visible = true`。
**责任落在"要演出的人"身上**，不是落在"清场的人"身上 —— 清场只管隐藏，谁要放谁自己打开，
这样将来任何新的隐藏点都不会再制造同一个 bug。

### 4.4 D —— 两端统一改用 SubViewport 纹理做扭曲

移动端不能用 `hint_screen_texture`（2026-07-11 实测 gl_compatibility 下整屏黑），
但本项目的 3D 世界**本来就渲在一个 SubViewport 里**（`battle_world_builder.gd:136-159`，
`battle._sub`，`UPDATE_ALWAYS`）。⇒ 把 shader 的输入从「读屏」换成
**显式 `uniform sampler2D` + `battle._sub.get_texture()`**：

- 不碰 back buffer ⇒ 移动端安全（黑屏那条路根本不走）。
- 两端**合并成一份 shader**，维护面 −1（现在是两份要同步改的分支，D 正是分支漂移的产物）。
- 扭曲只作用于 3D 世界、不含血条/数字 —— 与 `_ts_overlay` 挂 layer 5 的设计意图
  （「只灰 3D 世界，数字/血条保彩」）一致，比原读屏版更贴设计。

⚠ 这一条**本机验不到真机**（见 §5 R1）。

### 4.5 文案同步

`data/phase2-equipment.json` `p2eq_059` 的 `effectDesc1` / `effectBrief`：
「一场战斗一次」→「**每个战场各一次**」。改完跑 `python tools/tooltip_number_audit.py`。

### 4.6 门禁

新增 `tests/verify_timestop_lanes.gd`（自动发现，无需登记）：

1. 换路后 `_ts_fired == false`；并直接驱动 `_ts_update_trigger()` 验「本路已打 0 秒不触发 /
   已打 11 秒才触发」（**同步断言**，不跨帧 ——
   跨帧就成了「时间过去了」的恒真式，memory `fb-gate-tautological-when-it-spans-a-frame`）。
2. 下路真能定格：走 `_dl_build_lane_field` 真流程，断言 `_ts_active` 非空且 `_ts_remaining` 落在
   `TS_DUR[star-1]`，判据**写死 20.0 不写 `TS_DUR[2]`**（写常量名等于拿被测对象当尺子）。
3. 蓄力中换路：走真入口 `_dl_lane_over()`，断言换路后 `_ts_charging == false`。
4. `_ts_visual_start()` 之后两层 `visible == true`（先手动置 false 再调，**否则是恒真式**）。
5. 分母断言：每条都先断言「这一路场上带 059 的单位数 == 1」。

每条都要**反向验证会红**（改坏产品代码确认门禁当场红，然后 `git diff` 逐行还原 ——
memory `fb-restore-mutations-after-reverse-verify`）。

### 4.7 收尾

`bash run-tests.sh`（**与 commit 分两次调用**，只认 `GATE_RC=` / `ALL PASS`）→ 版本号五处
（project.godot / export_presets ×2 / CHANGELOG / 路线图）+ tag → 本地 commit，**不 push**（除非点名）。

## 5. 已知风险与未决点

| 编号 | 事项 | 状态 |
|---|---|---|
| **R1** | **D 无法在本机验证**。移动端 shader 只有真机跑得出来，headless 不渲染、本机开 3D 窗口有 BSOD 记录。只能出 IPA 交给用户在 iPhone 上看。**若 SubViewport 纹理方案在 iOS 上仍黑屏，得回退到「移动端无扭曲」并另想办法** | 🔲 待用户真机验 |
