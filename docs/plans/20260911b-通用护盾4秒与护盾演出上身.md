## 2. 调查结论（现状 + 文件:行号）

### 2.1 「通用护盾 4 秒」确实是封板规则，装备层确实没实装

事实源：[`docs/design/技能改制设计决策.md:80`](../design/技能改制设计决策.md)
> 「全局规则: 所有"通用护盾"持续=4秒（嘲讽的"永久护盾"是特例除外）。」

原语本来就支持：[`battle_damage.gd`](../../scripts/scenes/battle/battle_damage.gd)
`_grant_shield(u, amt, dur = 0.0)`，`dur > 0` 才写 `u["shield_until"]`；
到期由 [`RealtimeBattle3DScene.gd`](../../scripts/scenes/RealtimeBattle3DScene.gd)
`_tick_periodic_passive` 的「限时护盾原语」那一段清掉。

**但 2026-08 那轮只扫了技能**：`bamboo_system.gd: REGEN_SHIELD_SEC := 4.0` /
`bubble_system.gd: SHIELD_SEC := 4.0` / `diamond_system.gd: FORTIFY_SHIELD_SEC := 4.0`
—— 三份各存各的，**装备层一处都没有**。

探针（穷举 `_grant_shield` / `_holy_convert` 全部调用点）：

| | 改之前 | 改之后 |
|---|---|---|
| 总给盾点 | 49 | 51 |
| 传了时长 | 18 | **24** |
| 没传（＝永久） | 31 | **25** |
| 豁免（写明理由） | 0 | **2** |

四件的调用点：
- `equip_tick_system.gd:411` — 012（`JELLY_IV = 4.0`、`JELLY_MAXHP_PCT = 0.04`）
- `equip_system.gd:2188` — 015（`THORN_SHIELD`）
- `equip_tick_system.gd:151` — 016（`IRONWALL_IV = 5.0`，全队均分）
- `equip_tick_system.gd:398` — 021（`BARNACLE_IV = 5.0`，给最高攻友军）

### 2.2 被否的那行金圈封着 44 个给盾点

`battle_damage.gd` 的 `_grant_shield` 末尾：
`battle._skill_ring(u["pos"], Color(1.0, 0.85, 0.2, 0.4), 44.0)`
—— 在**地上**画一个躺平的圆环（`axis = AXIS_Y`、`y = 0.05`）。

同一行 **2026-08-09 就被否过一次**（看 095：「又是程序生成的环？哪个商业游戏是你这么做啊」），
当时我只加了 `_own_grant_vfx` 让 095 自绘时跳过，注释里写「那是单独一轮的事（已记路线图）」
—— 而路线图里其实没记。**一年后原样撞回来。**

### 2.3 已有的两张罩子不能拿来用

`shield-dome.png`（046 幽灵墨鱼闪避得盾）、`fx-hex-bubble.png`（石龟岩石护盾常驻罩）
各是那两件的招牌。铁律 `fb-no-asset-reuse-unless-told`：「新内容一律新素材……别拿别的顶替」。

## 4. 方案（穷举清单）

### 4.1 一个共用常量

`BattleDamage.COMMON_SHIELD_SEC := 4.0`，放在 `_grant_shield` 自己头上。
技能层那三份是各系统的常量，本轮**不动**（合并它们不在需求里）。

### 4.2 四个调用点各加一个参数

`equip_tick_system.gd` ×3（016 / 021 / 012）、`equip_system.gd` ×1（015）。

### 4.3 `_holy_convert` 跟随母次时长

015/016/021 都是**盾类**装备 ⇒ 盾羁绊 9 档时每次给盾都会额外转 20% 圣光盾。
不传 `dur` 的话主盾 4 秒过期、那 20% 永久留着 = 把刚修的漏又开回来 20%。

### 4.4 限时 / 永久分账（三个触点）

- `_grant_shield`：`dur > 0` 时把这份记进 `u["shield_timed"]`（与 `shield` 是**包含**关系）
- `ShieldMath.absorb`（两条伤害路的收口，CLAUDE.md §3.3）：扣盾时**先扣限时那份**
- `_tick_periodic_passive` 到期：只扣 `minf(shield_timed, shield)`，永久那份留着

### 4.5 演出换到身上

- 新素材 `assets/sprites/vfx/shield-shell.png`：8 帧 × 64×64，**4 色 / 0 半透 / 纯灰**
  （颜色由调用点 `modulate` 决定，同 `skill-ring.png` 的理由）
- **格子镂空** —— 罩子必须看得见里面的龟；用半透明做"透"正是被否掉的观感
- 8 帧：外缘合拢 → 满格 + 高光沿缘扫 → 按确定性顺序掉落，**每帧内容都在变**（防淡出病）
- 帧推进挂在 `_follow_vfx` 新增的 `anim_fps` 上走**游戏时钟**，不用 tween（＝第二条钟）
- 生成器 `tools/gen_shield_shell.py`，**直接按最终分辨率画**：格线宽度就是 1 个最终像素，
  走 BOX 下采样会被摊薄再被 alpha 阈值切成断线

### 4.6 012 改名 + 图标 + 来源标识

- `data/phase2-equipment.json` `name`/`emoji`；代码注释 8 处
- 新图标：三片带状叶片从固着器长上来；新增 `kelp` 板（5 色），与 019 的薄荷青 `jade` 拉开色相
- 新素材 `kelp-frond.png`（6 帧 × 32×48），脚下长四丛、**错开起跳**
- **不置 `_own_grant_vfx`** ⇒ 通用六棱罩照样罩上。罩子是全游戏「我有盾了」的统一语言，
  海藻说的是「这次的盾是谁给的」，两层各司其职

### 4.7 台账 + 棘轮（对应 E）

`tools/shield_duration_audit.py` + `tools/shield_perm_debt.json`，进 `run-tests.sh`。

- 存量冻结（一刀切要求清零 = 门禁第一天就红，而第一天就红的门禁只会被 `|| true` 掉）
- **新增当场红**
- **还了债要销账**：台账里某条已经改成限时了也 FAIL ——
  棘轮才只往一个方向转。（`zero_caller_audit` / `arch_budget` 只做了前两条。）
- 豁免写 `# shield-perm-ok: 原因`，**必须写原因**，原因会被打印

为什么不是「写进路线图等拍板」：memory `fb-registered-todos-rot` ——
这仓库里「待用户拍板的登记会烂」有前科（4 条里 3 条我后来照着念全念错了）。
**文档不会自己红，台账会。**

**实际改了什么（与第 4 节的偏差）：**

| 计划 | 实际 | 偏差 |
|---|---|---|
| 4.1 共用常量 | `battle_damage.gd` `COMMON_SHIELD_SEC := 4.0` | 无 |
| 4.2 四个调用点 | `equip_tick_system.gd` ×3 + `equip_system.gd` ×1 | 无 |
| 4.3 `_holy_convert` 跟随 | 加了 `dur` 形参并透传 | 无 |
| 4.4 分账三触点 | `_grant_shield` / `ShieldMath.absorb` / `_tick_periodic_passive` | 无 |
| 4.5 护罩 | `gen_shield_shell.py` → 8 帧 512×64，**4 色 / 0 半透 / 满格帧中心 17×17 填 0 个** | 无 |
| 4.6 012 | 改名 + `kelp` 板 + 新图标 + `kelp-frond.png` 6 帧 | 无 |
| 4.7 台账 | 25 条存量冻结，进 `run-tests.sh` | 无 |

**新发现的坑（都是做的过程中量出来的）：**

1. **护罩第一版渲出来是个高尔夫球** —— 格子太小（`HEX_S = 0.285`）+ 棱边太粗，
   剩下的格心是圆的；而且满盘 1312 个不透明像素**会把龟盖住**。
   ⇒ 格子放大到 0.40、棱边收到 1px、**中心 `CORE_R` 以内不画格线**，降到 624。
2. **格线按"像素自己的半径"判会留一堆朝内扎的 1px 断桩** ——
   同一条棱边一半在里一半在外。改成按**格子中心**判，格子整进整出。
3. **海藻第一版是铁丝** —— `hw = 0.10~0.175` 渲出来只有 2px 宽，
   而且 2px 里塞不下"受光/主色/暗面/描边"四档。海藻是**带状叶片**，得宽；
   同时把最亮那档从**尖端**（渲出来是一截白线头）挪到**受光边中段**。
4. **海藻图标第一版是个绿色的 X** —— 三片都从中间起、填满整格。
   改成窄叶 + 三个分开的根 + 向上开扇 + 底部固着器 ⇒ 叶与叶之间有缝，轮廓才读得出来。
5. **我自己写的门禁判据错了两条**（不是产品错）：
   ① 帧序列用 `_t += 1.0/fps` 累加，八次 0.05 累出来是 0.39999997 ⇒ `int()` 掉回 7，
   量出 `[1,2,3,4,5,6,7,7]`。改成**绝对时刻**落在每帧中间。
   ② 断言 `not is_instance_valid(spr)` —— `queue_free()` **延到帧尾**才真删，
   同步跑的测试里它一直是 true。改成量真实产品账：**从跟随表里摘销** + `is_queued_for_deletion()`。
6. **门禁跑完还红 3 条，全是这次改动的必然后果**（不是回归）：
   `text_golden` / `text_value_golden` 因为 012 改名（`--update` 重录快照），
   `plans_lint` 因为本文件第一版没按七节骨架写（就是现在这一版）。
7. **开窗前自己先看了 36 帧，抓到两个真问题**（这次没端给用户看）：
   ① 海藻 50 码太高，把龟的头和壳全埋了 —— 读成「龟站在灌木丛里」而不是「海藻缠上来」；
   且 `KELP_R = 0.30` 太紧，四丛堆在正中间。⇒ **34 码 + `KELP_R = 0.46`**。
   ② 海藻（0.565 秒）比六棱罩（0.40 秒）多活 0.17 秒 ⇒ 收尾剩一丛孤零零的草。
   ⇒ `KELP_FPS` 14→18 + `KELP_STAGGER` 0.045→0.030，总时长 0.42 秒 ≈ 罩的 0.40 秒，两层同时收。
8. **改了行为就要连描述旧行为的话一起改**（memory `fb-no-such-channel-needs-repo-wide-grep`）：
   全仓 grep「现状…通用金环」找到 **8 处现在时描述**（台子备注 / 两处羁绊演出注释 /
   095 门禁的两条断言措辞 / …），逐条改掉；095 那段**重做前的历史记录**保留原样，只加一行追记。
9. **门禁跑出过一条假红**：`verify_eq_venom_drone` 的【每帧开销 < 1.0 ms】在并行门禁里量到 1.0781 ms。
   它自带的**机器参照负载**同时报 ×1.98（冷机 = 1.00）⇒ 判定是降频不是回归。
   单跑三次全绿，冷机实测 **0.3324 ms**（预算 1.0，参照 ×0.99）。
   这正是 CLAUDE.md 里登记的本机 CPU 硬件故障；**阀值一个字没改**。

**门禁结果**：第一轮 `GATE_RC=1` —— FAIL x3 / PASS 301，三条全是本次改动的必然后果（见上面第 6 条）；修完重跑 **`GATE_RC=0` · ALL PASS (304/304)**。

### 9.3 ★挖出一个我自己埋的坑

### 9.4 门禁判据换形状（不是放松）

| 原判据 | 现判据 | 为什么 |
|---|---|---|

### 9.5 additive（用户当场拍板「开」，只给护盾罩这一层）

**为什么非开不可**（1:1 实拍量过）：不用 additive 时，任何浅色以低 alpha 叠在近黑地图上都会变成
**灰褐薄雾**（深金→淡金只减轻一点），读不成「发光的罩」。

spec 阶段 4 那条「不用 `blend_add`（会洗白，颜色该由美术定）」是给**不透明手绘素材**定的；
护盾罩是**刻意的半透明叠加层**，additive 正是它该用的工具。**例外范围就这一个函数。**

⚠ 开完还要调 alpha：additive 下 alpha 只决定**加多少光、不遮挡** ⇒ 留在 64 时
淡金×0.25 叠黑底 =（64,59,40）暗橄榄，**看着像没开**。`A_FILL` 64→150 才真发光。

⚠ 做法细节：`Sprite3D` 的 billboard / modulate / texture_filter 都是喂**内部材质**的，
而 `material_override` 会整个替掉 ⇒ 这几样得在材质上再设一遍；帧选择不受影响（`hframes` 改的是网格 UV）。

### 14.3 ★★ 粒子做出来之后 1:1 仍然不合格 —— 两个互相独立的毛病

**ⓐ 配色串档**: 素材重索引到了 `jade` 板, 而 jade 板自己的注释就写着「薄荷青(偏蓝绿)」
(主色 110,200,148)。战场上龟本身就是青身 + 暗绿壳, 同色系 + 泛光 ⇒ 认不出是绿的。
判据形状: 光说「g 最大」卡不住(jade 的 g 也最大), **区别在蓝** ——
正绿 b−r=+8 / 薄荷青 b−r=+38 ⇒ 判据 = `g−r ≥ 100` 且 `|b−r| ≤ 25`。

**ⓑ 贴图被压 3.4 倍**: **染色实测**(把 `_mote` 整体 modulate 成品红 + 关泛光, 数连通域) ——

⇒ 改成 12px 一格 + 21.3 码 ⇒ `pixel_size` 0.0426 = **1 texel : 1 屏幕像素**。

标尺是**同一帧里量的**: 一只龟 ≈45 屏幕像素高 / 立绘帧高 = `TARGET_BODY_H` = 2.0 m
⇒ 台子(1280×720 · zoom=1.0)下 ≈23.5 px/m。这个数**随视口高度变**
(别处文件写的 28.148 px/m 是另一档视口, 两边都不算错);

### 16.2 ★★我立刻犯的第二个错：范围
