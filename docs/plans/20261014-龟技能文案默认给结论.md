## 调查
图鉴实拍（彩虹龟，1561×720）：
- 技能「查看全部」正文写的是推导式：「（50%×攻击力(40) = 20）生命值」。全库 `data/pets.json` 有 159 处（彩虹龟改写后 160）这种括号推导组
  （detail 138 / desc 17 / descMelee 4）；按系数来源：攻击力 137、最大生命值 14、攻击+生命 3、护甲 2、魔抗 2、三项合 1。
- 被动展开后，上面那行简述还在，下面全文第一句又说一遍（「每 6 秒随机获得一种颜色…」出现两次）。
- 「共 6 段」仍上色：10-14 去色规则只列了 秒/码/次/层，没有「段」。
- LoL 依据（`ref/20260930-LoL文案体例.md` §6.1，用户截的阿利斯塔 Shift 前后两张）：默认「74 (🔮) 魔法伤害」，
  按 Shift 才是「74 = (60 + 80%🔮)」。四条思路的第 1 条：默认给能直接决策的结论，推导按需展开。
- 多选项分点：LoL 688 条详细版 tooltip 里用 `<li>` 分点的只有 8 条，全是「几种模式选一种」的技能（卡牌大师 W 三张牌）。
  彩虹龟的红 / 蓝 / 绿正是这个形状。

## 出入
- 需求说「按参考来」；代码事实是 159 处推导式在所有落点（图鉴 / 战斗信息面板 / 选龟页）都**默认展开**。
- 「简介 + 全文」两层本身是对的（与 LoL desc / tooltip 对应），错在展开时两层同时显示。

## 方案
1. **渲染层收起推导**（不改数据，`text_golden` / `brief_detail_audit` 不受影响）：`SkillText.render_html` 把
   「（… = {X:expr}）」整组换成「{X:expr}」+ 后面一组系数来源的属性小图标（照 LoL「74 (🔮)」）。
   `SkillText.show_formula` 默认 false；图鉴技能 / 被动详情加一个「公式」切换钮，打开即恢复原推导式。
2. **展开时隐藏简介行**：被动 / 普攻条 / 技能卡点开后只留标题 + 全文。
3. **「段」也不上色**：`copy_lol_style_lint` 单位表加「段」，pets.json 里包着「共 N 段」的颜色 span 去掉。
4. **彩虹龟改分点**：被动三色效果、反射附带的【强化棱镜】四色效果改成每色一行「• 红色：…」。数值占位符不变。

## 已知风险与未决点
- 收起只认「括号里有 `= {X:…}`」这一种形状；另有 11 处「= {X:」不在括号里，不收（保持原样），实施时逐条看。
- 小图标只覆盖 攻击力 / 最大生命值 / 已损失生命值 / 护甲 / 魔抗；推导里出现别的属性就不画图标，只给数字。
- 切换钮是全局静态开关（`SkillText.show_formula`），战斗信息面板与选龟页不加钮，永远给结论。
- 分点用「• 」行首符号 + 换行，不是真正的列表控件；窄框里第二行不会缩进。

## 验收

- [x] 展开时简介行不再与全文同时出现 —— `verify_skill_formula_collapse` ⑤（反向验证: 去掉条件 ⇒ 红）
