## 2. 调查

参考与证据全部记在 `docs/plans/ref/20261026-周末弹窗商业参考.md`：

- 荒野乱斗客户端字符串表的键名写明每句话用在哪一屏：「段位提升！」= `TID_BATTLE_END_RANKED_RANK_UP`（**升段那一局的结算屏**）；「排位赛赛季已结束 / 本赛季最高段位 / 领取」= `TID_RANKED_SEASON_END_POPUP_*`（**赛季结束后登录**）；战队联赛（**按周**结算）= `TID_CLUB_LEAGUE_FLOW_*`。
- 两段不剪辑实录逐秒：战队联赛周结束后登录 = 「比赛日已结束」→ 整屏「赛季已结束」自动过 → 最终排名 + 本周奖励数上去 → 旧联赛徽章闪光变新徽章「已晋级」→ 回大厅奖励飞进钱包；排位一局 = Match over → 双方数据 → 进度屏（升段在这里演）→ 大厅。
- 炉石百科：新赛季后**第一次登录或第一次进对局**出一次赛季公告。
- 结论：**达成那一刻在结算屏上庆祝（徽章变身）；周期结束后登录平实结算，一屏一件事。**

## 3. 需求 ↔ 代码的出入

- 积分赛第 11 胜那一局（晋级的那一刻），结算屏只写「胜利」「赛季胜场 +1」——**晋级一个字没有**（`battle_hud._result_headline/_result_subtitle`）。
- 闯关赛第 4 胜那一局只有「已晋级！」三个字。
- 收盘弹窗是一张塞满的卡：战绩混在句子里、奖励一行小字、无标题底板、主次按钮同样子。
- 积分赛 / 闯关赛 / 决赛日在全游戏**没有图形标识**（赛程页、模式卡都是纯文字）。
- 我第一版把「徽章加光」的庆祝塞进收盘弹窗 —— **时刻放错**（用户指出后查证）。

## 5. 已知风险与未决点

- **R1（已定）徽章跟游戏其它地方的关系**：只放弹窗 = 玩家没见过的图案。用户 10-26「不用动主菜单吧，赛程条这些要动」⇒ 赛程页 + 弹窗 + 晋级仪式用同一套，**主菜单模式卡不动**。
- **R2 按钮仍是平涂棕色**：`UISkin.card_button` 是用户 10-22 点名的统一样式，本次不动；离商业游戏的立体按钮有差距，单独提给用户。
- **R3（已做）仪式背后的光**：用户「出」⇒ 放射光 1 次 + 循环动画 1 次（共 12 次额度）；动画 8 帧风格不一，只用其中一致的 4 帧。
- **R6 与参考仍有差距（如实记）**：用户「你自己觉得和你参考的东西有任何关系吗」「你知道人家是动态的吗」⇒ 按荒野乱斗升段 30fps 逐帧重做了动作时间线（过曝落定 / 白光换徽章 / 大字滑入 / 高光扫过）；但参考的冲击是**斜向白色碎光**、落定后有**本档主题电光**持续闪，大字是**定制字形** —— 这三样要美术，现在是整屏均匀闪白 + 静态光束 + 普通字体。
- **R4（已做）休赛日徽章**：同一套盾形，深蓝盾面弯月星星。
- **R5 服务器裁判的对局**（`referee_watch.gd`）走同一个结算屏；`_promotion_moment` 读的是 `_last_settle_kind` 与 GameState 战绩，服务器路径若在建结算屏之前没回填战绩，仪式不会出 —— 未实拍验证。
