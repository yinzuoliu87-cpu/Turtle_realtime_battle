## 出入

1. 问题总表写「按新商店流程重写」——不止商店：站位从对局挪进了背包（10-19），而教程**把站位按钮藏起来了**（调查 B 第 1 行），这比商店更要紧（玩家反馈第 2 条就是布阵）。
2. 玩家说「看半天还是没玩明白」——教程战斗全程零提示，三路与碎蛋这两条决定胜负的规则没人讲（调查 B 第 3 行）。云顶教程「部署」一段专讲站位与羁绊（调查 C）。
3. 07-23 用户原稿要「两把 + 图鉴」，10-07 用户改成「缩」：一把、删图鉴站。**本篇照 10-07 的「缩」**，不加第二把（D2）。
4. 周末赛事、服务器裁判 / 观赛、训龟大师都不进教程正文，改为「第一次遇到时」一行提示（参考共性 ③）——这些是账号侧的提示，不是教程的一部分，不违反沙盒约束（D4）。

### 2. 沙盒约束（不变 + 补两条）

1. 不变：整份状态替换、`save()` 不写盘、唯一带出 `onboarded`、完成 == 跳过 == 中途放弃（逐字节）、被杀 / 关窗下次再问。
2. **补：站位编辑在教程里也只改沙盒**。`formation_editor.gd:299-315` 每拖一下就 `GameState.dual_lineup = …; GameState.save()` —— 沙盒下 `save()` 已 return，但要在门禁里**真拖一次**再比存档字节（现有门禁从没在教程里走过站位，因为按钮是藏着的）。
3. **补：教程期间对服务器的写请求 = 0**。门禁装假传输，整条教程走完数 `_http` 发出的非读请求条数；读请求（服务状态等）照常。理由：教程战斗不该上传快照、不该进任何服务器账本；现在靠分散的几道闸，没有一条总量断言。
4. 教程战斗是本机对练习木桩，不走服务器裁判、不录像、不直播 —— 与周六 / 周日的服务器局无关，不在教程里提服务器。
