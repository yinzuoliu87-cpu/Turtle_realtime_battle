# 主菜单「处理存档冲突」提示条

日期：2026-10-23　|　状态：已完成（随下一个包生效，用户「这次攒多点再出包」）

## 1. 需求原文

- 我（2026-10-23）：「真冲突现在只在设置页显示「处理存档冲突」，不打开设置就看不到。要不要在主菜单也提示？我建议加。」
- 用户：「什么意思」→ 解释后「你觉得怎么做，就怎么做」

## 2. 调查（改之前的现状，代码实查）

- 冲突状态 `SupabaseNet.save_conflict()`：冲突 = 停推，等玩家二选一。
- 只有设置页反映它：账号行「云端存档与本地存档不一致」+ 一颗「处理存档冲突」键 → `_open_conflict_dialog()`。
- 主菜单齿轮下面已有一条「绑定账号 · 保存进度」提示条（`_bind_nudge`，只给没绑邮箱的号）；冲突只发生在绑了邮箱的号上 ⇒ 两条不会同时出现。
- 主菜单已有每秒一次的 `_sb_poll` Timer。

## 3. 需求 ↔ 代码的出入

- 冲突是推送回包里才知道的，进主菜单之后才可能出现 ⇒ 只在开屏时判一次不够。

## 4. 方案

- 提示条画法抽成 `_nudge_strip(name, txt, cb)`，绑定提示与冲突提示共用（各画一份必然漂）。
- `_conflict_nudge_sync()`：开屏对一次，之后挂在 `_sb_poll` 上每秒对账；冲突出现就亮、解除就收。
- 文案 `phase2_config.save_conflict_nudge_text()` =「处理存档冲突 · 云端同步已暂停」（与设置页那颗键同一个说法）。
- 点它 ⇒ 立一次性旗子 `SettingsScene.open_conflict_on_entry` 去设置页，进门直接打开二选一框。

## 5. 已知风险与未决点

1. ⚠ 只在主菜单提示；在别的页面（商店 / 背包 / 对局中）出现冲突，回到主菜单才看到。
2. ❓ 二选一框原有文案「云端存档已被其他设备更新」：加了回包丢失自愈（`docs/plans/20261023-云存档回包丢失自愈.md`）之后，能走到这个框的冲突基本就是另一台设备造成的，这句话成立。
