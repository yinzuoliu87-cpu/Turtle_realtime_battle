## 2. 调查

### 2.1 交互点清单与拍法

`scenes/` 下共 11 个场景，战斗场有自己的 `SELFSHOT`，其余 10 个走
**仓库里早就有的** `tests/_shot_scene.gd`（`SHOT_SCENE` + `SHOT_SETUP` 种子 +
`SHOT_POST` 交互钩子 + `SHOT_WAIT` 帧数）——**没有新造轮子**。

每个点拍两个比例：**1280×720（16:9 基准）** 与 **1280×960（4:3，最窄）**。
溢出只在窄的那个比例上看得见（训龟面板当年 1280 超屏而 1560 完全看不出）。
等 **450 帧**：实测 140 帧会拍到四个木牌互相重叠、420 帧才干净。

## 3. 与现状的出入

### 3.1 A：存档保护只有一道闸，而它盖不住台子

`GameState._ready()` 原来只判 `DisplayServer.get_name() == "headless"`。
**台子必须真渲染 ⇒ 都不是 headless ⇒ 那道闸对它们一条都不生效。**

探针 `tests/_probe_save_pollution.gd` 实证（全新空 `user://`）：

| 跑法 | 场景 `_ready` 时刻 | 跑完后存档文件 |
|---|---|---|
| 不带任何开关 | `savegame.json` **已存在** · `test_mode=false` | **1 个** |
| `NO_SAVE=1` | 不存在 · `test_mode=true` | **0 个** |
| 只给 dev 场景路径（第三道闸） | 不存在 · `test_mode=true` | **0 个** |

根因：写入发生在 **autoload `_ready` 的 `ensure_season()`** 里，
台子自己在 `_ready` 里置 `test_mode` **永远来不及**。

### 3.2 B：同一个概念在两处各写一遍

A8 那轮改了标题、改了行文案、改了比较器，**漏了表头**。
而 `verify_leaderboard_sort`（11 条）一条都没红——它只测 `Backend.leaderboard()`
这个函数，**没有任何判据看得见 UI 上的字**。

### 3.3 C：手写的数字迟早会漂

`SKILLS` 是 7 条；同一个文件 `:20` 的注释自己都写着「技能行 **7**×124」，
`battle_render.gd:26` 也写着「【七选一】」——**只有玩家看见的那一行是错的**。

### 3.4 D：九宫格默认 STRETCH，而中段有周期性装饰

`UISkin.nine()` 只设 margin，没设 `axis_stretch_*` ⇒ 默认拉伸。
`portrait-frame` 中段 32px 被拉到 168px，边上那排蓝宝石铆钉被拉扁成细线，
实拍只剩四个孤立的金角块——**我当时差点把它当成「占位符/调试辅助线」去查**。

## 4. 方案

| # | 改法 | 为什么是这个改法 |
|---|---|---|
| A | `GameState` 加**第二道闸** `NO_SAVE=1` 与**第三道闸**「命令行给了非主场景的场景路径」 | 第二道靠人记得，**第三道不用任何人记得**；导出版禁用了 `disable_path_overrides`，真玩家进程里不可能出现场景路径参数 |
| B | 表头改成「胜 · 余命 · 横扫」；两处描述现行行为的过期注释一起改 | — |
| C | 标题数字**从 `SKILLS.size()` 现算** | 把「五」改成「七」只是把同一个病推迟一次 |
| D | `UISkin.nine()` 加 `tile` 参数（`TILE_FIT`），匹配屏那处启用 | 素材不动、尺寸不动，只改「中段怎么填」 |

## 5. 已知风险与未决点

### 风险

- **R1（A）**：第三道闸靠「命令行里有非主场景的 `.tscn`」判定。
  编辑器 F5 跑的是主场景 ⇒ 不锁（门禁里有专门一条守这个，「挡多了也是错」）；
  但 **F6 跑当前场景会被锁** —— 开发者用 F6 试玩时存档不落盘。这是刻意取舍。
- **R2（D）**：`TILE_FIT` 会把中段微调到整数块（168/5=33.6 ⇒ **1.05 倍**），
  不是严格 1:1。像素风上 1.05 倍肉眼看不出，但它**确实不是零缩放**。
- **R3（D 的判据）**：阈值 `CV > 0.10` 是**按现状标定**的（实测 portrait-frame 0.210
  vs 其余三张 0.018~0.023，差一个数量级），不是从原理推的。
  将来哪张框在更低的 CV 上就糊了，该调的是阈值不是判据形状。
- **R4**：门禁**不扫匹配屏**——那两张卡是 `await create_timer(2.2)` 之后才建的、
  `2.6` 秒就 `change_scene` 进战斗，扫它要么量到空、要么撞上换场景把测试树掀掉。
  那一处的修复证据是 A/B 实拍，**这是显式登记的缺口不是静默截断**。
- **R5**：本轮只拍了**静态首屏**。弹窗、二级面板、拖拽中、动画中途这些态没拍。
