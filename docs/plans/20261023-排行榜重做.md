## 2. 调查结论（代码实查，2026-10-23）

### 2.1 现在是什么样

- 场景全由代码搭：`scripts/scenes/LeaderboardScene.gd`（1147 行，下称 LB）。
- **只有一张榜、没有页签**：按星期几自动决定（LB:132-137, 257-259）—— 周一「上周终榜」、周二~周五「本周排行」、周六周日都叫「积分赛终榜」。
- 面板宽 760 居中、固定 10 行可滚、只建可见行按页取数（LB:56-69, 705-719, 784-806）；自己那一行钉在底部（LB:721-734）；「我的位置」滚到自己（LB:860-881）。
- 列：「剩余生命 | 胜场 | 总场次」纯文字，格里零图标（LB:118-119, 645-667）。前三名金银铜签牌，0 胜不上领奖台（LB:953-972）。只有重名的人才显示玩家 ID（LB:99-104）。
- 点别人只弹「举报 / 拉黑」（LB:986-988）—— **没有个人资料、看不到阵容**。
- 数据：服务端 `week_leaderboard_page`（一页 50，`scripts/net/supabase.gd:2817-2844`）；排序 胜场 → 余命 → 横扫 → 先到 → 账号（`migrations/20261010_week_leaderboard_v3.sql:34-45`）。每行只有名次 / 昵称 / ID / 胜 / 余命 / 横扫 / 总场次 / 头衔（恒空）；**快照里有头像和统领，但服务端没下发**（`scripts/net/backend.gd:429`）。
- 每周二 00:00 UTC 清上周的 `ghosts` ⇒ **最多只能看本周和上周**，没有历史 / 总榜。

### 2.2 赛制决定了「排名」意味着什么

- 周二~周五积分赛：16 场、6 条命，**晋级线是绝对的（11 胜且没被淘汰）**，名次本身不决定晋级（`scripts/gamedata/phase2_config.gd:86-141`）。
- 周六闯关赛、周日小组赛 + 冠军杯赛的结果在另外两个场景（全场赛况 / 对阵图）。

- 10-19「排行榜你学一下其他游戏的，开放所有排名」；「周六 / 周日赛况保留到周一」。
- 10-20 App Store 审核要求举报 / 拉黑。

### 2.4 现在的问题（实拍 + 代码）

1. 人少时整屏「—」（10 行里大半空位）。
2. 每行纯文字，没头像、没阵容，点名字只能举报。
3. 晋级线（11 胜）没画出来，玩家看不出自己离晋级还差多少；淘汰的人没有「出局」标记。
4. 横扫不显示 ⇒ 三个数一样、名次却不同，看不出为什么。
5. 只有一张榜、不能切换：看不了好友、看不了上周（周一以外）、周六周日标题都叫「积分赛终榜」。
6. 面板固定 760 宽，宽屏两边大片空白。
7. 翻页失败不重试。

## 3. 需求 ↔ 代码的出入

- 「大型重做」本身没有和代码冲突的事实，但有两条**硬限制**会限制方案：① 历史榜 / 总榜需要改服务端保留策略（现在每周清）；② 头像 / 阵容要改 `week_leaderboard_page` 多下发字段。

## 4. 方案（方向，待用户拍板 §5 后细化）

参考：`docs/plans/ref/20261019-排行榜参考/`（荒野乱斗全球 / 本地 + 分类页签、大号数字、自己钉底；部落冲突好友榜）。

- **页签**：「本周」（积分赛）｜「好友」（好友之间按本周积分赛排）｜「上周」。周六 / 周日入口仍在顶栏跳全场赛况 / 对阵图。
- **每一行**：名次牌 → 头像（第一只统领立绘）→ 昵称 + 玩家 ID → 生命（心形，剩几颗亮几颗）→ 胜场（大号数字）→ 状态签（已晋级 / 已出局 / 进行中）。总场次进个人卡。
- **晋级线**：在「第一个达不到 11 胜的人」上方画一条线，写「晋级线 11 胜」；自己那一行显示「距晋级还差 N 胜」。
- **个人卡**（点任意一行）：头像、昵称、ID、本周战绩、当前阵容（3 只统领 + 装备），按钮「加好友 / 切磋 / 举报 / 拉黑」—— 与好友系统接起来。
- **人少时**：不画空位行，列表只放真实的人；下面一句说明。
- **服务端**：`week_leaderboard_page` 多下发头像 + 统领；新增 `friends_leaderboard()`；个人卡阵容复用好友方案的 `lineups` / ghosts（非好友只看统领与装备，不给完整快照）。

### 8.3 主会话接的一刀（2026-10-24 已接）

`scripts/net/supabase.gd::_week_lb_row` 是**白名单搬键**：服务端迁移加了 `lead` 之后，这里不放行就会被丢掉 ⇒ 屏上全是名字首字（假传输实测过）。在它返回的字典里加一项即可：

```gdscript
"lead": str(d.get("lead", "")) if d.get("lead", null) != null else "",
```

加完之后建议在 `verify_week_leaderboard` ③ 的假服务端行里带上 `lead`，补一条端到端断言（回包 → 头像贴图）。

**已接（2026-10-24 主会话）**：`_week_lb_row` 放行 `lead`；`verify_week_leaderboard` 假服务端每行带 12 只两两不同的 `lead`，新增「列表每行的头像 = 服务端下发的 lead（画出了贴图）」，去掉放行那一行当场红。服务端 `20261024b_leaderboard_lead`（`week_leaderboard_page` 每行多 `lead` = `snapshot_lead(snapshot)`）：PGlite 5 条 + 内测服已上。排行榜行的玩家菜单带上 `account`（「加好友」直接申请）。
