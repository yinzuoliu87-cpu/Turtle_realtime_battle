## 2. 调查

`tools/login_screen_audit.py` ＋ `/c/tmp/loginref/`：**558 张截图 / 343 款游戏**。
★**本节是参考数据的唯一事实源，别再重新抓。**几何数字一律现读 `python tools/login_screen_audit.py thresholds`。

### 2.1 诚实的边界（先写在最前面）

- **只有 13 屏是逐像素量过几何的**。其余是看图归类，几何数字**不来自它们**。
- 用 **Title Screen 当「首次启动屏」的替身** —— 真正的首启流程外人抓不到，这是替代品不是本体。
- 样本**偏西方/偏独立游戏**。国内手游的强制实名+登录墙在这批样本里**欠采样**。
⇒ 这些数字能用来判「我们是不是异类」，**不能**用来判「所以必须照抄」。

### 2.2 一条把我们单独拎出来的结论

> **224 款手机标题屏里，强制凭据墙 0 款。83% 连账号元件都没有。**

差别**不在尺寸、不在配色**，在**关不掉**。

### 2.3 逐像素那 13 屏 vs 我们（v0.19.470 那一版；现值现读工具）

| 指标 | 我们 | 全体中位 | 横屏手机中位 |
|---|---|---|---|
| 说明文字行数 | **5** | **0** | 0 |
| 一屏文本输入框 | **3** | **0** | 0 |
| 一屏可点元件 | 5 | 2 | 2 |
| 最小相邻间隙 | **2.2pt** | 23.3pt | 20.2pt |
| 靶短边 | 22.7pt | 45.5pt | 30.0pt |

间隙的**参考下限**：Hungry Shark **8.2pt**、Free Fire 9.2pt。中位 23.3pt。

### 2.4 参考在拼命消灭的那件事：打字

| 游戏 | 做法 |
|---|---|
| Sonic Rumble | 昵称框**预填** `Player_561962`，直接点 OK 就过 |
| Monster Hunter Stories / Lapis / Worms | 给一个 **Generate / Random** 钮 |
| Cat Game | 重名时给**三个候选**让你点 |
| Angry Birds Match | 直接发一个系统生成的 `AwesomeHyacinth` |

### 2.5 参考在反复说的那句话

「**以后还能改**」——Pokémon HOME「you can change this later, too!」／Nier「This can be changed later.」／Octopath／Smash Legends／Sonic Rumble。
那是在**降低这一步的心理成本**。

而我们那 5 行说的是：「你的进度还在这台手机上 —— 不绑就会丢档」「⚠ 换设备仍然会丢」。
**参考里没有一屏靠恐吓把人推过去。**

## 5. 已知风险与未决点

**★未决 1 · 墙要不要留出口 —— 这个我不替用户翻。**

参考说 224 款里强制墙 0 款。但用户 2026-09-24 亲口定过「直接改为必须绑定账号吧」。
**两件事直接冲突，而后者是用户自己的原话。**
⇒ 本轮**代码里一个出口都不许出现**。只在报告里写清「将来要加出口需要动哪几处」。要翻也得用户翻。

**风险 2 · 「好不好看」我量不到。**
能量的只有**形状**（行数、框数、间隙、靶子大小）。数字代表不了它（见 §3）。
⇒ 本轮不拿计数当结论。出截图，用户判。

**风险 3 · 我拍的阈值会把好素材改坏**（memory `fb-my-thresholds-degrade-good-assets`）。
间隙往上抬是照参考真值，但「抬到多少」仍是我在拍 ⇒ 先算净空再定，**算式要写出来**。

**风险 4 · 改文案会动 `tests/golden/gd_text_snapshot.txt`。**
预期之内。`--update` 之后**先看 diff 确认每一行都是自己的**。

**风险 5 · 随机名可能撞既有断言。**
昵称长度/字符集/重名策略都可能有现成判据 ⇒ **先 grep 清楚再定生成器**。

**风险 6 · 预填名熵太低会让排行榜一片同名。**
⇒ 判据量**熵**，不是量「有没有预填」。

**不做什么**：不加游客/跳过出口（未决 1）；不碰邮箱绑定后端链路（v0.19.471 刚端到端验过）；不动主菜单版式（另有停工点 `project-mainmenu-relayout-resume-point`）；不为让门禁绿而放宽判据。

★**间隙算式**（现值读源码、净空读 ⑥ 节、参考真值现读 `python tools/login_screen_audit.py thresholds`）：

```

旧值 12px = 6.5pt  —— 低于参考里任何一屏
天花板(最坏一档键盘): 3×81 + 2×gap ≤ 720×(1−0.580) − 2×8 = 286.4  ⇒ gap ≤ 21.7
⇒ 取 21px = 11.4pt   实测 band 285 ≤ 286.4, 剩 1.4px
★中位 43px 算不出来: 3×81 + 2×43 = 329 > 286.4。要到中位只能一步两行 ⇒ 分三步,
  而参考「分几步」中位是 1、我们已经是 2 ⇒ **这一格到此为止**。
```

判据两头卡：⑥a 下限 12 → **20**（棘轮）、⑥g 上限「没越顶」+「剩余净空 < 一个行隙 ⇒ 抬不动了才叫到顶」。
