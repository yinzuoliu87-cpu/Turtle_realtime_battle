## 4. 方案

### 4.1 一句话
**权威状态 = 本周开局空状态，按顺序重放「客户端操作流水」与「服务器对局结果」。** 客户端照旧即时算、即时显示；服务器事后用同一份代码算一遍，比对。

### 4.2 随机数由服务器发
- **掷货 / 刷新 / 开糖果罐**都先向服务器要种子：`econ_commit(周, 起始序号, 未传的操作, 种类)`，拿到再掷。游戏本来就必须联网（方案书 20261101b）。
  - （原稿写「打完一局自动换货用裁判任务种子派生、不多一次往返」—— S3 细化时改掉：本机打的局没有裁判种子，两套来源要两套核法；统一走 `econ_seed` 只多一次往返。）
- ★**种子绑在「流水第几条 + 什么操作」上，发出去就算这一笔已经发生**（S3 细化，11-06）：服务器发种子的同时往 `econ_ops` 写下这一条（序号、种类、种子，来源 = 服务器）。同一序号再要 ⇒ 回同一个种子（重试幂等）。
  - 防的是「挑种子」：多要几个、本机各掷一遍、只用好的那个。绑死之后每个序号只有一个种子，那一条只能是这个操作；客户端后来上传的同一序号内容对不上 ⇒ 拒。
  - ★只给「紧接着已上传流水的下一条」发种子：要种子的请求里先带上还没传的那几条（`econ_commit(周, 起始序号, 操作数组, 种类)` 一次往返，上传 + 要种子合一）。否则可以先要「第 50 条」的种子，知道之后再倒过来安排前 49 步（先买哪几件改卡池）把货架凑成想要的。
  - 拿到种子却没用上（恰好闪退）⇒ 服务器账上这一笔照样发生（刷新照扣 2 币、货架照换），本机下次对齐时按服务器的来 —— 没有可钻的空子，也不会凭空丢东西。
- 玩家拿不到后面的种子 ⇒ 没法预知货架。`test_mode` / 没配后端（本机开发、门禁）用本机种子，流程不变。

### 4.3 经济操作收成纯函数
- 新文件 `scripts/gamedata/econ_ledger.gd`：`EconLedger.do(gs, op)` = `apply` 成交才往 `gs.econ_log` 追加一条（序号 + 当时场次 + 操作）；`apply(gs, op) → {ok, reason, …}` 直接改 `GameState`（S1 实做：没有另造一份纯字典状态 —— 背包合成、卡池、小木斧这些函数都长在 GameState 上，另抄一份就是两份实现；服务器重放时进程里也有 GameState，从本周开局状态起跑同一份）。
- S1 已接：掷货 `roll`（种子）、买 `buy`、刷新 `refresh`（种子）、锁货架 `lock`、买经验 `buy_xp`、开糖果罐 `candy`（种子）。`meta_shop_battles` 只是「什么时候自动换货」的戳、不是资产，不进比对。
- S2 已接（11-06，`econ_ledger.gd` `apply` 里逐条有注释）：
  - 背包（`econ_inv.gd`，原 `equip_ops.gd` 的记账部分原样搬来，界面只按返回的 reason 出原来那几句话）：穿 `equip` / 卸 `unequip`（统领按 `pid`、小将按 `lane + idx`）/ 换人 `move` / 卖 `sell` / 等级器 `leveler` / 换位 `swap`。换位不改资产，但小将按「哪一路第几格」寻址，不记就会在重放里穿到另一只身上（门禁 ②′ 反向证明过）。
  - 锁统领 `leaders`（选龟页「开始」）：统领不是资产，但羁绊赠送件、斧头独立出货、有没有糖果罐都看它，重放要有。
  - 小木斧：选最终造物 `axe_final`、局内击杀 / 助攻经验 `axe_exp`（一局几次，逐次记；三个进度字段仍只经 `axe_add_exp` 写）。
  - 收入 `income` {src, coins, xp, axe, candy}：积分赛 / 闯关 / 决赛（本机打与裁判结果两条路）/ 决赛揭晓 / 两种配额补发 / 陪练号推演，一种操作。S4 服务器按 `src` 去对自己的裁判账，客户端报的数不算数。
  - 宝箱 / 香火：裁判结果单走 `chest` / `incense`（原 `RefereeWatch.apply_chest / apply_incense` 的「只往前走」原样搬来）；本机打的那一局里战斗当场写存档（换路要读回来，是对局规则，不改），哨兵在下一次存档 / 记账时发现变了就补一条 `prog`（终值）。
- **运行时哨兵**（`EconLedger.check`，每次 `save()` 与每笔记账之前）：资产指纹与上一笔记账后的不同 ⇒ `econ_drift` +1，记下在哪、哪几块变了（设备本地、不进云存档 —— 否则漂移计数一变就多推一次云存档；S4 另行上报）。专抓静态扫描看不见的写法（`var b = gs.persistent_bench; b.append(..)`、经函数参数改卡池）。指纹不含：装备实例上的 `chg`（香火石充能的旧镜像，局内写、没人读）、`axe_evo_pending`（演出排队）、阵型站位；小将按「装了什么 + 临时等级」排序比；卡池按「补齐之后」比。沙盒（回放 / 切磋 / 裁判机 / 设备自检 / 教程）里静音：`econ_quiet` 在 `capture_all` 之后 +1，离场整份还原。
- 操作（原计划清单）：买（货架第几格）/ 刷新 / 锁货架 / 卖 / 穿 / 卸 / 换位 / 用等级器 / 开糖果罐 / 买大轮经验 / 小木斧进化选择；自动合成是买 / 穿之后的确定性后续，不单独成操作。对局结果作为一种特殊操作，金额从服务器取。
- §2.3 里每一处写入点都改成调它；`GameState` 原来那些函数变成薄壳。门禁扫「这些字段在 `econ_ledger.gd` 以外不许直接写」（白名单：读档 / 换周清零 / 教程沙盒 / 截图工具）。

### 4.4 流水上传
- 每条操作带：序号、操作、参数、当时的 `season_total_battles`（与对局结果交错的位置）；要种子的那几种带的就是服务器发的那个种子（序号即编号）。
- 新表 `econ_ops`（账号 + 周 + 序号为主键、只能追加；`src` = client / server）；函数 `econ_ops_append(周, 起始序号, 操作数组)`：起始序号必须接在已有的后面（拒断号）；碰到服务器预先写下的种子行 ⇒ 种类与种子必须一致，否则整批拒。客户端没传上去的留在存档队列里，断网攒着、连上补齐。
- 本机留整周流水（S3 实做：一周几百条、几十 KB，云存档放得下；换周清空），`econ_up` = 服务器已经有前几条，下一次从那里传。（原稿写「只留没传的那一截」—— 留整周更简单：重放门禁、换设备接着记都不用另算序号。）
- S3 实做（11-06）：服务端 `server/supabase/migrations/20261106_econ_ops.sql`（表 + `econ_commit`）/ `20261106b_econ_flag.sql`（开关 `econ_on` 进 `referee_flags`，默认关）；客户端 `scripts/net/econ_net.gd`：`seeded`（掷货 / 换一批 / 开罐要种子：带上没传的流水一起交，拿到种子再成交；等的时候商店货架清空、点买 / 锁 / 再换不理）、`pump`（`GameState._net_tick` 每 20 秒那一拍，与云存档同一拍）。开关关着这两条一个请求都不发，行为与 0.22.8 一字不差。
- 顺带补的漏洞：掷货不花钱 ⇒ 只在「该换货」时成交（`EconLedger.roll_due`：货架空 / 没锁且打过新的一场；商店 `_restore_offer` 改用同一条判据），否则服务器给 roll 发种子就等于免费刷新。

### 4.5 重放与比对
- 重放：本周流水 + 本周裁判结果，按 `season_total_battles` 交错，逐条 `apply`；缓存「算到第几条 + 状态」，只补算新增的。任何一条不合法（钱不够、货架上没有、种子对不上、收入没有对应裁判局）⇒ 从那条起作废。
- 比对点（不一致 ⇒ 拒，并把服务器状态发回本机对齐，同 `adopt_ranked_ledger`）：
  1. 积分赛开局 `referee_ranked_start`；
  2. 周六进队 `gauntlet_queue_join`；
  3. 金宝罐锁罐。
- 比对内容：快照里的身上装备、大轮等级、小木斧 / 宝箱 / 香火石起点 = 重放结果。
- S4 细化（11-06，我定的做法）：
  - **重放起点 = 全新 GameState 的初值**（换周 `start_new_season` 把经济全清：币 0、背包 / 身上 / 卡池空、等级 1、统领空）。不另抄一份「起点清单」（手抄必然漂移）；门禁守「换周之后的资产 = 全新初值的资产」，两边谁改了没跟上就红。
  - **在裁判机上重放**（它本来就跑无头 Godot + 同一份游戏代码）：`referee_main` 加一种 `--econ-replay` 模式，进一份流水、出{能重放到第几条、第一条不合法的序号与原因、资产 / 宝箱香火的规整结果（`EconLedger.assets_of / progress_of`，与本机同一把尺子）、按来源汇总的收入}。
  - 逐条校验：操作种类白名单；开关开着时收入只认「裁判结果」那几种来源（`ranked_ref` / `gauntlet` + `gauntlet_ref` / `finals` + `finals_ref` / `finals_coins` / `finals_reveal` / `backfill_*`），本机计分局才有的 `match` / `ranked` / `prog` / `sim_econ` 一律不认（R7）。
  - 收入金额：重放出「按来源汇总」，服务器拿自己的账（`ranked_records.coins` 等）对 —— 对不上 ⇒ 不认。
  - 拆两步：S4a 裁判机重放（Godot 侧 + 门禁，本机可全测）；S4b 服务器表 `econ_state` + 轮询器领活 / 回写 + 三处开局比对 + 本机按服务器对齐（动现行函数 `referee_ranked_start` / `gauntlet_queue_join` 与裁判机部署 ⇒ 内测服先上，正式服逐次问）。
