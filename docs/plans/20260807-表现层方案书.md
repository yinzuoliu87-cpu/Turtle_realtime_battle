## 0. 判据：什么叫「做好了」

用户 2026-08-06 定的长期标准是**触手水准**（逐帧量参考做成包络表驱动动画）。
但那一件花了两天几十轮 —— **全表都上那个标准不是几天的事**。所以本文把标准拆成两档，
每一条都要标它该上哪一档，**这个取舍才是真正决定工期的东西**：

| 档 | 标准 | 判据 |
|---|---|---|
| **A 档·能读懂** | 玩家**看得出在发生什么** | ① 触发时屏幕上有明显的东西 ② 看得出是**哪一件**在响（不是一团通用光效）③ 手机屏上也成立 |
| **B 档·触手水准** | 逐帧量参考 → 包络表驱动 + 形态有物理模型 + 状态边界连续性门禁 | ★**用户 2026-08-07 拍板：现在一件都不上**（见 §5 U2）。理由: 那套方法解决的是「动作像不像参考」, 而当前问题是**根本没有形象** |

★**全部先做到 A 档。**等全表都「能看懂」了再回头挑值得上 B 档的 —— 真要上也是给**全程在场**的召唤物，不是给一闪而过的大招。

### 判「看不见」时必须带数字

标尺：**≈0.69 屏幕像素 / 码**（1280×720）。参照物：**龟立绘高 ≈44 px**、**头顶等级徽章 ≈16 px**。
低于徽章尺寸（16 px）的东西，实战中基本等于不存在。
⚠ 这是**桌面**的数；手机端另算（见 §3.1，**尚未实测**）。

#### ⇒ 规格（2026-08-07 定稿，照这个做）

**① 三座炮台要有本体**（与六件本体同一优先级，一起排进"先做本体"那一批）

炮台是**逻辑实体**（有位置 + 计时器、没有血量、不会被摧毁）⇒ 它**常驻在场**，
所以本体是"一直画着"的，不是一闪而过 —— 这决定了它必须做得住看。

- **本体**：矮座 + **可旋转炮管**。炮管**始终朝向它当前的目标**（这是"朝谁打"的唯一信息载体）
- **三座要能数得出来、且各不相同**（它们本来就职责不同）：
  · **第一座**（3 件起 · 每 2.5 秒）—— **单管**
  · **第二座**（6 件起 · 每 5 秒 · 两相位交替）—— **双管**，两相位分别用深橙/正蓝（已有的两相位配色）
  · **第三座**（9 件 · 火控 · **不开火**）—— 做成**雷达碟/天线**，不给炮管。
    "它不开火"本身就是信息，给它炮管反而误导
- **素材**：PixelLab 出立绘 + 开火动画（同六件本体的做法：**插值锁两端**防形状跳变）

**② 冲击波要读得出是"盾"的** —— 换颜色不算

现在是平滑圆环，而**场上任何 AOE 都是圆环**。盾的专属特征走**形状**，不走颜色：

- 波前不是平滑圆，而是**由多块六边盾牌面拼成的环**向外推（盾的剪影重复 N 次）
- 每块盾牌面**朝向法线方向**（外推时像一圈盾牌被顶开）
- 保留现有的琥珀色 + 施放者→目标的能量带（那条带解决"命中的是谁"，是对的，别动）

**③ 其余 10 条：从"只有颜色不同"升到"形状 + 运动都不同"**

现在同场时玩家看到的是**一堆彩色圆环**。加**两个维度**把它们拉开：

| 类 | 形状 | 运动 |
|---|---|---|
| 盾 | **六边盾牌面拼环** | 外推 |
| 弓箭 | 三角环（已有） | 外推 |
| 奇械 | 六边环（已有） | **内收**（冰封/僵硬是"锁住"，收比扩对） |
| 遗物 | 八边环 + 金柱（已有） | 上升 |
| 法器 | 竖直光柱（已有） | 上升 |
| 枪 | 柱 + 辐射带（已有·两相位） | 外推 |
| 食物 | 圆环 + 上升火花 | 上升（★对比度全表最低，**要提亮或改色**） |
| 药水 | 辐射带 | 外推 |
| 灵物 | 实体触手（已有，最好的一个） | 甩动 |
| 剑 | **不做**（§5 U3） | — |

★**判据**：截一张"多类同时触发"的图，**遮住颜色只看剪影**，仍要分得出是哪几类在响。
这条比"RGB 差多少"硬 —— 撞色检测已经抓出过两轮，但它抓不出**撞形状**。

**其余已知缺口**：
- 持续态一条都没做 —— ✅ 已拍板**不另造载体**：超出就截断，信息面板的状态栏就是它的去处（§5 U1）

- 阈值提示三条 —— ✅ 已拍板**不做**，且**要把已实装的拆掉**（§5 U4）
- 食物对比度全表最低（翠绿压在青蓝海底地图上）

## 3. 全局系统层（不属于任何一件，但决定所有件能不能被看懂）

### 3.1 ★移动端 —— **尚未实测**

这游戏**要出 iOS 包**（`.github/workflows/ios-build.yml`），而**所有特效测量都是 1280×720 桌面，

### 6.1 「散在龟身上的黄方块」= 金弹弹迹的菱珠串（✅ **2026-08-12 已修 · v0.19.132**）

> 照本节自己给的结论改的：一颗沿飞行方向拉长的弹在动 + 身后拖影，整体平移、到点即灭。
> 门禁判据是**量位移**不是数节点（静止的珠子同样存在）。

干净台里每一件带枪的装备，挨打的那只龟身上都会堆一坨亮黄小方块。查证过程：

| 排除的假设 | 证据 |
|---|---|
| 是伤害数字渲染成豆腐块 | `VFXLAB_TEXT` 开/关两边都有约 **1000 个亮黄像素**；开 TEXT 时数字本身是正常的红色 "72" |
| 是 080 的机炮子弹 | 递归扫全场景树，黄色 `Sprite3D` 只有 **1 个**（炮台充能条） |
| 是 3D 世界里的粒子 | 假人周围 3 世界单位内只有 4 个精灵 |

**真凶：`golden_shot_vfx.trail()`（v0.19.37 做的「金弹菱形族」）。**
它在**贴近目标的最后一段**铺 `TRAIL_BEADS` 颗**静止**的菱形珠子，
每颗 `BEAD_PX = 26` 码。射速高时（080 三星一轮 10 发）多批弹迹重叠 ⇒
读起来不是"一颗弹飞过去"，而是"目标身上堆了一坨黄方块"。

**该怎么改**：弹迹应该是**一颗沿飞行方向拉长的弹**在动，不是一串静止的珠子。
菱形本身没问题（它确实和场上一切圆形区分得开），问题是**它不动、而且会叠**。

### 6.2 077 的开火动画只做了枪口火焰与后坐力，枪身没有开火帧

PixelLab 连出两版 `pistol_fire`，火焰都画在**枪机**位置而不是枪口
（燧发枪历史上确实在那儿闪，但读起来不像开枪），后坐也几乎看不出。
当前方案是**枪身用 idle 表、火焰与后坐用代码**，锚点算得准且能跟着射速缩放。
如果以后要枪身也有开火帧，得换生成方式（比如自己画一帧再用插值模式补中间）。

### 6.4 假人身上那个大白圆环（✅ **2026-08-13 已查明并修复 · v0.19.143**）

> **真凶是 `battle_vfx._hit_spark()`** —— 挂在 `_impact()` 上、**每一次命中都走**的全局命中反馈，

> **两条未查线索是同一个东西**。已改成复用现成的四尖星纹理，并治了淡出病。
