## 2. 调查结论

### 2.1 游戏里的「等级」现在是整队一个数
- `RealtimeBattle3DScene.gd:1554` `_unit_level(side)`：左方读 `GameState.season_level`，右方读对手快照的 `season_level`（`backend.gd:201`）。**一侧一个等级，三只龟同级。**
- 等级的作用全按这一个数：主属性每级 +5%（`unit_scaling.gd:9`，10 级 = 1.45 倍；出生缩放 `battle_spawn.gd:502`、等级牌 `battle_spawn.gd:435`、装备固定加值与固定召唤物 `RealtimeBattle3DScene.gd:1580`）；龟蛋血量按平均等级（`phase2_config.gd:1111`，`dual_lane_flow.gd:572-574`）；小将等级（`battle_spawn.gd:338`）；全队装备上限 `(等级 − 1) × 2`（`phase2_config.gd:1058`）。
- `_unit_level(` 全仓只有 3 个真实调用点，改成按龟改动面小。

### 2.2 周赛的节奏（擂台赛「锁当前阵容」要跟它对齐）
- 三只统领**整轮不可换**（`GameState.gd:1134`）；选龟页现在 28 只全部能选（`DataRegistry.gd:37`、`pet_grid.gd:29`）。
- 赛季等级、经验、装备每周一清零重来（`start_new_season`）；全队装备上限随赛季等级涨 ⇒ **同一个玩家周日的阵容比周一强得多**。
- 一周积分赛 16 场（`phase2_config.gd:94`）、闯关 6 场（`:154`）。

### 2.3 服务器对快照只查「格式」，不查「来路」（擂台赛头号漏洞的来源）
- 上传校验 `server/rules.mjs:38` `reject()`：龟 ID / 装备 ID 在白名单、单只装备 ≤ 3 件、等级 1 ~ 10、分路完整。裁判开算前 `referee_job.gd` `validate()` 只查三只统领与分路（`:60-65`），数据库 `referee_lineup_ok`（`schema.sql:4043`）同。
- **不查**：这些装备是不是真买来的、星级是不是真合成的、全队装备数是否 ≤ 本周等级允许的上限、赛季等级是不是真练出来的。装备与赛季进度都在客户端存档里（`GameState.persistent_equipped`，`GameState.gd:1136`）。
- ⇒ 周赛里改存档只影响排名；**押真币的擂台赛里，改存档 = 直接抢钱**（§4.5 L1）。

### 2.4 服务器裁判、录像、在线配对都有现成的
- 裁判任务 `referee_jobs`（`schema.sql:2716`），`referee_job.gd` `MODES`（加一种 = 加一个落账出口，战斗不用新写）；`client_version` 不等就拒算。
- 录像 `matches.replay`（`schema.sql:170` 注释）：一局约 1.6 KB 输入 + 每 60 步一个校验码，播放 = 重算。
- 周六闯关的在线配对 `gauntlet_queue`（`schema.sql:6590`，加入 / 心跳 / 取消 `:6881` / `:6959` / `:6992`）：同战绩配对、锁阵容进队列 —— 但它要客户端每 2 秒心跳、等久了配陪练号，擂台赛这两条都要去掉（D9 / D11）。
- 裁判机上已有定时调度（`server/referee/gauntlet_bot_planner.py`），擂台赛的服务器配对照它做。

## 4. 方案

### 4.0 一页看懂（玩家视角）
1. 在游戏里建号 = 主站同时有一个号，主站送一只小龟（D13）。选龟页能选：自己的龟（主站几级就几级）+ 本周 7 只 1 级限免（自己有的不在里面）。
2. 打周赛、打擂台赛，上场的自己的龟都涨经验，记在主站；主站自己的玩法也涨（D14 / D15）。限免龟一律 1 级、不涨经验（D16）。
3. 主菜单左下有一只**金宝罐**。点开 = 擂台赛：往罐里投龟币、设「最多打几场」、锁定当前阵容 / 训龟大师 / 装备，点「准备」。
4. 服务器只给你配**本大轮总场次相同**的对手（锁罐那一刻的场次，和积分赛匹配是同一个数；等不到就一直等、永不放宽、永不配机器人）；每场押双方罐里较少的那个，全押；赢的拿走、输的给出，一分不多一分不少（D11 / D17）。
5. 打完自动接着排下一场，直到罐空 / 打满场数 / 自己喊停 / 本周结束。睡觉也在打，醒来打开游戏先看到「离开期间」战况（D9）。

### 4.1 账号互通（D13 / D15）
- **游戏建号 ⇒ 主站建号**：匿名建号成功后（`supabase.gd:1377` 之后，新文件 `scripts/net/mainsite_link.gd`），我们的服务器（Edge Function，持主站给的服务端密钥）调主站「建号」→ 拿到主站用户编号写进我们库；主站照它的规则送一只小龟。失败重试、幂等键 = 我们的账号 ID；建号没成之前游戏照常能玩周赛（龟只按小龟 + 限免显示）。
- **主站 ⇒ 游戏**：主站签发 5 分钟通行证（原稿接口 1），网页版用它登录 / 绑定同一个号。
- **游戏 ⇒ 主站**：游戏里「去主站」按钮（选龟页「解锁更多龟」、金宝罐页「充值龟币」两处）→ 我们服务器向主站要一次性免登录链接 → 打开浏览器。原来只规划了单向，现在双向。
- **同步什么**：拥有的龟与等级 / 经验（读）、龟币余额（读）、上场经验（写，只报事件）、金宝罐（开 / 建场 / 结算 / 停，见 4.6）。主站是钱、龟、等级、经验的唯一账本；我们只存擂台赛的连战状态与对局。

### 4.2 龟：拥有 + 限免 + 养成等级（D2 / D3 / D13 / D15 / D16）
- **选龟页**只显示「拥有 ∪ 本周限免」：拥有的角上挂主站等级牌、限免的挂「限免」角标 + 1 级；底部一条「去主站解锁更多龟」。
- **限免**：每号每周一个固定的 28 只排序（种子 = 账号 ID + 周号，客户端与服务器同一个纯函数），跳过已拥有、取前 7 只；周中在主站新得到一只限免龟 ⇒ 只换掉那一只。换周时刻 = 周赛换周时刻（周一 00:00 UTC），所以选龟时合规、整周合规（统领整轮不可换）。
- **等级（R1）**：快照加 `lv` 表（龟 ID → 1 ~ 10）；改 3 个调用点按龟取等级；龟蛋血量按三只平均；**赛季等级保留它另外三个作用**（全队装备格数 / 龟蛋基础 / 小将等级 —— 那是周赛经济，不是龟的养成）。周赛结果会变 ⇒ `RULES_VER` 升、`verify_rules_fingerprint` 金标重生成。没有 `lv` 表的旧快照退回整队等级。
- **经验（R11）**：每局裁判算完，上报「这只龟（拥有的）上场了这一局：对局 ID、模式、胜负」，主站按自己配置换算（建议胜 30 / 负 15，主站可改）；幂等键 = 对局 ID + 龟 ID；主站「只给当前装备的龟」对游戏来源开例外。限免龟不报。

### 4.3 擂台赛规则（D7 ~ D11）
- **开一轮**：投入 N 龟币进金宝罐（主站冻结；上下限主站定）+ 设「最多打几场」（玩家选，主站定上限）+ 锁阵容。一个号同时只能开一轮。
- **锁什么**：当前三只统领、分路、技能选择、训龟大师、装备配置（= 积分赛对战快照，`backend.gd:1930`）+ 主站等级（锁定那一刻的值，本轮内升级不影响）+ 配对场次（锁定那一刻的本大轮总场次）。
- **锁之前服务器验**（§4.5 L1）：三只都在「拥有 ∪ 本周限免」；等级以主站为准（快照里的作废）；全队装备件数 ≤ 服务器认可的本周等级上限；装备星级不超过服务器记录的本周可得范围（具体口径见 L1）。
- **配对**（D17）：只看一个数 —— 锁罐那一刻的**本大轮总场次**（`season_total_battles`，积分赛匹配用的同一个数，`backend.gd:286` `pool_find_battles`）；服务器以自己记录的本周裁判局数为准，快照自报的作废。不按胜场、不按等级分档。同场次里先到先配；永不放宽；永不配机器人；等不到就一直等（D11）。
  - 我定的口径（不是用户原话）：配对场次取锁罐那一刻、整轮不变；擂台局不计入大轮场次（L13）。理由：锁住的阵容与装备是那一刻的，场次跟着锁才量得准强弱；擂台局要是也加场次，锁在 0 场的裸阵打几场后会撞上已经买了装备的人。
  - **防刷号过滤只剩一条**（不是分档）：同设备的号不互相配（D20）。不按网络挡：误伤一家人 / 室友 / 同一 Wi-Fi / 运营商共用公网 IP，而擂台只配同场次、永不放宽，被误挡的人可能一直配不上。没有注册天数门槛（D21：主站原稿那条「注册满 3 天」删掉，两边都不做）。
  - **不连着打同一个人**（D22，是排序不是过滤）：同场次里除了上一场的对手还有别人在等，就按先到先配挑别人；只剩上一场那个对手在等，照配，不让任何人多等一秒。
    - 为什么删「同一对手 24 小时最多 1 场」：① 它防的「熟人对刷转币」挡不住 —— 全押制下一场就能把罐转空，限次数没用；转币靠主站对账盯（L5）。② 刷经验由主站的擂台经验每日上限管（L12）。③ 代价大：擂台只配同场次、永不放宽，人少时同一场次段常常就两个人，打完一场两人都得干等 24 小时。
    - 为什么不干脆什么都不加：锁罐场次整轮不变，同段只有两个人时两轮会一直互配；有第三个人在等时还让他俩连着打，输的那边整晚对着同一套克制阵掉币，体验差，第三个人也白等。排序偏好两头都顾到：有人可换就换，没人可换照打。
    - 这样配不会没完没了：每场押双方较少的那个、全押 ⇒ 罐小的一方一输就空、出队；它赢了罐翻倍、大罐跟着缩小，几场之内必有一方空；另有玩家自设的「最多打几场」（D8）。
  - 设备怎么认：锁罐时客户端带上设备标识（`OS.get_unique_id()`，网页版没有就记空、不参与这条），服务器记进这一轮；配对时两轮设备标识相同就不配。
- **每场赌注** = 建场那一刻双方罐里余额较小者，全押（主站建场时算、冻结、返回）。赢 ⇒ 拿走对方赌注；输 ⇒ 赌注给对方；算不出胜负 / 超时 / 出错 ⇒ 双方原样解冻。严格零和。
- **自动连战**：结算完自动用同一份锁定阵容排下一场。结束条件：罐空、打满设定场数、玩家喊停（本场打完才生效）、本周结束（L2）、主站那边龟没了（L11）。结束时罐里剩的由主站退回钱包。
- **离线照打**：不要心跳、不设排队超时；配对、建场、结算全在服务器（4.6）。
- **擂台赛不碰周赛**：不吃周赛配额、不进周赛战绩 / 排行、不发深海币（L13）。

### 4.6 服务器与接口（龟战一侧）
- **我们的新表**：`arena_runs`（账号、周、状态、锁定快照、锁定等级、配对场次、场数上限、已打、胜、负、喊停标记）、`arena_queue`（轮、配对场次、入队时刻）、`arena_matches`（对局 ID、两轮、赌注、状态、裁判任务、结果、结算时刻）。客户端一律不直连，只走函数（同 `gauntlet_queue` 的做法）。

### 4.10 装备与深海币上服务器记账（L1 ④，D23）
**为什么非做不可**：装备、深海币、商店货架现在全在客户端存档里（§2.3），服务器只查格式。周赛里改存档只影响排名；擂台赛押的是主站真币，改存档 = 直接抢钱。①②③ 只能卡「件数 / 星级上限」，挡不住「上限之内全挑最好的」。

**现状（11-06 查实）**——要进账本的全部进出口：
- 深海币进：每局结算奖励（`RealtimeBattle3DScene.gd:7564`、`sim_driver.gd:386`、`referee_watch.gd:242 / 524 / 585 / 746`）、补发（`GameState.gd:763 / 2451`）、糖果罐（`GameState.gd:2562`）、卖装备（`equip_ops.gd:195`）。
- 深海币出：商店买（`ShopScene.gd:1225`）、刷新（`ShopScene.gd:1555`）、买大轮经验（`GameState.gd:2672`）。
- 装备进出：商店货架 + 私人卡池（`pool_take` / `ensure_equip_pool`）、自动合成（`auto_merge_all`）、羁绊赠装（`sync_synergy_grants`）、小木斧进化（`axe_evo_take`）、临时等级器（`consume_temp_leveler`）、糖果罐装备、穿 / 卸（`persistent_bench` ↔ `persistent_equipped`）。
- 两处真随机：货架 `ShopScene.gd:173` `_rng.randomize()`、糖果罐 `GameState.gd:2561` 全局 `randi_range` —— 服务器复现不了，必须改。

**做法：服务器发随机数 + 记操作流水 + 裁判机按流水重放**（不把商店逻辑另抄一份到服务器）：
1. **随机数由服务器发**：每次换货 / 刷新 / 开糖果罐用的种子由服务器给并记账（换货的种子跟着那局的结算一起回来，不多一次往返；刷新与开罐各一次请求，游戏本来就必须联网）。客户端照旧用现在的 GDScript 算货架，只是种子不再自己掷 ⇒ 玩家也没法预知后面的货。
2. **经济操作收成纯函数**：买、卖、刷新、合成、穿卸、开罐、买经验、小木斧进化，统一成 `econ_apply(状态, 操作) → 新状态`（新文件 `scripts/gamedata/econ_ledger.gd`）；商店 / 背包界面只调它。每一步追加一条操作流水（序号、操作、参数、用到的服务器种子编号）。
3. **流水上传**：每次操作后后台补传（新表 `econ_ops`，账号 + 周 + 序号唯一，只能追加）；断网就攒着、连上一次补齐。
4. **收入只认服务器**：每局奖励（深海币、小木斧经验、糖果罐进度、装备效果给的币）从裁判结果单里取；流水里的「收入」只写对局 ID，金额由服务器查。没有裁判局的收入 = 不存在。
5. **裁判机重放出权威状态**：从本周开局空状态起，按流水逐条跑同一份 `econ_apply`，得到深海币、背包、身上装备、货架、卡池。流水里任何一步不合法（钱不够、货架上没有、种子对不上）⇒ 从那一步起作废。
6. **两处比对**：周赛快照上传、金宝罐锁罐时，快照里的装备必须与重放出的「身上装备」逐件相同；不同 ⇒ 拒（周赛：这场不进池、不计成绩；擂台：不让锁）。

**影响**：周赛也一起被保护（改存档在周赛里也没用了）；对局本身不变（不升 `RULES_VER`）；老存档：本周已经在打的人从下周一换周起算，本周照旧（换周时一切清零，正好是起点）。
**工作量**（我的估计）：约 1.5 ~ 2 周的量。⇒ 不等 11-09，今天（11-06）就在分支上开工；0.22.8 周日发完之前不进 main（防止混进 0.22.8）。
