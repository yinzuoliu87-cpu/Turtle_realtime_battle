## 1. 需求原文

用户 2026-11-05（逐字）：

- 「这是下一周的任务安排，你审核一下」，附主站原稿（逐字，排版按原样）：

> 一、分工
> 谁 负责什么
> 主站（我们） 账号、玩家拥有的龟、龟币钱包、金库、偷币结算、消息通知、运营后台
> 龟战（他们，用他们的服务器） 游戏本体（保留周赛、深海币、商店）、阵容、匹配、战斗、服务器裁判、录像、限免龟
> 原则：钱只在主站账上动。龟战只负责算出"谁赢了"，告诉主站，由主站记账。
> 二、玩家流程
> 1. 在主站点「龟战」，用主站账号直接进入游戏，不用重新注册。
> 2. 上阵 3 只龟，只能用主站里自己拥有的龟。龟不够 3 只时，用龟战的限免龟补位。主站的等级和稀有度不加战斗力。
> 3. 设好防守阵容，并在主站把一部分龟币存进金库。从这时起，别人可以来偷你金库里的币。
> 4. 偷袭：系统推荐 3 个对手，挑一个发起挑战，并押一笔押金。服务器裁判算出结果后，播放录像，主站自动结算。
> 5. 被偷的人会收到消息「你的金库被 某某 偷走 120 龟币」，24 小时内可以复仇一次。
> 三、金库和偷币规则（建议的默认数值，运营后台都能改）
> - 金库：最少存 100，最多存 1 万。只有金库里的币会被偷，主钱包永远安全。
> - 取出要等 1 小时生效，等待期间照样可以被偷，防止"看到有人来打就马上取走"。
> - 每次能偷多少：对方金库的 10%，单次最少 10、最多 500。
> - 押注对等：进攻方押多少，就能偷多少。赢了：拿走这笔币，押金退回。输了：押金全部归防守方。平局：押金退回。平台不抽成，币只在两个玩家之间转。
> - 防守保护：被偷一次后有 8 小时护盾；每天最多被偷 3 次。
> - 进攻限制：每天最多偷袭 10 次。
> - 防小号刷币：对手由系统按龟战积分推荐，不能点名打某个人。同一网络或同一设备的账号不会互相匹配。注册未满 3 天的账号不能参加偷币。
> - 超时：30 分钟内没算出结果，自动退押金、解除冻结。
> 四、接口约定（需要两边对齐）
> 主站提供：
> 1. 登录通行证：主站签发一张 5 分钟有效、带签名的通行证（里面有用户编号、昵称、头像），并公开验签用的公钥。龟战验证通过后，建立或绑定他们自己的账号。
> 2. 查询玩家拥有的龟：返回这个玩家在主站拥有的龟（11 种之一，代号两边相同）。
> 3. 推荐对手 / 发起偷袭：由主站检查金库、护盾和次数限制，冻结押金、建好这次偷袭，再通知龟战服务器建一个"偷袭"类型的裁判任务。
> 4. 结算回调：裁判算完后，龟战服务器把结果（谁赢、对局编号）发给主站，附带签名。同一场只结算一次，重复发也不会重复记账。
> 龟战提供：
> 1. 用主站通行证登录的入口。
> 2. 防守阵容变化时通知主站（有没有防守阵容、龟战积分），主站用它来推荐对手。
> 3. 新的裁判任务类型"偷袭"，算完后回调主站。
> 4. 上阵检查：只允许用主站拥有的龟，加上限免龟。
> 5. 网页版入口和瘦身。
> 6. 改名：他们游戏里也有一种叫"龟币"的东西（目前只累计，没有地方花），要改个名字，避免玩家和主站龟币搞混。深海币保留不动。
> 五、风险，要先说清楚
> - 网页版太大：素材约 190 MB（图片 116 MB、音频 61 MB），手机上第一次打开会很慢。需要瘦身和分包，首次下载最好压到 30 MB 以内。这是第一周就要验证的事。
> - 裁判服务器算力：现在每分钟大约能算 10 到 20 场。偷袭玩的人多了会排队，需要按量加机器。
> - 版本必须一致：裁判只认同一个游戏版本，主站嵌入的网页版要和裁判同步更新。
> - 先只做网页版：他们还有 iOS 应用。应用里接主站钱包会碰到苹果关于虚拟货币的审核规则，先不做。
> 六、排期（粗估）
> 1. 第 1 周 · 技术验证：网页版嵌入主站、测手机加载速度、打通登录。
> 2. 约 2 周 · 友谊赛：用主站的龟打异步对战，不涉及龟币，先看平衡和玩家热度。
> 3. 约 2 周 · 金库偷币内测：先用小额上限测，没问题再放开。
> 4. 之后：复仇、偷币排行、赛季奖励。
> 主站这边要做的：金库和偷袭的托管账户（照暗盘、开撕台、地下钱庄现有的托管模式）、上面 4 个接口、运营后台的参数和对局记录、主站「龟战」入口页（金库存取、被偷记录、复仇），以及把新账户加进每日对账。

## 2. 调查结论

### 2.1 游戏里的「等级」现在是整队一个数
- `RealtimeBattle3DScene.gd:1554` `_unit_level(side)`：左方读 `GameState.season_level`，右方读对手快照的 `season_level`（`backend.gd:201`）。**一侧一个等级，三只龟同级。**
- 等级的作用全按这一个数：主属性每级 +5%（`unit_scaling.gd:9`，10 级 = 1.45 倍；出生缩放 `battle_spawn.gd:502`、等级牌 `battle_spawn.gd:435`、装备固定加值与固定召唤物 `RealtimeBattle3DScene.gd:1580`）；龟蛋血量按平均等级（`phase2_config.gd:1111`，`dual_lane_flow.gd:572-574`）；小将等级（`battle_spawn.gd:338`）；全队装备上限 `(等级 − 1) × 2`（`phase2_config.gd:1058`）。
- `_unit_level(` 全仓只有 3 个真实调用点，改成按龟改动面小。

### 2.2 周赛的节奏（擂台赛「锁当前阵容」要跟它对齐）
- 三只统领**整轮不可换**（`GameState.gd:1134`）；选龟页现在 28 只全部能选（`DataRegistry.gd:37`、`pet_grid.gd:29`）。
- 赛季等级、经验、装备每周一清零重来（`start_new_season`）；全队装备上限随赛季等级涨 ⇒ **同一个玩家周日的阵容比周一强得多**。
- 一周积分赛 16 场（`phase2_config.gd:94`）、闯关 6 场（`:154`）。

### 2.3 服务器对快照只查「格式」，不查「来路」（擂台赛头号漏洞的来源）
- 上传校验 `server/rules.mjs:38` `reject()`：龟 ID / 装备 ID 在白名单、单只装备 ≤ 3 件、等级 1 ~ 10、分路完整。裁判开算前 `referee_job.gd` `validate()` 只查三只统领与分路（`:60-65`），数据库 `referee_lineup_ok`（`schema.sql:4043`）同。
- **不查**：这些装备是不是真买来的、星级是不是真合成的、全队装备数是否 ≤ 本周等级允许的上限、赛季等级是不是真练出来的。装备与赛季进度都在客户端存档里（`GameState.persistent_equipped`，`GameState.gd:1136`）。
- ⇒ 周赛里改存档只影响排名；**押真币的擂台赛里，改存档 = 直接抢钱**（§4.5 L1）。

### 2.4 服务器裁判、录像、在线配对都有现成的
- 裁判任务 `referee_jobs`（`schema.sql:2716`），`referee_job.gd` `MODES`（加一种 = 加一个落账出口，战斗不用新写）；`client_version` 不等就拒算。
- 录像 `matches.replay`（`schema.sql:170` 注释）：一局约 1.6 KB 输入 + 每 60 步一个校验码，播放 = 重算。
- 周六闯关的在线配对 `gauntlet_queue`（`schema.sql:6590`，加入 / 心跳 / 取消 `:6881` / `:6959` / `:6992`）：同战绩配对、锁阵容进队列 —— 但它要客户端每 2 秒心跳、等久了配陪练号，擂台赛这两条都要去掉（D9 / D11）。
- 裁判机上已有定时调度（`server/referee/gauntlet_bot_planner.py`），擂台赛的服务器配对照它做。

## 4. 方案

### 4.0 一页看懂（两种玩家）

**游戏玩家**
1. 装 App 直接玩。打完第一场，我们在主站建号，主站送一只小龟（D13、约定 2.1）。
2. 选龟页显示自己的龟（主站几级就几级）和本周 7 只 1 级限免。
3. 打周赛，上场的自己的龟涨经验，记在主站。限免龟和擂台局不涨（D16、D33）。
4. 想上主站：在设置页取绑定码，到主站设置密码（D35、约定 2.3）。

**主站玩家**
1. 在主站注册，我们同时建一个账号，没装 App 也有（D26）。
2. 想打擂台赛就装 App，点「用主站账号登录」，在浏览器确认后回到 App（D32）。
3. 打完本大轮第一场才能打擂台（D29）。
4. 主站开轮 → App 里点「准备」锁阵容 → 离线也自动打 → 主站收到战果决定继续或停 → App 和主站都能查战果，电脑上能看录像（D25、D26、D36）。

### 4.1 账号互通（D13 / D26 / D32 / D35）
- **新表**：`mainsite_accounts`（账号 ↔ 主站用户 ID、是否陪练）、`mainsite_codes`（登录码 / 绑定码、5 分钟过期、一次性、设备型号）。
- **建号（游戏 → 主站）**：服务器在玩家第一场出结果时写发件箱（§4.6），不靠客户端。存量老号和陪练号（`bot: true`）上线时各批量跑一次。
- **建号（主站 → 游戏）**：网关用服务端密钥建 Supabase 用户并写 `mainsite_accounts`，幂等键 = 主站用户 ID。
- **还没有主站号时**：拥有 = 小龟 1 级 + 限免，正常打第一场。
- **登录（约定 2.2）**：App 取登录码 → 打开系统浏览器 → 主站回调 `link/confirm` → App 轮询到结果 → 网关给目标账号签发登录态 → 复用换设备那段收尾（§2.10）。本机旧号不合并，切换前弹窗说明。
- **绑定码（约定 2.3）**：设置页只显示码，不放链接；还没有主站号时不显示。
- **删号（约定 2.4）**：小游戏删号时写发件箱发 `account/unlinked`。主站删号走 `mainsite/account/deleted`，和 `account_delete_self` 共用同一段删除逻辑。
- **新文件**：`scripts/net/mainsite_link.gd`、`scripts/scenes/mainsite_link_dialog.gd`。

### 4.2 龟：拥有 + 限免 + 按龟等级（D2 / D3 / D13 / D15 / D16）
- **拥有数据**：新表 `mainsite_pets`（账号、`pet_key`、等级、查询时刻）。进选龟页和开打前由 App 经网关刷新；主站不可用时用上次结果（约定 3）。
- **选龟页**：只显示「拥有 ∪ 本周限免」。拥有的挂等级牌，限免的挂角标和 1 级。不放跳转主站的链接。
- **限免**：每号每周一个固定的 28 只排序（种子 = 账号 ID + 周号，客户端与服务器同一个纯函数），跳过已拥有、取前 7 只；周中新得到一只限免龟 ⇒ 只换掉那一只。换周时刻 = 周一 00:00 UTC。新文件 `scripts/gamedata/weekly_free.gd`。
- **按龟等级（R1）**：快照加 `lv` 表（`pet_key` → 1 ~ 10）；改 `_unit_level(` 的 3 个调用点按龟取等级；龟蛋血量按三只平均；赛季等级保留它另外三个作用（全队装备格数、龟蛋基础、小将等级）。周赛结果会变 ⇒ 升 `RULES_VER`，重生成 `verify_rules_fingerprint` 金标。没有 `lv` 表的旧快照退回整队等级。
- **等级盖章（Q5、D37）**：裁判开算时按 `mainsite_pets` 覆盖快照里的 `lv`，快照自报的作废；不在「拥有 ∪ 限免」的龟这场不计。
- **经验（约定 3）**：周赛每局裁判算完写发件箱发 `exp`，`mode` 取 `ranked` / `gauntlet` / `finals`；幂等键 `match_id + pet_key`。限免龟和擂台局不报。

### 4.3 擂台赛规则（D7 ~ D11、D17、D20 ~ D22、D26 ~ D29）
- **开放**：周二 00:00 到周日结束（UTC）。
- **开轮**：主站调 `arena/open`。拒绝原因：`closed`、`no_first_match`、`run_active`。一个号同时只有一轮。
- **准备**：玩家在 App 点「准备」，锁定三只统领、分路、技能选择、训龟大师、装备（= 积分赛快照，`backend.gd:1957`）+ 此刻的等级 + 此刻的总场次。一直没点的到换周按 `not_ready` 结束。
- **准备前服务器验**：三只都在「拥有 ∪ 本周限免」；等级以 `mainsite_pets` 为准；快照装备与记账重放的身上装备逐件相同（§4.10）。不过 ⇒ 不让准备，界面写明原因。
- **配对（D17）**：只看本大轮总场次（`backend.gd:313` `pool_find_battles` 用的同一个数），以服务器记录为准，快照自报的作废。先到先配，永不放宽，永不配陪练号，等不到就一直等（D11）。
  - 我定的口径（不是用户原话）：配对场次取点准备那一刻、整轮不变；擂台局不计入总场次。理由：锁住的阵容是那一刻的，场次跟着锁才量得准强弱。
  - 同设备的号不互相配（D20）。锁定时带 `OS.get_unique_id()`，记进这一轮。
  - 不连着打同一个人（D22，是排序不是过滤）：同场次有别人在等就先配别人；只剩上一场的对手时照配，不让人多等。
- **对局**：等同切磋（D28、D33）。按锁定内容打；不发深海币、宝箱、香火、小木斧经验、命运之轮层数，不给龟经验，不计总场次。
- **连战**：战果发给主站，主站回复 `continue` 才排下一场，阵容不变；回复 `stop` 或调 `arena/stop` 就结束。主站不可用时这一轮暂停，不多打。
- **离线**：不要心跳，不设排队超时，配对和对局全在服务器。
- **结束**：`stopped`、`week_end`、`not_ready`、`lineup_invalid`、`pet_lost`，每一轮只发一次 `run-ended`。换周时已经开打的那一场打完，照常发战果。

### 4.4 擂台界面（App）
小游戏只显示阵容、对手、胜负和录像，不显示主站的任何数额，也不放跳转主站的链接。做法照手游大厅通行写法，做完交两比例视频自验。

- **网关（D38）**：裁判机新增 `server/referee/mainsite_gateway.py`，Caddy 反代到 `api.turtlearena.xyz`（内测 `api-beta.turtlearena.xyz`），内测、正式各一个 systemd 服务。它做三件事：验 HMAC 接主站的请求、调数据库函数、替 App 转发要用主站密钥的请求。
- **发件箱（D38）**：新表 `mainsite_outbox`（主题、幂等键、内容、重试次数、下次时刻、完成时刻）。建号、经验、战果、一轮结束、解绑全部先写表，`referee_poller.py` 新线程 `outbox_loop` 发送，退避重试。同一账号先建号再发经验。主站挂了不丢数据，也不阻塞裁判。
- **擂台表**：`arena_runs`（主站 run_id、账号、周、状态、结束原因、锁定快照、锁定等级、配对场次、设备、胜、负、上一对手）、`arena_queue`、`arena_matches`（对局 ID、两轮、裁判任务、结果、发送状态）。客户端只走函数（同 `gauntlet_queue`）。
- **配对器**：`referee_poller.py` 新线程 `arena_loop`（同 `econ_loop`），每 5 秒扫各场次：硬条件过滤 → 先到先配 → 建裁判任务。
- **裁判 `arena` 模式**：`MODES` 和 `referee_jobs.kind` 约束加 `arena`；用裁判当前正式版本；领活排在其他模式后面；落账走单独出口；录流照常。
- **录像**：擂台局保留 30 天，`purge_old_matches` 跳过擂台局，流目录单独清理。
- **总开关**：远程开关 `arena_on`，出问题可单独关擂台。
- **假主站**：`tools/mock_mainsite.py` 实现约定里主站的全部接口，门禁和主站接口到位前的开发都用它。

### 4.7 网页播放器（D25 / D36）
