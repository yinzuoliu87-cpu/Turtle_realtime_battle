用户 2026-11-05（逐字）：

> 一、分工
> 谁 负责什么
> 主站（我们） 账号、玩家拥有的龟、龟币钱包、金库、偷币结算、消息通知、运营后台
> 龟战（他们，用他们的服务器） 游戏本体（保留周赛、深海币、商店）、阵容、匹配、战斗、服务器裁判、录像、限免龟
> 原则：钱只在主站账上动。龟战只负责算出"谁赢了"，告诉主站，由主站记账。
> 二、玩家流程
> 1. 在主站点「龟战」，用主站账号直接进入游戏，不用重新注册。
> 2. 上阵 3 只龟，只能用主站里自己拥有的龟。龟不够 3 只时，用龟战的限免龟补位。主站的等级和稀有度不加战斗力。
> 3. 设好防守阵容，并在主站把一部分龟币存进金库。从这时起，别人可以来偷你金库里的币。
> 4. 偷袭：系统推荐 3 个对手，挑一个发起挑战，并押一笔押金。服务器裁判算出结果后，播放录像，主站自动结算。
> 5. 被偷的人会收到消息「你的金库被 某某 偷走 120 龟币」，24 小时内可以复仇一次。
> 三、金库和偷币规则（建议的默认数值，运营后台都能改）
> - 金库：最少存 100，最多存 1 万。只有金库里的币会被偷，主钱包永远安全。
> - 取出要等 1 小时生效，等待期间照样可以被偷，防止"看到有人来打就马上取走"。
> - 每次能偷多少：对方金库的 10%，单次最少 10、最多 500。
> - 押注对等：进攻方押多少，就能偷多少。赢了：拿走这笔币，押金退回。输了：押金全部归防守方。平局：押金退回。平台不抽成，币只在两个玩家之间转。
> - 防守保护：被偷一次后有 8 小时护盾；每天最多被偷 3 次。
> - 进攻限制：每天最多偷袭 10 次。
> - 防小号刷币：对手由系统按龟战积分推荐，不能点名打某个人。同一网络或同一设备的账号不会互相匹配。注册未满 3 天的账号不能参加偷币。
> - 超时：30 分钟内没算出结果，自动退押金、解除冻结。
> 四、接口约定（需要两边对齐）
> 主站提供：
> 1. 登录通行证：主站签发一张 5 分钟有效、带签名的通行证（里面有用户编号、昵称、头像），并公开验签用的公钥。龟战验证通过后，建立或绑定他们自己的账号。
> 2. 查询玩家拥有的龟：返回这个玩家在主站拥有的龟（11 种之一，代号两边相同）。
> 3. 推荐对手 / 发起偷袭：由主站检查金库、护盾和次数限制，冻结押金、建好这次偷袭，再通知龟战服务器建一个"偷袭"类型的裁判任务。
> 4. 结算回调：裁判算完后，龟战服务器把结果（谁赢、对局编号）发给主站，附带签名。同一场只结算一次，重复发也不会重复记账。
> 龟战提供：
> 1. 用主站通行证登录的入口。
> 2. 防守阵容变化时通知主站（有没有防守阵容、龟战积分），主站用它来推荐对手。
> 3. 新的裁判任务类型"偷袭"，算完后回调主站。
> 4. 上阵检查：只允许用主站拥有的龟，加上限免龟。
> 5. 网页版入口和瘦身。
> 6. 改名：他们游戏里也有一种叫"龟币"的东西（目前只累计，没有地方花），要改个名字，避免玩家和主站龟币搞混。深海币保留不动。
> 五、风险，要先说清楚
> - 网页版太大：素材约 190 MB（图片 116 MB、音频 61 MB），手机上第一次打开会很慢。需要瘦身和分包，首次下载最好压到 30 MB 以内。这是第一周就要验证的事。
> - 裁判服务器算力：现在每分钟大约能算 10 到 20 场。偷袭玩的人多了会排队，需要按量加机器。
> - 版本必须一致：裁判只认同一个游戏版本，主站嵌入的网页版要和裁判同步更新。

> 3. 约 2 周 · 金库偷币内测：先用小额上限测，没问题再放开。

## 2. 调查结论

### 2.1 游戏里的「等级」现在是整队一个数

- `RealtimeBattle3DScene.gd:1554` `_unit_level(side)`：左方读 `GameState.season_level`，右方读对手快照里的 `season_level`（`Backend.ghost_level`，`backend.gd:201`）。**一侧一个等级，三只龟同级。**
- 等级的作用（全部按这一个数）：
  - 主属性每级 +5%：`unit_scaling.gd:9` `level_multiplier = 1 + 0.05 × (lv − 1)`，10 级 = 1.45 倍。出生时乘（`battle_spawn.gd:502`），装备固定加值与固定召唤物也吃（`RealtimeBattle3DScene.gd:1580` `_lvl_mult_for`）。
  - 血条上的等级牌：`battle_spawn.gd:435`。
  - 龟蛋血量：`phase2_config.gd:1111` `egg_hp(avg_level) = 3000 + 300 × 平均等级`，双路开场按两侧等级各算一次（`dual_lane_flow.gd:572-574`）。
  - 小将等级：`battle_spawn.gd:338` 读 `spec.level`。
  - 全队装备上限：`phase2_config.gd:1058` `team_equip_cap = (等级 − 1) × 2`。
- `_unit_level(` 在全仓只有 3 个真实调用点（上面的 502 / 435 / 1580），改成「按龟」改动面小。

### 2.2 服务器裁判

- 任务表 `referee_jobs`（`server/supabase/schema.sql:2716`）：`kind` 有约束（`:2718`），`level` 一列是「双方共用等级」（`:2728`）。
- 裁判程序 `scripts/referee/referee_job.gd`：`MODES = gauntlet / finals / ranked`，三种算法相同，种类只决定落哪本账；`client_version` 与本机不等就拒算（`wrong_version`）。
- ⇒ 加「偷袭」= 加一个 `mode`、一个落账出口（回调主站），战斗本身不用新写。

### 2.3 录像

- `matches.replay`（`schema.sql:170` 的注释）：一局只存「重算所需的输入」约 1.6 KB（deflate 后），**每 60 步一个 16 位校验码（cps）**，播放 = 重算。
- ⇒ 用户回放第 3 条（以服务器结果为准）可以做得更彻底：重算途中校验码对不上就停下，直接显示服务器结果，不会出现「画面输了、字幕写赢」。

### 2.4 稀有度不决定强弱（正式服只读实测）

正式服 `matches` 表，2026-11-03 ~ 11-05 积分赛 3,791 场，按「阵容里有这只龟」统计胜率（左右两侧都算，每只约 800 场，误差约 ±1.8 个百分点）：

|---|---|---|
| 石头龟 stone | C | 53.6% |
| 凤凰龟 phoenix | S | 53.3% |
| 龟壳 shell | SSS | 53.1% |
| 熔岩龟 lava | S | 53.0% |
| 小龟 basic | C | 52.2% |
| 财神龟 fortune | B | 52.0% |
| 天使龟 angel | B | 51.2% |
| 闪电龟 lightning | A | 49.5% |

### 2.5 主站一侧（只读 `GitHub/turtlebet`）

- `backend/internal/models/models/user_pet_models.go:22` `UserPet`：每只龟各有 `Level` / `XP`。
- `backend/prompt/project/宠物/04-特性详情介绍-龟种配置.md`：龟种 ID 与我们同名（basic / stone / … / shell），等级上限 10，经验只给当前装备的龟。
- 升级方法归主站（用户 11-05），我们只读等级。

### 2.6 网页版现状

- `export_presets.cfg:25` Web 导出 `variant/thread_support=false`（单线程，主站嵌入不需要特殊响应头）。
- 体积大头（仓库源文件）：`assets/sprites` 147 MB、`assets/audio` 62 MB；字体 `NotoSansSC-Regular.otf` 8.3 MB、`fusion-pixel-12px-zh_hans.otf` 5.1 MB、`NotoEmoji-Regular.ttf` 2.0 MB；引擎 wasm 约 38 MB（7 月实测，未压缩）。美术分支 `art/turtle-seq` 还会再加约 37 MB。
- 手机浏览器跑 3D 战斗的帧率与内存、wasm 与服务器算得是否一致：**都没测过**。

### 2.7 其它

- 游戏里叫「龟币」的是 `GameState.gd:986` `coins`（龟币累计），全仓没有消费入口（`GameState.gd:2446` 注释），显示在主菜单右上货币牌（`MainMenuScene.gd:1095`）。
- 登录：现在是 Supabase 匿名 + 补绑（`supabase.gd:1377` `sign_in_anonymous`）。`supabase.gd` 已 2994 / 3000 行（`tools/arch_budget.py` 上限），新登录代码必须放新文件。
- 限免：全仓没有（grep「限免 / free_turtle」为 0）。

## 4. 方案（龟战一侧，穷举）

### R1 每只龟各用自己的等级（只在偷袭 / 友谊赛生效）
- 快照加一个 `lv` 表（龟 ID → 等级 1~10）。战斗场新增「这只龟的等级」：有 `lv` 表按表取，没有就退回 `_unit_level(side)`。
- 改 3 个调用点：`battle_spawn.gd:502`（出生缩放）、`battle_spawn.gd:435`（等级牌）、`RealtimeBattle3DScene.gd:1580`（`_lvl_mult_for`）。
- 龟蛋血量用三只的平均等级（`egg_hp` 本来就收平均值）；小将等级 = 平均等级四舍五入。
- **周赛快照没有 `lv` 表 ⇒ 走老路，结果逐字节不变**（`verify_rules_fingerprint` 证明）。偷袭是新模式，`RULES_VER` 照 CLAUDE.md §3：只要改了 sim 代码就按指纹是否变来定。

### R2 阵容
- 3 只龟只能从「主站拥有 ∪ 本周限免」里选；拥有的按主站等级，限免一律 1 级。
- 存：3 只龟、分路、每只的技能选择、`lv` 表。不带装备（U3）。
- 点准备时锁定阵容（只有一套；配对前看不到对手，不存在针对换阵）。配上时双方阵容与等级原样写进裁判任务，之后改阵容、升级都不影响这一场。
- 校验做两遍：客户端点准备时（选龟页加过滤），服务器建任务时（向主站查拥有列表）。

### R3 每周限免（用户 11-05：每号每周 7 只、1 级、各号不同、自己拥有的不在里面）
- 每个账号每周一个固定的 28 只排序，种子 = 账号 ID + 周号（纯函数，客户端与服务器同一份）；从前往后**跳过已拥有的**，取前 7 只。
- 这样周中在主站新得到一只限免龟，只会把它换掉、由排序里的下一只补上，其余 6 只不变。
- 拥有 ≥ 22 只时剩不到 7 只，有几只给几只。

### R4 「偷袭」裁判任务
- `referee_jobs.kind` 约束、`referee_job.gd` `MODES` 加 `raid`；幂等键 `raid:<主站偷袭编号>`。
- 一律用裁判当前的正式版本算（快照只有龟 / 等级 / 技能 / 分路这些 ID，跨版本可用）。
- 排在周六闯关、周日决赛后面；任务被领到时已超过 30 分钟就直接作废，不算、不回调（主站那边已退押金）。
- 算完回调主站：带签名（主站公开验签方式待对齐），带偷袭编号、赌注额、胜方、录像 ID、双方新偷袭分。重复发不影响主站，因为主站按编号只结算一次。

### R5 偷袭分（不清零）
- 存我们库里（新表），初始 1000，Elo；前 20 场每场最多变 40 分，之后 20 分；进攻、防守都计。
- 只作配对参考（R10 同分段优先）与展示，随回调推给主站。

### R6 主站通行证登录

### R9 网页版与回放器（用户回放三条的落地）
- **第一天先量，不先改**：iPhone Safari 跑一局的帧率与内存峰值、wasm 重算与服务器校验码是否一致、首包真实大小（压缩后）。卡在哪量出来再定，不先认定是贴图。
- 首包：字体只留用到的字（中文字体可从 5 ~ 8 MB 降到几百 KB）、音效改为按需下载、按龟分包（`ProjectSettings.load_resource_pack`）。
- 贴图压缩对像素画有风险（描边糊、出色块），先拿两只龟试。
- 回放器：重算途中每 60 步对校验码，对不上就停、显示服务器结果。

### R10 准备队列（用户 11-06：填数额 → 点准备 → 等另一个也在准备的人 → 赌注取较小值）
