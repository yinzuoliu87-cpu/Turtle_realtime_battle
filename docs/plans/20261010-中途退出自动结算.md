# 中途退出的对局自动结算（杀进程 / 闪退 / 断电）

日期：2026-10-10　|　状态：**实施中**

## 1. 需求原文

用户 2026-10-10 问「商业游戏中途杀掉 App 怎么处理」。主会话答：皇室战争（服务端继续打完、结果照算、重连接着打）、
云顶 / LoL（断线后对局继续、棋子照打、名次照算）、炉石（回合计时继续，回来接着打或超时判负）——
共同点：**退出不作废对局，也不直接判负，而是按正常规则把这一局打完**。

用户：「学习他们的做法」。

## 2. 调查结论

- 对局是**本机模拟**打对手快照，给定「种子 + 双方阵容 + 人的输入事件」可确定复算：
  `scripts/systems/replay/replay_recorder.gd`（`rec = {v, client_version, plat, arch, seed, state, events, cps, id}`）。
- 人的输入只有三种：`fight`（开打 + 那一刻全部站位）/ `present`（点掉幕布）/ `surrender`（认输），
  `replay_recorder.gd:20-24`；训龟大师不由人操控。摆位拖动的**过程**不进对局，只有开打那一刻的站位进。
- 幕布不点也会走：`RealtimeBattle3DScene.gd:2285-2286`（`DL_PRESENT_SEC = 5` 秒自动推进，是 sim 步里的，确定）。
- **摆位没有时限**：`_dl_state == "place"` 时 `_t` 不涨（`dual_lane_flow.gd:503-504` 的注释），不按「开始战斗」就一直等。
- 结算只在对局结束那一刻：`RealtimeBattle3DScene._settle_season`（7525 起）——积分赛扣命/配额/胜场、
  周六 `gauntlet_settle`、周日 `finals_settle_sealed` + `Backend.report_finals_if_any`。
  杀进程 ⇒ 这一段一行都没跑 ⇒ 不扣命、不记负、不吃配额（= 本次要堵的洞）。
- 结算是否「已经发生过」可以从存档里看出来：`record_match` 把本局录像 id 挂到战绩行 `replay_id`
  （`GameState.gd:1605-1610`），而战绩行随 `save()` 落盘。
- 赛程阶段属于开局那一刻：`TeamSelectScene.gd:1414`（积分赛/周六）与 `BracketMapScene.stamp_finals_match`（周日）写 `week_phase`；
  `finals_match` / `dual_ghost` / `dual_active` **不进存档**（`GameState._save_dict` 1723 起没有它们）。
- 换周：`GameState._ready → ensure_season()`（2176 起）发现周锚点变了就 `start_new_season()` 清档。
- 主菜单开机补报的那一串 `ensure_* / retry_*` 都在登录墙之前（`MainMenuScene.gd:207-221`）。
- 周日服务端：结果先到先得（`on conflict do nothing`），没报的那一场靠 960 秒宽限按 side 0 补判（`backend.gd:1505-1510` 注释）。

## 3. 需求 ↔ 代码的出入

- 「服务端继续打完」—— 我们没有服务端模拟，但对局可在本机**确定性复算**。等价做法：开局落一份「待结算单」，
  下次打开游戏时把它**在本机打完**，再走同一条结算路径。效果与「服务端替你打完」一致（玩家回来看到结果）。
- 「断线后棋子照打」—— 我们的对局在开打后本来就没有人的输入（大师自动）；断线后唯一缺的是**后面几路的「开始战斗」**。
  摆位没有时限 ⇒ 必须新定一条：**复算时摆位屏立刻按默认站位开打**（等价于「玩家不在，棋子按原位打」）。

## 4. 方案

新文件 `scripts/systems/replay/abandoned_match.gd`（`AbandonedMatch`，全静态 + 复算遮罩）：

| 时机 | 做什么 | 位置 |
|---|---|---|
| 开局 | 计分对局（录像判据 `should_record` ∧ 战斗场 `_is_scored_match` ∧ 非表演赛 ∧ 存档会落盘）落一份待结算单 `user://pending_match.bin`：录像（不带校验点）+ 开局那一刻的 `week_anchor_ts / week_phase / finals_match / dual_opponent / left_team / left_slots` + 已试次数 | `ReplayRecorder.start` |
| 每条输入 | 覆盖写一次（事件很少：开打 ×3 / 幕布 / 认输） | `ReplayRecorder.allow_input` 录制分支 |
| 结算 | `record_match` 把录像 id 写进战绩行并 `save()` ⇒ 这就是「已结算」标记；之后（deferred）删单 | `ReplayRecorder.on_settle` |
| 打开主菜单 | 登录墙之前 `AbandonedMatch.resume_if_any()`：有单且未结算 ⇒ 判定（下表）⇒ 进战斗场复算 | `MainMenuScene._ready` |

复算 = `ReplayRecorder` 新模式 `"resume"`：
- 种子 / 状态取自单子；前缀事件按步号重放（与回放同一套 `_fire_due` / `allow_input`，站位按事件写回）；
- 前缀放完后**没有人的输入**：幕布照 5 秒自己走；**摆位屏立刻按当前（默认）站位开打**，这一下照常记进录像；
- 每帧在 `sim_feed` 里直接推 sim（帧内时间预算 12ms，帧切法不改结果——回放倍速已证），遮罩盖住战场、SubViewport 不渲染、音效静音；
- 结算走 `_settle_season` 原路（`on_settle` 在复算里按录制处理：落录像、挂战绩 id、入上传队列、直播行收尾）——**没有第二份结算公式**；
- 结算后撤遮罩，露出正常结算屏，顶上一行「上一局已结算」。

判定（`AbandonedMatch.decide`）：

| 情形 | 处理 |
|---|---|
| 没单 / 单坏了 | 什么都不做（坏单删掉） |
| 战绩里已有这一局的 id | 已结算过（结算后、删单前被杀）⇒ 只删单 |
| 单子的周锚点 ≠ 现在的周锚点 | 跨周 ⇒ 作废删单，主菜单提示「上一局已作废 · 已换周」 |
| 录像版本 / 格式 ≠ 本机 | 复算不可信 ⇒ **判负**：同一个战斗场开局即认输，走认输结算；顶上一行「上一局判负 · 版本已更新」 |
| 已试 ≥ 2 次复算都没结算完（复算本身闪退） | 第 3 次改为判负（同上，认输结算） |
| 判负那一次也没结算完 | 第 4 次作废删单（不让玩家卡死在开机） |
| 其余 | 复算 |

## 5. 已知风险与未决点

默认值都已实现，标 🔲 的请用户过目：

- 🔲 **U1 版本更新后判负**（默认）。理由：换版本后复算不确定，复算出的结果不可信；若改成「作废」则「打输了就杀进程、等更新」成为免费的逃负路径。版本只在周一休赛日换，实际很少碰到。
- 🔲 **U2 跨周作废**（默认）。换周 `start_new_season` 已清命/币/胜场，结到新一周里是错账。
- 🔲 **U3 摆位屏按默认站位开打**：玩家在摆位时被杀，他拖过的站位没有提交（只有开打那一刻的站位进对局）⇒ 用出生站位。后面几路同理。
- 🔲 **U4 收盘后才回来**（积分赛周五 23:00 / 周六 23:00 收盘后、同一周内）：照常结进开局那一周（`week_phase` 用开局那一刻的）。
  代价：积分赛收盘后的配额补发（`backfill_ranked_quota`）已按「少打一场」发过，复算那一场再记配额 ⇒ 最多多发一场的补发（补发只增不退）；
  晋级判定在下一次 `ensure_season` 惰性重算（`promoted` 只会从假翻真）。周六收盘后结算会照常传闯关快照 / 报名决赛（服务端桶已切时它自己回 `already_seated`）。
- 🔲 **U5 周日决赛**：复算后照常 `report_finals_if_any`（带那一场的种子）。服务端先到先得 + 960 秒宽限：若宽限已过、该轮已按 side 0 补判，晚到的这次上报不改结果（服务端 `on conflict do nothing`），本机仍走封存/揭晓那套（揭晓以 feed 为准）——不会双报出不同结果。
- 🔲 **U6 复算闪退两次后判负、判负也闪退就作废**：防「某份单子必崩 ⇒ 每次开机都崩」的死循环。
- 【已堵】只结一次：已结算标记就是存档里的战绩行 `replay_id`（与结算同一次 `save()` 落盘）；结算时录像存不下来（拿不到 id）就当场删单，宁可漏不可双。
- 【已堵】教学 / 调试场 / 特效台 / 表演赛 / 回放 / 存档不落盘的进程（`test_mode`：无头、`NO_SAVE`、命令行场景）都不落单。
- 【已堵】直播行：复算结算时直播行补一行 `ended = true`（周六才有直播）。跨周作废的那一局直播行不补（服务端会话超时自己收）。
- 【未决】复算对不上原局前缀（同版本同设备理论上不会）：放弃剩余前缀事件、继续自动打完，结果照算（打警告日志）。
- 【未验】真机（安卓 / iOS）上杀进程后重开的完整流程只在无头门禁里模拟（释放战斗场不结算 + 重新读单）；⏳ 待真机过一遍。
- 【已知小窗口】结算函数中途（扣命之后、战绩 `save()` 之前）被杀：中间若有别的 `save()`（上传队列入队）会先落半份账，再复算一次会多扣一次。窗口在同一帧同步代码里（微秒级），不另做事务。

- `scripts/scenes/battle/dual_lane_flow.gd`：摆位屏「不建开打钮 / 拖不动」从 `is_playing()` 换成 `blocks_input()`（回放 + 复算）。
- `autoload/Audio.gd`：`mute_sfx`（复算期间一帧几百步，不静音会一帧生几百个播放器）。
- `RealtimeBattle3DScene.gd` 一行未改（arch_budget 8643 不变）。

与方案的偏差 / 新发现的坑：
- 复算自己按的输入发生在 pre_step（`_in_step` 为真），第一版照录成 `i=true` ⇒ 存下来的录像播放时这几条永远不发。改成「本模块自己按的记 i=false」（与人在两步之间按的同一口径）；变异把它改回去，A 的事件序列比对当场红。
- 复算速度：桌面无头约 5000 步 / 250 帧（每帧预算 40ms），约 10 秒；手机慢几倍，遮罩可能挂 30 秒以上（⏳ 真机量）。
- 反向验证（每条都还原并核对 sha1）：`is_settled` 恒假 ⇒ B/C/D/E/F 7 条红；去掉自动开打 ⇒ A 3 条红（跑到防卡死上限认输，结束步 72000）；去掉版本闸 ⇒ E 5 条红；去掉「本模块按的记 i=false」⇒ A 事件序列红；持久装备改成整份覆盖 ⇒ 「未上场统领的装备」红；主菜单去掉调用 ⇒ G 红；去掉「进场前先记一次已试」⇒ D 2 条红。
