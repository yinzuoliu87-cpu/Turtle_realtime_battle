# 小木斧进化演出

日期：2026-10-22　|　状态：**已完成**（演出部件 + 三个触发点 + 门禁 `verify_axe_evo_show`）

> 参考：`docs/plans/ref/20261022-进化动画参考/`（9 款游戏实机录像逐帧抽帧，`分析.md` 有逐款时长与共同做法）。

## 1. 需求原文

- 用户 2026-10-22：「小木斧需要设计进化动画吧」
- 同一段对话的上文（用户问「说说小木斧整个是什么情况」，我答「现在进化时什么都没有，下次打开商店名字和图标已经换了」）。

## 2. 调查结论（现状）

**进化本身有，演出一处都没有。** 进化在三处静默发生，最终造物在第四处：

| # | 何时 | 经验 | 代码 | 进化返回值有人用吗 |
|---|---|---|---|---|
| a | 商店里买小木斧（含已有时再买一把） | +20 | `scripts/scenes/ShopScene.gd:1179` `GameState.axe_add_exp(AxeEvo.EXP_ON_BUY)` | **没有**（返回值丢弃） |
| b | 打完一整场（赛季结算） | +15 | `autoload/GameState.gd:2070` `axe_on_match_end()` | **没有** |
| c | 战斗里斧头击杀 / 3 秒内助攻 | +5 | `scripts/systems/equip/axe_system.gd:470` `on_death()` 返回是否进化 | **没有**。`axe_system.gd:453` 注释原话「返回是否发生了进化(调用方将来放演出用)」——位置早就留了 |
| d | 钻石斧再攒 400 ⇒ 商店说明卡里四选一 | — | `autoload/GameState.gd:2087` `axe_pick_final(key)` | 选完只是卡上换名字 |

- `axe_add_exp` 返回 `evolved`（`autoload/GameState.gd:2049-2062`，由 `AxeEvolution` 纯函数算，`scripts/gamedata/axe_evolution.gd:212`）。
- 战斗中进化**不会让场上那把斧头变身**：属性在登场那一刻算（`axe_system.gd:180` 注释）。⇒ c 的演出不能在战斗里放，只能事后放。
- 现成素材：九个形态各有悬空 3D 像素斧头的待机帧表 `assets/sprites/vfx/eq096-axe-<形态>-idle.png`（8 帧 × 112 格，`scripts/gamedata/axe_art.gd`），还有九张装备图标。演出的主体可以直接用这两套（同一件装备自己的图，不算借用素材）。
- 档位与数值：`axe_evolution.gd` `STAGES`（80/110/130/160 进化，售价 1→5 费）、`FINAL_NEED = 400`、四个造物 `FINALS`；召唤物血 / 攻随**累计经验**涨，不随档位跳。

## 3. 需求 ↔ 代码的出入

- 需求只有一句，没有和代码冲突的地方。
- 要先讲清的一个事实：**c（战斗中击杀）发生进化时没法当场演**（场上斧头不变身、也不能打断战斗）⇒ 必须「记下来、事后在某一屏补放」。这一点决定了下面的方案要有一个待播队列。

## 4. 方案

**一个演出部件，四个触发点。**

1. **演出部件** `scripts/scenes/shop/axe_evo_show.gd`（RefCounted，照 `dmg_stats_panel.gd` 模板：构造注入要挂的 CanvasLayer）。内容暂定（节奏以参考实测为准）：
   - 实际节奏（照参考第 1、3 条；时间轴是纯函数 `state_at(t)`，门禁按时间点查）：

     | 段 | 普通进化 | 最终造物 | 依据 |
     |---|---|---|---|
     | 压暗（0.9） | 0.12 s | 同 | 7/9 款接管画面；0.78 实拍时身后货架抢眼，加到 0.9 |
     | 旧形态原色 | 0.15 s | 同 | 7/9 款揭晓前先给旧的 |
     | 旧形态变白剪影 | 0.12 s | 同 | 宝可梦第 3 世代 |
     | 新旧白剪影交替 | 11 次，0.12 → 0.033 s，共 0.8 s | 15 次，0.2 → 0.033 s，共 1.5 s | 宝可梦 365 → 66 ms 越换越快，压到约 1 秒 |
     | 闪光盖住换图 | 升 0.05 s、峰值 0.85、落 0.25 s | 同 | 6/9 款先变白 / 变亮盖住换图；颜色取新形态主色 |
     | 换图 | 1 帧硬切 + 24 颗方块粒子 | 同 | 6/9 款硬切；像素图只平移不缩放 |
     | 名字 / 副行 | 换图后 0.3 s 出 | 同 | 弹壳闪后 0.5 s 出数值 |
     | 停留 + 淡出 | 1.0 + 0.2 s | 1.8 + 0.2 s | |
     | **总长** | **≈2.4 s**（实测 2.37 s） | **≈3.9 s** | 反复发生的短，一大轮一次的长 |

   - 斧头用它自己的待机帧（九张共用同一裁切 44×60，5 倍最近邻）；揭晓后新形态放待机动画。
   - 名字横幅写新档名（如「石斧」），副行写「售价 2 费」；最终造物副行写「最终造物」。不写「属性提升 X」（召唤物随累计经验涨，不随档位跳）。
   - **不能跳过**（用户 10-22「点一下就跳过？不行」）：播的时候遮罩挡住底下的点击，点了也不跳过；播完自己收起，有多段就一段接一段播。
2. **待播队列**：`GameState.axe_evo_pending`（存档字段，元素 `{from, to}`）。`axe_add_exp` 判出进化时追加；四个触发点各自消费。存档里有它，杀进程 / 重开也不丢。
3. **触发点**：
   - a 商店买 ⇒ 买完当场播（就在商店里）。**如果这时待播队列里还有没补放的（结算 / 战斗里攒的），先播它们再播这一次**，否则会先看到 2→3、进背包才补 1→2，顺序反了。
   - b 结算 / c 战斗击杀 ⇒ 入队，**下次进背包时补放**（用户 10-22 拍板，§5 ①）。
   - d 最终造物 ⇒ 点下按钮当场播加长版。
4. 门禁 / 教程 / 模拟号里：演出走「瞬播」（不等动画），队列照常消费，避免拖慢测试或卡住自动驾驶。

## 6. 验收标准

- 新门禁 `verify_axe_evo_show`：
  - a 路：造一个差 1 点就进化的存档，真点「购买」⇒ 演出节点出现、名字横幅是新档名、点一下能跳过、结束后节点释放。
  - b / c 路：直接调 `axe_add_exp` 跨档 ⇒ 队列多一条且存档里有；重开场景后在补放位置播一次、队列清空、再进不重播。
  - d 路：点四选一 ⇒ 播加长版、横幅是造物名。
  - 门禁模式下瞬播：整段不超过 N 帧。
- **证明它会 FAIL**：拿掉 a 路的触发调用 / 拿掉入队 / 让补放不消费队列，各自必须红（变异后逐字节还原）。
- 实拍：三种比例各截演出的揭晓帧，自查名字、斧头、横幅不出框不压字。

**实际门禁** `tests/verify_axe_evo_show.gd`（63 条）：时间轴逐毫秒采样（交替次数、越换越快、换图时剪影撤掉 + 闪光峰值、名字晚出、收尾淡出）· 商店真点「购买」当场播且不入队 · 待播的排在前面、第一段播完自动接第二段 · 测试模式瞬播 · 结算入队 → 进背包补放一次 → 再进不重播 · 四选一真点「余烬」· 商店 / 背包整页重建后演出还在 · 点一下不跳过、播完自己收起（推它自己那条 tween 的 custom_step，不靠墙钟）· 播的时候点货架被遮罩挡住（先等过买完 0.4 秒的防连点闸；收起后再点同一格能选中当分母）。
11 处变异（拆掉商店触发 / 不先补旧的 / 商店重建清掉 / 不入队 / 背包不补放 / 背包重建清掉 / 四选一不播 / 交替不加速 / 揭晓不撤剪影 / 点一下又能跳过 / 遮罩不挡点击）各自打红，已逐字节还原。
实拍（`tests/_shot_axe_evo.gd`，1560×720 与 1280×720）：真时长 2.37 s，形态切换 11 次，收尾停在新形态。
