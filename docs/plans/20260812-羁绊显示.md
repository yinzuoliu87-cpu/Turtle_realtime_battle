## 3. 需求 ↔ 代码的出入

1. **「出战页没做羁绊显示」不准确** —— 版面和函数都在，只是调用被注释、内容是老系统。
   ⇒ 工作量比"从零加一块 UI"小，且**位置不用我重新设计**（设计稿本来就留了这块）。
2. **「羁绊跟阵容走」需要确认**：羁绊算的是**装备**，而装备挂在龟身上、只有出战的龟带上场
   ⇒ 换阵容确实会改羁绊（`team_p2_equips_for_synergy()` 读的是 `lineup_leader_ids()`）。
   **这条成立**，所以出战页显示羁绊是有意义的，不是装饰。
3. **战斗内羁绊是静态的**：`_by_side` 在 `apply_all()` 里算一次（`if 空 then 算`），
   局内不随单位死亡变化 ⇒ 常驻条不需要每帧重算，建一次即可。

## 4. 方案

### 4.1 出战页（TeamSelectScene）

| 改动 | 位置 | 说明 |
|---|---|---|
| 恢复调用 | `TeamSelectScene.gd:641` | 取消注释，并把注释改成「接的是 10 类型装备羁绊」 |
| 重写函数体 | `_build_synergy_region()` | 标题「类型羁绊」；chips 由 `_refresh_synergy_chips()` 填 |
| 新增刷新函数 | `_refresh_synergy_chips()` | 清空 `_synergy_box` → 按当前阵容重算 → 逐类型建 chip |
| 挂到阵容变化 | `_refresh_after_team()`（:1019） | 选/换/清空阵容后调一次 |

chip 形式（与商店总览条同一套写法，玩家两处看到的是一致的）：

```
🔫枪 4/6 ★☆☆        ← 已激活: 金色 #ffd93d
🛡盾 2/3 ☆☆☆        ← 未激活: 暗色 #7a92a8
```

- `n/next` = 当前件数 / 下一档阈值；顶档时只显 `n`。
- 星位数 = 该类型的档位数，实心星 = 已达档位。
- 排序：已激活优先（档位高的更前），其次「差得最少」的 —— 与商店总览条同一条排序规则。

### 4.2 战斗内（battle_hud）

| 改动 | 位置 | 说明 |
|---|---|---|
| 新增 | `scripts/scenes/battle/battle_hud.gd` `build_synergy_chips(side)` | 一侧一条，极简 chip：`🔫3`（emoji + 档位数字） |
| 数据源 | `battle._synergy._by_side[side]` | 战斗自己算好的，不另算一份 |
| 位置 | 左右队伍头像列的**正上方** | 跟着 `_topright_positions()` / 队伍列的现有锚点走，不写死坐标 |

- **为什么选常驻条而不是开局横幅**：横幅一闪而过，玩家想确认时看不到；而局内羁绊是静态的，
  常驻条随时可查。代价是占一点屏，所以做到最简（只有 emoji + 档位数字，不写类型名不写星）。
- **不做的**：不显示敌方的详细档位？——**做**，两侧都显示（对手带什么羁绊是有用信息，
  且数据本来就在 `_by_side["right"]`）。

### 与方案的偏差

1. **R1 真的发生了**：设计槽 `synergy` 宽 407（换算 316px），而羊皮纸右缘**实测只到 x≈303**
   （panel 左缘 x≈142）⇒ 第一版实拍第三个 chip 掉在木头背景上。按实测把 panel 宽收到 0.50。
2. **字色改了两轮**：羊皮纸底实测 `rgb(132,96,56)`，第一版的金色 `#8a5a10` / 浅褐 `#8b7a5c`
   在上面**读不出来**。最终 已激活 `#3a2408` / 未激活 `#5c4322`（深色系才压得住纸）。
3. **R4 没在真实路径上发生，却在台子上发生了**：`battle_spawn.gd` 是 `apply_all(:174)` →
   `_build_team_panels(:191)`，顺序本来就对；但 VFXLAB 是**先建场、后写 `_by_side`**，
   所以台上 chips 是空行。补了 `refresh_synergy_chips()`（只换那一行，不动整层 UI）。
   —— 一开始我在台子里调 `_build_team_panels()`，结果**整层 UI 连血条都没了**。

### 新发现的坑

1. **★我写了一条假判据，反向验证当场抓到。** 「出战页的羁绊区有真调用」那条：我按行扫描、
   跳过 `#` 开头的行、找 `_build_synergy_region()` —— 但**函数定义那行也含这个名字**，
   于是把调用注释回去之后判据照样绿。加了「跳过 `func ` 开头」才真。
   ⇒ 这正是本文件 §6 要求"怎么证明这个检查会 FAIL"的价值：**不反向跑一次就发现不了**。
2. **门禁抓出了我的测试数据错**：我拿 `p2eq_049` 当枪，实际它是**弓箭**（连发弩），
   于是"枪=4"断言报"实得 3"。装备属于哪个类型一律查 `data/p2eq-types.json`，别按名字猜。
3. **`_by_side` 疑似跨路不重算（待查证）**：`synergy_system.apply_all()` 只在
   `_by_side[side].is_empty()` 时算，而**全仓没有任何 `_synergy.clear()` 调用者**；
   `dual_lane_flow.gd:502` 换路时调 `apply_all()` 显然是指望它重算的。
   ⇒ 若两路阵容不同，第二路可能沿用第一路的档位。**这是显示之外的机制问题，需要探针确认，
   已单独记下，不在本方案范围内改。**
