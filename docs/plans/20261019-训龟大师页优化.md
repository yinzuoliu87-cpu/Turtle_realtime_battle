## 2.5 需求 ↔ 代码的出入

- 需求只有一句「优化好」，没有和代码相反的描述。
- 唯一要先核对的前提：「只改呈现、不改逻辑」—— 存档字段、旧档迁移、战斗派生都在 `GameState`（`trainer_active_skill()` / `trainer_passive_skill()`），本页只写 `trainer_skill` / `trainer_appearance` 两个字段，改前改后一致（`verify_trainer_config` 守着）。
- `SKILLS` 不只是这一页的数据：`scripts/net/backend.gd::_bot_trainer_skill`、`tools/pet_effect_dump.py`、`tools/copy_lol_style_lint.py`、`verify_trainer_audit`（按源码串 `{"id": "..."` 找）都直接读这个文件 ⇒ 常量块必须原样留在 `TrainerConfigScene.gd`，不能挪进新文件。

## 4. 方案（已实施）

版式（1280×720 设计框，`UIFrame` 居中；顶栏铺满视口宽）：

```
← 训龟大师                                                     （TopBar.DEEP，与背包/设置同一原语）
┌ 形象 ───────────────┐ ┌ 技能 · 7 选 1 ─────────────── 被动与主动只能装配其一 ┐
│   聚光 + 石台        │ │ [被动]   [主动──────────────────────────]           │
│   立绘 ×6（120×234） │ │ [魔法石]  [钩锁][药水][口哨][冰川][猎龟令][驯服]     │
│   形象名（28px）     │ │ ───────────────────────────────────────────────── │
│ [村民][魔法师][少女] │ │ [大图标×2]  名字（32px）  [主动] ✓已装配            │
└──────────────────────┘ │ 说明（通栏，SkillText 关键词上色 + 属性小图标）     │
                         └──────────────────────────────────────────────────┘
```

- **点一下 = 装配并存盘**，去掉「保存 / 取消」；顶栏返回再存一次兜底（P6、P8）。
- 被动 / 主动分两组，组签 + 组线，中间留宽缝 —— 规则靠排版看得出来（P4）。
- 选中：金框 + 右上金色勾徽记 + 名字变金；点中时槽弹一下（1.08→1）；换形象时人物在石台上跳 3 个立绘像素（P1）。
- 说明走全项目同一个渲染 `SkillText.plain_to_bb`（与图鉴、商店同口径）；排版只加换行：冷却一句另起一行，口哨三个分支各起一行，**一个字不改**（P5）。
- 新素材（`assets/sprites/trainer_page/`，16/24 原生像素 ×3 最近邻，PIL 逐像素画）：`slot-normal/hover/selected.png`、`panel.png`、`pedestal.png`（×4）、`spotlight.png`（×5，三档抖动光）、`badge-check.png`。不借别屏的框；立绘与技能图标是这一功能自己的（`asset_borrow_audit` 白名单已有理由）。
