## 2. 调查结论（含 `文件:行号`）

### 2.1 ① 大师头像格 —— **主线上已经做掉了**

- `scripts/scenes/battle/info_panel.gd:46` 建头像栏时 `if u.get("is_trainer", false): continue`，注释写着
  「★U2「移除掉训龟大师的信息栏」」。来自提交 `3ed9a17b`（今天 10:13，回放 S1 + U2 那一笔）。
- 门禁已有：`tests/verify_trainer_move.gd:118-129`「★③ 头像栏里没有训龟大师(分母: 头像框 N 个)」。
- 头顶血条也已经去掉：`verify_trainer_move.gd:112` / `verify_trainer.gd:62`（`bar_root` 为空）。
- 头像栏是 `VBoxContainer`（`info_panel.gd:18`），跳过一格只是少加一个子节点 ⇒ **天然不留空位、不错位**。
- 依赖那一格的东西：点头像框开详情走 `u["panel_frame"]`；大师不建框，`_update_team_panels`
  （`info_panel.gd:61`）读 `panel_frame` 时 `fr == null` 就跳过 ⇒ 不报错。点战场上的大师本体开详情的那条路
  不经过头像栏，不受影响。
- 实拍（本轮重拍，屏幕外窗口）：`img-20261004-五件新需求/battle-side-columns.png` —— 左右各 3 张龟卡，没有大师格，竖直排布正常。

### 2.2 ② 血条刻度 —— 现状确实是「100 小 / 500 大」

- 改前 `scripts/scenes/hp_bar.gd` `_draw()` 里写死 `v += 100.0` / `v2 += 500.0`，两组都挂在同一个
  `if minor_px >= w * 0.02` 下面（88px 宽的条上是 1.76px）。
- ⇒ **改前有一个连带毛病**：barMax > 5000 时小刻度太密被收起，**大刻度也跟着一起消失**
  （1 万血的单位血条上一道刻度都没有）。
- 刻度跟的是 `_bm`（barMax = max(maxHp, hp + 各种护盾)，`hp_bar.gd` `update_state` 末尾），
  不是 maxHp ⇒ 有护盾时刻度跟着变密。这条行为本轮**不改**。
- 全仓再没有第二处画血条刻度的代码（grep `刻度`/`tick` 只有特效里的装饰刻度）。

### 2.3 ③ 罩子破裂（只调查，本轮不改）

- 罩子 = 基地穹顶 `battle._base_domes[side]`，建在 `battle_world_builder.gd:1660-1663`，每路开场
  `_reset_domes()` 复原（`RealtimeBattle3DScene.gd:1408`）。
- 破裂只有一个入口：`dual_lane_flow.gd:769` `_dl_drop_fence(side_lr)`，**只在** `_dl_flow_check` 的
  `if battle._dl_state == "fight"` 分支里调（`dual_lane_flow.gd:808-815`）。
- 问题就在这：第一方团灭后状态立刻变成 `"eggwindow"`（:815），而 `eggwindow` 分支（:817-820）
  **只看计时，不再看另一方是否团灭** ⇒ 另一方后来也团灭了（DoT、蛋自损、反伤、同归于尽……），它的罩子**不破**。
- 同帧双灭：`:811` 写的是 `"left" if la == 0 else "right"`，两边都是 0 时只处理左边 ⇒ 右边的罩子也不破。

### 2.4 ④ 装备统计（只调查，本轮不改）

- 现在只有**按单位**记账：`battle_damage.gd:139-158` `_st_dealt`/`_st_taken`、`:718` `_st_shield`、`:787` `_st_heal`。
- **没有按装备的记账**：`_apply_damage_from` 只有一个 `from_equip: bool`（`battle_damage.gd:325`），
  不带是哪一件装备；`_heal`（:763）和 `_grant_shield`（:694）连这个 bool 都没有。
- 改动面：`_apply_damage_from(` 调用点 **229** 处、`_apply_damage(` **30** 处、`_heal(` **72** 处、
  `_grant_shield(` **50** 处，装备系统文件 37 个。要给每次结算带上「哪件装备 iid」才能记账。
- 现成可复用的显示通道：`scripts/gamedata/equip_readouts.gd`（装备格右下角徽章 `COUNT` / 充能条 `CHARGE`），
  以及详情面板装备区每帧刷新的读数行（`info_panel.gd` `_info_eq_readouts`）。

### 2.5 ⑤ 商店自动刷新 —— 只有一个入口

- 货架在 `GameState.meta_shop_offer`，配一个戳 `meta_shop_battles`（掷货那一刻的 `season_total_battles`）。
- **自动换货只发生在一处**：`ShopScene._ready` → `_restore_offer()`（`ShopScene.gd:173`）发现
  `meta_shop_battles != season_total_battles` 就返回 false ⇒ `_roll()`。
- `season_total_battles += 1` 的三处结算（`GameState.gd:666` 闯关 / `:716` 决赛 / `RealtimeBattle3DScene.gd:7604` 积分赛）
  都**不碰货架** ⇒ 拦住 `_restore_offer` 这一处就拦住了全部自动刷新。
- 其他清货架的地方：`reset_save`（清档）和 `start_new_season`（新赛季）各把 `meta_shop_offer = []`。
- 手动刷新：`_on_refresh()`（扣 2 币 → `_roll()`）。
- 现成图标：`assets/sprites/ui/icon-lock.png`（32×32，背包页 `InventoryScene.gd:21`、对阵图 `BracketMapScene.gd:629` 已在用）。
  **只有「锁着」这一张，没有「打开的锁」**。

## 3. 需求 ↔ 代码的出入

1. **① 已经做完了。** 用户说「待完成」，但 `3ed9a17b`（U2）今天早上已经把头像栏里的大师格去掉，并且有门禁。
   推测用户手上的包早于这一笔。本轮做的是：核实 + 重拍 + 对现有门禁做反向验证，不另改代码。
2. **② 「500 一个大刻度」属实**，但改前还有一个用户没提的毛病：血一多（>5000）大刻度会跟小刻度一起消失。顺手修了。
3. **⑤ 云顶「锁着时手动刷新」的真实规则和派活时的假设相反。** 派活说明写「云顶里手动刷新照样可以、而且不解锁」；
   查到的说法（[TFT Ninja · The Shop](https://tft.ninja/guides/game-mechanics/the-shop)）是
   「锁住的商店会一直锁着，**直到你手动解锁或者刷新**」——刷新会顺带解锁。用户的话是「学云顶的」，所以**照云顶做：刷新顺带解锁**，
   列为 U5-1 等用户确认（反过来改只是一行）。⚠ 来源只有一个第三方攻略站，没有在游戏里实测。
4. **③ 用户说「另一方因为某种原因团灭了罩子也要破裂」—— 代码里那条路根本不存在**（§2.3：eggwindow 状态下不看第二方团灭）。不是演出漏了，是判定漏了。

### 4.4 ③ 罩子破裂（留给后续 agent）

做法提要（不是拍板）：在 `_dl_flow_check` 的 `eggwindow` 分支里也查 `_dl_side_alive` 另一方是否归零，归零就
`_dl_drop_fence(另一方)`，并在 `fight` 分支处理同帧双灭（两边各破一次）。`_dl_drop_fence` 要幂等（同一方别缩两次 tween、
别把 `EGG_FENCE_RES` 扣两次）。**定局路给蛋挂 ×5 承伤这一条要不要对第二方也生效，需要用户拍板（U3-1）。**

### 4.5 ④ 装备统计（留给后续 agent）

做法提要：每件装备实例（`iid`）一份 `{dmg, heal, shield, …}` 账本，由伤害/治疗/护盾三条结算路径按「来源装备 iid」记账；
两条伤害路径（CLAUDE.md §3.3）都要记。显示逐件定（用户原话「慢慢看」）。
