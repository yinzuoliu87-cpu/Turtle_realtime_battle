## 4. 方案

**回放 = 重算，不是录像。** 每局记下「重算这一局所需的全部输入」，打完写进 `matches`；
别的设备点开 → 下载 → 本机按 det 节奏重算并照常渲染。理由：录像（逐帧单位状态）一局要几 MB，
重算输入只要几十 KB（§4.8），而且 D7 第二步（服务端复算）要的正是同一份输入。

分三步走，**每步各自可验收、可停**：

| 步 | 做什么 | 证明了什么 |
|---|---|---|
| **S1 本机录、本机播** | 打一局 → 录 → 同一台机器重算播放 | 实战可复现 + 录制字段完整 |
| **S2 上传** | 打完写 `matches`，失败可重试 | 数据完整到服务端 |
| **S3 他人设备播** | 另一台设备列出、下载、播放 | 跨平台一致 |

### 4.1 难点①：实战改成可复现（S1 的主体）

三个选项：

| 选项 | 做法 | 手感风险 | 工作量 |
|---|---|---|---|
| **①A（推荐）** 把交互模式也做成「sim 只吃 sim 步」 | (a) `_reg_tween()` 在交互模式也 `pause()`，`_step_sim_tweens()` 去掉 `if not _deterministic: return` —— 一处改，38 处一起对；(b) 14 处 `process_frame` 协程搬进 sim 队列（= B 阶段 B2 本体，`verify_sim_step_rate` 的 `KNOWN_GAP` 清零）；(c) 大师输入改成「每帧采样、每个 sim 步施加」 | (a) 演出 tween 的更新粒度变成 60Hz sim 步：60Hz 屏无差别，120Hz 屏 tween 驱动的动画只按 60Hz 动（立绘 / 相机仍按真实帧，不受影响）。(b) 会动玩法数值 ±1 步（现状调查条目 1：小熊 `bear.frame >= 3` 的伤害时刻、宽刃命中顺序） | (a) 小；(b) 14 处 / 5 个文件（来源：`20261002-B阶段确定性现状调查.md` 条目 1）；(c) 小 |

### 4.2 难点②：全局 RNG / 演出随机不能进 sim

- `trainer_system.gd:874` 的裸 `randf_range` 改走 `_battle_rng`（与 `:872` 同一个源）。

### 4.3 难点③：站位、局内输入必须录

**录什么**（一局一份 `replay` 记录，JSON）：

| 字段 | 内容 | 在哪一刻取 |
|---|---|---|
| `v` | 记录格式版本（整数） | —— |
| `client_version` | `ProjectSettings` 的 `application/config/version` | 打完 |
| `seed` | `GameState.battle_seed`（已规范化到 2^53 内） | `RealtimeBattle3DScene.gd:917` 之后 |
| `mine` | **我方上场所需的 GameState 子集**（分路 / 小将 / 持久装备 / 等级 / 技能选择 / 大师技能与被动 / 局内等级与蛋血 / 宝箱进度……） | 开第一路之前 |
| `foe` | `GameState.dual_ghost` **原样**（下发来的那份，不是重建的） | 开第一路之前 |
| `lanes[]` | 每路：开打瞬间**双方全部单位**的 `pos`（量化后，见下） | `_dl_start_fight()` |
| `inputs[]` | `{step, kind, ...}`：`surrender`；`move`（大师移动向量，**只记变化**）；`cast`（主动技 + aim 向量） | 事件发生处，按 `_sim_step_n` 打步号 |
| `cps[]` | 每 60 个 sim 步一个指纹摘要（校验点） | sim 步末尾 |
| `result` | 胜负 / 各路结果 / 时长 | 打完 |

`mine` 的字段清单**不能靠我列**（memory `fb-recursive-scan-not-structured-walk`：白名单天生会漏）。
判据交给 V3：重算前把 GameState 里**所有**对局相关字段改成垃圾，重算结果仍一致 ⇒ 清单是全的。

**量化**：浮点经 JSON 往返可能掉位（`GameState.gd:229-238` 种子那次就是实测漂了 532）。
站位、移动向量、aim 向量一律**先量化、再在实战里施加量化后的值**（不是只在存的时候量化）——
否则实战用的是精确值、重放用的是量化值，第一步就分叉。站位量化到 0.5 码、向量到 1/256，实战里最多偏半码（不可感知）。

**U2 与录输入的关系**：如果先把 U2（大师不由人操控）落地，`move` / `cast` 两类输入就不存在了，`inputs` 只剩投降。
这是**用户 2026-09-16 已经拍过板的**，但它是玩法改动，要不要先做是 Q2。

### 4.4 难点④：版本不一致不给播

- 播放前比 `client_version`，不等就显示「这场比赛是旧版本打的，当前版本播不了」，**不进战斗场**。
- 只比版本号是够的：同一版本号 ⇒ 同一份脚本与数据（导出包里打进去的）。引擎版本跟着导出包走。
- 跨平台不一致**不是**版本能挡的（同版本、Windows 与 iPhone 可能算出不同），由 §4.1 的校验点兜：
  播放中第一个对不上的校验点 ⇒ 停下，显示「这一场在本机重算对不上，无法播放」，**不许默默播一场错的**。

### 4.5 难点⑤：播放入口

| 位置 | 用途 | 改动 |
|---|---|---|

**播放实现**：走真入口，不另起一套（memory `fb-verify-must-run-the-real-path`）：

### 4.6 难点⑥：写入时机与失败重试

照 `finals_report_pending` 样板（§2.5）：

1. 打完（`_settle_season` 那一刻，**无条件**，含投降）组装记录 → **先**追加进 `GameState.replay_upload_pending`（数组，落盘）→ 再发。

3. 销单判据是「**服务端真有这一行**」（回读 `match_id`），不是「拿到了 2xx」（memory `fb-200-ok-is-not-it-happened`）。
4. 主菜单每次打开补一次（与 `retry_finals_report()` 同一处、同一形状）；结构上发不出去的（缺字段）直接销单并打日志。
5. 超过 U7 可见期的单子不再补（补上去也看不到）。

**`matches` 表要改**：加一列 `replay jsonb`（放 `lanes / inputs / cps / mine`），或者把它们塞进现有的 `left_snapshot / result`。
推荐新列（Q4）—— 塞进 `left_snapshot` 会让「快照」这个词有两种形状。改表走 SQL（memory：Management API 能执行）。

### 4.7 难点⑦：谁能看、看多久

### 8.3 录 / 播

- 新文件 `scripts/systems/replay/replay_recorder.gd`（`ReplayRecorder`，RefCounted）。主场景只加钩子（`_sim_step` 开头 `pre_step`、末尾 `sim_stepped.emit()`、`_settle_season` 第一行、`_do_surrender` 闸、`_exit_tree` 还原）。主文件 8649 → 8632 行（台账未下调，留给合并时一起调）。
- **编码用 `var_to_bytes` + deflate**，不用 JSON：探针实测 `JSON.from_native` 把 `0.30000000000000004` 存成 `0.3`，`var_to_str` 也有回不去的值。⇒ §4.3 说的「站位量化」**不需要了**（二进制逐位精确，实战不改站位）。⚠ S2 上传时 jsonb 里放 base64；D7 服务端复算要能解 Godot 二进制格式，那是另一件事。
- `state` = GameState 全部脚本变量去掉 `STATE_DENY`（令牌 / 邮箱 / 安装 id / 云版本号 / 战绩 / 补报单）——**不列白名单**，完整性由 V3 篡改法量。
- 局内输入事件三类：`fight`（带开打那一刻双方全部单位站位）/ `present`（点掉呈现幕布——**§2.7 没列这一条**：它决定下一路在第几步建场）/ `surrender`。按步号记，播放时在下一步开头重放；重放后重新取 frozen（「开打」会顿帧 0.18 秒，不重取就差一步——实测踩到）；校验点在重放之后取。
- 摆位屏上的站位是人还在拖的中间态，**不进校验点**（开打那一刻逐个比对）；播放时摆位期 8 倍速快进（一帧多跑几步，结果与帧率无关正是 ①A 换来的）。
- 播放：`ReplayRecorder.play(tree, rec)` → 比版本（V6）→ 备份 GameState → 写入记录 → `test_mode=true` → 进战斗场；种子从记录进；结算一律跳过，不出结算卡，出「回放结束」；任何离场路径 `_exit_tree` 都还原 GameState。录制的那一局在 `record_match` 那一行挂 `replay_id`。
- 实测一局（两路 + 认输，约 2700 步）记录 **约 2.5 KB**（deflate 后），远小于 §4.8 的估算。
- 顺手修：伤害飘字的 tween 绑在 battle 上，换路兜底清场先释放飘字 ⇒ `_dmg_float_step` 报 `Cannot convert argument 2`（门禁致命正则不认这一形态）；飘字离树即 `kill` 掉 tween（`battle_vfx.gd`）。
