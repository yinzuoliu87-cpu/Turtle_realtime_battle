## 2. 调查结论（2026-10-07 读代码，行号以当天工作区为准）

- 015 的属性事实源 `scripts/gamedata/equip_stats.gd:120`：`hp 100/200/1000 · reflectPct 12/25/40`；展示镜像 `data/phase2-equipment.json` 的 `baseStats1`；生成表 `docs/design/装备逐件审查进度.md`（`tools/gen_equip_review_table.py` 重生成）。
- 015 的反伤是**专属分支**自己发的：`scripts/systems/equip/equip_system.gd` `_eq_on_target` 的 `"p2eq_015"` 分支，通用钩显式跳过它（`equip_stats_apply.gd` `REFLECT_OWNED_BY_BRANCH`）。
- 通用反伤：`scripts/scenes/battle/battle_damage.gd` 约 478 行，`StoneSystem.reflect_generic(u)` = 装备 `reflectPct`（013 海胆壳）+ 龟壳觉醒 + 石头龟坚壁。
- 治疗强度 / 护盾强度：结算在 `battle_damage._heal`（原 `amt *= 1 + heal_amp`）与 `_grant_shield`（原 `amt *= 1 + shield_amp`）；面板在 `info_panel.gd` 两处（小字行 `_info_stat_rows_minor` 与网格 `_info_stat_tiles`）各自手写 `_pct_mult(1 + amp)`。面板属性每帧按下标刷新文字，不靠状态签名。
- 「治疗削减」（`heal_reduce_until` / `heal_reduce_pct`）是另一条独立机制（毒箭、凤凰涅槃、猎人等写），本次不动。
- 全仓 `["shield"] =` / `+=` 写点穷举 13 处：给盾只走 `_grant_shield`，唯一例外是 011 饮血护符坠「溢出治疗转盾」（`_heal` 内直接加）——它本来就不吃 `shield_amp`。
- `equip_system.gd` 正好 3000 行 = `arch_budget` 单文件上限 ⇒ 新逻辑不能往里加。
- 时停里单位自己的到期时刻由 `timestop_system.gd` 的 `TS_EXTRA_UNIT_TIMER_FIELDS` 补表顺延。

## 3. 需求 ↔ 代码的出入

1. 「携带者的反伤」—— 携带者身上的反伤来源不止 015 自己一条（石头龟坚壁 / 013 / 龟壳觉醒走通用路径）。**解读（主会话定）：携带者任何来源的反伤命中攻击者都施加**；没带 015 的单位反伤不施加。
2. 「治疗效果和护盾效果的削弱」= 对目标的**治疗强度 / 护盾强度属性**打折（用户确认有这两个属性）。打折是**乘在属性上**：+30% 治疗强度的目标 → 130% × 0.5 = 65%。
3. 面板原先自己算 `1 + amp`，若只改结算，削弱生效时面板仍显示 100%，与实际不符 ⇒ 结算与面板改成读同一个函数。
4. 旧效果保留（用户更正）。

- 用户 10-07：hp 180/350/1000；新效果 3 秒 50% 治疗 + 护盾削弱。
