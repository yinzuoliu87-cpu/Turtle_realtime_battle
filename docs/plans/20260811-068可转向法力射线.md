### ③ 转向速率

第一次施放玩家只是慢慢划（~22°/s），**不是上限**。第二次甩得狠：

| 时段 | 角度 | 速率 | 束身点数 |
|---|---|---|---|
| 116.30 → 116.47s | 23.6° → 11.7° | **72 °/s** | 1.4 万（完整） |
| 116.00 → 116.10s | 0.3° → 19.0° | 187 °/s | 6000 ⇒ **光束还没成形，不算数** |

**屏幕角上限 ≈ 72 °/s。** 换到世界角要过地面压缩 `tan(θ屏)=k·tan(θ世界)`，
k 取 0.55 ⇒ 倍率 ≈1.6 ⇒ **世界转向速率 ≈ 110～120 °/s**。

> ⚠ **k=0.55 是我的估计，不是量出来的**（见 §五 未决点 2）。
> 但有一条好性质：**角速度是无量纲的**，不随场地尺度变 ⇒ 参考值可以 1:1 搬过来，
> 不需要知道 LoL 的码与我们的码怎么换算。

## 一、要做成什么

一道**可转向**的法力射线：指着一个目标，目标死了就转向新目标，
**转的过程中扫过谁就烧谁，离开就停**。

---

## 二、验收清单（逐条列全，别挤牙膏）

1. 射线**能转向**：当前目标死亡/失效 ⇒ 自动改指新目标（最远的活敌），按角速率上限逼近，**不瞬移**
2. 射线**跟踪活着的目标**：目标位移时方向持续跟随（同样受角速率上限约束 ⇒ 快速绕后能甩脱）
3. **扫到即伤、离开即停**：伤害按「本 tick 内被射线照到的时长比例」结算，不是「tick 结束瞬间在不在线上」
4. **不漏人**：转向时 tick 之间跨过的敌人必须结算（见 §三·B 的扫掠区间）
5. **数值契约不变**：一个全程被照的目标，3 秒仍吃满充能值的 100/120/600%
6. 演出是**真 3D 几何**：芯／晕两层独立网格，转向时整体旋转
7. 横截面照实测：**白芯占 15～20%**，外缘浓琥珀金（饱和度 0.55～0.65），中间平滑过渡
8. 时间曲线照实测：**蓄势→爬升→持续→末端峰值→一帧切断→余辉**
9. **伤害与亮度仍走同一条曲线**（现状这个设计是对的，要保住）
10. **枪口星芒**
11. **命中特效**（用户点名）：射线照到谁，谁身上就持续有爆点，离开即停
12. 换路／战斗结束时**全部清干净**（068 的头顶条就是死在这条上）

## 三、怎么实现

### A. 转向

```
每帧:
  若 target 无效/已死 → target = 最远的活敌
  desired = (target.pos - origin).angle()
  cur = move_toward_angle(cur, desired, TURN_RATE * delta)
```

`TURN_RATE = 110 °/s`（实测换算值）。**伤害判定用 `cur`（射线真实朝向），不是用 target 的位置** ——
否则"扫过谁烧谁"就成了假的。

### B. ★不漏人：按【角度扫掠区间】结算，不是按当前直线

`BEAM_TICK = 0.25s`，110°/s ⇒ **一个 tick 转 27.5°**。
在 500 码处是 240 码弧长，而射线全宽只有 116 码 ⇒ **照直做会整个漏掉敌人**。
（与「逐帧机制门禁必须逐帧喂」「合成单位被钳到同一点」同族：粗粒度采样看不见缝隙。）

解法 —— 每个 tick 用**角度区间求交**，是闭式解不是采样：

```
θ0 = tick 开始时的朝向, θ1 = tick 结束时的朝向
对每个敌人:
    d = |敌人 - 原点|;  超出射程 → 跳过
    α = atan((HALF_W + 敌人半径) / d)      # 敌人占的角半宽
    β = 敌人方位角
    若 |θ1-θ0| < ε:  f = 1 if |β-θ0| ≤ α else 0        # 不转 ⇒ 退化成现状
    否则:            f = |[β-α, β+α] ∩ [θ0, θ1]| / |θ1-θ0|
    伤害 = 本 tick 伤害 × f
```

★两条好性质：
- **不转时 f=1，与现有行为逐字一致** ⇒ 天然的回归保护（门禁可以断言这一点）
- f ≤ 1 自动成立（交集不可能超过扫掠区间本身）

### C. 为什么契约不变

`_beam_hit` **现在就是「带内每个敌人各吃全额」**（不是平分）。
所以「3 秒共造成充能值的 100/120/600%」本来就是**对单个持续被照的目标**说的。
改成扫射后这条不变；变的只是**被扫过的敌人按被照时长拿一部分**。

⇒ **不需要改任何数值契约**，也不需要重新平衡星级倍率。

### D. 真 3D 几何（不是贴图、不是"简单程序图形"）

- **两层同轴套管**（不是平铺地面的四边形）：
  - 内层：窄白芯，半径 = 外层的 15～20%（实测值）
  - 外层：浓琥珀金晕，饱和度按实测 0.55～0.65
  - 各自 N 段径向细分 ⇒ 是**真的扫掠体**，从任何角度看都有体积
- **`CULL_BACK` 只画正面**：实心闭合曲面 + 加色混合 + 双面 ⇒ 中心必然加爆成白
  （v0.19.90「白球家族」那轮的结论，四件同一个病）
- **亮度靠 alpha 给，不靠把颜色洗白**（同上）
- 沿程**不做强衰减**（实测大致持平），只在射程末端轻微收束
- 网格**建一次**、每帧只转节点 ⇒ 转向不重建，热路径零分配

### E. 时间曲线

把 §〇① 的实测包络做成**相对包络表**（等比拉伸 2.5s → 3s），
`beam_current` = 表（瞬时强度），`beam_frac` = **表的归一化积分**（累计伤害比例）。
两者是导数关系 ⇒ **画面最亮那一瞬也正是打得最狠那一瞬**，现状这个性质保住。

### F. 枪口与命中（用户点名）

- **枪口**：白热点 + 放射星芒，强度跟着同一条包络
- **命中**：每个**当前被照到**的敌人身上持续一个爆点（星芒 + 白芯），**离开即停**
  —— 不是一次性的爆炸，这是"扫射"的关键读数

## 五、已知风险与未决点

1. **实战总伤害多半会下降。** 契约（对单目标）不变，但扫射把伤害摊到被照时长上，
   而旧版是"一条固定直线上的所有人全程吃满"。**这是玩法削弱，量级未测。**
   要不要补一轮胜率验证（既有双 worktree 全循环赛流程）？—— **等你拍板**
2. **地面压缩因子 k=0.55 是估计值，不是实测。** 转向速率 110°/s 依赖它。
   要真量，得用"光束末端在地面上画的是圆弧"去拟椭圆解出 k —— 更贵，且末端常常出画面。
   **要不要花这个成本？** 我的意见：先用 110°/s，手感不对再调 —— 角速度是可感知量，
   你在真机上一眼能判断"太慢/太快"，比我把 k 量准更快。
3. **命中爆点数量 × 性能未测。** 一次扫射可能同时照到多个敌人 ⇒ 多个爆点并存。
   路线图 §二·五 第 12 条「特效性能预算未测」本来就欠着。
4. **是否允许跟踪活着的目标**（验收清单第 2 条）。我按"跟踪"设计——理由是
   不跟踪的话，目标一走位射线就空放，"可转向"这个特性一大半就没用了。
   但这也意味着**它比旧版更容易打满**，与风险 1 部分抵消。**如果你要"只在目标死时才换靶"，说一声。**
5. **转向会让射线扫过友军所在的方位**。当前实现只对敌人结算，不会误伤 —— 但
   视觉上射线会从友军身上扫过去而没反应，可能读成"穿模"。要不要给友军一个被照的轻微反馈？

## 六、门禁（判据落在真实对象，不量替身）

| # | 断言 | 反向验证 |
|---|---|---|
| 1 | 不转向时，带内每个敌人吃满 —— **与改动前逐字一致** | 把 f 写死成 0.5 ⇒ 必须红 |
| 2 | 转向时，扫掠区间内的敌人**都**被结算（不漏人） | 把扫掠改回"只测当前直线" ⇒ 必须红 |
| 3 | 角速率**受钳制**：一帧内朝向变化 ≤ TURN_RATE·delta | 去掉钳制直接瞬移 ⇒ 必须红 |
| 4 | 目标死亡 ⇒ 换靶（读真实 target 字段，不是"我调用过换靶函数"） | 让换靶只写日志不改 target ⇒ 必须红 |
| 5 | 全程被照的目标，3 秒总伤害 = 充能值×倍率（**契约不变**） | 改倍率 ⇒ 必须红 |
| 6 | 白芯宽度／外晕宽度 ∈ [0.15, 0.20]（实测区间） | 芯改成和晕一样宽 ⇒ 必须红 |
| 7 | 时间曲线**末端最亮**：`current(0.95T) > current(0.1T)` | 换回指数衰减 ⇒ 必须红 |
| 8 | 亮度与伤害同源：`frac` 是 `current` 的归一化积分 | 让两者用不同的表 ⇒ 必须红 |
| 9 | 换路后射线／枪口／命中爆点节点数归零 | 去掉清理 ⇒ 必须红 |

★所有"数值对不对"的用例**不依赖任何动画 tween 跑完**（CLAUDE.md §3.5）：
扫掠结算是闭式解，直接同步喂 delta 即可判定。
