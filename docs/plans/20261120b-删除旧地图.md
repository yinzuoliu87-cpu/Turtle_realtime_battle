# 删除旧地图（V0_BASE 石墙珊瑚深海场）

日期：2026-11-20　|　状态：**已完成**

## 1. 需求原文

> 用户 2026-11-20（看宝箱龟普攻特效录像时）：「然后还有，我看你这个这调色这地方怎么还是用的旧地图啊？能不能把旧地图都删掉？我感觉。」

（「调色」= 语音识别的「调试」：录像用的审阅台。）

## 2. 调查结论

- 地图主题表 `scripts/gamedata/arena_theme.gd`：`V0_BASE`（石墙 + 珊瑚 + 海星的深海场）+ 四张新图 `V1_DUSK` 暗林 / `V2_REEF` 深礁 / `V3_SHOAL` 紫墟 / `V4_STORM` 赤林。
- 正式对局 10-04 起只从四张新图里按种子随机（`MATCH_POOL`），教学固定暗林（`TUTORIAL_THEME`）；`V0_BASE` 只剩开发工具（调试场 / 审阅台 / 装备演示台 / 特效实验台）与单测的默认（`static var active: String = V0_BASE`）⇒ 录像里看到的就是它。
- 四张新图每一层都给了自己的配置（95 ~ 102 项），`V0_BASE` 只有 12 项 ⇒ 建场代码 `scripts/scenes/battle/battle_world_builder.gd` 里「主题没给就走原来那套」的分支、明写「base(现状) 一个像素不动」的分支，实际只有旧图走得到：旧装饰坐标表 `_build_decorations`、`_build_tilemap_decor` 的海底系装饰表、`_build_theme_decorations` 的回退、远景 `bg_kind = undersea`、`TILE_COLS` 回退调色等。
- 碰撞障碍表五张图共用一张（主题只换贴图），`tests/verify_arena_theme_pick.gd` ① 验过同种子五张图逐步结果相同 ⇒ 换开发工具的默认图不改任何对局结果。
- 点名 `V0_BASE` 的测试 8 条：`verify_arena_layers_drawn` / `verify_arena_themes` / `verify_arena_theme_pick` / `verify_cam_extent` / `verify_debug_arena_map` / `verify_island_ambient` / `verify_replay_roundtrip` / `verify_theme_decor_census`。

## 3. 需求 ↔ 代码的出入

- 「都删掉」：旧图在玩家能玩到的地方早已不出现；要删的是主题表那一条 + 只被它走到的建场代码与素材，开发工具改用新图。

## 4. 方案

1. 先存底：四张新图各按固定种子建场，导出世界树（节点名 / 类型 / 贴图 / 位置取整）指纹。
2. `ArenaTheme`：删 `V0_BASE` 与环境变量别名；开发工具默认 = 暗林（与教学同一张）。
3. 建场代码：删只有旧图走得到的分支、函数与常量；只被它们引用的素材一并删（逐个 grep 确认没有别的引用）。
4. 再导一遍指纹：四张新图必须与删之前逐节点相同。
5. 8 条测试按新契约改（「进场前默认 = 暗林」「主题表里没有旧图」）。

## 5. 已知风险与未决点

- R1【我定】开发工具默认用暗林（固定一张，便于前后对比；正式对局仍按种子随机）。
- R2【已堵】旧图分支与新图共用函数交织，删错会改到新图 ⇒ 指纹对比 8 份删前删后逐节点相同。
- R3【已处理】有的测试量的是旧图特有的东西 ⇒ 阳性对照换人造 / 源码检查，只验旧图功能的 3 条删除（见回填）。

## 6. 验收标准

- [x] 主题表里没有旧图；开发工具进场是暗林；四张新图建场指纹与删之前逐节点相同 —— `verify_arena_theme_pick` 等 18 条相关测试全绿；指纹 8 份（4 图 × 调试场 / 正式对局）删前删后逐节点相同（`tests/probes/_probe_arena_fingerprint.gd`，单位立绘的待机呼吸 y 抹掉后比）。
- [x] 旧图专属素材删除后全仓没有悬空引用 —— `tools/data_integrity.py` / `tools/asset_orphan_audit.py` / `tools/zero_caller_audit.py` / `tools/arch_budget.py` / `tools/repo_hygiene_audit.py` 全过。
