## 一、目标（想得到什么）

1. **交互游玩帧率无关**：60fps / 144fps / 300fps 下游戏**逐 tick 一致**，根除「逻辑按 60fps 写死」这一类 bug。
2. **交互确定性**：为将来 netcode（多人实时同步）铺路——所有客户端同 tick 同状态。

## 二、现状实测（决定这一刀难度）

- `_process(delta)` = **129 行**，sim / render / input **交织**（不是干净分块）：
  - **SIM**（要进固定步）：`_t += delta`、`_tick_unit`、`_step_projectiles`、`_step_pending_shots`、决胜、时停/顿帧、训龟大师战斗 tick、分离 pass、熔岩/冰川区。
  - **RENDER**（每帧一次·带插值）：相机震屏、`_update_world_transforms`、立绘帧动画、各种 overlay/连接线/飘字。
  - **INPUT**（每帧一次·读一遍）：`_trainer_input_tick`（键盘/摇杆）。
- 中段 `if frozen / elif timestop / else` 三分支**每支都先 sim 再 visual** → 拆分要逐支解交织。
- **★关键新事实（2026-07-25 帧率审计）**：全文件"按每帧写死"的只有 **2 处**（走路 `moved>0.8`、击飞 `vx*=0.9`），**已在 v0.15.7 修掉**。其余位置/重力/滞空/动画/累加/减免**本来就帧率无关**。

## 三、方法（增量·前松后紧）

- **切片 1（安全·可等价验·先做）**：把 `_process` 的 sim 部分抽成 `_sim_step(dt)`，render/input 留在 `_process`。**先仍每帧调一次 `_sim_step(delta)`**（用当前 delta）→ **行为逐字不变**，纯重构。用 `verify_battle_determinism` + smoke 验等价。这一步把「sim 与 render/input 分层」做出来，不改行为、不动手感。
- **切片 2（改行为·必须 F5）**：`_process` 改累加器：
  ```
  _acc += minf(real_delta, 0.25)
  while _acc >= SIM_DT: _sim_step(SIM_DT); _acc -= SIM_DT
  _render_step(real_delta)   # 相机/立绘/overlay·可选插值
  ```
  → 交互游玩变固定步长。**这一步改所有技能的精确时序**，需你在 60/144/300fps 各玩几场验平衡/手感。
