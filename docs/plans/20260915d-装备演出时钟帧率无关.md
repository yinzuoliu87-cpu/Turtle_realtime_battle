# 装备演出时钟：低帧率下不再慢一倍

状态：实施中（修复与门禁随 v0.19.389；060 重录的验收视频待用户看）

## 需求原文

- 2026-09-15 用户逐件验收装备：「一个个给我看视频」；058 过了之后问「059呢」（059 早已验收）。
- **本件不是用户点名的需求**，是我录 060 磷光水母伞的验收视频、逐帧看的时候发现的：伞在屏上挂了约 4.6 秒，而文案写的是「持续 2.5 秒」。录像本身是错的，发出去等于让用户验收一个 bug，所以先修再发。

## 调查

### 探针（临时 `tests/_probe_fps_vfx060`，用完已删）

关掉场景自己的 `_process`，手动喂固定步长累加器，**每喂一帧真的等一帧**（引擎帧号要走）。

| 每帧 sim 步数 | 效果 开 → 收 | 伞的演出 出现 → 消失 | 效果开约 1 秒时，演出句柄自己的 t |
|---|---|---|---|
| 1（≈60fps） | 7.017 → 9.533 = 2.517 秒 | 7.017 → 9.533 = 2.517 秒 | 1.000 / 1.000 |
| 2（= 30fps，录屏与掉帧手机） | 7.033 → 9.533 = 2.500 秒 | 7.033 → 12.067 = **5.033 秒** | 1.017 / **0.500** |

分母：喂 572 / 362 帧，引擎帧号同样走了 572 / 362。

### 根因

- sim 是固定步长累加器（`RealtimeBattle3DScene.gd` 的 `_advance_sim_accum`，一步 1/60 秒）：30fps 下一帧跑两步。
- 灵物（`eq_spirit_batch.gd`）、食物（`eq_food_batch.gd`）、药水（`eq_potion_batch.gd`）三层演出挂在**每单位**的 `tick_unit` 里，用 `Engine.get_process_frames()` 去重（防止多个携带者一帧推进 N 次）⇒ 一帧只放过第一步 ⇒ 演出慢一倍。
- 068 激光收尾（`mana_beam_vfx.gd` 的 `advance`）同样按帧号去重。
- 附带的第二个问题：这三层只在「带装备的活单位」tick 时推进 ⇒ 携带者死光时整层定格，战斗结束后也定格。
- 同一形状的第五处：`equip_system.gd` `_eq_on_hit` 的「同一刻命中 ≥2 个目标 = 范围」按帧号判（009 宽刃弯刀充能减半）。30fps 下相邻两步各打一个目标会被判成范围。
- 2026-08-06 已经因为同样的理由删掉 `_sig_tick_fr`、把全局推进搬进 `EquipSystem.tick_global`（见该函数头注）；这五处是当时没搬的。全仓 `get_process_frames()` 只有这五处在产品代码里。

### 影响面

- 只影响每帧跑两步以上 sim 的情形：**录屏（固定 30fps）与掉到 30 帧左右的手机**。60 帧及以上每帧最多一步，本来就对。
- 我已经发给用户验收过的视频：058 远古炮台、084 手半剑的演出走 `tick_global`，059 时停不在这五处之列，都不受影响；**060 这份录像作废**，修完重录。
- 070 砖块的溅射伤害按 sim 钟延时（距离 ÷ 冲击环速度，与环的扩张用同一个常量）⇒ 30fps 下环慢一倍时，伤害会先于环到人。这一条是按代码推的，门禁量的是环的在屏时长。

## 出入

- 我一开始以为是 060 单件的演出时长写错了，量完才知道是四个演出层 + 一个判定共用的时钟问题，一次修。
- **时停里的行为没有顺手改**：修前，时停携带者自己的 tick 会顺带推进这三层（连别人的演出一起）；修后在时停分支里补调三层的 `tick_global`，保持修前行为。这与用户 2026-09-14「所有东西都定住」的口径不一致，列为未决。

## 方案

1. 灵物 / 食物 / 药水三批各加 `tick_global(delta)`，由 `EquipSystem.tick_global` 每步 sim 调一次；顿帧期间不推进（逐单位的效果计时在顿帧里也不走，两边同步）。药水的瓶雾到期扫描一并搬过去。
2. `mana_beam_vfx.advance` 去掉帧号去重，改由药水的 `tick_global` 全局调一次；`_tick_pressure_can` 里那一行删掉。
3. 主循环加 `_sim_step_n`（每步 +1），`_eq_on_hit` 的范围判定改按 sim 步号。
4. 时停分支补调三层 `tick_global`（保持修前行为，见出入）。
5. 数值一个都不改。

## 已知风险与未决点

- **时停**：见出入。修前修后，时停里都会推进场上所有人的灵物 / 药水 / 食物演出，而那些人的效果计时是冻住的 ⇒ 时停结束时演出可能已经比效果走得靠前。要改成「只推时停携带者自己的演出」需要演出句柄带归属，本版没做。
- **顿帧口径**：这三层现在顿帧里停；而弓箭 / 枪 / 奇械 / 法器 / 遗物各批的演出与效果都在 `tick_global` 里、顿帧里照走（第九批 U9 同一个口径问题，待用户定）。本版只保证「每层演出与它自己的效果同步」。
- **战斗结束后**这三层演出现在会播完（修前定格在原地）；换路仍由各自的 `clear_all` 立即清。
- **瓶雾到期扫描**现在每步 sim 都跑（修前只在带药水的活单位 tick 时跑）：它只读 `_t`，顿帧与战斗结束后 `_t` 不走，没有副作用；多一次遍历场上单位。
- **未验证**：068 激光收尾时如果没有正在照的爆点，`mana_beam_vfx.gd` 的 `finale` 会直接把句柄摘掉，枪口与飘带节点可能不再有人推进渐隐、留在场上。门禁 ⑤ 只覆盖了「有爆点」的情形。
- 60 帧及以上的设备本来就不受影响，实机手感基本不变；变的是 30 帧设备与录屏。
