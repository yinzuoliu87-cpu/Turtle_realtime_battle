## 调查
- 周日链路（代码现状）：
  - 模拟号 17:50 UTC 上线（`tools/beta_daily.sh` 周日分支，只起闯关 4 胜的号，`SIM_QUIT_WHEN_DONE` 空、23:30 关）。
  - 18:00 UTC 小组赛分桶开打（`Phase2Config.FINALS_SEAT_HOUR_UTC = 18`），20:00 冠军杯赛。服务端分桶 / 推进由 pg_cron 按**真实时间**跑。
  - 每轮先有 3 分钟备战购物窗（`phase2_config.gd:155` 起），窗口内不能开打。
  - 模拟号：`SimFinalsPilot`（`scripts/systems/sim/autopilot_finals.gd`）在对阵图看到「备战窗开着、剩 ≥ 40 秒、这一轮没买过」⇒ 回主菜单，`sim_driver` 进商店买 → 背包 → 回主菜单 → 再进对阵图开战。
- 现成工具：`tools/probe_finals_server.py` 用**假周号 WEEK=2** 在生产库验服务端推进（建桶 / 不剧透 / 不早推 / 收盘 / pg_cron 会跑），会留两个匿名测试账号；**不含客户端买东西这一段**。
- 客户端时间穿越：`TURTLE_FAKE_NOW` / 设置页「测试时间」只改客户端；服务端分组推进照真实时间走（`phase2_config.gd` 头注）。

## 出入
- 约定是「开测试赛周彩排整链」，但没有测试服；正式服上服务端按真实时间推进 ⇒ 要么等到真实周日，要么在**假周号**上手动建桶 + 手动推进。
- 时间穿越会让客户端以为换周了 ⇒ 若用 p01~p140 原存档彩排，可能触发每周重置、弄坏它们本周（周六周日还要正式打）的进度。

## 方案（草稿，逐步待用户确认）
1. **隔离**
   - 假周号：选一个从来没有数据的周（如 2026-08-31 那周，后端 9-20 才上线），先查生产库该周 `ghosts / standings / finals_*` 都是 0 行。
   - 账号与存档：**新建 4~8 个彩排专用存档目录**（`C:\tmp\turtle-rehearsal\rNN`），各自匿名注册新账号；不碰 p01~p140 的存档。
2. **建桶**：用管理员令牌按 `probe_finals_server.py` 同一套 SQL，在假周号下建一个小组赛桶，参赛者 = 上面几个彩排账号（先各上传一份快照）。
3. **开客户端**：彩排号带 `SIM_DRIVER` + `SIM_AUTOPILOT` + `TURTLE_FAKE_NOW=<假周的周日 18:0x>` 开窗口（右屏）。
4. **观察**（每条要有证据，不靠「没报错」）：
   - 对阵图看到备战窗 → `shop_trips` 增加、商店里真买了东西（shop 事件 stars 分布）→ 回到对阵图 → 开战 → 结算 → 返回。
   - 手动推进到第 2 轮，重复一遍；推到收盘，冠军公布。
5. **清理**：删假周号下全部行 + 彩排账号；删 `C:\tmp\turtle-rehearsal`；复查该周 0 行、正式周数据行数与彩排前一致。

## 已知风险与未决点
- **会写正式服**：彩排账号、假周号的快照 / 桶 / 结果都写在生产库；清理靠删行，漏删会留垃圾。⇒ 彩排前后各数一次行数对账。
- 假周号的选择要先查空；若客户端对「很久以前的周」有特殊处理（如拒绝显示），整链可能走不通 —— 待验证。
- 时间穿越下客户端与服务端时间不一致：服务端推进必须手动调；pg_cron 那一路彩排里**验不到**（`probe_finals_server` ⑭ 另验）。
- 需要管理员令牌（`~/.supabase/access-token`），SQL 上生产前要用户点头（memory「SQL上生产仍要问」）。
- 未决：彩排几个号、跑小组赛几轮、要不要连冠军杯赛一起演。
