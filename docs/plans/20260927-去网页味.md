## 调查 · 「网页味」的可操作定义

不是感觉词。落成能 grep 的形状：

| 形状 | 例子 | 游戏该怎么做 |
|---|---|---|
| 表头行 | 排行榜「排名 \| 玩家 \| 胜·余命·横扫」 | 行本身自带语义，不要列标题 |
| `label: value` 属性表 | 「稀有度：C」「定位：近战斗士」 | 徽章 / 词条 / 图标 + 数字 |
| 括号计数 | 「装备 (59)」「龟 (28)」 | 不显示，或做成角标 |
| chevron | 「展开全文 ›」「点开看全部 ▸」 | **注意有功能含义**：它是「可点」的暗示，删了就丢了暗示，要换不要删 |
| 纯圆角矩形卡片 | `StyleBoxFlat` + `corner_radius` | 本仓已有像素 9-slice：`UISkin` |
| 标题里写规则 | 「本周排行（按胜场→余命→横扫）」 | 标题只写它是什么 |
| 居中细灰字提示 | 网页空态占位文案 | 游戏说法 |
| 说明书腔 / 后台词 | 「列表」「详情」「配置」「暂无数据」 | 玩家说的话 |
| 内部术语漏出 | reason / bucket / settle / seed 的直译 | 一律换掉 |

## 3. 已知风险与未决点

**风险 1（★2026-09-28 查实后推翻重写）· 拦路的不是快照门禁，是硬写了屏幕词的断言。**

我原先写的是「本仓有 `text_golden`（483 段快照）…**改文案必然撞它们**，查清流程前不许批量改文案」。
**这条是错的。** 读过四个审计器的 `collect()` 之后：

| 门禁 | 实际覆盖范围 | 改 `.gd` 屏幕字符串会红吗 |
|---|---|---|
| `text_golden`（487 段，不是 483） | 只走 `data/pets.json` + `data/phase2-equipment.json` | **不会** |
| `text_prose_guard`（580 段） | 同上 | **不会** |
| `text_value_golden`（432 段 / 1952 值） | 同上 | **不会** |
| `codex_text_lint` | 上两个 + `status.json` + `battle-rules.json` + `p2eq-types.json` | **不会**（改这三个 json 才过它） |

⇒ **改 `scripts/scenes/**.gd` 里的屏幕字符串，一条快照都不用更新。**
真正会拦你的是散在 `tests/verify_*.gd` 里**硬写了屏幕词的断言**。本轮已被打红三条：
`verify_codex_desc:97`（搜源码串 `点开看全部 ▸`）、`verify_codex_layout:113`（按前缀数提示条数）、
`verify_leaderboard_header`（表头行已按设计删掉 ⇒ 整条测试前提不存在）。

⇒ **正确流程只有一行**，改任何一个词之前跑：

```bash
grep -rn '要改的那个词' tests/ tools/
```

查出来的断言必须同步改，而且**要改成量行为，不是换一个新字面量继续搜**
（`verify_codex_desc` 自己的头注就写着「搜字符串的判据是假判据」—— 犯规的正是它自己）。

**唯一真的要更新快照的情形**：改 `data/pets.json` / `data/phase2-equipment.json` 的措辞。
顺序不能反：先跑不带 `--update` 看差异逐条确认，再 `--update`，快照与代码**同一个提交**。

**这条风险判断错了的教训本身要记**：我没读 `collect()` 就写下了「必然撞」，
于是方案书里立了一条**不存在的墙**，还据此下了「查清之前不许批量改文案」的禁令。
本仓 memory 里这叫 `fb-my-invented-rules-become-the-wall`：被硬规矩挡住先 grep 出处。

**风险 1b · 但 UI 文案确实一条快照都没有。**
`scripts/scenes/**.gd` 里的屏幕字符串**完全没有快照门禁** ⇒「文案悄悄变了」在 .gd 侧看不见。
本轮 18 个 agent 并行改文案就撞上了这个：**没有任何机制能说出谁改了哪句**。
⇒ 已派 agent 把 `text_golden.collect()` 扩到收 `.gd` 里赋给 `.text` / `.tooltip_text` 的字面量，
存成**独立的一份**快照（不许和现有 487 段混在一起，混了会让现有判据的分母含义变味）。

**风险 2 · 「品味」没有客观判据，我量不到。**
去网页味能量的只有**形状**（圆角盒个数、chevron 个数、表头行有没有）。
「好不好看」量不到。上一轮我拿 `0 网页盒 / 0 圆角盒` 当「全清了」报给用户，
用户当场说「一点也看不出来游戏的味道」——**数字代表不了它**。
⇒ 未决：本轮**不拿计数当结论**。每一屏都出截图，由用户判。
