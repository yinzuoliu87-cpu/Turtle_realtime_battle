## 2. 调查结论

### 2.1 终极战场谁上场（代码链，查实）

| 步骤 | 证据 | 说明 |
|---|---|---|
| 每路打完 → 存幸存快照 | `scripts/scenes/battle/dual_lane_flow.gd:905-922` `_dl_lane_over` 先调 `_dl_snapshot_survivors()` 再 `record_lane_result` | 上路、下路各存一次，**累加**进 `GameState.dual_survivors[left/right]` |
| 快照收谁 | `dual_lane_flow.gd:931-967` | 只收**活着的**统领 + 小将；**不收召唤物**（`:941` `is_summon` 跳过）、**不收训龟大师**（`:943`）；回 30% 已损生命（`:945`）；带装备（`:951`） |
| 1:1 才打终极 | `dual_lane_flow.gd:919` + `autoload/GameState.gd:580-581` `dual_lane_needs_final` | 2:0 横扫直接结束 |

| 一路怎么算「团灭」 | `dual_lane_flow.gd:711-731` `_dl_side_alive` | 存活数**算战斗型召唤物**（只排 `_DL_INERT_SUMMON` = 糖果炸弹 / 水晶球，`RealtimeBattle3DScene.gd:1523`），不算训龟大师 |
| 同一步双方都灭 | `dual_lane_flow.gd:881-891` | 注释原话「同帧双灭仍判左」：循环先看 left，**左方判本路败方** |

⇒ 「名单为空」在三种情况下真的会发生（注释说「理论不会到」是**错的**，见 2.2 实测）：

1. **同一步双灭**：某路双方同一步全灭 ⇒ 左方判输，右方「赢」了这一路却一个活人都没有。
2. **赢了之后在破蛋窗口里被反杀光**：对方先团灭，本方在 10 秒破蛋窗口内又被 DoT / 反伤 / 召唤物打光（`dual_lane_flow.gd:877-897`，第二方团灭只破罩，不改本路胜负）。
3. **只剩召唤物赢下一路**：召唤物算存活（不触发本方团灭），但快照不收召唤物 ⇒ 赢了但名单为空。

再加上「另一路本方被团灭」，进终极战场时这一方的名单就是空的。

### 2.3 现在顶上来的那只「小龟」是什么（查实，回答 Q1）

**是的，会默认顶一只小龟**，而且就是一只完整的小龟（不是小将外观）：

- 走 `battle_spawn.gd:274` `_make_unit("basic", side, pos)` → 龟分支 `:350-353`：名字「小龟」、立绘 `pets/animations/basic/idle.png`、被动「不屈」、技能按 `_resolve_active_skills`（左方读玩家的技能选择，右方用默认）。
- 等级缩放按龟口径（`:496-502`，+5%/级）：S1 实测 lv6 = 1181 血 / 50 攻 / 17.5 甲 / 16.3 抗，技能 `basicBarrage`（打击），龟能表三招齐全。
- **装备两边不对称**：`RealtimeBattle3DScene.gd:7899-7903` `_inject_equipment` 对**左方**会按 `persistent_equipped["basic"]` 塞装备 ⇒ S2 里左方那只小龟带着玩家背包里给小龟配的 `p2eq_001★1`（攻击 55），右方那只裸装（攻击 50）。玩家根本没上小龟时也一样会出小龟。
- 头像框 / 顶栏头像 / 终极战场对阵幕布 / 结算表上都显示为「小龟」。

### 2.5 技能可复用的原语（查实，回答 Q5~Q7 的实现路径）

- **直线技能弹 `fire_skillshot`**：`scripts/scenes/battle/battle_ballistics.gd:765-790`。沿方向匀速飞、每 0.05 秒推一截，这一截上**第一个**敌人才结算并消失（`_first_on_segment` `:793-808`），飞满就消失；走 `_pending_shots` ⇒ 按 sim 时间推进、时停按施法者冻结、换路随队列清。**正是 Q6「打第一个碰到的」**。
  - 现成用例：小龟·打击 `battle_ballistics.gd:860-874`（10 道气波、每道朝随机敌人飞 420 码、半宽 55 码，`BasicConsts` `basic_consts.gd:56-62`）。
  - ⚠ 起点写死为 `src["pos"]`（`:767`），而 Q5 的气波起点不在施法者身上 ⇒ 要加一个可选的起点参数（默认值 = 原行为）。
  - ⚠ 拦截名单 = `_enemies_of`（`battle_targeting.gd:140-146`）：排除未破罩的蛋，**含已破罩的蛋、含对方训龟大师**（大师只吃 1 点）；友军不挡；**地形障碍不挡**（全仓没有任何「弹体被墙挡」的机制，grep 过）。
- **物理段**：`_atk_dmg(u, 1.0, tgt)`（`RealtimeBattle3DScene.gd:4145-4149`，内部 `_resolve_dmg` 会掷暴击，小将暴击 0）。
- **最大生命值百分比魔法段**，仓库里两种写法：
  - `_resolve_dmg(src, tgt.maxHp × pct, tgt, true)`（`trainer_system.gd:882`、`equip_system.gd:2416`）——吃魔抗、会掷暴击；
  - `_dot_after_resist(tgt, tgt.maxHp × pct, true, src)` + `set_dtype("magic")`（无头龟撕咬 `RealtimeBattle3DScene.gd:2876`）——吃魔抗、不掷暴击。
  - 物理版的现成写法：近战小将接触「10% 目标最大生命值物理」`hiding_system.gd:337` `_phys_after_armor(u, tref.maxHp × 0.10, tref)`。
  - 口径：**按真实 `maxHp`，不除 `HP_MULT`**（CLAUDE.md §3.1，门禁 `verify_eq_maxhp_pct_basis` 静态扫 `/ HP_MULT`）。
- **两条伤害路径**（CLAUDE.md §3.3）：本技能两段都是「有来源的技能命中」⇒ 两段都走 `_apply_damage_from(src, u, dmg, col, …)`（`battle_damage.gd:365`），各调一次（两个飘字：物理红 / 魔法蓝）。**不改伤害管线本身**，所以 `_apply_damage` 那一条不受影响。

### 2.6 龟能条（查实，回答 Q3）

- 龟能**没有独立字段**，是「技能冷却倒计时」：`_tick_skill_cd`（`RealtimeBattle3DScene.gd:2582-2609`）每帧减 `skill_cd[type]`；充满秒数 = 龟能花费 × 0.075（`_skill_cd` `:5174-5175`，`SkillEnergy.CD_FACTOR` `skill_energy.gd:13`）。眩晕 / 击飞 / 施法定身期间不充。
- 满了由 AI 在射程内放技：放技射程表 `_SKILL_CAST_RANGE`（`:5062`），可放技能白名单 `_IMPL_SKILLS`（`:5140-5166`），分派 `_do_skill` 的 `match`（`:5306`，小将三招在 `:5342-5344`）。
- 头顶龟能条：`_make_status_bar` 给所有非大师单位建（`battle_spawn.gd:424-429`），小将本来就有。
- ⇒ 新小将接入只要：`active_skills = [新 type]` + `energy_cost[新 type] = 花费` + 上面三张表各登记一行。

## 4. 方案

### 4.1 总体

- **触发**：终极战场开场时，某一方的幸存名单为空（即现在 `_dl_survivor_specs` 走兜底的那一刻，覆盖 2.1 的三种情形）⇒ 这一方上**一只援军小将**（名字待 U1 拍板，下文暂称「援军小将」）。两方都空 ⇒ 两边各一只（U7）。
- **身份**：归入小将一族（`id = "__minion__"`、`_isMinion = true`、`minion_role = "reserve"`），复用小将的「无装备 / 跳过龟式等级缩放 / 图鉴深海小将组 / 信息面板走 MinionCodex」整套口径；**不进** `dual_lineup`、背包、合成池、快照上传。
- **技能**（暂名「四面合围」，U1）：见 4.3。

### 4.3 技能「四面合围」（按我的建议填的默认值，全部待 U2~U5 拍板）

1. 目标 T = AI 当前目标（`_do_skill` 传入的 `tgt`；为空则 `_pick_enemies_of` 里最近的一个——**不选训龟大师、不选不可选中**）。
2. 以「施法者 → T」连线定方向：**前** = T 靠施法者一侧、**后** = T 背后、**左 / 右** = 垂直方向；出发点距 T 260 码，夹在战场边界内。纯向量运算走 `DetMath`，不用三角函数、不用随机数。
3. 按 前 → 后 → 左 → 右 依次出手，间隔 0.2 秒；施法者定身 0.8 秒。
4. 每道：从出发点朝【它出手那一刻】T 的位置直线飞，速度 380 码/秒、半宽 55 码、飞满 520 码（穿过目标点再飞一段）；不追踪 ⇒ 目标走开就可能落空或打到别人。
5. 碰到的**第一个敌方单位**结算并消失：
   - 物理：`_atk_dmg(u, 1.0, o)` → `_apply_damage_from`
   - 魔法：10% × **o 的**真实 `maxHp`（U2）→ 吃魔抗、不掷第二次暴击 → `_apply_damage_from`
6. 施法者死亡 ⇒ 还没出手的气波取消（同小龟·打击 `battle_ballistics.gd:864`）；已经飞出去的照常结算。
7. 目标中途死亡 ⇒ 剩下的气波仍飞向 T 最后的位置（不重新选目标，保持「依次飞向这个目标」的读感）。

强度估算（我算的，未实测）：等级 6、攻击 63.8，打一个 1200 血 / 20 甲 / 20 抗的目标（抗性系数 40/(20+40) = 0.667，`DamageMath.resist_multiplier`）：每道 ≈ 42.5 物理 + 80 魔法 ≈ 122；4 道全中 ≈ 490，约目标 41% 生命值；每 9 秒一次（120 龟能）。

## 实施回填

**实际改动**（2026-10-29）：

- 出场：`dual_lane_flow._dl_survivor_specs` 名单为空 ⇒ `{kind: minion, role: reserve, battles: 该方本周已打场数}`（左 = `GameState.season_total_battles`，右 = 对手快照的同名字段，缺省回落左方）。两方都空各一只。
- 属性：`scripts/gamedata/reserve_consts.gd` 单一来源，`base_stats(battles)` = 1000/50/15/15 × (1 + 0.04 × 场数)，线性乘加不用 `pow`（跨平台逐位一致）；远程 400 码、攻击间隔 0.85、移速 105、龟能 135。
- 回放 / 裁判：`season_total_battles` 进 `replay_recorder.STATE_KEYS`；`referee_job.state_for` 从 A 快照补这个字段 —— 否则回放 / 服务器重算出的援军属性与现场不同。
- S5 修复：`battle_spawn` 有 `hp_frac` 的（终极战场快照）按快照里的 `elite` 生成，不再把第一只普通小将升精英；`role == reserve` 恒不升。
- 技能 `reserveConverge`（`scripts/systems/skills/reserve_system.gd`）：锁定一名敌人，在其前后左右 360 码各出一道气波，**四道同时**出现、原地停 0.5 秒后出发（210 码/秒，弹体 120 码长），每 0.05 秒重新对准**锁定目标的当前位置**（追踪），碰到的第一个敌人结算后消失；目标死了飞到它最后的位置消散；最多飞 900 码。每道 100% 攻击力物理 + 该敌人 10% 真实最大生命值魔法（只吃魔抗、不掷暴击）。
- `battle_ballistics`：`fire_skillshot` 加可选 `from` / `catchup`，`_first_on_segment` 加 `catchup`（往回补查，防迎面走来的敌人从两步之间穿过去）。默认 0 ⇒ 其余技能逐字节不变。
- 美术（全新，不复用）：立绘 + 待机 / 跑 / 攻击 / 施法 / 死亡动作（PixelLab，黄铜潜水盔 + 气瓶 + 橙色信号旗）、技能图标、有方向的动态气波弹体与六种演出素材（`tools/build_reserve_vfx.py` 确定性生成）；演出模块 `scripts/systems/skills/reserve_vfx.gd`（锁定标记跟目标走 / 出现印 / 凝聚 / 拖尾 / 命中爆点 / 消散）。
- 界面：图鉴「深海小将」一行（`minion_codex.gd` 文案用 `{C:ReserveConsts.X}` 占位读常量）、对阵幕 / 信息面板 / 结算 / 顶栏头像，援军不显示等级。两份权威文档同步。
- 门禁：`verify_reserve_minion`（真入口 `RefereeRunner.run` 五个场景 + 几何 / 伤害 / 追踪 / 补查，34 项）、`verify_reserve_minion_ui`（59 项）、`verify_reserve_vfx`、`verify_minion_skill_icon` 等。反向验证：兜底改回小龟 / 去掉成长 / 去掉精英修复 / 10% 改成自身 / 去掉重新瞄准，各自变红。

**与方案的偏差**：U4 由「依次 0.2 秒」改为「四道同时、出现后原地停 0.5 秒」，龟能 120 → 135，出发半径 260 → 360，速度 380 → 210；普攻由通用光点改为专属气弹 `reserve-shot.png`；U6 由「按等级 ×1.05」改为「按本周场数 +4%」；气波由直飞改为追踪（用户看第一版录屏后提出）；V9「出手时刻差 = 间隔」作废（同时出发）；V13 改为「施法者死后已飞出的照常结算」（四道同时出发，没有『未出手』的）。

**新发现的坑**：

- 直线技能弹每 0.05 秒走一步，迎面走来的敌人会从两步之间穿过去（`_first_on_segment` 只查前方）。本方案只给援军开了补查；其余技能是否也有这个问题、要不要统一修，另议。
- **共用延时队列的步长与 sim 步不对齐**：`SKILLSHOT_STEP` 0.05 秒在 1/60 秒 sim 步下浮点余量略大于 0 ⇒ 要第 4 步才到点，所有直线技能弹实际速度只有标称的 3/4、每 3 帧顿 1 帧。援军气波已用 `STEP_EPS` 对齐（门禁 `verify_reserve_vfx` J 段量实际速度）；其余技能用户 10-29 定不改。
- 季内场数是战斗里读的玩家存档字段，不进回放状态就会让回放 / 裁判重算的属性和现场不一样 —— 以后任何「按玩家进度缩放」的战斗数值都要同时进 `STATE_KEYS` 和裁判任务单。
