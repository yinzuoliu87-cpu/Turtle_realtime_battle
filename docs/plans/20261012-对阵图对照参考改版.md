## 方案

1. **去掉「胜」小签**（参考无一家用字）。保留亮底条 + 前缘竖条 + ✓（✓ 有 02 为据，且 `verify_bracket_map` ① 以它为分母）。
2. **去掉决赛格里的「冠」小签**：冠军由顶部横幅单独展示（参考 08 / 01）。保留「你」小签（自己那一格，参考 03 的 P1 / 06 描边同义）。
3. **名字不再为空着的小签槽让位**：只有这一行真挂「你」时才留槽宽。
4. **轮空不画成赢**：对面是轮空的那一场，不画 ✓ / 亮底条（这一场没打）。轮空那一行照旧最暗。⚠ 无参考，是我们自己的判断。
5. **轮次标题**：有轮空（人数不是 2 的幂）时，第一轮叫「第 1 轮」，不按坑位数叫「8强/16强」（参考 06 / 07 第一轮叫 ROUND 1）。人数正好 2 的幂时照旧。
6. **底部一行操作提示「点击对局观看」**：图上有可点开观看的场次时出现（参考 06）。
   ⚠ 初稿写「查看回放」，被 `verify_bracket_map` ① 拦下：这屏不许出现「回放」——开播窗口里它等于说「已经打完了」（文件头 ★④）。改「观看」。

不做（第一轮）：比分；轮空格整个不画（无参考，改动大）。

### 第二轮（用户：「你参考了谁的，比分呢」「要做，然后你参考的不到位啊，整个界面条条框框都没有人家商业游戏感觉啊」）

第一轮只抄了「怎么标胜者」这类规则，整页观感没学。按 07/08 Brawlhalla、01 VALORANT 量：
7. **一场 = 两根独立实心条**（中间 4px 缝），去掉外框 / 硬投影 / 内斜面 / 虚线框 / 中缝 / 四角准星；
   胜者整条填色（青的暗调）+ 左缘 4px 色条，败者压暗；我 / 正在打 / 决赛只在两根条外描一圈（参考 08 进行中那场描亮边）。
8. **去掉「条条框框」的其余几层**：本轮竖带、决赛底板、轮次标题下的杠、每格右沿的 ▶、连线终点的小箭头（参考 01/06/07 都没有）。
   ▶ 的节点保留（`verify_weekend_watch` 认它是「这格能点」），不再画。
9. **竖向铺满**：6/8 人图原来只占屏幕中间一条；首轮场间距按可用高度撑开（`bracket_layout.gap_in_half`，上限一格高 ×1.6），参考 01。
10. **名字 18→20、列标题 15→17 且提亮**。
11. **比分**：一场 = 上路 + 下路（1:1 再打终极）⇒ 只有 2:0 / 2:1 ⇒ 服务端只存「败方赢了几路」（0/1）。
    - 服务端 `20261012_finals_scores.sql`：`finals_results.loser_lanes` + `finals_report_score`（**只认 seed 与采纳那份相同的报** —— P9 两边各打各的，另一份的比分对不上采纳的胜负）+ 两个视图下发 `scores`（与 `done` 同一道可见性）。
    - 客户端：结算时 `phase2_duallane.loser_lanes()` 算出来，结果报成功后紧接着补报；补报单带着它。
    - 画：每根条右端一枚比分方块（参考 07 Brawlhalla），胜方青底、败方暗底；没有数据不画。
    - ⚠ 10-11 及更早的场次没有比分（那时还没上线），显示时没有方块。
