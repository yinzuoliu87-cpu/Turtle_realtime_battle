## 2. 调查结论（现状）

- 普攻命中：`scripts/scenes/RealtimeBattle3DScene.gd` `_do_basic` 糖果分支，目标身上一张 `candy-burst.png`（95 码粉黄糖爆，0.35 秒）；另外叠通用星芒火花（`battle_damage.gd` `_impact`）。
- 糖果锤：`scripts/systems/skills/candy_system.gd` `_sk_candy_hammer` 砸中回调里沿线 4 张**同一张** `candy-burst.png`（150 码，每张晚 0.03 秒）+ 重震屏；伤害按直线（糖果龟脚下起往前 200 码、两侧各 70 码）一次结算。
- 录像（`tests/_rec_candy.gd`，改前 `.out/candy/now.avi`）：糖果锤 = 四团一样的粉黄斑，看不出「砸地」也看不出打到哪；普攻 = 一团小一号的同款斑；两者分不开。
- 真实时间线（量动作帧）：普攻命中 = 动作第 4 帧锤头扫到目标（`AttackHits` 登记 4）；糖果锤释放帧 5（技能前摇 0.34 秒）+ 0.38 秒 ≈ 第 10 帧锤头着地，砸中回调就在这一刻。动作帧 1 像素 = 0.80 码：着地时锤头在身前约 58 码、离地 0.3 米。

## 4. 方案

参考：波比「咖啡甜心」Q 与普攻（`docs/studies/20261115-糖果锤参考-波比咖啡甜心Q逐帧.md`、`20261115b-横扫大锤参考-波比咖啡甜心普攻逐帧.md`），按 Riot 的排序 玩法清晰 > 力度 > 主题。

1. 新文件 `scripts/scenes/battle/candy_vfx.gd`：`sweep_hit`（普攻）、`slam`（糖果锤砸地）、`slam_hit`（糖果锤打中的每个敌人）。全是按游戏钟驱动的粒子（`_anim_fx` 带 p0 + life ⇒ 直播只发出生参数 `@afx`），贴地件（判定框 / 冲击环 / 糖浆渍）建节点时定朝向。
2. 贴图 `tools/assetgen/paint_candy_fx.py`（脚本按我定的几何盖软笔刷，不是手画；重跑逐字节相同），全是糖果龟自己的：`candy-pinwheel`（薄荷风车糖闪光 2 帧）、`candy-bits`（薄荷碎片 / 粉糖块 / 蓝糖晶 / 彩针糖）、`candy-ring`、`candy-streaks`、`candy-zone`（拐杖糖圆角框，比例 = 判定区 200×140）、`candy-splat`、`candy-glow`、`candy-star`、`candy-puff`。颜色取自糖果龟动作帧（锤头红 #ba4149、奶白、身体粉）。
3. 普攻：风车糖闪光 0.2 秒 + 软光晕 + 奶油圆罩 + 放射线 + 顺挥动方向的糖粉烟与碎屑。
4. 糖果锤：落点星闪 + 亮芯 + 果酱色暖光 → 地面冲击环 → **判定区框（就是真实伤害范围）** → 奶油糖云 + 长边扬尘 → 整条区域同一刻糖块崩飞 → 糖浆渍 1.3 秒；每个被砸的敌人一团光 + 碎屑。去掉沿线 4 张糖爆。
5. 两处都不再叠通用星芒（`own_hit_vfx` / 普攻按 id）。只改画面：不改对局结果、不升 RULES_VER。`candy-burst.png` 仍留给糖衣炮弹与糖果炸弹（不在这次范围）。


**第二版（11-15 下午，取代上面 1~4 的画面做法；接线、时机、不叠通用星芒照旧）**——用户看第一版：「整个观感看上去给人就很假，给人就像一个图片贴在那儿，感觉不到任何…某种质量的存在…你需要去用他们那些工具，然后去做一版，然后我只看成果」。

6. 主体改成 Blender 序列帧（`tools/assetgen/blender_candy_fx.py` → `build_candy_sheets.py`）：建模糖块碎片（薄荷楔块 / 硬糖碎块 / 糖晶 / 彩针糖，Freestyle 深色描边）+ 云噪声置换的体积糖云 + 环面尘浪；卡通三档着色（法线 · 光向）；只接影子的地面（碎块落地有影子，影子拼表时减半）；碎块逐步物理（抛出 / 重力 / 落地弹跳 / 摩擦 / 自转衰减，写成关键帧，不是刚体解算器）；糖云 / 尘浪噪声侵蚀溶解（背面透明，洞是真缺口）。正交相机 = 游戏镜头俯角 51°，游戏里当公告板放。产出 `candy-slam`（27 帧）、`candy-erupt`（两种 × 21 帧）、`candy-sweep`（16 帧，往左挥时水平翻转）。
7. 地面裂痕 `candy-crack.png`：在 Aseprite 里用它的工具画（实心椭圆 / 椭圆描边画坑，铅笔画裂缝、糖浆光、碎屑；每笔坐标我定，脚本 `tools/assetgen/ase_candy_crack.lua` 驱动落笔，源稿 `assets/sprites/vfx/src/candy_crack.aseprite`），贴地、沿砸出去的方向转、1.6 秒淡掉。
9. **2.5D 分层**（用户 11-15「我们的技能…是二点五 D…除了海浪上次做的三 D…我们这次是二点五 D」→ 选「修层次，画风不变」）：每段在 Blender 里分两遍渲 —— 立着那遍（游戏镜头俯角、公告板、画在龟前面）只留飞起来的糖块 / 糖云 / 拖影；贴地那遍（正上方往下看、平铺在地上、开深度、压在龟脚下）只留尘浪与糖块影子。原来尘浪和影子渲在立着的图里，盖在站在里面的龟身上。产出多一套 `candy-*-gnd.png`。
10. **普攻命中帧**（用户 11-15「这个普通攻击命中帧到底是哪一帧？到什么时候跳数字？什么时候就跳出这个命中特效的？不对吧？」→「糖果龟不是第五帧是命中帧吗？」）：探针 `tests/probes/_probe_candy_hit_timing.gd` 量出命中 = 第 5 帧（从 1 数；11-07 用户通过的横扫「锤子扫到正前方」那一帧，`tools/oneoff/turtle_seq_1107/three_bare.py` rel=4），t 0.517 显示、伤害数字与命中特效 t 0.533 同时冒出（差 1/60 秒）⇒ 原登记就是对的。我一度按「包围盒往前伸到最远 85%」把它和另 4 只改早了——第 4 帧是锤子从侧面绕过来的过渡帧、轮廓先伸出去，规则量错；已全部撤回（`attack_hits.gd` 与提交时逐字节一致），那条门禁删除。
11. **锤头能量**（用户 11-15「你能不能给锤子做个特效？就是它这样子劈下去，它锤子能不能加什么那种特效发光啥？这一股能量砸下去呢？单看这个锤子太太没有感觉了呀」）：逐帧量出糖果锤动作 30 帧里锤头中心（`candy_vfx.gd` HEAD_PX），技能生效那一刻按锤头轨迹一次排好叠加发光粒子：蓄力聚能（第 6~8 帧，光晕变大 + 漩涡 `candy-swirl` 转 + 光点往锤头吸）→ 劈下能量光轨（帧间沿曲线插，到点才亮、随后变淡）→ 砸地锤头能量炸开 + 火花 → 余光褪到第 13 帧（从 1 数）；落点原来那层白粉亮芯去掉（与锤头能量重复）。蓄力中被控这一锤作废时，排好的能量一并删掉（探针 `tests/probes/_probe_candy_energy_cancel.gd`：漩涡 4 个建出、作废后剩 0、砸地序列帧 0）。
8. 引擎里只留叠加发光：落点星闪 + 亮芯 + 果酱色暖光、普攻星闪 + 光晕（`candy-glow` / `candy-star`，`paint_candy_fx.py`）。第一版的风车闪光 / 碎屑 / 圆环 / 放射线 / 判定框 / 糖浆渍 / 烟团七张平面小图删掉。

## 8. 实施回填（2026-11-15）

用户「嗯，可以，我觉得蛮好」后一次提交。实际做的：
