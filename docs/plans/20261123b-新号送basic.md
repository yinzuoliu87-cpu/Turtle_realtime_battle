# 每个号永久拥有 basic（小龟）

日期：2026-11-23　|　状态：**实施中**

>
> 用户 11-22（回 Tom 运营 10 条时拍板，AskUserQuestion）：新玩家一进游戏**永久送一只 basic**（+ 每周 7 只限免），随下一版（0.23.6）。
>
> 用户 11-23（我列待办、说先做这一条时）：「行」。

## 2. 调查结论

- 「能上场的」= 拥有 ∪ 本周限免，客户端与裁判共用纯函数 `WeeklyFree`（`scripts/gamedata/weekly_free.gd:49` `free_ids` / `:62` `allowed_ids`）。
- 服务器的「拥有」只有一处：`pet_owned(账号)`（迁移 20261109b ③，= `mainsite_pets` 里的 28 只之一）。它被三处用：领活盖章 `pet_stamp_on_claim`（a_owned / b_owned ⇒ 裁判 `RefereeJob.pets_allowed`，`scripts/referee/referee_job.gd:122`）、开算等级表 `pet_lv_table`、发经验 `pet_xp_grant`。
- 升级通知主站（`mainsite_outbox_put` 'pet-level'）自己按 `mainsite_pets` 挡（20261109a），主站上没有的龟不会推。
- 客户端「我拥有哪些」= `PetLevelsNet.owned`（来自 `pet_levels_me` / `MainsiteLink.owned_ids`，都是主站真拥有）；选龟页角标 `is_free_pick`、经验条 `PetXp`、结算页都读它。
- 兜底机器人 `Backend.make_bot`（`scripts/net/backend.gd:397`）只从限免 7 只里抽统领。

## 3. 需求 ↔ 代码的出入

- 「送」不经主站：主站那边这个号不一定有 basic ⇒ 不写 `mainsite_pets`（那张表是主站 /player 的缓存，每次刷新整份替换），而是在「拥有」的定义里并上赠送。
- 「永久拥有」= 跟买来的龟一样：涨经验、升级、按服务器等级上场、不挂「限免」角标；限免 7 只另外选（不会再抽到 basic）。

## 4. 方案

| 层 | 做什么 |
|---|---|
| 迁移 `20261123b_pet_gift_basic` | `pet_gift_ids()` = `{basic}`；`pet_owned` = 主站拥有 ∪ 赠送（账号为 null 仍为空）。盖章 / 等级表 / 发经验自动跟着走，旧版裁判代码也放行 |
| `WeeklyFree` | `GIFT = ["basic"]`；`_owned_set` 并上 GIFT（限免跳过、能上场的必含）；`with_gift(owned)` |
| `PetLevelsNet` | `owned` 一律过 `with_gift`（adopt / adopt_owned / 换号） |
| `Backend.make_bot` | 改从 `allowed_ids`（basic + 7 只）抽，与真人同一池；随机数消耗不变 |

## 5. 已知风险与未决点

- 上线次序：迁移只会让「能上场的」变多（旧客户端以为的限免 7 只 ⊂ 新的 basic + 7 只），先上迁移不会把旧版本玩家的阵容判成不合法。★done-when: 0.23.6 换版那晚（周一 21:00 窗口）正式服迁移跟裁判机一起上，`sb_migrate.py prod --rehearse --apply` ALL PASS。
- 一部分号这周的限免名单会换一只（原来排序里 basic 在前 7 的，basic 变成拥有、补进第 8 只）。随 0.23.6 在周一换周时上，与换周同时发生，不会出现周中变化。
- 正式服写入要用户点头（CLAUDE.md §3）。
