## 3. 与现状的出入

1. **确定性不是「没做」，是「只在窄条件下验过」**：`TURTLE_SEED` 那条路已经存在且在用
   （det 模式每帧恰 1 个 `SIM_DT` 步，`:2207`），今天查 059 沙漏时多种子复现完全一致。
   但验过的是**同一进程内、同一台机器、1v1**；从没验过「满阵容满装备 + 跨机器」。
2. **`_sim_step` 与演出用的是两条时钟，这是有意的**：演出走未钳制真实 delta（`rd`），
   sim 走固定步长。B 阶段**不是要把演出也变确定性**，而是把**结算**从演出时钟上摘下来。
   摘错方向会让手感变差却换不来确定性。
3. **今天刚踩过这条线**：059 沙漏定格比设定长 1~2%，根因正是「顿帧那几帧倒计时不走」——
   `if frozen: … elif in_ts:` 二选一。这类「时间口径不一致」就是 B 阶段要清的同一类东西
   （已记在母方案书 U2，**数值不擅自改**，等用户拍板）。

## 4. 方案

### B1　先把尺子做出来（**不动产品代码**）

把 `tests/verify_battle_determinism.gd` 从 1v1 扩到「3 统领 + 3 小将、每只带装备、打到分出胜负」，
指纹取每 N 步的血量与坐标摘要。

**先跑一遍证明它现在就会红** —— 这一步的产出是「缺口有多大」的**实测数**，不是猜。
⚠ 顺序不能反：先改代码再做尺子，等于永远不知道自己修好了多少（memory `fb-verify-check-can-fail`）。

**B1 的验收不是「绿」，是「红得可复现」**：同一份代码连跑 3 次，指纹分歧出现在同一批位置。
若分歧位置每次都不同，说明尺子本身不稳（采样点挂在演出上了），要先修尺子。

### B2　12 处 `process_frame` 协程 → 走 sim 队列

弹道进 `_pending_shots`，定时进 `equip_tick_system.schedule`，等待用 `_wait_sim`。
**一批一跑门禁**，每批跑完记一次 B1 的指纹分歧数 —— 这个数应当单调下降。

### B3　48 处 tween 回调 → 结算与演出分家

数值结算抽成能同步调用的函数，tween 只留演出（CLAUDE.md §3.5 海盗钩索的办法）。
**先做附录 B 里「按固定节拍排队」那批**（`ice_system.gd:312-314` 每 0.5 秒一跳、
`lightning_system.gd:143-145` 每 0.075 秒一道雷等 16 处），最机械、风险最低。

顺路把**改结果的裸随机**（约十来处）改走 `_battle_rng`。

### B4　四处难点单独做

小熊按立绘帧号 / 星星 `tween_method` 逐帧染 / 宽刃帧 delta 扫描 / 踩背 0.833 秒协程。
每一处都要**重新表达成「按 sim 步推进」**，不是把 delta 换个来源就算完。

### B5　种子接线

现在只有环境变量能定种子（`battle_world_builder.gd:371-376`）⇒ 改成也能从 `GameState.battle_seed` 进来，
并把种子存进战绩记录（**这一条同时是 C1 的前置**）。

### B6　跨机器验证

CI 加一个 job，用同一组种子跑同一批对局，指纹与本机逐字比对。
**这是「确定性从没端到端验证」真正被关掉的那一刻**，也是 D7 第二步的开关。

### 8.6 副作用：把随机路由对了，反而让另一条门禁红了（已换形状，不是放松）

`verify_timestop_global_freeze`（「时停期间全场系统状态一个字段都不许变」）在本轮之后红：
`_battle_rng.state` 动了。逐站点二分（7 次单点变异、每次都复核还原）定位到**唯一**一处：
本用例的携带者是财神龟，它在测量窗口里放了一次骰子（`_sk_fortune_dice`）——
**时停文案本来就写死「active 携带者照常施法」，而施法要掷骰**。
以前不红只是因为那一掷走的是**裸全局 `randi_range`**（引擎全局状态，本用例根本扫不到）；
路由到 `_battle_rng` 之后才落进扫描面。**红的不是「时停漏了什么」，是「原来有一处漏在扫描面之外」。**

⚠ 第一版我把 `_battle_rng` 加进了那条门禁的 `ALLOW` —— 主会话否掉了，理由正确：
那是**放松判据**，加完之后「时停里偷偷掷骰」的真 bug 也不会红。
改成**换形状**：让携带者在窗口内本就不该掷骰（摘掉它的 `active_skills`），`_battle_rng` 留在禁止集里。
配两条分母：⑥ 控制组真放一次骰子 → 金币 +8（证明「金币增量」确实等价于「施过法」，不是恒真式）；
⑦ 窗口内金币增量 == 0（证明确实一次都没放）。反向验证：不摘 `active_skills` ⇒ ⑦ 报「+13 金」、
主判据报 `_battle_rng.state` 当场红。

**已知缺口**：这条门禁因此不再覆盖「携带者边施法边冻结」那一路。要覆盖它，判据得写成
「`_battle_rng` 变的次数 == 窗口内施法次数」，两边都要有分母 —— 另案。
⇒ **2026-10-04 已补**（`verify_timestop_global_freeze` 第二段 ⑧~⑪）：`_deterministic = true` 让一帧恰一步，
携带者装回【骰子】、冷却置零，360 步窗口里**逐步**对账「`_battle_rng.state` 变了的步 == 金币涨了的步」
（实测 3 次施法 / 3 次变化，步号 [19, 146, 273] 逐个对上），其余全部系统状态仍一字段不许变。

### 8.5 这一轮**没有**做到的（照实写）

1. **只有 det 模式的 tween 被搬上 sim 钟**。玩家实际打的那一局仍不是逐字节可复现的；

   （战斗路径 `get_process_delta_time()` 必须 0 处，扫 108 文件 / 75969 行；反向验证：写回一处当场红）。
3. **16 处裸 `create_tween()`**（不经 `_reg_tween`）仍走真实钟：时停演出 5、HUD 4、飘字 3、换路过场 4。

   ⇒ **2026-10-04 已补门禁** `tools/battle_tween_audit.py`（进 `run-tests.sh`）：实数是 **20 处**
