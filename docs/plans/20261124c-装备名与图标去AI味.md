## 2. 调查结论

- 商店可刷装备 95 件（`data/phase2-equipment.json` `shopAvailable = 1`）；总览图 `.out/equip_names/sheet_0.png`（1–2 费）/ `sheet_1.png`（3–5 费）。
- 名字的玩家可见出处：`data/phase2-equipment.json` 的 `name`；英文 `locale/en.po`（以中文名为 msgid）+ `locale/glossary_en.md`；个别界面 / 图鉴代码里写死的名字（例：`scripts/scenes/CodexScene.gd`、`scripts/gamedata/glossary.gd`）；文案快照 `tests/golden/text_*.txt` 跟着变。其余出现处多为代码注释 / 历史文档（`docs/archive`、方案书、研究记录）—— 不改。
- 图标尺寸混杂：32px 干净像素（001 木制长剑等）与 500–1024px 的 AI 出图缩小（034 玩偶小熊 609px、052 左轮 1024px、056 飞镖 1024px、026 雷电法杖 1024px …）并存；后者一看就是另一种画法。
- 图名不符：036 温泉蛋画的是孵化器、039 竹制弓箭画的是竹叶、082 护心甲画的是贝壳、025 雷鸣贝壳画的是水晶。看不出：064 溺者的浮囊（白色蛋形）、037 蛋糕蜡烛（一团）。
- PixelLab 额度：本期剩 1981 次（11-24 查），12-19 重置。

## 3. 需求 ↔ 代码的出入

- 用户说「一些」：没有点名哪几件。本方案书给出全量审查后的建议清单（59 件改名 / 29 件图标），**等用户圈定**最终范围与每个新名字。
- 效果说明里的机制词（如 `【海葵】` `【符纸】` `【气环】` 层数名、「祖龟碑」召唤物名）与装备名同源，改名后要不要一起改 —— 列为未决点 U3。

## 4. 方案

**命名标准**（参考商业游戏装备名：《杀戮尖塔》遗物、云顶之弈装备 —— 都是一眼认得的真实物件，2–4 字为主）：
1. 名字 = 一件真实存在的东西，看名字就知道是什么；
2. 与效果、图标对得上；
3. 不叠修饰词、不硬加海洋前缀、不用技术术语；
4. 全表不重名、不近似重名。

**建议清单**：`tools/oneoff/equip_rename_1124.py`（`RENAME` 59 件 / `ICON` 29 件），`python tools/oneoff/equip_rename_1124.py sheet` 出对照图 `.out/equip_names/rename_1..4.png`（图标 · 旧名 → 新名 · 理由码 · 图标问题）；脚本自查新名无重名、不与不改的撞名。

**实施（用户圈定后）**：
- S1 改名：数据表 `name` + `en.po`（msgid 换新中文名、msgstr 按新名重译）+ 术语表 + 写死名字的界面代码；`python tools/regen_goldens.py` 重算文案快照；一次预检 + ship。名字是玩家可感知改动 ⇒ 随下一版（0.23.6 / 0.23.7）。
- S2 图标：按 `ICON` 清单逐件重画为 64px 像素风（PixelLab `create_image_pro` 级出图 + 手工修边；风格以现有 32/64px 干净像素件为准），出对照图给用户看，认可后才提交（美术规矩：用户认可前不预检不推）。

## 5. 已知风险与未决点

- **U1（要用户定）**：改名范围 —— 按建议全改，还是用户在对照图上圈 / 改。新名字每一个都以用户认可的为准。
- **U2（要用户定）**：图标重画范围 —— 只重画 29 件问题图标，还是 95 件全部统一画风。
- **U3（要用户定）**：效果说明里跟着旧名起的机制词（【海葵】【符纸】【气环】、祖龟碑召唤物等）要不要一起改。
- 风险：英文版以中文名为 msgid，漏改 en.po 会让英文模式退回中文（`verify` 文案快照 + i18n 审计会抓）。
- 风险：周一换版前改名会进 0.23.6 —— 若来不及用户过目，顺延 0.23.7，不赶。

## 6. 验收标准

- 改名后数据表、英文、术语表、图鉴里新名一致；旧名在玩家可见文本里 0 处（扫描 `data/` `locale/` 与界面代码字符串；**先证明扫描会 FAIL**：故意留一处旧名确认能扫到）。
- 新名全表无重名（脚本自查）。
- 图标：重画件 64px、零半透明、与名字对得上；两比例（1560×720 / 1280×960）商店 / 背包 / 图鉴实拍给用户看过。
