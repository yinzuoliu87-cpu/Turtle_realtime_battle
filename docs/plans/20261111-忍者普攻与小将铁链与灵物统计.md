## 2. 调查结论（实测 + 行号）

### 2.1 忍者普攻 `ninja/slash.png`（13 帧，命中帧 6）
- 帧序来自 `tools/assetgen/build_attack_rhythm.py` UNITS["ninja"]：待机 0 → AI 起手 w2 / w3 → 关键姿势 wind → AI 挥动 s2 / s3 → 关键姿势 slash（命中）→ AI 收回 r1~r5 → 待机。
- **身体缩小**：逐帧量本体包围盒，待机高 56 像素、脚底第 60 行；第 5~10 帧高 45~49、脚底第 56 行 ⇒ 每次出刀身体缩两成、往上飘一截。AI 帧本身画小了。
- **刀路**（图 `.out/ninja/sword_path.png`，逐帧量亮灰刀身两端）：命中前 4 → 5 → 6（头顶 → 前上 → 正前方）顺着挥砍路线；但第 1 帧刀已在前下方、第 2 帧瞬移到右肩后上方（一帧 62 像素）；命中后第 7、8 帧刀尖往回抬（角度 190° → 177° → 160°，原路倒回），第 9、10 帧刀凭空消失，第 11 帧又插回背上。根因：收回段是 AI 从「横斩」直接插值到「站姿」。
- **播放问题**（探针 `.out/ninja/ninja_anim_probe.gd`，审阅台 3 × 60 秒，90 次普攻）：6 次结算时没在播普攻（idle / run）。根因：被动冲刺在普攻前摇里触发（`RealtimeBattle3DScene.gd:6638` 只看冷却），冲刺把动作换成 dash（`ninja_system.gd:119`），滑行期间 AI 整段让出（`RealtimeBattle3DScene.gd:2483`）⇒ 前摇计时冻住；落地回待机（`ninja_system.gd:187`）后前摇照走完、伤害结算时身上是待机 / 跑。另见一次前摇挂了 2.1 秒（无冲刺），疑似被控（`if stunned: return` 在前摇之前），同一类：前摇被打断后动作没重开。
- 冲刺落地三帧取表末三帧（`ninja_system.gd:180`），第 15 帧是半透明幽灵帧 ⇒ 每次落地闪一下。

### 2.2 精英小将铁锁（`RealtimeBattle3DScene.gd:5993` `_tick_elite_whip`）
- **像素方块** = `_bolt_line(from5, to5, …)`（`:6019`）通用程序画线，暗红虚线方块，与铁锁美术无关、压在链子上。
- **链子** = `PullRopeVfx.elite_links`（`pull_rope_vfx.gd:53`）：`bio-chain.png` 32×32 画的是**竖着**两节链，代码当「横向一节」按链方向转 ⇒ 每节与链垂直；每 55 码一节、20 码高 ⇒ 一排漂着的小竖记号。
- **拉人身后红拖影** = `fx-trail.png` 线性过滤（`:6046`），不是像素画。
- **拉人运动** = 补间线性插值 `DetMath.vlerp(fromp, dest, q)`（`:6050`），时长 `距离 ÷ 500 码/秒`（`elite_system.gd:33`）。位移写 sim 坐标。

### 2.3 近战小将人体浪板（`hiding_system.gd:280`）
- 时间线：0~0.64 蓄力起跳到后上方 120 码、高 5.76 → 0.68 射链 → 空中顿 0.6 秒 → 1.28 俯冲（`_minion_bodysurf_ride` `:357`）：水平线性 `vlerp(from, tref.pos, kk)`（`:372`）+ 高度 `h0 - (h0-0.3)·kk²`（`:373`）⇒ 从顶点水平匀速、竖直加速下坠，看着像直直掉下来 → 踩着目标滑 0.833 秒 → 跳下。
- 链子 `minion-chain-link.png` 26×12 横向一节、间距 28 码，基本连续（不用改图）。
- 7 段帧条（`ACTION_MELEE` `RealtimeBattle3DScene.gd:439` + attack / run）画风尺寸不一：surf 段人大一圈半且脚下画了木浪板；三叉戟时有时无；没有抓链拉的姿势。

### 2.4 灵物触手伤害（`spirit_synergy_system.gd:347` `_slap_resolve`）
- 拍击伤害以「携带者 / 本方任一存活单位」为来源走 `_apply_damage_from(shooter, …)`（`:360`）⇒ `_record_buckets`（`battle_damage.gd:137`）记进那只龟的 `_st_dealt` ⇒ 伤害面板 / 结算表都算成龟的。
- `_st_dealt` 有 sim 读者：`equip_tick_system.gd:353`（钩爆触发门槛）、`incense_stone_system.gd:132/155`、`eq_blade_batch.gd:553`、`trainer_system.gd:880`（猎龟令标输出最高）⇒ 改账会改对局结果。

## 4. 方案（穷举）

**A. 忍者播放（只改画面，不改结果）**
1. `AttackRhythm` 加 `resync_windup(battle, u)`：普攻前摇中（state=windup、pending=B）且当前没在播普攻（anim_action 为空、不在手动逐帧）⇒ 按剩余前摇重开普攻动作，命中帧对上结算。sim 的 windup 分支每步调一次（只写渲染键）。覆盖冲刺落地、被控解除两种。
2. 冲刺落地三帧改用不含半透明的帧（量 dash.png 每帧 alpha，挑落地姿势帧），不再取表末三帧。

**B. 忍者普攻帧重画（PixelLab，约 30 次）**
- 按刀路图的蓝线：右肩后上方蓄力 → 过头顶 → 正前方水平命中（第 6 帧）→ 顺势劈到前下方 → 收刀回背 → 待机。身体全程与待机同尺寸（本体 56 像素、脚底第 60 行，生成后量，不合就缩放回去或重出）。
- 帧序 / 命中帧不变（13 帧、命中 6），`build_attack_rhythm.py` 换源帧。

**C. 铁链（精英 + 近战，位移在 sim ⇒ RULES_VER 5 → 6 + 刷规则指纹）**
1. 新 `scripts/gamedata/pull_curve.gd`：`frac(s)` 先快后中速（速度起步约 2.6 倍中速、前 45% 降到中速后匀速；纯四则，确定性）。
2. 精英：拉人改走 `PullCurve.frac`；删 `_bolt_line`；删 fx-trail 软拖影；链子改用横向链环（`bio-chain` 转 90° 生成 `bio-chain-h.png`，确定性脚本）、首尾相接、由近到远快速伸出。
3. 近战：俯冲水平走 `PullCurve.frac`；高度 = 下落基线 + 起步上扬一小段（约 0.8 米，峰在前 1/3）⇒ 先往上带一点再弧线落到目标身上。
4. 时长不变（距离 ÷ 500 码/秒 = 平均速度）。

**D. 灵物触手伤害单列（只改显示，不改结果）**
- `_slap_resolve` 在结算前后对来源打「灵物」标记，`_record_buckets` 额外记 `src["_st_spirit_dealt"]` / 按类型；sim 账（`_st_dealt`）不动。
- 战中伤害面板与结算表：每方多一行「灵物·触手」（合计该方所有单位的灵物份额），龟那一行显示时扣掉灵物份额。直播流带上新键（`stream_recorder` UKEYS_ST）。

**E. 视频交付**：忍者（普攻 / 冲刺）、精英铁锁、近战人体浪板改后实拍，正常速度 + 慢放。

**F. 近战小将整套重做（另起，等用户看形象图）**：先 1 张形象（Pro Flash + 认可过的风格参考，约 5 次）；点头后按技能时间线出整套（待机 / 跑 / 普攻 / 蓄力起跳 / 空中甩链 / 抓链拉 / 弧线俯冲 / 踩人滑（无浪板）/ 跳下），约 40~50 次。
