## 2. 调查

### 2.1 我们的现状

| 项 | 现状 |
|---|---|
| 数据结构 | `effectBrief`（一句话）+ `effectDesc1`（全文）+ `effectDesc3`（多数为空） |
| 渲染 | **纯文字**，无颜色、无图标、无字重变化 |
| 数值 | 三档**并列静态文字**（`15/30/50`），不算「当前星级实际值」 |
| 已有基础设施 | ★`{C:类名.常量}` 占位符 + `SkillText.render_consts()` 统一展开 |
| 消费点 | `equip_brief` 四处（背包底栏 / 战斗信息面板 / 换路图标悬浮 / 图鉴列表）<br>`equip_full` 两处（商店 / 图鉴详情） |
| 版面 | `BRIEF_MAX = 60`（`codex_text_lint`），落点最紧的是 44×44 图标的 `tooltip_text` |

### 2.2 三个游戏的做法

见 [ref/20260930-LoL文案体例.md](ref/20260930-LoL文案体例.md) §6 与
[ref/20260930-Botworld逐帧参考.md](ref/20260930-Botworld逐帧参考.md) §4.6。要点：

- **两层是同一句话的展开**，不是两段文案：`74 (🔮)` ⇄ `74 = (60 +80%🔮)`
- **只有伤害数值上色**；紫色**只给控制效果**（状态词不上色）
- **专有名词统一一个颜色**（LoL 紫 / 中文 ARPG 黄 / Botworld 青）
- **属性图标是纯白剪影，运行时染色**（三方印证）
- 详细版底部有**专名解释行**与**分档表**

## 3. 出入（需求与现状对不上的地方）

1. ★**我们的两层分工与 LoL 根本不同**：LoL 是「结论 ⇄ 推导」，我们是「短 ⇄ 长」。
   `effectBrief` 不是 `effectDesc1` 的结论，只是它的**随机删减版** ——
   实测 96 条 brief 里 **62 条带数值、34 条不带**，分界线根本不存在。
2. ★**我们算不出「当前值」**。文案里只有三档原始数字，而玩家真正想知道的是
   「我这件 ★2 的现在打多少」。LoL 那个 `74` 是**算好的实际值**。
   ⚠ 我们其实**已经有算式**（063 的 `15/30/50 + 0.8×攻击力 + 2.5/4/6% 最大生命值`），
   只是写成了静态文字 —— 差的是**运行时求值**，不是数据。
3. ★★**更正（2026-09-30，写完这份方案书之后才查的）**：上面两条我原先写成
   「纯文字没有任何视觉分层」「没有嵌在文案里的图标」—— **对装备成立，对龟技能不成立**。
   我当时看的是 **JSON 里的原始字符串**，没查渲染层。实际情况是：

   | | 颜色 | 内联图标 | 走哪条管线 |
   |---|---|---|---|
   | **龟技能 / 被动** | ✅ 有 | ✅ 有 | `SkillText.render_bbcode()`，12 处调用 |
   | **装备** | ❌ 无 | ❌ 无 | 只走 `render_consts()`（展开 `{C:}` 占位符） |

   仓库里**早就有**整套机制：
   - `skill_text.gd:29` `VAL_HEX` —— 18 个语义色类（val-normal 物理 / val-magic 魔法 /
     val-true 真伤 / val-crit / val-lifesteal / val-dot …），且**已经引用 `UIPalette`**
   - `skill_text.gd:42` `KEYWORD_RULES` —— **29 条关键词自动上色规则，第 3 项就是图标 key**
     （`["攻击力", "val-normal", "atk"]` = 上色 + 在词前内联 `atk-icon.png`）

   ⇒ 但也多出一个必须先验的技术点，见 §5.8。
4. ✅**已做（v0.19.491）**：`scripts/gamedata/glossary.gd` 29 条，详细说明底部一行灰字。

## 4. 方案

### 4.0 分期（每期可独立上线，不必一次做完）

| 期 | 内容 | 依赖 |
|---|---|---|
| **P1** | 文案体例统一（装备两层 + 龟技能）+ 专名标记规范化 | 无 |
| **P2** | 颜色编码（伤害类型 / 控制 / 专名）—— 渲染层 ✅ **v0.19.490 完成**（装备侧接上龟技能那条管线） | P1 |
| **P3** | 属性图标内嵌 | [属性图标重做](20260930-属性图标重做.md) |
| **P4** | 数值算式化（当前值 = 基础 + 成长）+ 两层展开 | P1、P2 |

### 4.1 P1 文案体例（把 LoL 那七条落成我们的规矩）

- 可叠加 / 有名字的效果一律用【】，并在详细层给**一行解释**
- 叠层写成三段式：「施加一层【X】」→「可叠加 N 层」→「满层时【X】引爆，造成 …」
- 复合伤害**末尾只写一次类型词**，中间用 `+` 串
- 伤害 / 治疗量的百分比**必带归属**（目标最大生命值 / 已损失生命值 / 自身最大生命值）；
  「低于 X% 生命值」这种**阈值判定**可以裸写
- 替换效果用「**转而**」
- 主语统一「**自身**」（`codex_text_lint` 的 DEV_UNIT 规则已经在守这条）
- 不用口语动词（炸开 / 攒到 / 攒够 / 打满 —— LoL 语料里这四个**零命中**；
  ⚠ 叠满 / 攒满 **LoL 自己也用**（4 次 / 2 次），不判硬错，只记台账）
- ★**brief 删的是修饰，不能删归属**（v0.19.487 量出来的）：实测写丢「是谁的生命值」的
  **全集中在 brief**，而同一条的 detail/desc 本来就写着「<b>目标</b>最大生命值」。
  简介是照着详细版删出来的，删的时候把归属词一起删了——装备与龟技能两边同形状。

### 4.2 P2 颜色

在 `scripts/util/ui_palette.gd` 定一组语义色，**文案侧只标语义不写色值**：

| 语义 | 标记 | 参考色 |
|---|---|---|
| 物理伤害 | `{P:...}` | 橙 |
| 魔法伤害 | `{M:...}` | 青蓝（LoL `#0acbe6`） |
| 真实伤害 | `{T:...}` | 白/金 |
| 控制效果 | `{C!:...}` | 淡紫（LoL `#ad76c4`） |
| 专有名词 | 【】 | 黄（中文 ARPG 那套） |

渲染走 `RichTextLabel` + BBCode。`SkillText` 增加一个 `render_rich()`，
与现有 `render_consts()` **同一个入口**（消费点不各写一遍）。

### 4.3 P4 两层展开（形式我们自己定，不抄 Shift）

- **结论层**（默认）：当前星级的**实际值** + 类型图标
- **推导层**（展开）：算式 + 分档 + 专名解释
- 触发方式**未决**（见 §5）：点击展开 / 长按 / 图鉴详情默认展开而战斗面板默认收起

### 4.4 数值算式化怎么落地

难点不在显示，在**求值**：文案里的 `15/30/50 + 0.8×攻击力` 现在是**字符串**，
要算出当前值必须让文案变成**可求值的结构**。两条路：

- **(A)** 文案里写标记 `{V:EqSpiritBatch.ring_damage}`，指向一个**产品自己的求值函数**，
  渲染时带上下文（星级、携带者）调用它 ⇒ **文案与代码同源**，不可能漂
- **(B)** 在文案里写算式字符串，渲染时解析 ⇒ 又造一个表达式解析器，且与代码两份

★**强烈倾向 (A)**：`tooltip_number_audit` 存在的全部理由就是「文案数值 ↔ 代码」会漂；
(A) 从根上消灭这个类别。

## 6. 验收清单

### ★ P1 第五批：专名记法三套并行（2026-10-02 量出来的，之前没人提）

**怎么发现的**：做 LoL 体例 ⑥「可叠加的效果一律有专名」时，先量「提到『层』却没有【】的段」——
369 段里 **85 段**。而名字全都在正文里（流血/硬化/灼烧/电击/墨迹/锻炼/吐息/中毒…）。
再往下量才看到**真问题不是漏了括号，是同一件事有三套记法在并行**：

| 记法 | 段数 | 不同名 | 渲染成什么 |
|---|---|---|---|
| `【X】` | 22 | 22（全部已登记 Glossary） | KEYWORD 色 **+ 加粗** |
| `「X」` | 12 | 12（**一个都没登记**） | **什么都没有**，只有一对角括号 |
| `<span class="val-normal">X</span>` | 55 | 47 | `val-normal`（= 物理伤害那个色） |

★★而 `val-normal` 在干**两件完全不同的事**：
  · 真专名（星能 / 结晶印记 / 墨迹 / 怒气 / 潜影 / 虚化 / 觉醒 / 水晶球 / 龟盾…约 20 个）
  · **根本不是名字的强调**（全场最远的敌人 / 随机 1 个敌人 / 最大生命值最高的敌人 /
    当前输出最高的友军 / 所有伤害 / 下一发普攻 / 射程 / 实时 / 单段 / 切近战时…约 27 个）
  ⇒ 和当初「同一个语义色散在三张互不相干的表里」是**同一个病**。

**这一批只做 `「X」 → 【X】`**（最小、最干净的一刀）。
数据里 `「」` 共 **25 处 / 19 个名字**，逐条看过**全是真专名**（技能名或效果名）。
