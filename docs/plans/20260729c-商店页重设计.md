## 1. 需求原文（逐字）

> 商店页面看不到装备的描述，思考整个页面重新设计下，交互也重新设计，应该怎能去购买呢，参考一些游戏的商店

---

## 2. 「看不到描述」的根因（已查实）

`scripts/scenes/ShopScene.gd:373`：

```gdscript
box.tooltip_text = "%s (%d费)\n%s" % [str(edef.get("name","?")), int(edef.get("cost",1)), str(edef.get("effectDesc1",""))]
```

**描述其实是有的，但放在 `tooltip_text`（悬停提示）里 —— 手机没有 hover，永远触发不到。**

★ 同一个坑图鉴和选龟页**早就踩过并修好了**：
它们加了「点击/触摸 → 弹窗」（`TeamSelectScene._show_detail_popup_from`，
被 `detail_panel.gd:190` 和 `skill_picker.gd:161` 调用，注释写明「手机无 hover 的唯一途径」）。
**商店页漏了这一步。**

→ 所以最小修复只要**复用现成的弹窗**即可；但用户要求「整个页面重新设计」，所以本方案做两层：
**P0 立刻可见的修复** + **P1 重设计**。

## 3. 现状盘点

`ShopScene.gd` 共 411 行，现有结构：

| 区块 | 函数 | 说明 |
|---|---|---|
| 出货 | `_roll()` / `_price()` / `_shop_level()` | 按大轮等级出货档 |
| 卡片 | `_card(idx,pos)` | 费用 / 图标 / 名字 / 「已有N」/ 价格 / 购买按钮 |
| 刷新 | `_on_refresh()` | 重roll |
| 备战席预览 | `_build_bench_preview()` | 已有装备 |
| 阵容装备 | `_build_lineup_equips()` | 三只统领已装的 |
| 出货概率 | `_build_odds_row()` | 各费档概率 |
| 锁定态 | `_build_locked()` | 未解锁时 |

**卡片信息密度**：费用、图标、名字、已有数、价格 —— **唯独没有效果描述**。

## 4. 验收清单

### P0 — 让描述看得见（不改版式，先解决"看不到"）

| # | 子需求 | 验收方式 |
|---|---|---|
| P0-1 | 点击卡片（非购买按钮区）**弹出装备详情** | 手机可触发；含名称/费用/星级/**完整效果描述** |
| P0-2 | 弹窗复用 `_show_detail_popup_from` 那套（不新造轮子） | 代码里确实调的是既有实现 |
| P0-3 | 描述取自 `effectDesc1`（装备文案单一事实源） | 与图鉴/背包显示一致 |

### P1 — 页面与交互重设计

| # | 子需求 | 验收方式 |
|---|---|---|
| P1-1 | 卡片上**直接显示一行效果摘要**（不用点开就能大致知道是什么） | 目视 |
| P1-2 | **选中态**：点一张卡片选中它，右侧/下方出**详情面板**（名称、费用、星级、完整描述、当前已有几件、买了会不会升星） | 目视 + 探针 |
| P1-3 | **购买改为两步**：选中 → 详情面板里点「购买」确认（避免误触花钱） | 目视 |
| P1-4 | 买不起 / 已满级 时**明确说明原因**（不是只把按钮变灰） | 目视 |
| P1-5 | 显示**买了之后的变化**（如「已有2件 → 买第3件可合成★2」） | 目视 |
| P1-6 | 保留现有的刷新 / 出货概率 / 备战席预览 / 阵容装备 | 回归不丢功能 |

## 5. 参考做法（供选型，非结论）

| 游戏 | 商店做法 | 可借鉴点 |
|---|---|---|
| 云顶之弈 | 一排 5 张卡，卡上有名字+费用+羁绊图标，**点一下直接买**（快节奏） | 信息密度高、单击即买 |
| 炉石酒馆 | 卡牌本体就是完整信息（图+文），**拖拽购买** | 卡面自带描述 |
| 杀戮尖塔 | 商店是**列表 + 选中详情**，点一次选中、再点确认 | 防误触、详情充分 |
| 皇室战争 | 卡片 + 底部固定详情条 | 移动端友好 |

★ **本项目的约束**：装备效果描述（`effectDesc1`）**很长**（带 HTML 富文本、属性图标），
卡片上放不下全文 → 所以 **「卡面摘要 + 选中详情面板」** 这条路（杀戮尖塔/皇室战争式）最贴合。

## 6. 已知风险与未决点

### 6.1 重设计范围 —— ✅ **用户 2026-07-28 已拍板：「一劳永逸的改，不动价格」**

= **布局与交互整个重做（中档往上），但经济数值一律不碰**：

| 动 | 不动 |
|---|---|
| 布局（卡片区/详情区/我的装备区） | `_price()` 价格 |
| 交互（选中 → 详情 → 确认购买） | `_roll()` 出货机制 |
| 卡面信息（加效果摘要） | `_shop_level()` 出货档 |
| 详情面板（完整描述/已有几件/买了会怎样） | 出货概率 |
| 移动端触摸尺寸 | 刷新规则与花费 |

「一劳永逸」的落点：**不要再出现"信息藏在 hover 里手机看不到"这类问题** ——
所以详情必须是**常驻可见的面板**，而不是又一个要触发才出现的提示。

### 6.2 商店是**局外经济**的一环，改交互不该改数值 —— 建议划清

`_price()` / `_roll()` / `_shop_level()` / 出货概率 都属于**经济平衡**。
本方案**只动展示与交互，不动这些**。若要动，应另开方案书（会影响对局强度）。

### 6.3 移动端触摸目标尺寸未验证

现有卡片 `SLOT_W × SLOT_H`，图标 52×44、名字字号 13。
**改成"选中+确认"两步后，卡片可以更大**，但没量过在真机上手指能不能舒服点中。
→ 需要真机验（同摸鱼模式，要走 CI 出包）。

### 6.4 描述富文本在小卡片上的渲染未验证

`effectDesc1` 带 `<span>` 和内联属性图标（v0.15.5 加的）。
详情面板里用 `SkillText.render_bbcode` 应该没问题（图鉴就这么干），
但**卡面摘要**若要截断显示，**截断点可能切在标签中间** → 需要先剥标签再截。

### 6.5 未决：卡面摘要显示什么

`effectDesc1` 第一句？还是单独给装备加一个 `shortDesc` 字段？
⚠ **加字段就是加一份手写镜像**（本项目栽过多次：`pets.json` 里 120/176 个数值字段没人读）。
建议**从 `effectDesc1` 剥标签后截断**，不新增字段。

## 7. ★固化版式（用户 2026-07-28 拍板 · 每个坐标都算过）

### 7.1 现状占用（1280×720）

| 区块 | 现状 |
|---|---|
| 头部 | y 0–130 |
| 卡区 5×2（卡 108×132） | x 80–740、y 150–460 |
| 阵容装备（**竖排 3 行**，`y = 178 + row*56`） | x 730–1270、y 148+ |
| 刷新按钮 | y ≈ 476 |
| 备战席 | y 560–654 |

**问题**：一屏塞了 5 个区块，卡片只有 108×132 —— **塞不下任何描述**，这才是"看不到描述"的结构性根因
（表面原因是描述放在 `tooltip_text` 里、手机没 hover）。

### 7.2 ★第一版草图放不下 —— 算账后否决

初稿用「卡 132×160 + 右侧详情」，算下来：

```
卡区高 = 2×160 + 24 = 344  → y 130–474
概率行 490–514；刷新 522–570
底部剩余 = 720 − 570 = 150 px
但 备战席 ≈94px + 阵容装备 ≈172px(3行×56+标题) → 并排也要 172px
→ ★放不下（差 22px）
```

**是用户追问「确定不会超界面吗」才发现的 —— 我出草图时没算。**

### 7.3 固化版式（总计 716 < 720 ✅）

| 区块 | y 范围 | 高 | 变更 |
|---|---|---|---|
| 头部 | 0–96 | 96 | **压缩 34px**：深海币与「Lv5 · 买经验」并到同一行 |
| 出货概率行 | 96–124 | 28 | **从底部挪上来**，紧贴卡区 |
| 卡区 5×2 | 124–420 | 296 | 卡 **132×136**（宽+24 / 高+4），行距 24 |
| 刷新按钮 | 436–484 | 48 | |
| 备战席 | 484–580 | 96 | 标题 22 + 格 64 |
| 阵容装备 | 580–716 | 136 | **竖排 3 行 → 横排**（每只约 400px 宽，一行放下） |

**右侧详情面板**：x **800–1240（宽 440）**、y **124–716（高 592）**
卡区：x **40–780**（`5×132 + 4×20 = 740`）

### 7.4 为塞下做的三处妥协（明写，免得以后当成疏忽）

1. 卡片高 **160 → 136**：效果摘要只放**一行**，字号 11
2. 阵容装备**竖排改横排**
3. 头部**压缩 34px**

### 7.5 触摸目标尺寸（用户 2026-07-28：「买经验按钮很小」）

| 控件 | 现状 | 改为 |
|---|---|---|
| 买经验按钮 | **200×36，字号 15** | **220×48，字号 18** |
| 返回 / 背包 | 120×44 | 保持（已达标） |
| 刷新 | 220×48 | 保持 |
| 购买（新增） | — | **≥ 220×56**（花钱的按钮要最大） |

判据：移动端触摸目标**高 ≥ 44px**。现有买经验按钮 36px **不达标**。

### 7.6 ⚠ 坐标是硬编码的 —— 只在 16:9 成立

这版坐标照 **1280×720 绝对定位**（与现有代码风格一致：满屏 `position = Vector2(...)`），
靠 `project.godot` 的 `stretch/mode=canvas_items` + `aspect=expand` 拉伸适配真机。

**所以"不超界"这个结论只在 16:9 下成立。**
用户 2026-07-28 已确认：**摸鱼模式是"跟手机横屏完全一样的比例、只是小屏"，不需要专门适配竖屏**。
→ 本方案**不做竖屏布局**。若将来出现别的宽高比，绝对坐标会露馅。
