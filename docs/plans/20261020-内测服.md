### D. 服务端怎么建、怎么迁移（读代码）

- `server/supabase/schema.sql` 是全量文件（`-- >>> BEGIN / END` 分段，号称可重复执行）；`migrations/` 22 份按 `YYYYMMDD[b|c|d]_名.sql` 命名；`tests/` 3 份检查脚本，结尾一定抛 `ALL PASS (N 条)` 让事务回滚。
- 本机沙盒 `tools/sql_sandbox.mjs`：PGlite（真 PG16）+ 桩出 auth / cron / 角色，跑「schema + 迁移 + 检查脚本」；文件头写明「生产库上没有别的约束那一层由同一份检查脚本在生产的回滚事务里再跑一次」。
- **上生产没有工具**：每次都是我手写 Management API 调用（`POST /v1/projects/{ref}/database/query`）或 SQL 编辑器整段粘贴；流程只记在方案书决策记录里（`20261019-服务器裁判.md` 10-20 三条：比对生产现行函数体 → 回滚事务里「迁移 + 检查脚本」→ 标记唯一、单事务 + `notify pgrst` 正式执行 → 回读函数体逐字相同）。
- ★**仓库建不出一份完整的生产库**：两条 pg_cron 任务（`finals_advance`、`purge_old_matches`）只以注释形式存在（`schema.sql:962`、`:277`），而且 `:962` 那段注释写的 `finals_seat` 还是 `'*/10 8-23 * * 0'`（已被 `20261012b` 改成 18-23）。内测服若照仓库建，周日推进器根本不会装。⇒ 建内测服的过程本身就是一次「仓库 ↔ 生产」对账。
- `.github/workflows/db-backup.yml:81-83` 已经在用 `supabase db dump`（连接串在 secret `SUPABASE_DB_URL`）⇒ 拿两边 schema-only dump 做 diff 的路是通的。

## 出入

1. 问题总表写「另开一套 Supabase，打包时决定连哪一个」——对；但**只换库不够**：裁判机、直播目录、Caddy 版本闸、pg_cron、探针工具、模拟号脚本都各自连着正式服，要一起分（见方案 §3~§6）。
2. 路线图写「客户端已有唯一时钟缝 + 内测服手动触发 finals_seat / finals_advance（假周号）」——**假周号只解决周日分组那一个函数**。周六闯关的「只有周六能交」、收盘、清理全是比 `now()`，假周号骗不过它们（现在靠在生产上临时翻 `gauntlet_any_day`）。⇒ 服务端也要一条时钟缝（§2）。
3. 「客户端穿越时写请求一律拦下」（`20261004-时间穿越测试.md`）在正式服上是对的，在内测服上**正好挡住了要测的东西**（报名、交阵容、闯关上报）⇒ 内测服包里放行。
4. 「schema.sql 可重复执行、是全量」——**不完整**：两条 cron 只在注释里（调查 D）。

## 方案

### 0. 总形状

```
                     正式服（不变）                         内测服（新）
Supabase 项目        turtle-realtime (London, Free)        turtle-beta (London, Free)
客户端               iOS / WinDist / MacDist / Android     WinBeta（开发包）+ 模拟号 + 门禁外的探针；需要时出 iOS 侧载包
裁判轮询器           turtle-referee.service（不动）         turtle-referee-beta.service（同机，WORKERS=1，低优先级）
工程版本目录         /opt/turtle/v*                         /opt/turtle-beta/<任意提交>
直播                 /streams/…                              /beta/streams/…（同一域名，不加 DNS）
时钟                 now()                                   app_now() = now() + 偏移（只在内测服可设）
cron                 真实星期几                              每分钟 beta_tick()，按 app_now() 判该不该推进
迁移                 只收「内测服已上过、同一 sha256」的迁移
```

### 1. 第二个 Supabase 项目（用户本人点，费用 0）

- 同组织新建 `turtle-beta`，区域 London（与正式服同区，延迟与行为一致）。免费额度 2 个刚好用满（调查 F）。
- 建库：仓库 `schema.sql` + 补齐的 cron 语句（§5 第 1 条）→ 回读 `cron.job`、函数清单、grants，与正式服 schema-only dump 做 diff，差异逐条归档。
- Auth：开匿名登录（默认是关的，memory `project-backend-supabase` 第 1 条）；SMTP 复用 `turtlesupport32@gmail.com` 那把应用专用密码，发件人名「斗龟场 内测服」；两封模板照正式服（只放验证码）。
- 配置行：`service_status`（`min_client_version` 跟内测服自己的节奏）、`referee_config`（`gauntlet_any_day` 可开）、`referee_versions`。
- 秘密：内测服 service key 只放两处 —— 裁判机 `/etc/turtle-referee/env-beta`（600）与本机 `~/.supabase/beta-service-key`；不进仓库、不进 memory 正文。
- Management API 令牌：现有令牌**限定只 turtle-realtime 一个项目，（10-20 在 dashboard 实看到期日为 2027-01-05，原写的 10-25 是过时 memory）**⇒ 用户本人新建一把覆盖两个项目的令牌（Database + Auth Config 读写），放 `~/.supabase/access-token`，旧的撤销。

### 2. 时间：服务端时钟缝 + 两边对齐

1. 新函数 `public.app_now()`：返回 `now() + 偏移`。偏移存在单行表 `public.server_clock(offset_sec bigint)`；**正式服这张表带 `check (offset_sec = 0)` 约束** ⇒ 正式服即使误执行「设偏移」也写不进去（双保险：`app_now()` 自己再读一行 `service_env`，值为 `prod` 时直接返回 `now()`）。
2. 把 `now()` 分两类，**只换赛程闸那一类**：「现在是不是周六 / 收盘没有 / 备战窗开着没有 / 这一轮该不该推进」改调 `app_now()`；「这一行什么时候写的」（`created_at`、`updated_at`、租约、清理年龄）保持 `now()`。134 处逐条分类，清单进实施回填（穷举，防低估）。
3. 客户端对齐：内测服包从 `service_status` 多读一列 `clock_offset_sec`（正式服恒 0），叠到 `now_utc()` 的服务器偏移上 ⇒ 所有内测服客户端与服务端看到同一个假时间，不再各穿各的。本机「测试时间」面板保留给离线测试用。
4. 内测服包里**穿越不拦写**：`travel_blocks()` 加一条「是内测服就放行」（判据是构建特性 `beta_server`，不是地址字符串）。正式服行为一字不变。
5. pg_cron：内测服不装按星期几的那几条，改装一条 `* * * * *` 的 `beta_tick()`：按 `app_now()` 判断该不该调 `finals_seat` / `finals_cup_seat` / `finals_advance`，周号也按 `app_now()` 算。正式服的 cron 不动。

### 3. 内测服手动推进：`tools/beta_ops.py`

- 只认内测服的项目 ref；参数里出现正式服 ref ⇒ 直接退出（写死的拒绝，不是配置）。
- 子命令：`status`（假时间、本周各阶段、各表行数）/ `clock set "sun 18:05"` / `clock reset` / `seat` / `cup-seat` / `advance [轮数]` / `close-week` / `wipe-week <周号>` / `seed-bots`（调裁判机 `--bot-pool`）。
- 每条命令打印「做之前 / 做之后」的计数（分母），不只打印「OK」。
- 这就是路线图「后台」的第一块地基：先命令行，后台网页另立方案书。

### 4. 客户端切服（构建期，不留玩家可见的开关）

1. `project.godot` 加 `turtle/supabase_url.beta_server`、`turtle/supabase_anon_key.beta_server`、`turtle/stream_base.beta_server`、`config/name.beta_server="斗龟场 内测服"`、`config/use_custom_user_dir.beta_server` / `custom_user_dir_name.beta_server` ⇒ 内测服包的存档与正式包分开，同一台电脑能同时装。
2. `export_presets.cfg` 新预设 `WinBeta`（`custom_features="beta_server"`）；需要手机时再加 `iOSBeta`（走现有侧载工作流出 unsigned IPA，不进 TestFlight，见 D3）。
3. 开发 / 无头进程：新环境变量 `TURTLE_SERVER=beta|prod` **同时**换地址与 key（补调查 B 的 key 缺口）；`TURTLE_SUPABASE` 照旧（门禁 `" "` 停层的用法不变）。
4. `stream_watch.gd` 的 `BASE` 改读 `turtle/stream_base`（默认值 = 现在的常量），环境变量 `TURTLE_STREAM_BASE` 照旧优先。
5. 内测服包主菜单版本号上方常驻一行「内测服」（同 `DevClockBadge` 的做法），截图 / 报 bug 一眼看出连的是哪台；问题反馈与报错上报附带 `server=beta`。
6. 正式包（iOS / WinDist / MacDist / Android 预设）**不带** `beta_server`，门禁量导出预设文本证明这一点。

### 5. 迁移流程固化：`tools/sb_migrate.py`

1. 先补洞：两条只在注释里的 cron 写成真语句进 `schema.sql`（`finals_advance`、`purge_old_matches`），并修掉 `:962` 那段过期注释。
2. 两边各建一张 `public.schema_migrations(name, sha256, applied_at, applied_by)`；正式服首次建表时按 `migrations/` 现有 22 份回填（这些已在生产上过）。
3. 一份迁移的标准路径（每一步不过就停）：
   1. `sandbox`：`node tools/sql_sandbox.mjs <迁移> <检查脚本>` ⇒ `ALL PASS`
   2. `beta --rehearse`：内测服回滚事务里「迁移 + 检查脚本」⇒ `ALL PASS`、事后计数不变
   3. `beta --apply`：标记唯一、单事务、`notify pgrst`；回读函数体与仓库逐字相同；写 `schema_migrations`
   4. 内测服冒烟（相关的 `beta_ops` 剧本 / 模拟号跑一轮）
   5. `prod --rehearse`：比对生产现行函数体 == 仓库迁移前版本（去注释空白）；回滚事务里「迁移 + 检查脚本」⇒ `ALL PASS`
   6. `prod --apply`：**拒绝**内测服 `schema_migrations` 里没有同名同 sha256 的迁移（紧急修复走 `--hotfix`，会在两边都记一行并要求事后补上内测服）
4. `sb_migrate.py diff`：两边 schema-only dump 对比（函数体、grants、RLS、cron），用来发现「有人在面板上手改了」。
5. 截 SQL 段落先断言标记唯一、打印长度 / 语句数（memory `fb-sql-extract-by-unique-marker`）。

### 6. 裁判机同时服务两台（同机两套轮询器）

- **R1（已解决·10-21）**：项目与只授权内测服的令牌已建（见验收清单第一条）。原文：建项目与新令牌只能用户本人在 supabase.com 点（或授权我用他的浏览器去点，10-20 夜里不开窗口，所以不在今晚）。现有令牌到期日实为 **2027-01-05**（10-20 dashboard 实看），只为覆盖内测服项目才需新建。

- **R4（未决·实施时穷举）**：134 处 `now()` 的分类。分错一处的后果：赛程闸那一类漏换 ⇒ 内测服上某个阶段骗不过去（测不到，不伤正式服）；时间戳那一类误换 ⇒ 内测服上清理年龄错乱（也不伤正式服）。正式服不受影响，因为正式服 `app_now()` 恒等于 `now()`（约束 + `service_env` 双保险）。
- **R5（已堵·设计）**：`app_now()` 进正式服后，正式服函数体变了（`now()` → `app_now()`）——迁移本身要走 §5 全流程；`app_now()` 在正式服的返回值必须与 `now()` 逐值相等，检查脚本里断言。
- **R6（未验）**：裁判机 CPX32 余量只有 2.0~2.4 倍实时；内测服轮询器限一核 + `Nice=15` 是推算，不是实测。实施时在内测服同时跑满一局、正式服跑最重局，量正式服步速掉多少；掉到 2 倍以下就把内测服改成只在非赛程日运行。
- **R7（已定·取舍）**：内测服直播走同域名路径前缀而不是子域名 ⇒ 省一次 DNS 操作；代价是两台共用一张证书、一个 Caddy 进程，Caddy 配置写错会同时伤两边 ⇒ 改 Caddy 一律 `caddy validate` 后 `reload`，不 `restart`。
- **R8（已绕开 + 已实测）**：没有依赖 Godot 对 `[turtle]` 段的自动覆盖 —— `scripts/net/server_env.gd` `setting()` 是内测服就显式读 `<名>.beta_server`，**少配一项拿到空、绝不回落正式服**（门禁 C5）。`config/name` / 存档目录仍靠引擎覆盖：真导出 WinBeta 实跑，存档目录就是「斗龟场 内测服」。
- **R9（已知）**：内测服 SMTP 与正式服共用一个 Gmail 发件额度。内测服只给团队自己发信，量极小。
- **R10（已照出）**：结构指纹对账（函数体 / grants / RLS / 约束 / 索引 / 触发器 / cron / 角色配置）仓库建出的内测服 vs 正式服，差异只有三处：两条注释 cron + 正式服面板「自动开 RLS」事件触发器 `rls_auto_enable`（内测服 bootstrap 补了同款）。Auth 设置差异见实施回填。
- **R11（已知·小）**：客户端只在问服务状态时（启动 / 版本墙）拿一次服务端偏移；`beta_ops clock set` 之后，已开着的客户端要重进主菜单 / 重开才跟上。主菜单「内测服」角标在第一次建菜单时偏移还没回来 ⇒ 只显示「内测服」，下次建菜单才带「服务端时间」。
- **R12（已知）**：内测服 `beta_tick` 每分钟叫一次周日三个函数，正式服是 */10 / */5 / 每分钟；三者幂等，结果相同，只有冠军杯赛「等组打完」可能早几分钟成表。
