日期：2026-10-19　|　状态：**实施中**

## 1. 需求原文

用户 2026-10-19：「然后是排行榜你学一下其他游戏的，开放左右排名」，紧接着更正「开放所有排名」。

同日主会话追加（用户 10-19）：「周六 / 周日赛况保留到周一」—— 排行榜顶栏周一也给「周六赛况」「周日对阵图」两扇门。

## 2. 调查结论

改之前的现状（`git show e6f30e02`）：

- 屏幕只画 **11 行**：`LeaderboardScene.gd` `const ROWS := 11`，`_pick_rows()` 自己在第 11 名开外时取「前 9 名 + ⋯ + 我」。第 10 名到最后一名**没有任何办法看到**。
- 服务端那一路：`SupabaseNet.WEEK_LB_LIMIT := 30`（`scripts/net/supabase.gd` 周榜段），`fetch_week_leaderboard_async(week, 30, …)`；服务端 `week_leaderboard(p_week, p_limit)` 里 `lim := least(greatest(coalesce(p_limit, 30), 1), 100)`（`server/supabase/migrations/20261010_week_leaderboard_v3.sql`）⇒ 就算客户端要，也最多前 100 名。
- 本机那一路：`Backend.leaderboard(pool, …, 1 << 30)` 是全量，但屏上同样只画 11 行。
- 排序口径：服务端 `row_number() over (order by season_wins desc, hearts desc, season_sweeps desc, uploaded_at asc, account_id)`；本机 `Backend.leaderboard` 胜场 → 余命 → 横扫（`verify_leaderboard_sort` 守）。**本次不改。**
- 机器人：服务端 `latest` 里 `coalesce(g.snapshot ->> 'is_bot', 'false') <> 'true'` 与 `seed_` 前缀两条把机器人 / 陪练整个排除在榜外，屏上没有任何「机器人」标签（用户 10-04：机器人对手不许露馅）。本次照抄这两条，不改。
- 截图：本工作区规矩不许开带窗口的 Godot，而 Godot 无头模式是 dummy 渲染器，取不到像素（实测 `--display-driver headless --rendering-method gl_compatibility` 下 `RenderingServer.frame_post_draw` 永不触发，进程卡到超时）。⇒ 现状与改后都**没拍到图**，只有门禁读节点量出来的数（见 §6）。截图脚本 `tests/_shot_lb_all_ranks.gd` 已备好，要窗口跑。

## 3. 需求 ↔ 代码的出入

- 「开放所有排名」与服务端上限 100 冲突：只改客户端 `p_limit` 拿不到第 101 名起 ⇒ 必须加按名次区间取的 RPC。
- 一次拉全榜再全建出来：上千人时就是上千行节点 ⇒ 列表只建看得见的那几行，按页取。

## 4. 方案（已实施）

**服务端**（只写文件，未执行到生产）：

- 新函数 `week_leaderboard_page(p_week bigint, p_offset int default 0, p_limit int default 50)`：`server/supabase/migrations/20261019_leaderboard_all_ranks.sql`，同一段逐字追加在 `schema.sql` 末尾（起止标记 `-- >>> BEGIN week_leaderboard_page 20261019 >>>`）。
  `latest` / `ranked` 两段与 v3 逐字相同；只把 `rk <= lim` 换成 `rk > off and rk <= off + lim`；回包 = 旧形状 + `offset`；每页上限 100；只读、security definer、只授 authenticated。
- 旧函数 `week_leaderboard` 一个字不动（老包照用）。

**客户端**：

## 5. 已知风险与未决点

- **未决（要主会话执行）**：迁移 SQL 没上生产。没上之前新包会先问新函数 → 404 → 退回旧函数（前 100 名 + 我），第 101 名起翻不到但不报错。⏳
- **已堵**：新函数 404 时只回退一次，不会每滚一下都问；某一页取失败不自动重试（断网不刷请求），那几行停在「只有名次」的待取样子。
- **未验**：真机手指拖动 —— 门禁只证明行里没有吞触摸的控件、`scroll_vertical` 能滚到底；iPhone 上的惯性手感没人摸过。⏳
- **未验**：没拍到图（§2 末段），版面只由门禁量的矩形保证（两个比例都在视口内、列表与钉住行不重叠、`verify_ui_consistency` 0 压边 0 圆角 0 热区不足）。⏳
- **未决**：周一两扇门是按「周一 = PHASE_REST」写的；主线已有 `Phase2Config.weekend_view_week(now_utc)`，合并时由主会话对接。🔲
- 名次在翻页之间可能变（别人刚打完一场）：两页之间名次重复或跳过一名。行按服务端给的 `rank` 落位，最多看到一名重复 / 空一名，翻回去会补上。未处理。
- 本机那一路不分页（池子本来就在本机），120 人实测流畅；上万条快照的本机池没测过。
