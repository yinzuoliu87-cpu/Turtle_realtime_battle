## 3. 需求 ↔ 代码的出入

- 「瑞士轮」需要**按当前战绩配对** ⇒ 第 r 轮的对阵依赖第 r-1 轮全部结果。现在的单败表第 r 轮对阵只依赖「上一场谁赢」，
  客户端按座次表就能现算。瑞士配对仍可在客户端从全部结果确定性现算（E-B3 精神不变），但**必须等上一轮全部结果到齐**才知道下一轮对手 ——
  现行 `finals_advance` 已是「整轮到齐才翻面」，可沿用。
- 「组冠军」头衔在瑞士轮下没有对应物 ⇒ 改为按名次；已发出去的历史「组冠军」不回收（推测用户会要这样，列 U4）。
- 「地区」在现有表里没有这一维（`finals_entrants` 列：season_week/bucket_no/seed/account_id/name/snapshot）。

## 4. 方案

### 4.1 赛制（建议，待拍板 U1~U3）
- 上午：全部晋级者一张瑞士表（不再分组）。轮数 R 按 MTG 附录 E 取：
  ≤8 人不打瑞士（直接冠军杯赛，沿用 2026-10-07「8 人或更少时直接杯赛」）；9–16 → 4 轮切前 4；17–32 → 5 轮切前 8；33–64 → 6 轮切前 8；更多 → 7 轮切前 8。
- 配对：第 1 轮按周六战绩种子（高 vs 低半区）；之后同积分组内配对、不重复对手；奇数人数最低分者轮空（记胜、每人至多一次）。
- 排名：胜场 → OMW%（下限 0.33）→ 周六战绩种子。
- 两边都没打的场（双缺席）：**U2**。
- 晚上冠军杯赛：前 4/8 单败（种子 = 瑞士排名），沿用现有 `finals_cup_seat` 的单败表与开播/观赛。

### 4.2 头衔
冠军 / 亚军 / 四强 照旧（冠军杯赛派生）；「组冠军」→「瑞士轮全胜」（R 轮全胜）。`sync_titles` 一处改。

### 4.3 地区字段
`finals_pending` / `finals_entrants` / `finals_buckets` 加 `region text not null default 'eu'`；读写函数带上它；客户端先固定传 'eu'。
本期**不**分地区开赛，只把这一维留出来（memory fb-id-without-owner-dimension）。

### 4.4 改动面（穷举，开工前按 grep 复核）
- 服务端：`finals_seat` / `finals_advance` / `finals_report` / `finals_view` / `finals_week_view` / `finals_opponent` / `finals_replay` / `finals_cup_seat` / `finals_champion_seed` + 新迁移文件 + `schema.sql` 同步。
- 客户端：`bracket.gd`（新增瑞士配对/排名纯函数）、`BracketMapScene.gd`（瑞士表视图：积分榜 + 本轮对阵，替代组内树）、`GameState.sync_titles`、`LeaderboardScene`（头衔显示 `:321` `:354`）、`autopilot_finals.gd`（找自己那场）。
- 门禁：`verify_champion_cup` / `verify_bracket*` / `verify_finals_*` 中断言组结构的条目要改；新增 `verify_swiss`（配对不重复、轮空至多一次、排名可复现、客户端与服务端同一结果）。
