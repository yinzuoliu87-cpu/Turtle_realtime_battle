## 1. 需求原文

> 用户 11-24：「我们来个筹码…赌场里面不是有那种十美金筹码，然后一百美金筹码」；筹码 = 消耗品：羁绊不给属性，只有一星不合成，买入进背包 → 装龟身上 → 带进一场对局 → 打完损坏；「强度肯定要比正常装备要大」「两个一费…两个五费」。
> 用户 11-26 逐枚：白 1 元「四十五点攻击力，百分之五十的攻击速度」；粉「七百点最大生命值和四十点护甲」；红 5 元「攻击力和暴击率没问题」；绿「生命值和每秒回复最大生命值，还可以给个魔抗」；黑 / 紫「都会为携带者提供六百的最大生命值…一个是登场时给所有友军提供携带者最大生命值百分之三十的物理护盾…不会再衰减…另外一个…魔法护盾」；黄「七十攻击力…百分之五十攻击速度，百分之三十暴击伤害和持续整个战场的控制免疫」；棕「生命值、护甲和魔抗…死亡时会在两点五秒内回复百分之六十最大生命值」（与威尼斯面具「一个是给 C 位的保护，一个是给坦克的…重生…并没有撞车」）；金「第八秒，为所有友军提供…金色护罩…三秒…免疫伤害和负面效果」+ 友军属性「差不多吧」；灰「专门为一个携带者…每次攻击或者受击会获得一层…最多四十层，每层…二攻击力、二护甲、二魔抗…二十的最大生命值…满层之后…百分之十的增伤和减伤」；黑色护盾「可以独立生效」。

## 2. 调查结论

- 背包 / 经济流水：`scripts/gamedata/econ_inv.gd`、`econ_ledger.gd`（服务器同一份逻辑重算，`server/` 经济合同）；装备字典重建一律走 `GameState.mk_eq`（093 香火石充能的教训）。
- 物理护盾（127 纸面具新加 `phys_shield`）/ 魔法护盾（012 海藻 `magic_shield`）都是现成通道。控制免疫 `cc_immune_until`（`battle_damage._stun` 入口判）。
- 对局结算入口 `_settle_season`（`RealtimeBattle3DScene.gd:7332`）；服务器裁判 `RefereeRunner` 结果单。

## 3. 需求 ↔ 代码的出入

- 「打完损坏」要同时改客户端背包与服务器账本，否则两边对不上（11-21 事故同类）—— 损坏在服务器侧也要按同一规则扣。
- 「一场」= 上路 + 下路 + 终极战场整场（我的理解，用户未否）；哪些对局消耗：正式对局（积分赛 / 周六闯关 / 周日决赛日）消耗，切磋 / 教程 / 调试不消耗（我的建议，用户未否）。
