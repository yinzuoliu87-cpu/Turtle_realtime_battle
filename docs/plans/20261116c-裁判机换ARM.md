# 裁判机换 ARM：CPX32（x86）→ CAX21（ARM），IP 不变

日期：2026-11-16　|　状态：**已拍板**

## 1. 需求原文

- 用户 11-16：「裁判机这么贵吗」
- 我建议「先花几毛钱租一台 ARM 测一小时，结果一致再谈换」，用户：「可以啊，按你的建议走吧」
- 测完后用户：「那到时候安排个日子换喽。嗯，看看到时候怎么换，因为我这个是买了一个月吧，一个月之后结算吧。那你看安排哪天，你给它搞好。」

## 2. 调查结论

**价格**（Hetzner API 11-16 实查，`/server_types` 的 `prices`）：
- 现机 CPX32（4 核 AMD 共享 / 8 GB）：€35.49 / 月不含税，€42.59 含税；按小时 €0.06828 含税、月封顶。
- CAX21（4 核 ARM Ampere Altra / 8 GB / 80 GB 盘）：€10.49 不含税（约 €12.59 含税）⇒ 每月省约 €30。
- 同规格 x86 便宜款 CX33 €8.49：10-19 实测单核太慢（录流 0.8 倍实时），不考虑。

**确定性**（`tools/oneoff/arm_referee_trial.py`，文件头记了全部数字）：
- 正式服 0.23.3 真实对局 84 局（决赛 24 / 闯关 30 / 积分赛 30）在 ARM 上用官方 `Godot_v4.6.3-stable_linux.arm64`（与现机同一提交 7d41c59c4）重算，胜方 + 结果指纹**逐字相同 84 / 84**；改坏一个结果单 ⇒ 比对报 NOT SAME。

**速度**（`tests/probes/_probe_stream_s1.gd`，最重那局 7951 步，两台各单独跑、取两遍最快）：

| | 不录 | 边算边录直播 |
|---|---|---|
| 现机 CPX32 | 245 步/秒 = 4.1 倍实时 | 117 = 2.0 倍 |
| CAX21 | 179 = 3.0 倍 | 89 = 1.5 倍（单核约慢 27%） |

**库存**：`/server_types?name=cax21` 的 `locations[].available`。11-16 傍晚 nbg1 / fsn1 / hel1 全是 false（下午试验机在 hel1 开到的大概是最后一台）。

**机器上有什么**（11-16 只读盘点，ssh `systemctl list-unit-files` / `ls`）：
- 服务：`turtle-referee`（正式）、`turtle-referee-beta`、`turtle-mainsite-gateway`（正式 / beta）、`turtle-gauntlet-planner-prod`、`turtle-relay-nft`、`caddy`；计时器：陪练号（prod 开 / beta 关）、裁判健康检查 ×2、直播最低版本闸 ×2、直播清理 ×2、内测高峰保护。
- 配置：`/etc/turtle-referee/` 七份 env（含密钥，只在服务器之间直接拷）、`/etc/caddy/`、`/etc/turtle-relay.nft`、ufw（22 / 80 / 443 tcp+udp / 8443）、用户 `turtle-referee`。
- 目录：`/opt/{godot,turtle,turtle-beta,turtle-bots-beta,turtle-bots-prod,turtle-prev,turtle-stage,turtle-staging}`；`/var/lib/turtle-referee` 5.1 GB（大头是直播块）、`/var/lib/turtle-bots-prod` 579 MB、`/var/lib/caddy`；盘用了 46 / 75 GB。

**写死这台机器的地方**：
- IP `49.13.166.188`：`tools/deploy.py:54`、`tools/beta_ops.py:45`、`tools/mainsite_deploy.py:64-65`、DNS 四条 A 记录（`stream` / `cn` / `arena` / `arena-beta.turtlearena.xyz`，见 `server/relay/README.md:75`、`server/referee/README.md:590`、`server/stream/README.md:88`）。11-16 查过这四个域名**没有 AAAA 记录**。
- 机器编号：`tools/referee_watch.py:44` `SERVER_ID = 171098941`（外部监控软重启用）。

## 3. 需求 ↔ 事实的出入

- 「买了一个月吧，一个月之后结算」：**不成立**。Hetzner 云服务器按小时计费、月封顶，月初结上个月实际用的小时数（API 里每个机型都有 `price_hourly`）。旧机删掉那一刻起停止计费 ⇒ 不用等满一个月，越早换越省。
- 「安排哪天」：日子取决于库存。主 IPv4 只能在**同一机房**里从旧机挪到新机，所以只等纽伦堡（nbg1）；换到别的机房就要改四条 DNS（Porkbun 登录要用户本人过手机验证）、监控 / 部署脚本里的 IP 全换。

## 4. 方案

### 4.1 日子怎么定

1. **抢货**：`.github/workflows/referee-arm-grab.yml` 每 30 分钟跑 `tools/referee_arm_grab.py --run`：nbg1 有货、且还没有 `labels.purpose=referee-arm` 的机子 ⇒ 当场开 `turtle-referee-2`（cax21 / nbg1 / ubuntu-24.04 / 钥匙 turtle-referee）。开出来就按小时计费（约 €0.017），最多一台。
2. **装机**：新机开出来后，第一个工作日装好（§4.2）。正式服不受影响。
3. **切换**：装好就切（用户 11-16 知道按小时计费后：「就现在转」），只避开周六闯关 / 周日决赛（周五晚到周日晚不动）。停机目标 ≤ 5 分钟（§4.3）。
4. 到 **11-27（周五）nbg1 仍没货** ⇒ 再问用户要不要接受别的机房（要改 DNS）。

### 4.2 装机清单（新机，切换前做完）

- 系统：ufw 同规则、用户 `turtle-referee`、时区 / journald 同现机；`/opt/godot/godot` 换成官方 arm64 版（4.6.3，同一提交）。
- 从旧机直接 rsync（服务器之间，临时钥匙，用完删）：`/opt/turtle*`（版本工程原样，`.godot` 导入缓存与架构无关）、`/etc/turtle-referee/`、`/etc/caddy/`、`/etc/turtle-relay.nft`、`/etc/systemd/system/turtle-*`、`/var/lib/turtle-*`、`/var/lib/caddy`、`/root`（部署脚本与记录）。
- 装 caddy（官方源）与 python3 依赖同现机；单元文件 enable 状态照旧机抄，但**先全部不起**（避免和旧机同时领活 / 同时发件）。
- 逐版本验确定性：现机装着的每个版本（正式 7 个、内测 8 个）各抽正式服 / 内测服已算完的对局重算比指纹（同 `tools/oneoff/arm_referee_trial.py` 的做法），不一致的版本不搬。
- 陪练号：`bot_runner` 跑的也是 Godot 客户端，用 arm64 二进制在新机空跑一局（连内测服）确认能跑。

### 4.3 切换步骤（停机窗口）

1. 旧机：停陪练号计时器并等在跑的退完；停 `turtle-*` 全部服务与计时器、caddy。
2. 最后一次增量同步 `/var/lib/turtle-*`、`/var/lib/caddy`、`/etc/turtle-referee/`。
3. 旧机关机；旧主 IPv4 设 `auto_delete=false`，从旧机解绑。
4. 新机关机；解绑并删掉新机自带的临时 IPv4；把 `49.13.166.188` 绑到新机；开机。
5. 新机按旧机的 enable 状态起服务；验：直播 `/healthz`、`referee_health()` 心跳、主站网关、大陆中转 8443、裁判领一局、陪练号一局。
6. `tools/referee_watch.py` 的 `SERVER_ID` 改新机编号；本机 `known_hosts` 更新新机主机钥匙。
7. 观察 24 小时没问题 ⇒ 删旧机（停止计费）、删 `referee-arm-grab.yml`、改 CLAUDE.md §7 / 技能里的机型描述。

**回退**：新机关机 → IP 挪回旧机 → 旧机开机（旧机在第 7 步之前一直留着，按小时计费）。

### 4.4 工具与演练（11-16 晚，等货期间先做完）

- 装机：`server/referee/arm_provision.sh`（新机上跑，从旧机直拉；只装不起；可重跑；`--final` 只同步 /etc 配置 + /var/lib 状态）。
- 编排：`tools/referee_arm_cutover.py`（status / keys / unkeys / provision / log / verify / cutover / check / rollback / finish / rehearse-ip）。
  cutover 顺序：①旧机照常跑时预同步全部 ②记 enable 清单、停旧机 ③`--final` ④挪 IP ⑤新机照清单起服务 ⑥验收（直播 / 主站网关 / 大陆中转 / 正式与内测心跳 / 没有起不来的服务）。
- **挪 IP 演练**（`rehearse-ip`，两台临时 cpx22）：第一次 403 `assignment limit reached` —— 只看 `assignee_id` 已清空就去绑，解绑动作其实没收尾；
  改成每步等 Hetzner 动作 `success`、忙 / 超限隔 5 秒重试后第二次通过：关源机 → 目标机用这个 IP 能 ssh 共 68 秒。演练机与 IP 已清（第一次失败留下的两个孤 IP 也已删）。
- **装机演练**（临时 x86 cpx22 `arm-provision-rehearse`）：全量 7 分半（约 125 MB/s，盘用 43 GB）；caddy 配置 / 中转 nft 规则校验过；正式 7 个、内测 8 个版本都认出；
  演练机上 turtle-* 起着的 0 个、enable 的 0 个、caddy 没起。`--final` 只要 29 秒 ⇒ 停机估计约 2 分半（停服务 10 秒 + 同步 30 秒 + 挪 IP 70 秒 + 起服务 20 秒）。

## 5. 已知风险与未决点

- R1 速度【未验】：ARM 录流 1.5 倍实时（现机 2.0）。直播仍快于实时；周六高峰两条线程排队时间约长 27%。切换后第一个周六看排队（`referee_backlog`）。
- R2 库存【未决】：可能长期没货 ⇒ §4.1 第 4 条，11-27 再问。
- R3 IPv6【已堵】：四个域名没有 AAAA 记录，只挪 IPv4；新机用自己的 IPv6。
- R4 主机钥匙【已列】：IP 不变但主机钥匙变；本机部署脚本（BatchMode）第一次连会拒 ⇒ 第 6 步更新 known_hosts。
- R5 其余版本的确定性【未验】：只验了 0.23.3；§4.2 逐版本抽查，不一致的不搬。
- R6 陪练号【未验】：bot_runner 在 arm64 上没跑过。
- R7 磁盘【未验】：新机 80 GB，现用 46 GB；搬之前清旧直播块与 `turtle-rehearsal-*`。
- R8 切换期间主站偷袭【未验】：网关停几分钟，主站那边会不会重试；切换前读 `server/referee/mainsite_gateway.py` 与对接约定，必要时先停偷袭开关。
- R9 自动开机花钱【已堵】：定时任务最多开一台（已有就不开，`decide()` 自测管），约 €0.017 / 小时。
