## 3. 需求 ↔ 代码的出入

- 「文件管理」不只是挪文件：根目录垃圾的根因是**写入方的默认路径**和**门禁转绿不清日志**，只清一次下个月又是 700 个。⇒ 改写入方 + 一个清理命令。
- 「流程」里最贵的事故（RULES_VER、tag、提审 422、env 没重启）全出在**没进仓库的那几步**；进了仓库并有门禁的两步（门禁、迁移）近一个月零事故。⇒ 每一步变成「仓库里一条命令 + 前置检查 + 回读」。

## 4. 方案

### 4.1 第一期 · 文件管理（主会话）

- F1 开发产物统一落 `/.out/`（点目录：Godot 不扫、`.gitignore` 一条规则）：门禁失败日志 → `.out/gate/<测试名>.log`，**测试转绿时删掉它的旧日志**；约 12 处 `res://_…` 截图默认落点 → `res://.out/shots/…`；`vfx_scan` / `vfx_ingame_check` 清理连 `.import` 一起删。
- F2 `docs/`、`tools/`、`build/` 加 `.gdignore`（先核：测试里读 `res://docs/…` 的 3 处是 `FileAccess` 读文本，不经导入；读 `res://tools/…` 的逐个核），删掉跟踪着的 `docs/**/*.import`。
- F3 `.gitignore` 收拢：`/.out/`、根目录锚定 `/_*`；`git rm --cached` 已跟踪的对局产物与 `60`、`tmpop_before.png`。
- F4 `tools/clean.py`：默认只列不删；`--apply` 删根目录旧开发产物与无源 `.import`，**不碰** `build/`、`.git/info/exclude` 里藏的参考图、worktree（worktree 只报有没有没合的提交）。
- F5 导出预设 `exclude_filter` 补 `_*`、`_show/*`、`.out/*`。
- F6 新门禁 `tools/repo_hygiene_audit.py`：根目录不许出现新的被跟踪零散文件；`docs/` 新增单文件 > 2 MB 红（存量记台账只减不增）；`docs/`、`tools/`、`build/` 的 `.gdignore` 在位。

### 4.2 第一期 · 流程（两个 agent 并行写，主会话审、跑、提交）

- P1 `tools/release.py`
  - `bump <版本> --rules same|changed`：五处 + CHANGELOG 骨架 + 路线图一行；**`--rules` 必填**，`changed` 时同时把 `RULES_VER` +1，`same` 时列出上个 tag 以来动过的 sim 路径文件让人确认。
  - `checklist <版本>`：生成 `docs/releases/<版本>.md` 发版清单（每步带命令与回读）。
  - `tag <版本>`：前置检查（工作区干净、HEAD 已推、CI 在 HEAD 上绿、五处一致、tag 不存在）→ 只推这一个 tag；已存在的 tag 拒绝挪动。
- P2 `tools/asc.py`：`status <版本>` / `submit <版本>`（等 VALID → 进公开组 → 说明取 CHANGELOG 该版 → 先作废同版本在审旧构建 → 提审）/ `expire <构建号>` / `group-remove <版本>`；钥匙 ID 与 issuer 放本机 `~/.config/turtle/secrets/asc.json`，不进仓库。
- P3 `tools/deploy.py <版本>` + 服务器端 `server/deploy/deploy_version.sh`：本机前置检查（tag 存在、版本一致、CI 绿）→ 服务器上**暂存目录**装 tag 那一提交、导入两次、两条一致性门禁 → 过了才原子换进 `/opt/turtle/v<版本>` → 登记 `referee_versions` → 生成两个对手池并回读行数 → 陪练号工程同样暂存 → 改 env → 重启调度器 → 读进程环境确认；失败不切换、旧目录保留可回退。长任务服务器上 `nohup` 起、本机短命令轮询。
- P4 `tools/prod_flags.py`：读正式服开关与 `min_client_version`；`set` 要 `--yes-prod`；`force-update <版本>` 先查苹果审核状态（未过拒绝）。
- P5 `testflight.yml`：tag 名必须 = `project.godot` 版本，否则红；缺密钥改成红而不是绿灯跳过。

**与方案的偏差**
- 暂存目录不放 `/opt/turtle/.staging-…` 而放 `/opt/turtle-staging/`：轮询器把 `/opt/turtle` 下每个带 `project.godot` 的子目录（点目录也算）都当成一个版本去领任务；被替换的旧目录同理放 `/opt/turtle-prev/`（同一文件系统，改名仍是原子的）。
- `--bot-pool` 只能补 `referee_versions.rules_ver`、不能插行 ⇒ 版本没登记时 `deploy.py` 自动不切陪练号，打印登记 SQL，由人执行后再 `--only bots-switch`。
