## 出入

1. **需求说「上架」，但 11-16 那一轮实际能做到的是 TestFlight**：账号注册 + 身份验证 + 首次 Beta App Review 都有不可控的排队时间（见 §B），正式上架审核还要再排一轮。⇒ 本方案把 **11-16 的目标定为「TestFlight 外部测试可装」**，正式上架作为紧接着的下一步，不把两件事绑在同一天。
2. **任务描述里说「若有注册账号必须提供应用内删除账号」——本项目是匿名账号 + 可选绑邮箱**。匿名号也是服务端真账号（`auth.users` 一行，有云端快照、战绩、报错记录），而且绑了邮箱就是标准的可登录账号 ⇒ **5.1.1(v) 适用，删除账号是必须项**，不能拿「我们是游客模式」豁免。
3. **隐私政策 §1.9「发邮件删号」不满足 5.1.1(v)**：Apple 要求在 App 内发起删除（详见 §B 原文）。删号做完要同步改隐私政策 §1.9。
4. **任务描述里说截图要 6.9"/6.5"**：现行唯一必交的是 6.1" medium 组（2622×1206 / 2556×1179 横屏，§B10）。⇒ 两套都出：6.1" 必交、6.9" 备用。
5. **任务描述里说「HTTPS 属豁免」**：官方的豁免例子是**系统自带**加密（URLSession）；Godot 自带 TLS，可能不算（§B9，R10）。
6. **任务描述里说审核「90% 24 小时」**：官方是 50% < 24 小时、90% < 48 小时（§B13）。
7. CLAUDE.md §1 写「28 龟 × 59 件装备」——`scripts/gamedata/equip_stats.gd` 的 `STATS` 实数 96 个 `p2eq_*` 键（2026-10-20 现量）。商店文案不写死装备件数，避免同一个数漂两处。

## 方案

### 4.1 用户本人做（我做不了：要付钱 / 实名 / 签协议）——按依赖顺序

见文末「用户本人清单」。

### 4.2 删除账号（必须项，代码 · 10-20 晚已做，SQL 10-20 已上生产）

**服务端**（`server/supabase/migrations/20261020b_account_delete_and_reports.sql`，已追加进 `schema.sql`；10-20 约 12:56 UTC 已上生产，证据见验收清单）：
- `public.account_delete_self()`：security definer，**不收参数**，只认 `auth.uid()`；没登录回 `{ok:false, reason:not_signed_in}`。
  1. 收集这个账号用过的玩家 ID：`player_tag_of(account_id)`（服务端版玩家 ID 算法，与客户端 `phase2_config.player_tag` 逐位相同，门禁对向量）+ 它上传过的各份快照里实际带的 `profile.tag`。
  2. 别人看得见的地方先抹名字：`matches`（自己那一侧 + 任一侧快照玩家 ID 是他的，即他当别人对手的那些场）、别人的 `live_matches` 里他那一侧、`referee_jobs` 双方快照、`finals_entrants` 的名字与快照 ⇒ `profile` 换成 `{name: 已注销玩家, avatar: basic, id: deleted, tag: <这次删号随机生成的一串>}`；**行与对局结构保留**（别人的录像 / 对阵图不坏）。
  3. 他自己还没算完的周六裁判任务作废（`failed / account_deleted`），任务 `meta` 里去掉账号；`referee_restream.requested_by` 断开；与他有关的举报（他举报的 / 举报他的）全删。
  4. `delete from auth.users where id = uid` ⇒ `accounts / ghosts / gauntlet_ghosts / saves / standings / finals_pending / finals_scout / live_matches / gauntlet_records / client_errors / player_feedback / nickname_reports / nickname_resets` 随 cascade 删；`matches.left/right_account`、`referee_jobs.a/b_account` 随 set null 断开。
  5. ★`finals_entrants.account_id` 原来是 `on delete cascade` ⇒ 周日组里有人删号会**挖掉一个种子位**（别人的 `finals_opponent` 回 no_such_seed、对阵图缺人）。本迁移改成 `on delete set null`（列改可空，外键名动态查出来再换）。
  6. 授权：`revoke all from public` + `revoke execute from anon` + `grant execute to authenticated`（匿名游客号也是 authenticated 角色，同样能删）。

## 已知风险与未决点

- **R1（未决·时间）**：11-16 只剩 4 周。开发者账号审核、D-U-N-S（若走组织）、首次 Beta App Review 都是 Apple 侧排队，我控制不了。⇒ 建议用户**这周就注册个人账号**（个人不需要 D-U-N-S）。
- **R2（未验·10-20 更新）**：签名 archive / exportArchive / 上传这半条没有密钥跑不了，**一行都没在真账号上执行过**。已知风险点：① 免签 archive 再交给 exportArchive 用云端托管证书签，这条路依赖 API key 是 Admin 角色，权限不够会报 cloud signing 权限错 ⇒ 换 Admin key 或填 P12 备路；② App Store Connect 里还没建这个 Bundle ID 的 App 时上传必拒；③ 若 Apple 拒「免签 archive」里缺的 entitlements，就改走 P12 备路（archive 时签）。
- **R3（未验）**：Info.plist 改动必须落在**产物**上 —— 7-29 改方向那次，xcodebuild 前改的 plist 被重新生成盖掉（memory `fb-verify-artifact-not-steps`）。`ITSAppUsesNonExemptEncryption` 若走 build setting 注入（`INFOPLIST_KEY_*`）要回读产物确认。
