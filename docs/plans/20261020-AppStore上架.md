### B. Apple 现行要求（WebSearch / WebFetch，**全部 2026-10-20 访问**；引号内是官方原文短引）

**B1 开发者账号** —— 入口 https://developer.apple.com/programs/enroll/
- 个人：卖家名显示本人法定姓名（"Your name will be displayed as the seller name"），**不需要 D-U-N-S**。
- 组织：要 D-U-N-S、要能签合同的法律实体（"We do not accept DBAs, fictitious business names, trade names, or branches"）、要有与组织域名关联的公开网站。
- 都要：Apple 账号开两步验证、成年。
- 年费 "99 USD per membership year. Prices may vary by region"；**英国本地价：官方页未查到**（只在第三方站看到 £79，不采信）。
- 身份验证：Apple Developer App 里拍证件（"We accept passports in most regions"）；个人用卡须是本人的卡，否则要补证件（https://developer.apple.com/help/account/membership/program-enrollment/）。

- D-U-N-S：D&B 最多 5 个工作日 + Apple 同步最多 2 个工作日（https://developer.apple.com/help/account/membership/D-U-N-S/）。

**B2 欧盟 DSA 交易者（trader）声明** —— https://developer.apple.com/help/app-store-connect/manage-compliance-information/manage-european-union-digital-services-act-trader-requirements
- 提交新 App 时必须声明是不是 trader；是 ⇒ 地址（可用邮政信箱，需凭证）/ 电话 / 邮箱**公开显示在欧盟商店页**；不是 ⇒ 不用填联系方式，商店页注明消费者权益不适用。
- 不声明 ⇒ "Apps without trader status will be removed from the App Store in the European Union"（https://developer.apple.com/news/upcoming-requirements/，2025-02-17 起）。
- 免费业余游戏算不算 trader：**官方未明说**。

**B3 App Store Connect 建 App**
- Bundle ID 在 Certificates, Identifiers & Profiles 注册 Explicit App ID（Account Holder / Admin）。
- 新建 App 填：平台、名称、主要语言、Bundle ID、SKU（建后不可改）、用户权限；**Account Holder 签最新协议之前不能建 App**。
- 免费 App 在 Apple Developer Program License Agreement 下即可分发；付费 / 内购才要签 Paid Apps Agreement；税务银行在签了 Paid Apps 之后才填 ⇒ **本游戏免费无内购，不需要税务银行**（这是推论，官方没一句话直说）。

## 出入

1. **需求说「上架」，但 11-16 那一轮实际能做到的是 TestFlight**：账号注册 + 身份验证 + 首次 Beta App Review 都有不可控的排队时间（见 §B），正式上架审核还要再排一轮。⇒ 本方案把 **11-16 的目标定为「TestFlight 外部测试可装」**，正式上架作为紧接着的下一步，不把两件事绑在同一天。
2. **任务描述里说「若有注册账号必须提供应用内删除账号」——本项目是匿名账号 + 可选绑邮箱**。匿名号也是服务端真账号（`auth.users` 一行，有云端快照、战绩、报错记录），而且绑了邮箱就是标准的可登录账号 ⇒ **5.1.1(v) 适用，删除账号是必须项**，不能拿「我们是游客模式」豁免。
3. **隐私政策 §1.9「发邮件删号」不满足 5.1.1(v)**：Apple 要求在 App 内发起删除（详见 §B 原文）。删号做完要同步改隐私政策 §1.9。
4. **任务描述里说截图要 6.9"/6.5"**：现行唯一必交的是 6.1" medium 组（2622×1206 / 2556×1179 横屏，§B10）。⇒ 两套都出：6.1" 必交、6.9" 备用。
5. **任务描述里说「HTTPS 属豁免」**：官方的豁免例子是**系统自带**加密（URLSession）；Godot 自带 TLS，可能不算（§B9，R10）。
6. **任务描述里说审核「90% 24 小时」**：官方是 50% < 24 小时、90% < 48 小时（§B13）。
7. CLAUDE.md §1 写「28 龟 × 59 件装备」——`scripts/gamedata/equip_stats.gd` 的 `STATS` 实数 96 个 `p2eq_*` 键（2026-10-20 现量）。商店文案不写死装备件数，避免同一个数漂两处。

## 方案

### 4.1 用户本人做（我做不了：要付钱 / 实名 / 签协议）——按依赖顺序

见文末「用户本人清单」。

### 4.2 删除账号（必须项，代码）

- 服务端：新 RPC `public.delete_my_account()`（security definer，`auth.uid()` 定位，只删自己）：
  1. 先把 `matches` / `referee_jobs` 里该账号作为一方的快照里的 `profile` 抹掉（昵称不再可见），
  2. `delete from auth.users where id = auth.uid()` ⇒ 其余表靠 `on delete cascade` 一起删。
  3. `revoke ... from public, anon` + `grant execute ... to authenticated`；执行后回读 grants（memory：`revoke from public` 收不掉 anon 的默认授权）。
  写进 `server/supabase/schema.sql` 末尾 + 一份 `server/supabase/migrations/2026xxxx_delete_my_account.sql`；**上生产前先问用户**（SQL 上生产仍要问）。
- 客户端：`scripts/net/supabase.gd` 加 `delete_account_async()`（POST `/rest/v1/rpc/delete_my_account`），成功后清本机会话（token/refresh/account_id/email）并删本机存档、回到首启状态。
  ⚠ `scripts/net/supabase.gd` 当前有别的助手在改 ⇒ 这一步排在它们合并之后，或拆成新文件 `scripts/net/account_delete.gd`（只调 `SupabaseNet` 已有的请求原语）。
- UI：`scripts/scenes/SettingsScene.gd` 账号框加第三颗按钮「删除账号」→ 两步确认（第一步写清「删除后无法恢复：进度、云存档、排行榜记录」；第二步输入「删除」二字或长按确认）→ 结果提示。
- 文案：短指令 / 名词（memory `fb-no-colloquial-copy`）。
- 门禁：`tests/verify_account_delete.gd`（纯函数 + 假回包：成功 ⇒ 本机身份清空；401/5xx ⇒ 不清；UI 按钮在场且两步确认），真服务器探针 `tools/probe_account_delete.py`（建匿名号 → 写一行 ghost → 调 RPC → 回读 0 行；**配对照**：另一个号同表仍有 1 行）。
- 同步改 `docs/隐私政策.md` §1.9：「设置 → 账号 → 删除账号」，邮件渠道保留为备用。

### 4.3 签名上传 TestFlight（CI）

新工作流 `.github/workflows/ios-testflight.yml`（**不改**现有 `ios-build.yml`，unsigned 侧载线保留到 TestFlight 跑通为止）：

1. 沿用 `ios-build.yml` 的 Godot 下载 / 模板 / 导出 Xcode 工程三步。

4. 构建号：`CFBundleVersion = github.run_number`（或 `年月日时分`），`CFBundleShortVersionString` 仍从 `project.godot` 读（单一事实源）。
5. `xcodebuild archive` → `xcodebuild -exportArchive`（`ExportOptions.plist` method = `app-store-connect`，`destination = upload`）**或** fastlane `pilot upload`；认证都用 App Store Connect API key：`secrets.ASC_KEY_ID` / `ASC_ISSUER_ID` / `ASC_KEY_P8_BASE64`。
6. 产物判据落在产物上（memory `fb-verify-artifact-not-steps`）：上传前拆 `.ipa` 读 `Info.plist`，断言 `CFBundleIdentifier`、`CFBundleShortVersionString == project.godot`、`CFBundleVersion` 是数字、`ITSAppUsesNonExemptEncryption == false`、`UIDeviceFamily == [1]`，并 `codesign -dv` 看到 `Apple Distribution`。
7. 失败日志推 `ci-logs` 分支（沿用现有逃生口）。秘密只进 GitHub Secrets，不进仓库、不进日志。
