## 调查

### 040~045 六件的现状（读文案 + 读实现 + 探针）

**结算层六件全是健康的** —— 延时一律走 `_pending_shots`（sim 时钟），没有一处埋在 tween 上。
它们的缺口是**六件里五件没有台子、全部没有属于自己的门禁**。

实际查出的缺陷集中在**演出**与**读数出口**：

| 件 | 查出来的 | 怎么查到的 |

## 出入（与最初设想不一致的地方）

1. **原以为「六件只需补台子与门禁」** —— 实际查出 9 处演出缺陷，其中 3 处要重做素材。
2. **原以为大熊冲击波该做成「一面墙」** —— 用户否掉：原版**概念是对的**（一段段突起），
   坏的只是执行。我把概念也换掉了。
3. **原以为 036 上一轮已体检完** —— 实际那一轮我**根本没读** `_egg_level_up_vfx`，
   录制没拍到升级就登记成「台子窗口不够长」。
4. **原以为图标要自己定 house style** —— 标准**早就在仓库里**（`tools/icon_art_audit.py`，
   405 张 MC mod 参考），我没查就自己造了一套。
5. **原以为 Blender 体积火能出爆炸** —— 量出来渲染本身是平的（亮度跨度只有 5 级），
   而且体积渲染 + 少色量化给不出白闪/尖刺/硬边烟；参考本身就是手绘像素画。

## 决策记录

| 决策 | 理由 |
|---|---|
| 大熊冲击波回到**逐段隆起**，不做平移墙 | 用户②：概念没错，只改执行 |
| 演出外缘钳到 `半宽 − 精灵半宽` | 用户③：演出范围必须等于判定范围 |
| 036 烘自己的 `egg-hatch-levelup.png` | 用户④：素材不复用铁律 |
| 借素材做成**台账式门禁**而不是逐件修 | 普查证明是一整类；照 `zero_caller_audit` 的规矩 |
| 037 爆炸**不走 Blender**，按 CC0 参考的量测包络手写 | v2/v3 量到体积渲染给不出这个形状语言 |
| 037 点燃**仍走 Blender** | 火舌是体积感的，三层嵌套壳出得来 |
| 037 爆炸时长砍到 0.36 秒 | 用户⑤：参考那条是电影级 50 帧，游戏里每 15 秒一次不能拖 |
| 枪补**虚拟装备槽**而不是塞进 `u["equips"]` | 塞进去会走 `_eq_apply_all_stats` 等一整套，风险大 |
| 图标改用**既有的** `icon_art_audit` 四条判据 | 标准已存在且有门禁；自造一套是重复造轮子 |
| **数值/文案/触发条件一个字未改** | 本批是体检不是平衡改动 |

## 方法上的教训（比具体缺陷更值得记）

1. **否定意见针对执行时，别动概念**（驳回②）。
2. **「没看见」不等于「没问题」**（驳回④）—— 录制没拍到就该去读代码。
3. **一件事被否，先 grep 它是不是一整类**（驳回④）—— 借素材普查出 12 处。
4. **造轮子前先搜仓库**（驳回⑦）—— 图标标准早就在，我却拿**被投诉的图标**当基准。
5. **样本量 1 不是基准**（驳回⑦）—— 哑铃是全套最扁的 p10。
6. **量了不等于量对了** —— 亮档不跨过 12% 时 p88 会揉进主色，量两次才找对原因。
7. **CRLF/LF 混排下按行删注释会吃掉代码** —— 这次真删掉了一行 `var xoff`，
   编译当场炸；`wc -l` 掉 13 而我以为只删了 3 行就是信号。
