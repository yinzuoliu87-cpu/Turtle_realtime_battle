## 3. 从哪里取「我走到了第几轮」

### 3.1 ★不能从本地结算取

最直觉的做法是在 `finals_settle(won)` 里数轮次。**不行**，而且不是小毛病：

周日现在的实现是**双方各自在本地打对方的快照**，两边都可能算出自己赢；
服务端 `finals_report` 用 `on conflict … do nothing` ⇒ **先报的那个说了算**，
后报的那一条被静默丢弃，而那个客户端**早就按自己的结果发过奖了**。
（= v0.19.446 登记的 P9「两边都赢」。根因是周日的实现偏离了 D5，本方案**不修它**。）

⇒ 本地 `won` 不是权威。拿它发冠军头衔 = **一个桶里出两个冠军**。

### 3.2 ★权威在服务端的 feed 里，而且客户端已经在用它

`finals_view()` 下发 `{n, round, closed, entrants, done}`，`done` = `{"轮-场": 赢家侧}`，
**当前轮不下发**（不剧透）。`BracketMapScene` 本来就靠它画整张图，已有的助手：

| 现成的 | 干什么 |
|---|---|
| `competitor(r, m, side)` | 顺着 `done` 递归算出那个坑位上是谁（含轮空自动晋级） |
| `is_my_match(r, m)` | 那一场里有没有我 |
| `my_focus()` | **我真正在的最深那一场**（赢一轮往里走一格，输了停在输掉那场） |
| `_i_won(r, m)` | 服务端说我赢了那一场没有 |
| `_B.rounds_for(n)` | 这个桶一共几轮 |

⇒ 头衔从这里派生，**天然不受「两边都赢」影响**：一个桶里 `done["决赛轮-0"]` 只有一个值。

### 3.3 「四强」怎么定义

原稿逐字：「四强: 周日打进四强」。⇒ **被排进倒数第二轮就算**（那一轮正好 4 个人），
不要求赢。判据 `total >= 2 and deepest >= total - 1`：
- `total == 1`（桶里 2 人）：只有决赛，**不发四强**（那一轮就是冠军赛）
- `total == 2`（3~4 人）：第 1 轮 = 四强、第 2 轮 = 决赛 ✓

「冠军」= 服务端说我赢下了第 `total` 轮第 0 场。**必须看 `done`**，不是「排进决赛」。

## 5. 方案

1. **`bracket.gd` 收下这份递归**：新增纯静态 `occupant_seed(r, m, side, n, done) -> int`
   （`-1` = 待定，`-2` = 轮空），以及 `my_progress(me, n, done) -> {total, deepest, champion}`。
   `BracketMapScene.competitor()` **改成调它**再套名字 —— 不许抄第二份
   （memory `fb-hand-rolled-copies-drift`：抄一次永远落后）。
2. **`GameState` 存三个事实**（持久，随周重置）：
   `finals_deepest_round` / `finals_rounds_total` / `finals_champion`。
   ★**只增不减**：feed 挡住当前轮，所以这几个值只会往上走；写回时取 max。
3. **`sync_titles()` 从这三个字段派生**冠军/四强 —— 与另两档同一个入口。
   理由与 `award_title` 头注一致：「离线版没有『那一刻』这个事件，统一在这里对一次账」。
4. **记录点**：`BracketMapScene.set_data()` 拿到 feed 后写字段 + `sync_titles()` + 存档。

| 方案原本写的 | 实际做成 | 为什么 |
|---|---|---|
| 「`bracket.gd` 新增 `occupant_seed` / `my_progress`」 | 还加了 `my_side_in` / `semifinal_reached` | 「我在这一场的哪一侧」原来也只住在场景里；「2 人桶不发四强」是个判据，值得有名字 |
