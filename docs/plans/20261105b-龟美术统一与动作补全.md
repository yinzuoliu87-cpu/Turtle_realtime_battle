## 3. 需求 ↔ 代码的出入

1. **「只提供了待机动画」** —— 对。10 只是拆部件骨骼网格动画（其中 7 只的特效是逐帧序列），只有龟壳是纯逐帧 ⇒ 转像素序列帧要一个 Spine 4.3 求值器 + 渲染器（§4.2）。
2. **「以 JSON 的动画形式」** —— Godot 4.6 不认 Spine；官方运行库（spine-godot）要另买 Spine 编辑器授权，而且它在游戏里实时算骨骼、录不进直播流。⇒ 方案是**离线渲成序列帧**再进游戏（游戏现有的路子）。
3. **「攻击、待机、放技能的动画」** —— 代码现在只有 attack / hurt / death / run 四张表、且只有 3 只龟登记；**「放技能」没有通用动作槽**。要加一个通用的 `cast`（放技能那一下）并接到 `_cast_skill`，否则画了也播不出来。
4. **「剩下一十七只自己创作」** —— 28 − 11 = 17 只里，忍者 / 变脸 / 幽灵 **已经有成套动作**（用户点名变脸龟「设计的是非常可以的」）⇒ 真正要从头做动作的是 **14 只**。小龟在外包 11 只里，而它游戏里现在也有一套动作（四个）。
5. **姿态**：外包 11 只是四脚龟；变脸 / 忍者是站立龟。用户说站立龟形象「都还是不错的」—— 28 只要不要统一成一种姿态，是 §5 U2。
6. **「释放三种技能，可能还有被动」**（第二版）—— 第一版 §4.1 只设了**一个通用 cast 槽**：错。每只龟 3 个技能都可能被带进战斗，项目规矩「同一只龟的技能和普攻也不共用素材」⇒ **每个技能一段**；被动只有改变身体的才做（§4.1）。
7. **「熔岩龟有普通形态和火山形态」** —— 现在变火山画面上只有跃起砸地特效 + 体型变大，形象不换（`scripts/systems/skills/lava_system.gd:480` `_lava_transform`）。⇒ 形态要一整套动作 + 变身 / 变回两段（§4.3b）。
8. **「其余…我不知道要不要搞」** —— 14 只现有立绘不是像素画（§2.4 末），第一版「以现有形象为底做动作」漏了「先像素化」这一步，额度估算也是拍的（「一只全套约 300 次」）。⇒ §4.4 重算。
9. **「普攻要有前摇 → 命中 → 后摇」** —— 现在 `_basic_attack`（`RealtimeBattle3DScene.gd:2829`）**出手当帧就结算伤害 / 发弹道**，动画是附带播的（`_vfx._play_action(u, "attack")`）⇒ 命中特效与挥砍对不上、近战小将「待机 → 突然戳一下 → 待机」。⇒ 这是 sim 时序问题，不只是美术（§4.0）。

## 4. 方案

### 4.0 普攻三段节奏（全项目：28 只龟 + 小将 + 召唤物）

- **目标**（用户点名盖伦平 A）：举起（前摇）→ 砍到一半命中（伤害结算 + 命中特效 + 对方受击，**同一帧**）→ 继续挥完收手（后摇）→ 回待机。远程：前摇末帧放出弹道，命中 = 弹道到达。
- **前摇比例**：LoL 每个英雄有自己的前摇占攻击间隔的比例（攻速越快整段越短）。具体数值动手前去 LoL wiki 查盖伦等几个代表（近战 / 远程）再定，**不拍脑袋**；定下后按「近战 / 远程」两档（或每龟一档）写进数据。
- **代码**：`_basic_attack` 拆成「出手」（播动画、进前摇）与「命中」（伤害 / 弹道 / on-hit 装备 / 命中音效）两步；命中排进 `_pending_shots`（`RealtimeBattle3DScene.gd:677`，已有的定时机制，无头稳定）。前摇期间目标死亡 / 自己被控 = 这一下作废（LoL 规则；作废要不要退攻击计时，定在实现时查 LoL 后写死）。
- **动画规格**：普攻帧条 = 前摇帧 + **命中帧（数据里标 hit_frame）** + 后摇帧；帧率随攻速缩放，保证 hit_frame 的时刻 == 代码命中时刻。小将（近战 / 远程 / 精英 / 援军）与召唤物同一规矩。
- **影响**：改变对局结果 ⇒ `RULES_VER` +1、`rules_fingerprint` 重生成；所有单位首次出伤延后一个前摇（总 DPS 不变）。随美术分支一起发，**不进 0.22.8**。

## 5. 已知风险与未决点

- **[已决·U1] 外包 11 只补动作由谁做**：用户「请原画师补全是不太可能的…价格太大…需要时间很久」⇒ 我们自己做：先把 Spine 待机转成像素序列帧，再在序列帧上逐帧创作其它动作（§7）。
- **[已决·U2] 姿态**：外包 11 只是趴着的四脚龟，照样做攻击 / 放技能（用户「趴着的也可以去…做这个攻击等等」）；其余 17 只保持各自设计。
- **[未决·U3] 版权**：画师交付的 `.spine` 源文件与导出物，委托合同里是否允许我们改动和再创作（补动作、重新渲染）？我的方案不装、不分发 Spine 运行库（自写求值器离线渲帧），不需要买 Spine 授权；但源文件的使用权要用户确认。
- **[未决·U4] PixelLab 额度**：全部做完约 5700 次，本期剩约 1050 次、每期 2000 次 ⇒ 按额度走要到约 1 月；要更快就升级档位（花钱）。
- **[已决·U5] 小龟换外包版**：这 11 只要与合作网站对应，待机只能用这 11 只原画、头像也按原画重做（用户原话见 §7）。
- **[风险] 骨骼旋转会让像素画变形**（像素大小不一）：渲染后做像素对齐与调色板锁定；待机先与画师原图逐像素比，差异超阈值就不用骨骼旋转、改纯平移 / 换图。
- **[风险] 自写求值器与 Spine 官方不一致**：网格变形 / 带权网格 / 序列是最容易错的三处；用 11 只待机的画师原图当金标，P0 不过关不往下做。
- **[风险] 动画时长 ≠ 代码节拍**（07-22 精英小将四段踩过，动画先播完角色站着）：每个动作帧率由代码节拍反推，门禁对账。
