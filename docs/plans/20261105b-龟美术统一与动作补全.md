### 2.2 游戏里现在的龟动作（代码）

### 2.3 风格对照（配图 `img-20261105b-turtle-art/现有立绘vs外包待机.png`）

- 外包 11 只：彼此统一 —— Q 版、厚描边、四脚着地侧面、256 画布、颜色饱和。
- 游戏现有立绘：**彼此就不统一** —— 熔岩 / 寒冰 / 天使偏写实，凤凰 / 彩虹 Q 版，石头 / 竹叶低分辨率，小龟另一种；忍者 / 变脸是**站立拟人**。
- 制作能力：变脸龟两套全动作是 PixelLab 做的（memory `project-face-change-turtle`：一套约 300 次生成）。PixelLab 本期额度 11-05 剩约 1050 次，11-19 重置（每期 2000）。

## 3. 需求 ↔ 代码的出入

1. **「只提供了待机动画」** —— 对。但其中 **6 只（闪电 / 龟壳 / 熔岩 / 凤凰 / 寒冰 / 彩虹）是画师逐帧画的像素动画，Spine 只负责播放**；另 5 只（小龟 / 石头 / 竹叶 / 财神 / 天使）才是拆部件的骨骼动画。两种补动作的办法不一样（§4.3）。
2. **「以 JSON 的动画形式」** —— Godot 4.6 不认 Spine；官方运行库（spine-godot）要另买 Spine 编辑器授权，而且它在游戏里实时算骨骼、录不进直播流。⇒ 方案是**离线渲成序列帧**再进游戏（游戏现有的路子）。
3. **「攻击、待机、放技能的动画」** —— 代码现在只有 attack / hurt / death / run 四张表、且只有 3 只龟登记；**「放技能」没有通用动作槽**。要加一个通用的 `cast`（放技能那一下）并接到 `_cast_skill`，否则画了也播不出来。
4. **「剩下一十七只自己创作」** —— 28 − 11 = 17 只里，忍者 / 变脸 / 幽灵 **已经有成套动作**（用户点名变脸龟「设计的是非常可以的」）⇒ 真正要从头做动作的是 **14 只**。小龟在外包 11 只里，而它游戏里现在也有一套动作（四个）。
5. **姿态**：外包 11 只是四脚龟；变脸 / 忍者是站立龟。用户说站立龟形象「都还是不错的」—— 28 只要不要统一成一种姿态，是 §5 U2。

## 4. 方案

### 4.1 统一动作规格（每只龟）

| 动作 | 循环 | 用在哪 | 帧数（参考） |
|---|---|---|---|
| idle 待机 | 循环 | 站着 | 外包 11 只照原 3.33 秒节奏抽帧 |
| run 跑 | 循环 | 走位 | 6~8 |
| attack 普攻 | 一次 | `_basic_attack`，标出**出手帧**（伤害 / 弹道在这一帧） | 6~8，帧率按攻速反推 |
| cast 放技能 | 一次 | `_cast_skill`，标出**释放帧** | 6~10 |
| hurt 受击 | 一次 | 受伤 | 3~4 |
| death 阵亡 | 一次 | `_kill` | 6~9 |

签名技能（例：熔岩变身、变脸换形态）另做专属段，放第二期。

### 4.2 外包 11 只的待机：原样接进游戏

- **逐帧 6 只**：按 JSON 里序列（sequence）的帧序与时长，把 atlas 里的帧直接切出来拼成待机序列帧，逐像素就是画师的画。
- **骨骼 5 只**：写 Spine 4.3 求值器（`tools/assetgen/spine_eval/`）：骨骼世界变换（平移 / 旋转 / 缩放 / 错切）+ 带权网格 + 网格变形 + 插槽颜色 / 换图 → 在 Godot 里用 `Polygon2D`（贴图 + UV）离屏渲染每一帧 → PNG → 像素后处理（最近邻、透明度二值、颜色锁回原部件调色板）。
  - **标定**：拿画师的 `乌龟N.png` 当金标，比我们渲出来的待机第 0 帧（不像就是求值器错了，先修求值器再往下做）。
- 不装 Spine 运行库，游戏里只认序列帧（直播、帧对齐、像素画审计都现成）。

### 4.3 外包 11 只补动作（攻击 / 放技能 / 受击 / 阵亡 / 跑）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 原画师补 | 请原画师在 Spine 里补 5 个动作 | 风格 100% 一致，6 只逐帧龟只有他能逐帧补 | 花钱、要排期 |
| B 骨骼 5 只我来 K 帧 | 在原骨骼上写关键帧（前冲咬、抬身甩尾、缩壳、仰翻），同一个求值器渲 | 不花钱，风格一致（同一批部件） | 只能做部件的位移 / 旋转 / 变形，画不出新姿势；动作设计我来，按商业参考逐帧定节拍 |
| C 逐帧 6 只用 PixelLab 补帧 | 以画师的待机帧为参考，PixelLab 出动作帧，再按原调色板修 | 不花钱（额度内） | 风格有偏差的风险最大；每只约 5 个动作 × 若干次 |

**我的建议**：骨骼 5 只走 B；逐帧 6 只先拿 1 只（凤凰龟，火焰最难）用 C 试做，做出来跟画师原帧并排比，不过关再走 A。

### 4.4 其余 17 只

- 忍者 / 变脸 / 幽灵：已有成套动作，**形象不动**（用户点名认可），只按 §4.5 的风格规范统一描边 / 调色板 / 画布尺寸，必要时补 cast。
- 14 只从头做：以游戏里现有形象为底（站立龟的设计保留），PixelLab 角色流水（变脸龟那套：定稿 → 各动作），**风格参考锁外包 11 只**（描边粗细、饱和度、Q 版比例）。
- 额度估算：一只全套约 300 次（变脸龟实测量级）× 14 ≈ 4200 次，加逐帧 6 只补帧约 1500 次 ⇒ 约 5700 次，按每期 2000 次要约 3 期（到 1 月），或升级档位（要花钱，§5 U4）。

### 4.5 风格规范（新增 `docs/design/龟美术规范.md`，写进权威前先给用户过目）

画布 256×256、地面线固定、描边 1px 深色、单只 ≤ 48 色、光从左上、Q 版头身比、朝左为默认朝向（与全项目约定一致）、零半透（`pixel_art_audit`）。外包 11 只即样板。

### 4.6 接进游戏（代码）

- 动作表从主文件挪到数据：`scripts/gamedata/turtle_actions.gd`（每只龟 → 六个动作的 [路径, 帧率, 出手帧]）；主文件那几张表改成读它（主文件只减不增）。
- `_play_action` 加 `cast`、`run` 两种；`_cast_skill` 放技能时播 `cast`，伤害仍按代码节拍（动画帧率反推到节拍）。
- 帧对齐：每个动作第 0 帧与待机第 0 帧的地面线 / 身体中心一致（照 `verify_minion_idle_align` 的做法）。

### 4.7 分期

| 期 | 内容 | 交付 |
|---|---|---|
| P0 | 求值器 + 渲染器 + 逐帧提取；标定 11 只待机 | 11 只待机序列帧（与画师原图逐像素对比报告） |

## 5. 已知风险与未决点

- **[未决·U1] 外包 11 只补动作由谁做**：原画师补（花钱，风格最稳）/ 我来做（骨骼 5 只 K 帧 + 逐帧 6 只 PixelLab 补帧）。我的建议见 §4.3。
- **[未决·U2] 姿态统一**：28 只全部四脚龟，还是允许站立龟（变脸 / 忍者 / 幽灵 + 其它适合站立的）与四脚龟并存、只统一画风？我的建议：并存，统一画风（描边 / 调色板 / 画布 / 比例），因为用户点名认可站立龟的设计。
- **[未决·U3] 版权**：画师交付的 `.spine` 源文件与导出物，委托合同里是否允许我们改动和再创作（补动作、重新渲染）？我的方案不装、不分发 Spine 运行库（自写求值器离线渲帧），不需要买 Spine 授权；但源文件的使用权要用户确认。
- **[未决·U4] PixelLab 额度**：全部做完约 5700 次，本期剩约 1050 次、每期 2000 次 ⇒ 按额度走要到约 1 月；要更快就升级档位（花钱）。
- **[未决·U5] 外包 11 只里小龟的形象**：游戏里小龟现在有一套动作（四个），外包版是另一种形象 —— 换成外包版（统一）还是保留现在的小龟？
- **[风险] 骨骼旋转会让像素画变形**（像素大小不一）：渲染后做像素对齐与调色板锁定；待机先与画师原图逐像素比，差异超阈值就不用骨骼旋转、改纯平移 / 换图。
- **[风险] 自写求值器与 Spine 官方不一致**：网格变形 / 带权网格 / 序列是最容易错的三处；用 11 只待机的画师原图当金标，P0 不过关不往下做。
- **[风险] 动画时长 ≠ 代码节拍**（07-22 精英小将四段踩过，动画先播完角色站着）：每个动作帧率由代码节拍反推，门禁对账。
- **[风险] 体积**：28 只 × 6 动作 × ~8 帧 × 256² —— 按现有 PNG 压缩比估约 30~60 MB；超了就降画布到 192 或按动作裁边。
- **[未验] 逐帧 6 只的序列帧序 / 时长**：只看了 atlas，没解析 JSON 里 sequence 的具体帧序；P0 第一件事。

## 6. 验收标准

- 每只龟六个动作齐（门禁 `verify_turtle_actions`：28 只 × 6 动作有表、帧尺寸 / 帧数 / 帧率在范围内、attack / cast 标了出手帧且帧率与代码节拍一致）。**证明会 FAIL**：删一只的 cast 登记 ⇒ 红；把 attack 帧率改成与节拍不符 ⇒ 红。
- 外包 11 只待机与画师原图逐像素对比（P0 标定）：差异像素占比 ≤ 阈值（阈值在第一只上标定后写死）。**证明会 FAIL**：求值器里故意把一根骨骼的旋转符号写反 ⇒ 红。
- 帧对齐：每个动作第 0 帧与待机第 0 帧的地面线 / 中心一致（同 `verify_minion_idle_align`）。
- `pixel_art_audit` / `asset_borrow_audit` / `verify_stream_coverage*` 全过（新序列帧录得进直播流）。
- 审核片：28 只 × 六个动作逐段录（`tools/review_reel.py`），我先自己看完挑完一整类毛病再交（memory `fb-self-approve-only-results-1105`）。

## 7. 决策记录

- 用户：11 只以外包待机形象为底补动作；17 只自己创作，站立龟形象（变脸龟等）认可；要完整方案书。
- 我：游戏里不装 Spine 运行库，一律离线渲成序列帧（直播录流与像素画规矩都只认序列帧）；骨骼 5 只用自写求值器；逐帧 6 只的补法与姿态统一、版权、额度、小龟形象五件待用户拍板（U1~U5）。
- 不进 0.22.8（本周发版范围已定）；拍板后从 P0 开始。
