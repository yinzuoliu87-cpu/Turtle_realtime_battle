# 游戏必须联网：断网不许匹配 / 不许打 / 不许本地排名

日期：2026-11-01　|　状态：**已完成**（11-02 清账：最后改动所在提交 517f49af 已随 v0.22.7 发版；CHANGELOG 0.22.7「联网」一节有记录）（客户端改完、新门禁 `verify_online_only` 54 条 + 9 处改坏验证全过；没提交、没发版，随 0.22.7；§5 的 U1 / U2 / U7 待用户定）

## 1. 需求原文

用户 2026-11-01 逐字：

> 「我们不应该有什么这种本地排名，我们这个游戏就一定要是要联网的，就是不可能说断网还可以匹配，断网可以打，这是肯定不行的，不能有什么这种本地。」

主会话定的口径（**主会话的话，不是用户原话**；用户授权「有依据的建议直接做」）：

- 正式包断网 / 连不上服务器时：匹配、任何对战（积分赛 / 闯关 / 好友切磋 / 教程）、排行榜、名次 / 战绩展示、商店购买等一律不给本地替代，改成明确的「需要联网」提示 + 重试（文案不口语化；卡片 / 弹框按钮用 `UISkin.card_button`）。
- 不许有任何「本地排名 / 本地排行 / 本地战绩当名次」。
- 门禁 / 开发机的 `TURTLE_SUPABASE=" "`、调试场 `DEBUG_EDIT`、VFXLAB、SIM 号等开发工具可以留，但正式包必须走不到（用已有的 release 判据），并用门禁守住。
- 教程也要联网。

## 3. 需求 ↔ 代码的出入

1. **「本地排名」只有一处，而且是 2026-10-06 有意加的回落**（LeaderboardScene 头注 `:253-260`：问不到就退回本机，并标「本地记录」）。当时的理由是「不许把过期数据当实时榜」，所以挂了角标；用户现在的要求是**连这一路都不要**。⇒ 正式包删掉这条回落。
2. **「断网可以匹配、可以打」不是 bug，是 2026-08 的设计纲领**（`remote_pool.gd:8-13`「离线完全可玩」，理由是当时测试者在国内靠 Sideloadly 装包、常连不上）。与用户现在的要求正相反。⇒ 正式包在进对局之前加一道联网判据。
3. **「战绩展示一律不给本地替代」（主会话口径）与代码对不上**：战绩页 / 主菜单显示的是玩家自己的存档（随云存档同步），服务器上没有另一份「真」战绩可以替代它 —— 它不是「本地替代」。改动面里不拦，列为 U1。
4. **联网 ≠ 对局在服务器算**。改完之后积分赛仍是「本机从缓存池挑对手 + 本机算 + 事后上传」，只是开局时必须连得上。用户 10-19 要的「对局放服务器」（memory `project-server-authoritative-matches`）只在周六 / 周日落了地，积分赛那一步是另一件事（U7）。
5. 教程对手是本地木桩：口径定「教程要联网」⇒ 拦的是**进教程那一下**，木桩本身不动（教程是隔离沙盒，`verify_tutorial_flow_v3`「整条教程对服务器的写请求 = 0」）。

## 4. 方案（已实施）

### 4.1 判据：`scripts/net/online_gate.gd`（新，`class_name OnlineGate`）

- `required()`：正式包恒真。`release_override`（门禁缝，默认 false）或 `not (OS.is_debug_build() or SB.offline_dev())`。与 `phase2_config.time_travel_allowed()` 同一个口径：**不认** `SB.enabled()` / `SHIP` / `DEVTOOLS` / 环境变量 —— 否则正式桌面包设 `TURTLE_SUPABASE=" "` 就能开出离线局；冒烟门禁 `SHIP=1` 在后端关着时要整局打通，那是调试构建。
- `dev_offline_ok()` = `not required()`：开发缝（本机排行榜那一路）只许从这里放行。
- `ready_now()`：网络层此刻 `ok`（后端配了 / 服务状态 OK / 令牌新鲜 / 不要求更新 / 登录没失效）**并且**是这一道自己在 `FRESH_MS = 20 秒`内亲眼看到的。主菜单开机时问到过一次 OK 不算数：开着十分钟后断网，状态还停在旧的 OK 上，只看它等于没拦。
- `check(host, what, resume, on_back)`：开发缝 / 刚看到过 OK ⇒ 同步返回 true（调用方照常走，一帧不等）；否则在 host 上开 `OnlineWall`（先去问），返回 false，调用方就地 return；问到连得上 ⇒ 调 `resume`（调用方把「原来那一步」交进来，通常就是它自己）。

### 4.2 框：`scripts/ui/online_wall.gd`（新，`class_name OnlineWall`，CanvasLayer 110，低于版本墙 120）

- 打开先问一次（`fetch_status_async` + `ensure_signed_in_async`），这期间整屏吃点击（防连点开两局）；问得快（< 0.4 秒）框不露面，问到 OK ⇒ 自己关、调 `resume`。
- 问不到 / 9 秒超时：标题「无法连接服务器」，正文「%s需要连接服务器。请检查网络后重试。」（%s = 对战 / 排行榜 / 购买 / 新手教程 / 切磋），按钮「重试」「返回」（`UISkin.card_button`，皮照 `TutorialChoice` 那块九宫格面板）。
- 维护中：「服务器维护中」+ 服务端公告（没有公告时「服务器正在维护，请稍后再试。」）；要求更新：沿用 `VersionWall.TXT_TITLE / TXT_BODY`；登录失效：「登录已失效」「请在设置页用邮箱重新登录。」
- 不自动重试；不写存档；关框先改名再释放（同一帧里再开一框不会找到将死的这个）。

### 4.4 明确不改（各有理由）

`MatchmakingScene._ready` / `TeamSelectScene._on_start` / `backend.gd` 的挑对手（被 R 段钉住，且前面已有 SceneNav 那一道）；`ST_LOCAL`（U5）；`abandoned_match` 补打（U4）；回放本机播放、战绩页、主菜单自己的数字（U1）；好友页 / 赛况板 / 对阵图（本来就只提示）；`BracketMapScene` 决赛开打（对手从服务端取，本来就联网）；`sim_driver.gd`（另一路的文件，U6）；离线测试包（U8）；本机排行榜代码本身（U9）。服务端 SQL、sim 一行没动。

## 5. 已知风险与未决点

| # | 内容 | 状态 |
|---|---|---|
| U1 | **战绩页 / 主菜单自己的胜场余命断网照看**。它们是玩家自己的存档（云存档同步），没有名次，不是「本地替代」。建议不拦；用户要拦的话是战绩页入口一行。 | **未决**（我的建议：不拦） |
