# 受击钩子回血绕过死亡判定（天使龟不死）

状态：已完成

## 1. 需求原文

用户 2026-10-08：「天使龟有不死bug」；追问后：「血条空了还在动/攻击」「敌方的天使龟」「就是刚刚看到的」（v0.19.561 Windows 包）。

## 2. 调查

- 合成场景（我方 / 敌方天使 × 祝福 / 平等 / 飞升，另加手半剑）9 轮都正常死亡 —— 复现不出。
- 从本机 `user://replays/` 找到用户那一局（`lane_assign` 里含 angel 的 16:45 那份），无头重放逐步盯敌方天使龟：
  第 27 秒到第 60 秒 hp 反复停在 0.06～0.10，被打几十次不死。装备：051 激光手枪 / 082 护心甲 / 054 瞄准镜。
- 在 `battle_damage._apply_damage_from` 临时插 env 门控打印（查完逐字节还原）：一击 96 伤害把 hp 从 1.06 打到 0，下一击时 hp 是 0.08。
- 根因：扣血之后、`if u["hp"] <= 0.0: _kill` 之前要跑受击钩子；护心甲反伤以【被打的这只】为来源结算，
  它的生命偷取当场回 0.04 血 ⇒ 判死条件不成立。DoT 路径 `_apply_damage` 同构（血线钩子在判死之前）。

## 3. 需求 ↔ 代码的出入

- 不是天使龟的问题：任何「受击即以自己为来源打回去（反伤）+ 生命偷取」的单位都会这样，我方同样。
- 天使「祝福」复活只触发一次 —— 这部分逻辑本身是对的。

## 4. 方案

- `battle_damage.gd` 两条路：正规免死（无头亡灵锁血 / 训练靶回满）处理完之后立刻记 `_lethal`，最后判死以它为准，并把 hp 置 0 再 `_kill`。
- `RealtimeBattle3DScene._kill` 开头记死亡处理计数 `_kill_n`：结算中途内层已经处理过一次死亡（复活 / 涅槃 / 驯服重生），外层不许拿过期的 `_lethal` 补刀。
  （第一版没有这一条，重放里表现为「复活后当场又死」—— 攻击方命中处决在钩子里先触发了复活。）

## 5. 已知风险与未决点

- 【已堵】双重判死：`_kill_n` 计数。
- 【未验】其它「受击钩子里回血」的组合（荆棘类反伤 + 吸血装备）在真局里的表现只靠同一判据推断，未逐件实测。
- 【有意】血线钩子（深海项链 50% / 三块糕等）在致命一击里仍会触发，但救不了命 —— 与「致命伤就是致命伤」一致。

## 6. 验收

- [x] 反伤 + 生命偷取，1 血挨一刀必死；带复活时只复活一次、活着约 25%；DoT 路径同样必死 —— `tests/verify_lethal_hook_heal.gd`
- [x] 反向验证：判死改回只看 hp ⇒ A 红（复现原 bug：挨 200 后活着 24.6 血）；去掉 `_kill_n` 条件 ⇒ B 红（`_kill_n=2` 被补刀）—— `tests/verify_lethal_hook_heal.gd`
- [x] 全量门禁 `run-tests.sh` 501/501；随 v0.19.562 发

## 7. 决策记录

- 用户报 bug 后要求出 IPA 与 Windows 包（v0.19.562）。
- 修法由我定：致命伤不被钩子回血救活（没有引入任何新的免死规则）。

## 实施回填

- 改动：`scripts/scenes/battle/battle_damage.gd`（两条路 `_lethal` + `_kill_n0`）、`scripts/scenes/RealtimeBattle3DScene.gd`（`_kill` 开头 `_kill_n`）、新门禁 `tests/verify_lethal_hook_heal.gd`。
- 偏差：第一版漏了嵌套死亡，靠重放发现后补 `_kill_n`。
- 新坑：探针用 `godot-quiet.sh` 直跑时 user:// 不隔离（指向真实存档目录），探针必须 test_mode 且只读；GDScript lambda 按值捕获局部变量。
