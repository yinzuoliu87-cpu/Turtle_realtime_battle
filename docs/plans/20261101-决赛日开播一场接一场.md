## 1. 需求原文

用户 2026-10-31（周六）逐字：「有任何商业游戏会同时播两个半决赛吗」；同日（主会话转）「能今天做完就今天」；随后（主会话转）纠正：
「桶内的话…十六场同时开打，然后到第二轮八场同时开打，第三轮四场同时开打…最多就是五轮」「桶内就是这样子同时跑，但是决赛里面就一定是一场场跑」。

由此定下的规则（主会话转述的任务单，逐条钉住；不是用户原话）：

1. ~~同一组同一轮按 match_no 一场接一场~~（被用户纠正）⇒ **小组赛各桶：同一轮所有有录像的场次同时开播**（都 = 翻面时刻），本轮档期结束 = 翻面 + 最长那场 + 一个场间间隔；**冠军杯赛：按 match_no 一场接一场**（第 k 场 = 翻面 + 前面各场的（时长 + 开场与幕布 + 场间 20~30 秒））。
2. 一轮全部播完（小组赛 = 最长那场揭晓 + 间隔），才开下一轮的 3 分钟备战（下一轮对手在备战开始时揭晓 ⇒ 不再剧透；对阵图「我的对手提前写出」那条例外随之去掉）。
3. 不同组之间照常并行（相当于不同场馆）。
4. 冠军杯赛 20:00 照旧等所有组收盘，按新节奏推演 4 人组、8 人组、组数 1~16 来不来得及。
5. 客户端每场三态：即将开播 · X 后 / 开播中 / 已揭晓；对阵图顶上那一句：小组赛「本轮 2 场开播中 · 下一轮备战 X 后开始」、冠军杯赛「第 1 场开播中 · 第 2 场 X 后开播」；主按钮只指向正在播的场次。
6. 0.22.6 / 0.22.7 老客户端收到新字段能忽略不崩；新客户端连没上新迁移的服务端退回老规则。
7. （追加）「购物结束后还要空等约 5 分钟才开播 —— 商业做法是备战一结束很快开播」：本轮翻面 = 本轮所有真实场次都出了裁判结果 且 已过备战结束 + 一个短缓冲（≤ 90 秒，按内测服数据定），超时兜底与 3 倍上限照旧；客户端在这段显示「结算中 · 即将开播」。核 `FINALS_LOWER_GRACE_SEC`（下半区 300 秒宽限）在裁判开启时还要不要。写清老客户端 0.22.6 在这种翻面时刻下的表现。
8. （追加，块 V / P21）服务端快照校验：入座（finals_seat / 冠军杯成表）与 finals_update_snapshot 都用 referee_lineup_ok 验；坏快照场次回退到上一份好快照照打（入座时那份 / 闯关赛最后一份），不再「a_bad_snapshot → 整组干等 24 分钟再判上半区晋级」。

调研补充（仪式与奖励，`docs/plans/ref/20261031-周日赛事参考/学到的.md` C 段，主会话 10-31 转来）：每场开播结束客户端放结束仪式 —— 看别人 ~4 秒、自己赢 ~7 秒、自己输 ~6 秒、组冠军 ~10 秒、冠军杯冠军 ~14 秒；开播前还有约 6 秒开场 VS。场间间隔要把这些算进去（建议 ≥ 20 秒），组内决赛 / 冠军杯决赛之后留够夺冠仪式。

## 2. 调查结论

- **服务端每轮固定 480 秒、整轮一次翻面**：`server/supabase/migrations/20261021_beta_server_clock.sql:494-587`（`finals_advance`）。到 `round_at + finals_round_sec()`（480，`schema.sql:441`）且结果齐了 ⇒ 同一条 update 写 `round + 1, round_at = 翻面, revealed_at = 翻面`（`:577-583`）——**下一轮 3 分钟备战与这一轮开播从同一刻起算**；480 里含「4 分钟重放」（`schema.sql:436`），备战结束后要再等 5 分钟才翻面。
- **客户端开播窗口整轮共用一个翻面时刻**：`scripts/systems/replay/live_spectate.gd:424-470`（改前行号）`premiere_round / flip_ts_of / premiere_end / premiere_hidden / premiere_session`。
- **剧透的例外**：`scripts/scenes/BracketMapScene.gd:1412-1418`（改前行号；现 `competitor()` 内）——「这一场有我」照写对手，理由是「本轮备战与上一轮开播同时进行」。
- **服务端各处按 `round_at + finals_shop_sec()` 判购物窗**：`finals_update_snapshot`（`20261021:374`）、`finals_opponent`（`:405`）、`referee_enqueue_finals`（`:453`）、`finals_report`（`:622`）；客户端 `phase2_config.gd:236-241` `finals_shop_open` 在 `srv_now < round_at` 时回 false ⇒ `round_at` 设到将来，购物窗 / 对手快照 / 建任务都自然「还没开始」。
- **结果在翻面时对客户端可见**（`20261021:283`、`:289`、`:320-325`、`20261020_referee_live_list.sql:199`）：开播期间不剧透一直靠客户端按窗口藏。
- **一场多长 / 裁判多快**：正式服近 14 天 222 场 `steps/60` 中位 103 秒、九成 ≤139、最长 171；开播画面另有约 25 秒开场与幕布。内测服 10-31 彩排 23 场周日裁判局：领取→写回中位 27 秒、九成 43 秒；建任务→领取中位 60 秒（两台工位排队）。建任务在购物窗关后的第一个整分（`finals_advance` 每分钟一次）。
- **下半区 300 秒宽限只管「本机代打」那条老路**：`phase2_config.gd:224-233` `finals_fight_open`；对阵图 `should_fetch_opponent` 在裁判开时第一句就回 false（`BracketMapScene.gd` `if _RN.finals_on(): return false`），`settle_wait_tip` 裁判开时也不走它；服务端 `finals_report` 裁判开时直接回 `referee`（`20261021:599-601`）。翻面闸从来不读它 ⇒ 裁判开启时它是一条走不到的路，**不需要，也不用改**（裁判关时的老路照旧要它）。
- **坏快照（P21）**：裁判 `scripts/referee/referee_job.gd:44-65` `validate` 拒算 ⇒ `a_bad_snapshot / b_bad_snapshot` 是永久失败（`:42`），`referee_fail` 直接置 failed（`20261019_referee_jobs.sql:430-444`）；`finals_advance` 只认结果行，等满 3 倍本轮时长（1440 秒 = 24 分钟）才走「缺哪场补 side 0」⇒ 交坏阵容的上半区反而晋级。服务端收快照只看「统领 ≥ 3 只」（`20261021:366-369`）、`finals_seat` / `finals_cup_seat` 入座不验、`finals_enter`（`20261019_referee_jobs.sql`）不验。判据现成：`referee_lineup_ok`（`20261020c_gauntlet_server_pick_and_coins.sql:64-92`，与裁判同一组条件）。
- **老客户端解析只取具名键**：`v0.22.6:scripts/net/supabase.gd:2232` `_bucket_from` ⇒ 多一个 `seq` 键被丢掉；`v0.22.6` 的 `round_tip`（`BracketMapScene.gd:2511-2514`）倒计时归零时写「下一轮 0 秒后开播」，没有「即将开播…」那一支。
- **`supabase.gd` 2994 / 3000 行**：解析只能放别处；`_bucket_from` 只改一行把 `seq` 原样带进组字典。

## 3. 需求 ↔ 代码的出入

| 需求里的说法 | 代码事实 | 处理 |
|---|---|---|
| 「同时开播」像是 bug | 是设计：480 秒里含「4 分钟重放」，翻面即开播且即开下一轮 | 小组赛仍同轮同时开播（用户纠正），冠军杯赛改一场接一场；两者都把下一轮备战推到本轮播完之后；480 只留给老规则 |
| 第 k 场开播 = 翻面 + 前面各场（时长 + 25 + 20~30） | 服务端翻面时知道每场 `steps`，**不知道**客户端的开场 VS / 结束仪式 | 每场 = ceil(步数/60) + 30（25 幕布 + 6 VS 取整）；场间 25 |
| 去掉「我的对手提前写出」那条例外 | 老规则下备战仍与开播重叠，那时例外还必要 | 只在组里带 `seq` 时去掉 |
| 冠军杯赛 20:00 等所有组收盘 | 组「收盘」（翻面）时组内决赛才刚开播，杯赛名单就是剧透 | 「收盘但档期没播完」也算没打完 |
| 备战结束很快开播（缓冲 ≤ 90 秒） | 建任务本身就要等到下一个整分、裁判两台排队；「结果齐」才是真正的闸 | 翻面闸 = 备战结束 + 60 秒 且 结果齐；60 秒是下限，实际多由裁判决定 |
| 坏快照回退到「上一份好快照」 | 服务端只存一份参赛者快照（被更新就覆盖）；入座时那份在 `finals_pending`，闯关赛的在 `gauntlet_ghosts` | 回退顺序：现在这份 → 入座时那份 → 本周闯关赛最新一份；都不行 ⇒ 当场判负 |

### 4.4 交给对阵图重做（20261031c 块 B）的显示点

1. 小组赛同一轮几场同时开播：几格同时标「开播」、都能点；主按钮（`_hero_cta`）在我那一场开播时指向我那一场，否则指向第一场开播中的 —— 多场同时播时要不要换成「观赛 · N 场开播中」再弹选择，由 B 定。
2. `ST_UPCOMING`（「即将开播」）只会出现在冠军杯赛（一场接一场）里 —— 格子现在画成中性，要一枚「即将开播 · X 分后」小签（`_PS.start_of(cur(), r, m) - srv_now()`），可带「第 k 场」。
3. 顶上那一句（`_sync_tip` → `_LS.premiere_round_line`）：小组赛「本轮 2 场开播中 · 下一轮备战 X 后开始」→ 短的那场揭晓后「本轮 1 场开播中 · …」→「下一轮备战 X 后开始」；冠军杯赛「第 1 场开播中 · 第 2 场 X 后开播」/「第 2 场 X 后开播」/「第 2 场开播中 · 下一轮备战 X 后开始」；收盘那一轮「决赛开播中」；备战结束到翻面「结算中 · 即将开播」。不带轮名，要「半决赛」就在调用处拼。
4. `hero_status_line`：冠军杯赛我的那一场「即将开播」时应说「你的X X 分后开播」；观众那句「N 场正在开播」在小组赛里是真的 N（可以照用）。
5. 冠军杯赛场间没有开播中的场次时主按钮消失，可换成不可点的「第 2 场 X 后开播」。
6. 开播段「备战那一行」隐藏，版面要不要收。
7. 「即将开播」的格子（杯）点不开，要不要弹一张只写「X 后开播」的卡。
8. 冠军杯赛自己那一场排在后面时 `start_referee_watch` 仍说「本场结算中 · 结果于开播时公布」，应改「你的比赛 X 后开播」。
9. 看别的组时顶上那一句仍按我那一组（P9）。
10. 判负（坏快照）那一场翻面即揭晓、没有录像 —— 卡片上可写「对手阵容无效 · 判负」（按「有结果、无档期、不是轮空」认）。
