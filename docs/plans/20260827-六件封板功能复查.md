## 调查（实测，每条带行号/数字）

### ④ 冲击波伤害类型 —— **已用探针坐实，是真 bug**

这条用户描述得最具体，所以先查。**结论：现象属实，而且根因和表面描述不一样。**

**文案怎么说**（`data/pets.json` → `shell.passive`，brief 与 desc **两处都写**）：

> 触碰到的敌人受到储能 {C:ShellSystem.RELEASE_DMG_PCT%}% 的**物理伤害**

**代码实际怎么做**（`shell_system.gd:505-508`）：

```gdscript
"dtype": battle._last_dmg_type,     # 捕获创建那一刻的全局伤害类型
```

命中时 `set_dtype(sw["dtype"], e)` 还原它。**而 `_last_dmg_type` 是个全局** ——
它是"场上最后一次伤害是什么类型"，不是"这一发是什么类型"。

**探针实测**（`tests/_probe_shell_dtype.gd`）：

| 创建冲击波之前，场上最后一发是 | 冲击波捕获到 |
|---|---|
| `phys` | `phys` ← 与文案一致 |
| `magic` | **`magic`** ← ★不是物理 |

⇒ **前一发伤害恰好是魔法时，冲击波就飘蓝字** = 用户报的现象。

★**2026-08-22 那次"修复"修错了方向。** 那行注释写着「飞行期间全局会被别的伤害覆写 ⇒
命中时飘字捡别人的颜色。捕获创建那一刻的类型」—— 它解决的是**飞行途中被覆写**，
但**起点本身就是捡来的**。同一个病只挪了位置。

### ④-b 顺带挖出更要紧的一层：这一发**不吃护甲也不吃魔抗**

`_resolve_dmg(u, base, tgt, **magic**)`（`RealtimeBattle3DScene.gd:4358`）才是算护甲/魔抗的地方，
靠那个 `magic` 布尔参数分流。而冲击波 **根本不调它** ——
`dmg = 储能 × RELEASE_DMG_PCT` 直接进 `_apply_damage_from`，
后者拿到的是**已减伤的数**，只用 `_take_dtype` 取类型给**飘字上色**。

探针实测（同一发 500 打两个只差护甲的靶子）：

| 靶子护甲/魔抗 | 实扣血 |
|---|---|
| 0 | 600 |
| 500 | **610** |

⇒ 500 点护甲**几乎没减伤**（正常物理该砍掉一大截）。**文案说「物理伤害」，
玩家会预期它吃护甲，实际上不吃。** 这比飘字颜色严重 —— 那是玩法。

⚠ 那个 **600 → 610「护甲越高扣得越多」的反常我没隔离出来**，列进未决点。
（500 基础打出 600 应该是 `_BASIC_RARITY_BONUS` 的 ×1.2，但 +10 的差额没定位。）

### ④-c 根因归一：**"物理伤害"和"吃护甲"在本仓库是两件事**（2026-08-29 查清）

这一节把 ④ 和 ⑤ 合到一起说，因为**它们是同一个病**，而且这个病比这两件更广。

#### 伤害管线上，护甲到底在哪一步算

| 函数 | 位置 | 它算什么 | 它**不**算什么 |
|---|---|---|---|
| `_resolve_dmg(u, base, tgt, magic)` | `RealtimeBattle3DScene.gd:4358` | **护甲 / 魔抗**（`DamageMath.effective_resist` → `resist_multiplier`）、暴击、攻击者增伤、受害者减伤%、虚化、水晶共鸣 | — |
| `_mitigate_incoming(u, dmg, raw)` | `RealtimeBattle3DScene.gd:4618` | 减伤%、flat 减伤、靶向器加成、暴露蛋、钻石、岩层、嘲讽期（`0.5×护甲`，**只在嘲讽时**） | **没有护甲公式** |
| `_apply_damage_from(...)` | `battle_damage.gd:225` | 小龟不屈、`dmg_out_mult`、决胜增伤、猎物、真伤暴击、墨迹、护盾、扣血 | **不调 `_resolve_dmg`** |

⇒ **`raw=false` 只保证"吃减伤"，不保证"吃护甲"。**
一发伤害只要没经过 `_resolve_dmg`，它就是**无视护甲与魔抗**的定额伤害 ——
哪怕它的飘字是红的、哪怕文案写着"物理伤害"。

**这解释了用户那句「物理伤害为啥不吃护甲啊」：不是某一件坏了，是"物理"这个词
在文案里指颜色、在代码里指走哪条路，两边根本没对齐。**

#### ④ 冲击波（龟壳被动）—— 两个病叠在一起

`shell_system.gd:459 / 500-545 / 584`

1. **类型是捡来的**：`"dtype": battle._last_dmg_type` 捕获的是"场上最后一次伤害的类型"，
   不是"这一发的类型"。前一发恰好是魔法 ⇒ 冲击波飘蓝字。
   （2026-08-22 那次"修复"只解决了**飞行途中被覆写**，起点本身还是捡的。）
2. **不吃护甲**：`dmg = 储能 × RELEASE_DMG_PCT` 直接进 `_apply_damage_from`，
   **从头到尾没调 `_resolve_dmg`**。

**改法（用户 2026-08-27 拍板「肯定是要真物理」）**：命中时走
`_resolve_dmg(u, base, e, false)`。**一次同时解决三件事**：
- 真物理（吃护甲）✅ 用户要的
- 飘字颜色**由构造保证**正确（`_resolve_dmg` 自己就写 `_last_dmg_type = "physical"` 且记归属）
- `"dtype"` 捕获那段 hack 可以整段删掉 —— 不再需要"捕获再还原"

⚠ **副作用要如实说**：`_resolve_dmg` 会**掷暴击**（冲击波目前没有暴击），
也会吃攻击者增伤 / 受害者减伤 / 虚化 / 水晶共鸣。
不这么做的替代是"只手抄护甲那一段"，但那正是 memory `fb-hand-rolled-copies-drift`
说的"抄一次永远落后一次"。**选走标准函数，把副作用写在这里。**

⚠ **这是一次实打实的削弱**：500 点护甲以前几乎不减伤，改完会按标准公式砍。
用户问的就是"为啥不吃护甲"，所以方向是对的；但**数值是否要补回来是另一轮的事**，
这一轮先把口径修对（改一件事，出问题才分得清是谁引入的）。

#### ④-d 那个 600 → 610「护甲越高扣得越多」

方案书原文记着我**没隔离出来**。这次查：

- ×1.2 = 小龟·不屈 `_BASIC_RARITY_BONUS`（`battle_damage.gd:231`），
  按**目标稀有度**给 0.20/0.23/0.26/0.29/0.32/0.34（`basic_consts.gd:19-24`）
- **610/500 = 1.22，而稀有度表里没有 0.22** ⇒ 单靠稀有度解释不了那 +10

⇒ 已建探针 `tests/_probe_shockwave_dmg.gd`：三个靶子**除 `def` 外逐字段相同**
（连 `rarity` 都写死 "C"，并打印"除 def 外仍不同的字段"当分母），
施放者 `crit=0 / damage_amp=0 / dmg_out_mult=1` 把随机项全部关掉。
**改之前先跑一次留基线，改之后再跑一次** —— 这样 610 是什么、改完变成什么，都是量出来的。

#### ⑤ 靶向器 p2eq_055 —— **同一个病，而且文件头注写反了**

用户 2026-08-27:「那还有靶向器，什么伤害类型，怎么跳数字的，伤害怎么过护甲减伤？」

★`:241` 那条注释还记着一个**已修**的坑，留档：位置参数顺序是
`extra_ls, raw, from_equip, pre_crit, no_dodge, no_popup` —— 少写一个 `false`
会让 `no_popup` 落到 `no_dodge` 上，通用红字根本没关，和自发飘字**双份**。

这类"按目标血量算"的伤害在业界通常**有意不吃护甲**（否则高护甲坦克双重免疫）。
⇒ **这一条我不擅自改**，列进未决点让用户拍：是要"真物理吃护甲"，还是"保持定额、
把文案里的『物理』改成不会误导的说法"。④ 用户已明确拍过板，⑤ 没有。

### ①-F 那条白名单规则**本身是错的**（用户 2026-08-27 明确指出）

记录在案的理由（`RealtimeBattle3DScene.gd:5450` + 权威文档 + 两份 archive）：

> 可复制的技 = **纯敌方向伤害技**（排除变身/召唤/自增益，否则从龟壳放会污染自身状态）

**规则错在三处：**

1. **把"实现麻烦"当成了"玩法规则"。** 真正的顾虑是「从龟壳放会污染自身状态」——
   那是技术顾虑。用技术顾虑去阉割玩法，方向反了。
2. **把技能当成不可分的整体。** 双头融合 = 变身 + 打波；虚化 = 自增益 + 伤害。
   复制偷的是"主动技能"，**完全可以只取能移植的那部分**。
3. **「排除自增益」站不住。** 龟壳偷个盾自己吃了是**一种正当结果**，不是 bug。

### ①-G 海盗船 —— **它其实是两个技能挤在一格里**（用户 2026-08-27 指出并拍板）

`_sk_pirate_ship` 的真实结构（`pirate_system.gd:209`）：

```gdscript
if not u.get("ship_summoned", false):
    ...召唤实体船 + 冲锋撞击      # 第一态
else:
    _pirate_shotgun(u, tgt)      # 第二态
```

| 态 | 效果（实测常量） |
|---|---|
| **一 · 海盗船冲锋** | 召出实体船：HP = 海盗龟 ×`SHIP_HP_SCALE 1.5`、ATK ×`SHIP_ATK_SCALE 1.0`、无双抗、近战 `SHIP_RANGE 110`、每发 `SHIP_SHOT_COEF 0.4`A 物理；登场冲锋 `SHIP_CHARGE_RADIUS 200` 码内第一敌 `SHIP_CHARGE_COEF 1.0`A 魔法 + 击飞 `SHIP_CHARGE_STUN 2.0` 秒；**船留在场上** |
| **二 · 霰弹** | 60° 扇面 `SHOT_PELLETS 8` 颗，每颗 `VOLLEY_ATK_COEF 0.5`A 物理 + 40 码击退，射程 400 |

**问题**：两态差别极大（一个是召唤+控制，一个是自己喷弹），而**玩家完全看不出自己在哪一态** ——
图标不变、名字不变、面板不变。

★**全仓只有这一个技能是这样的**（`if not u.get("..._summoned")` 只此一处）⇒
拆开不是开先例，是给**一个已经存在但没被承认的事实**正名。

**★用户拍板的设计**：拆成**两个独立技能**，各有 name / icon / detail；
槽位按当前态显示对应图标；**各 120 龟能**（`skill_energy.gd:23` 现在是
`"pirateShipPassive": 120.0` 单条共用，拆后两条各 120 ⇒ **数值等价，不改节奏**）。

**拆开之后复制那条规则自然成立**：

```
龟壳扫敌方 → 看海盗龟【当前挂的是哪一态】
    ├─ 还没召船 → 抄「海盗船·冲锋」
    └─ 已召过   → 抄「霰弹」
```

⇒ **不需要"裁掉召唤部分"这种特殊处理** —— 海盗龟自己就在两态间切换，复制只要**照抄当前态**。
这比"复制期挂标志跳过召唤"干净得多。

## 方案

### ④ 冲击波伤害类型（唯一一条已经清楚该怎么做的）

**改法一（必做）**：把"捕获全局"换成**显式声明物理**。

```gdscript
"dtype": "phys",     # ← 文案写的就是物理, 直接写死, 不捡场上的
```

★**判据必须是"打完之后飘字是物理色"，而不是"dtype 字段等于 phys"** ——
后者是数我自己插的值。要走真入口 `_shell_spawn_shockwave` → tick → 命中。

**改法二（要你定，见未决点）**：让它**真的吃护甲**（走 `_resolve_dmg(..., magic=false)`），
使文案的「物理伤害」名副其实。这是**数值改动**，会削弱龟壳 —— 所以不能我自己拍。

### ① 复制 —— **已有完整方案（用户 2026-08-27 逐条拍板）**

按依赖顺序分四步，**每步都能独立验、独立回滚**：

**第 0 步 · 做【通用多形态技能】机制**（①-G2，是后面几步的前提）

- 一个技能可以声明它有多个形态，以及"当前是哪个形态"的判据（由技能自己给，
  因为判据千奇百怪：海盗船看布尔、铁锤看计数器模 3）
- 提供一个统一查询：`当前形态(u, stype) -> {name, icon, detail}`
- **技能槽显示**与**龟壳复制**都只读这一个接口，不认识各技能的内部字段

**第 1 步 · 海盗船接上多形态**（①-G）

- `pets.json` 海盗龟 skillPool 里那一条拆成两条：`pirateShipCharge`（冲锋召船）/
  `pirateShipShotgun`（霰弹），各自 name / icon / detail
- `skill_energy.gd` 两条**各 120**（现在是单条 `pirateShipPassive: 120.0`）⇒ **数值等价**
- 槽位**按 `ship_summoned` 显示当前那一条**（`info_panel.gd` 取图标处要加"动态图标"的口子，
  现在只认静态 `sk["icon"]`）
- ⚠ 兼容: 老存档 / 老 ghost 快照里存的是 `pirateShipPassive`，要能解析到新的两条之一

**第 1b 步 · 精英铁锤接上多形态**（①-G2）

- 两条：`eliteHammerNormal`（60° 锥形 500 码 4×ATK）/ `eliteHammerBig`（700 码全域 6×ATK）
- 判据 `u["_hammer_n"] % 3 == 2`（**下一发**是不是第 3 次）
- 动画帧已经是两套（`hammer` / `hammer_big`），不用新做
- 龟能仍是 100（与海盗船同口径：拆分不动数值）

**第 2 步 · 白名单改成"按当前态解析"，并修掉放错的条目**

- 13 个**普攻位技能**从白名单移出（它们走普攻分派，放这里永远不执行）
- **小将三技加进来**（`eliteHammer` / `minionBodysurf` / `minionRocket`）——
  按规则字面它们本来就该在
- 海盗船按第 1 步的两态解析
- **焊门禁**：白名单每一项必须能被 `_do_skill` 真正执行（防再次放错地方）

**第 3 步 · 重写那条规则**（①-F）

从「白名单：默认不能抄、逐个批准」倒过来：

```
默认全部可抄；只裁掉"会污染龟壳自身状态"的那一段效果，而不是丢掉整个技能。
```

实现上**不需要给 57 个技能各写一份复制版**，只要复制期挂一个标志
（如 `battle._copy_mode = true`），**只在真正会污染的那几处**（变身 / 换形态）判它跳过；
伤害 / DoT / 击退 / 范围 / 给自己加盾加 buff **全部原样执行**（它们在龟壳身上都成立）。

⚠ 动手前必须先数清"真正做变身/换形态的地方有几处" —— 个位数才走这条路，
散得到处都是就要重新想。**这一步是本方案里唯一没被量过的假设。**
