## 2. 调查结论

- 旧画法 `scripts/systems/trainer/trainer_system.gd` `_hook_chain`：每个 sim 步调 `battle._beam_vfx`（`scripts/scenes/RealtimeBattle3DScene.gd` `_beam_vfx`）在地上平铺一条拉长的 `hook-chain.png`（线性过滤、`axis = Y` 平躺、每条活 0.13 秒淡出）⇒ 同一根钩锁同时叠着 7 ~ 8 条在闪；贴图被拉糊；40° 镜头下读成两条深色虚线横穿场地（11-05 用户就以为是 bug）；没有甩出去的过程，也没有拽的手感。
- 调用点两处：飞行中（`_tick_hook_flights`，大师 ↔ 钩头）、拽的期间（`_tick_hooks`，大师 ↔ 被钩目标）。
- 参考（只找外部商业游戏）：锤石 Q / 诺提勒斯 Q 官网演示逐帧，`docs/studies/20261120d-训龟大师锁链参考-锤石诺提勒斯逐帧.md`。

## 3. 需求 ↔ 代码的出入

- 「锁链技能」不改机制：射程、命中判定、眩晕、一段段拽全不动（用户只说锁链「完全不行」，指的是画法）；`verify_hook` 等 6 条老门禁照绿为证。

## 4. 方案

1. 一根链 = 一张常驻四边形（`scripts/scenes/battle/trainer_chain_vfx.gd`），长边顺着链子、正面朝镜头，每个 sim 步改位置与着色器参数（`assets/shaders/trainer_chain.gdshader`）。全在 sim 步里建 / 改 / 删 ⇒ 直播镜像照收、时停照停。
2. 飞行 = 拖影带（四档硬边，靠钩头粗浓）+ 若隐若现的链节；钩中同一步收成直链 + 亮光从目标跑回大师；每拽一下再跑一道；拽完 / 空放 0.18 秒收回再删；换路随 `clear_flights` 清。
3. 链节贴图 `assets/sprites/vfx/trainer-chain-link.png`（脚本 `tools/assetgen/build_trainer_chain.py`，确定性），从目标那头平铺，拽短了链节不滑。
4. 删旧 `_hook_chain`。

## 5. 已知风险与未决点

- R1【已堵】画法不能改对局结果：只读单位位置、不写任何单位字段；`verify_hook` / `verify_hook_lane_clear` / `verify_trainer` / `verify_trainer_audit` / `verify_trainer_skills` / `verify_seq_hooks` 本机全绿，预检含规则指纹。
- R2【已堵】直播：四边形与着色器参数在 sim 步里改，录流跟踪表覆盖 Node3D 变换与 ShaderMaterial 参数；预检里的直播门禁把关。
- R3【我定】旧素材 `hook-chain.png` 不删（`vfx_discipline_debt.json` 还登记着它，别处没人用，孤儿审计不报）。
