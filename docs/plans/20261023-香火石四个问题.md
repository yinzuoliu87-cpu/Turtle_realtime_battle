# 香火石四个问题（充能零头 / 同龟多块 / 对手与服务器局的刻痕 / 局外看不到）

日期：2026-10-23　|　状态：实施中（客户端与内测服已完成；正式服迁移排在周一 10-26）

## 1. 需求原文

- 用户 2026-10-23「香火石有bug啊」→「你知道香火石是干啥的吗」→ 我讲完机制、指出「周末服务器对局里你这一方的刻痕和充能按 0 算」→ 用户「这是个问题，还有呢？」
- 我列出 5 条 → 用户「3，4要修」（1、2 是纯 bug，我说直接修；5 没说要改 ⇒ 维持）
- 用户「那如果上半战场叠了20%那到终极战场呢」→ 实测：会带过去（见 §2 第 5 条）

## 2. 调查（改之前的现状，代码实查 + 探针）

1. **充能零头丢失**：局内充能只在刻成一道痕时由 `_persist_chg` 写回 `GameState.incense_charge`；换路 / 撤场那个写回点 `clear_all()` 全仓零调用。探针 `tests/_probe_incense_bugs.gd`：局内充能 2300、存档 500 ⇒ 这一局若此刻结束，1800 丢掉。门禁 `verify_incense_stone_real` 那条「不满一道的余额也回写」是恒真式（每次正好打 4000，余额恒为 0 == 起点 0）。
2. **同一只龟带两块，强化双倍消耗**：`_eq_on_basic_attack` 对每件装备各调一次 `on_basic`，两块共用一份 `eq_state` ⇒ 一次攻击扣 2 次强化。探针：第 1 次攻击后剩 2、第 2 次后剩 0，攻速 2 次就撤（设计是 4 次）。
3. **对手与服务器局的刻痕按 0**：右方刻痕「每场从 0 起」（D3，当初理由是右方是即时生成的 bot）；快照上传（`backend.gd`）不带刻痕，而宝箱进度是带的；裁判机 `referee_job.gd` 把两侧的 `incense_marks / incense_charge` 都写死 0；结果单不带香火 ⇒ 周末服务器局里攒的充能 / 刻痕不进存档。
4. **局外看不到**：背包 / 羁绊面板 / 图鉴都不读 `incense_marks / incense_charge`，只有局内装备格有读数。
5. （用户问）上路攒的刻痕到终极战场：会带过去。探针 `tests/_probe_incense_lanes.gd`：上路 88 道 ⇒ 携带者 +26.4% / +13.2%、空手队友 +8.8% / +4.4%；真 `_dl_clear_units` 换路、新建单位后一模一样；携带者死在上路、终极战场无人带石头，队友照样 +8.8% / +4.4%。

## 3. 需求 ↔ 代码的出入

- D3「右方 = bot」已不成立：对手现在是真人快照（宝箱进度 2026-08-14 已改成按对手真实进度）。
- D4「刻成痕时 + 撤场时写回」：撤场那一半从来没接上。

## 4. 方案

1. 充能每次变化都写回 `GameState.incense_charge`（与宝箱龟财宝值、命运之轮一样当场写）。
2. `on_basic` / 命中兑现按「同一时刻只认一次」去重；附带伤害按身上星级最高的那块算（全表口径「多件同带取星级更高的那一件」）。
3. 照宝箱龟 2026-10-22 那条链路接一遍：
   - 快照上传带 `incense_marks` / `incense_charge`；ghost → 对局的转换透传；bot 默认 0。
   - 右方刻痕 / 充能从对手快照起算（本机打别人快照、裁判机两边都是）。
   - 裁判机 `referee_job` 按快照建两侧；`referee_runner` 结果单带 `incense`（A）/ `incense_b`（B）。
   - 新迁移 `20261023_referee_incense.sql`：`referee_job_status` / `referee_finals_coins` 多回 `incense`（以 20261022b 版为底）。**只写不执行**，排进周一正式服迁移（在 20261022b 之后）。
   - 客户端 `RefereeNet.parse_incense` + `RefereeWatch.apply_incense`（取较大的那份，防迟到回包倒退），与 `apply_chest` 同一处调用。
4. 背包里香火石的说明卡加一行当前「刻痕 N / 300 · 充能 N / 4000」。

## 5. 已知风险与未决点

1. ⚠ 对手带上刻痕后，打满刻痕的对手会明显变强（这是设计本意，但改变了现在的强度体感）。
2. ⚠ 服务器局的香火要等「周一迁移上正式服 + 裁判机装新版本」之后才生效；在那之前结果单没有 `incense`，客户端不动存档（与现在相同）。
3. ⚠ 旧快照池里没有刻痕字段 ⇒ 按 0（与现在相同），新上传的才带。
4. ❓ 5（300 上限在每周 16 场下基本到不了）用户没说要改，维持。
5. ⚠ 充能改成每次变化都写 GameState：教程沙盒 / 调试场 / 回放观看时的写入，与刻痕现在的写法一致（刻痕本来就当场写）；回放观看有存档备份还原。
