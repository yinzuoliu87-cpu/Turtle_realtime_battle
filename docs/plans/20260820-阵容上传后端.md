### 已经做好的那一半（这是好消息）

### 隐私: 快照里没有个人信息

`profile` 是 `{"name": "玩家阵容", "avatar": <第一只龟的id>, "id": <ghost_id>}`

| 用户以为 | 实际 | 影响 |

## 方案

### 架构: 本地池 = 缓存, 服务器 = 交换所（改动最小）

```
打完一局 → build_ghost_snapshot() ──┬─→ 本地 pool（现状, 不动）
                                    └─→ POST /ghost   （新增, 失败静默忽略）
进入匹配 → find_opponent(本地池) ←──── GET /ghosts?bracket=N （新增, 拉回来并入本地池）
```

**为什么这样**: 现在的游戏**完全不依赖网络**也能玩(有策划队+bot)。
把网络做成"锦上添花的同步"而不是"必须联通的依赖", 断网/被墙/服务器挂掉都不影响开局 ——
这对一个测试者在国内、要靠 Sideloadly 装包的项目是刚需。

### 服务端只需要两个接口

| 接口 | 作用 | 数据量 |
|---|---|---|
| `POST /ghost` | 收一份快照, 按 `bracket` 分桶存, 每桶封顶(照抄 `BUCKET_CAP := 50`) | 一份约 1~3 KB |
| `GET /ghosts?bracket=N&limit=20` | 随机返回该档若干份 | 几十 KB |

没有账号、没有登录、没有实时对战 —— **异步 PvP 只需要这两个**。

### 选型（用户让我选一个）

**我的推荐: 先用「腾讯云开发 CloudBase 云函数 + 云数据库」。**

| 候选 | 优点 | 致命问题 |
|---|---|---|
| **腾讯云开发 CloudBase** ✅推荐 | 国内节点、延迟低; **默认域名 `*.service.tcloudbase.com` 开通即用、免备案**(已核实); 免费额度够这个量级 | 需要**实名认证**; 想绑自己的域名才要 ICP 备案 |
| Supabase | 免服务端代码(自动 REST)、免费额度大、上手最快 | 海外节点, **国内访问不稳定**, 测试者可能连不上 |
| Firebase | 生态成熟 | **中国大陆被墙**, 直接出局 |
| 自己租 VPS | 完全可控 | 要备案(国内)或忍受延迟(海外) + 运维成本, 对单人项目不划算 |

**决策逻辑**: 你和测试者都在国内 ⇒ 海外后端会让一半人连不上, 而"连不上"在这个设计里
表现为"永远只能打策划队", **和没做一样**。所以国内节点优先。

### 落地步骤（每步都可独立验证）

1. 在 `scripts/net/` 新增 `remote_pool.gd`: 两个 `HTTPRequest` 封装 + 超时 + 失败静默
2. `upload_ghost()` 末尾追加一次 POST（**不改现有本地逻辑**, 失败不影响存档）
3. 进匹配前拉一次 GET, 结果并入本地池（`pool_add` 现成, 幂等）
4. 门禁: 新增 `verify_remote_pool_offline` —— **断网时必须一切照旧**
   （判据: 把 URL 指到不可达地址, 断言开局仍能找到对手且不卡顿）
5. 服务端: 一个云函数 + 一张表, 逻辑照抄 `pool_add`/`pool_find` 的分桶规则

## 已知风险与未决点

**风险 1 · 备案这条已核实, 但免费额度没核实。**
免备案已确认(官方文档: 默认域名 `*.service.tcloudbase.com` 开通即用, 只有自定义域名要 ICP 备案 ——
https://docs.cloudbase.net/run/develop/access/client )。
**仍未核实**: 免费额度具体多少、超额后是静默降级还是扣费。开通前必须先看计费页并设消费上限。

**风险 2 · 作弊。** 客户端直接 POST 任意快照 ⇒ 有人可以伪造一支"全 SSS 满级满装备"的队。
这个量级的项目**先不做防作弊**(没有排行奖励, 伤害有限), 但要在服务端加最基本的
字段校验(龟 id 在白名单、装备数 ≤ 上限、等级 ≤ 10), 免得一条脏数据让所有人开局崩。

**风险 3 · 池子污染没有回滚手段。** 现在 `_drop_stale_schema` 靠 `SCHEMA_VER` 整批丢弃
（backend.gd:206）。远端也必须存 `schema_ver`, 否则升 schema 时**只能清库**。

**风险 4 · 成本失控。** 免费额度用完会静默降级还是扣钱? 上线前设消费上限。

**未决点 1 · 用户要不要做实名认证**（国内后端的前置条件）。
**未决点 2 · 玩家阵容要不要带名字。** 现在是写死的"玩家阵容"。
  一旦允许玩家自填昵称, 隐私政策与内容审核(脏话/敏感词)都要跟上 —— **建议先不做**。
**未决点 3 · 上传时机。** 现在是"打完一局就传"(RealtimeBattle3DScene.gd:7794)。
  要不要改成"只传赢的局"或"每赛季只传一次最终阵容"? 影响池子质量与流量。

## 验收

- [ ] V1 断网启动游戏, 能正常开局并找到对手（**离线不退化**是硬指标）
- [ ] V2 A 手机打完一局 → B 手机在同一 bracket 能匹配到 A 的阵容（**这是需求原话**）
- [ ] V3 服务端拒绝伪造快照(龟 id 不在白名单 / 装备超上限 / 等级 > 10)
- [ ] V4 `schema_ver` 不匹配的远端快照被丢弃, 不进本地池
- [ ] V5 上传/下载失败时不弹错、不卡顿、不影响存档
