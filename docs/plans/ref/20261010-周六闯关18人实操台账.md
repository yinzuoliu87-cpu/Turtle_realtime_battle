## 一、问题（按严重程度排）

### G1 ★★★周六从服务器拉回的真人快照【一份都用不上】⇒ 闯关赛几乎全是机器人 —— ✅ 已修（本地）
- 现象：第一批 10 个号同一时刻都在 0-0 / 1-0…，**49 场 0 场真人**。p14 第一场日志 `[SupabaseNet] 拉回 9 份, 入池 9`，紧接着匹配到机器人（`opp_is_bot=true`）。
- 根因（代码事实）：`Backend.find_gauntlet_opponent` 先发 `pull_gauntlet_async(当前标签)`（异步），然后**当场**用本地池算对手 —— 照搬积分赛「拉取填下一局」的纪律。
  积分赛拉 N 与 N+1 场次，下一局用得上；闯关赛**打完这场标签就换了，永远不会回到这一格** ⇒ 拉回来的永远是用不上的那一格。全仓只有这一个调用点。
- 修：新增 `Backend.prefetch_gauntlet_pool()`，在**已知下一格**的两个时刻拉：主菜单（当前格：第一场 / 重开 App）、每场闯关赛结算后（新格）。匹配那一步仍不碰网络。
- **实测**：第二批（修复后）**25/25 场真人**（截至 13:50 UTC），每次提前拉回 10~40 份；第一批（修复前）0/49。

### G2 ★★观赛：观众自己切后台 / 断网 45 秒 ⇒ 永久「直播中断」；打的人切后台 50 秒 ⇒ 全部观众被永久踢出 —— ✅ 已修（本地）
- 根因（代码事实，`live_spectate.gd`）：中断按**观众本机墙钟**判「horizon 多久没涨」，时限 45 秒（与赛况板收卡同一个数）；`broken` 是终态，判了就不再轮询。
  观众切后台回来第一帧（轮询还没发出去）就满足条件；打的人回来接着打，观众也接不回去。屏上「直播中断」读起来像是打的人掉线。
- 修：终态只认**服务端回过话、证明 horizon 真没涨**的那段（`_last_ok_ms - _last_adv_ms`），时限 180 秒；10 秒没涨先在屏上提示「信号中断」，照常轮询，一涨就接着放。
- 门禁：`verify_live_spectate` ⑤b 两条（观众断 60 秒不判中断只提示 / 一涨就恢复）；变异回旧判据当场红（`broken=true status=直播中断`）。

### G3 ★★计分对局里按 ESC / R 就把这一局抹掉（负场不记、命不扣） —— ✅ 键盘已修（本地）；杀进程未修
- 代码事实：`RealtimeBattle3DScene._unhandled_input` 里 R = `reload_current_scene()`、ESC = 回主菜单，**不分场合**；胜负只在打完时 `_settle_season` 记，全仓没有「开打先记一负 / 下次启动补判」。
- 后果：PC / Mac 包（内测要发）积分赛劣势按 ESC 逃掉一条命，周六逃掉一负；与用户 2026-07-30「认输 = 整场负，不许直接回主菜单」相反。
- 修：计分对局没打完时 ESC = 弹认输确认（再按收起），R 不响应；非计分（没阵容 / 教程 / 回放 / 开发工具场）照旧。门禁新增 `verify_scored_match_keys`（发真按键事件），变异回旧行为 ⇒ 测试自己被换场景卸掉、不打 ALL PASS。
- ⚠ **手机杀进程 / 断电同样逃负，没修** —— 要不要「开打即记一负、打完再改正」是规则决定，待拍板。

### G4 ★★赛况板战绩榜会让机器人露馅 —— ✅ 已修（本地）
- 代码事实（`gauntlet_board.build`）：对手侧的人也进战绩榜，战绩取他快照上的标签。机器人每场用一个新号 ⇒ 榜上一堆「只出现过一次、战绩冻在赛前、整天『在打』、从不出现在流水录像方」的人；顶部「N 人」也被撑大（实测 46 人，真在打的远没那么多）。
- 修：**只以对手身份出现过的人不进榜**（自己传过一场才进），规则对真人机器人相同。门禁 `verify_weekend_replay` ①② / `verify_weekend_watch` ① 原来钉着旧行为（「机器人上榜、与真人同一种长相」），一并改为新口径；变异去掉过滤 ⇒ 两份 6 条红。

### G5 ★赛况板 / 周日对阵图：进页面头 30 秒「账号未连接，请检查网络」；对阵图头像整天出不来 —— ✅ 已修（本地）
