学句式不需要真数字；而 `cd` / `cost` 字段本身就是真值（`14/12/10/8/6`）。

## 2. 量出来的（每条都带计数，不是印象）

### ① 两层的分界线是「有没有数值」，不是「长短」
- `desc` 层含数值（%/点/秒）的只有 **51 / 865 = 5.9%**，且那 51 条给的是
  **层数 / 秒数 / 阈值**，不是伤害值。例：复仇焰魂被动「在4秒里持续造成伤害，最多可叠加3次」。
- 同一个技能两层对照（韦鲁斯 W）：
  - `desc`：「普通攻击会造成额外的伤害，并附加枯萎效果。其它技能会引爆枯萎效果，
    造成基于目标最大生命值的魔法伤害。」——**一个伤害数都没有**
  - `tooltip`：「施加一层持续〔debuffduration〕秒的⟨枯萎⟩(最多至〔maxstacks〕层)…
    引爆⟨枯萎⟩层数来造成每层⟨魔〔percenthpperstack〕最大生命值伤害⟩」

### ② 数值贴着伤害类型词，整体被类型标签包住
- 857 个类型标签实例：magicDamage **528** / physicalDamage **301** / trueDamage **28**。
- ⚠ **不是零例外**（我第一次说"零例外"是印象）：标签内没带类型词的 **74 条**（8.6%），
  类型词掉在标签外的 **3 条**。所以这是**强倾向**，不是铁律。

### ③ 复合伤害只在末尾写一次类型词，中间用 `+` 串
- 安蓓萨 Q：「⟨物〔A〕+〔B〕最大生命值的物理伤害⟩」
- 卑尔维斯 R：「⟨真〔A〕 + 〔B〕%已损失生命值的真实伤害⟩」
- 不是「X 物理伤害 + Y 物理伤害」。我们 `effectDesc1` 与 008 的 brief 已经是这个写法。

### ④ 伤害/治疗的百分比必须带「谁的」；阈值判定语境可以裸写
- 「%+生命值」共 **69** 次，其中裸写「%生命值」**16** 次。
- ⚠ 我第一次说「692 条里没有一条裸写」是**错的**。看那 16 条的语境就清楚了：
  痛苦之拥 R「如果敌人低于**30%生命值**，则此伤害提升至…」、深渊巨口 R
  「低于**40%生命值**的敌人们会转而…」——全是**阈值判定**，不是伤害量。
- ⇒ 真规律：**伤害/治疗量的百分比必带归属**（目标最大生命值 / 已损失生命值 /
  当前生命值）；**「低于 X% 生命值」这种阈值可以裸写**。
- 连带更正：我曾据此判定自己「把『30% 最大生命值』改成『30% 生命值』是实打实的错」
  —— **那个自我判决下错了**，要看是伤害量还是阈值。

### ⑤ 叠层是固定三段式
施加「施加一层⟨X⟩」→ 上限「可叠加 N 层」→ 触发「在 N 层时…引爆」。
- 实例：泰隆被动「可叠加3层。当泰隆用普攻攻击一个带有3层创伤效果的目标时，目标会流血」
- 阿利斯塔 E「在〔maxstacks〕层效果时，他的下一个对英雄打出的攻击会⟨晕眩⟩目标」
- 韦鲁斯 W「引爆⟨枯萎⟩层数来造成每层⟨魔…最大生命值伤害⟩」
- 用词计数：**引爆 31 / 获得一层 17 / 可叠加 16 / 提供一层 13 / 满层 12 / 施加一层 7**
- 口语词：**炸开 0 / 攒到 0 / 攒够 0 / 打满 0**；⚠ 但 **攒满 4 / 叠满 2**（不是零）。
  ⇒ 真正一条都没有的是「炸开」「攒到」「攒够」「打满」——用户骂的那两版正好各踩一个
  （「攒到 3 个就炸开」「普攻叠环」）。

### ⑥ 可叠加的效果一律有专名，并当专有名词反复引用
出血 / 枯萎 / 烈焰焚身 / 电浆 / 震荡猛击 / 培养品味 / 旋转飞斧 / 黄沙士兵 / 月光 / 破绽…
⇒ 是【气环】，不是「气环效果」。

### ⑦ 替换效果的固定词是「转而」
**转而 41 / 变成 12 / 作为替代 7 / 改为 0**。⇒「改为」一次都没有；「转而」是主力。

## 3. 回头量我们自己：分界线根本不存在

96 条 `effectBrief` 里 **62 条带数值（甚至带 `{C:...}` 占位符）、34 条不带**。
- 063 在不带的那派 ⇒ 只剩「敌人受到真实伤害」，玩家看不出这件 3 费装备值不值。
- 隔壁 008 却写着「造成 1/1.2/1.5×攻击力物理伤害，外加 8/12/18% 目标最大生命值的魔法伤害」。

⇒ 用户问的「为什么装备会有两个描述」有答案了：**两个是对的**（LoL 也是两层，
而且我们的 `effectDesc1`≈tooltip、`effectBrief`≈desc，连 `{C:}` 占位符机制都对应），
**错的是我们没把分界线定下来**，于是 brief 变成了 desc1 的随机删减版。

**★这一条登记为未决点：统一 96 条要用户拍板方向，本版只改了 063。**


## 3.5 方向定了：brief 不带伤害数值 —— 依据是**落点**，不是我的偏好

查 `equip_brief` 的消费点（`grep -rn equip_brief scripts/`）才定得下来：

| 落点 | 版面 |
|---|---|
| `dual_lane_flow.gd:324` | 塞进 **44×44** 装备图标的 `tooltip_text` |
| `info_panel.gd:901` | 注释原文：「战斗中的信息面板空间最紧 —— 用一句话简述，点开才看全文」 |
| `InventoryScene.gd:1299` | 背包底栏一行 |
| `codex/detail_views.gd` | 图鉴列表 |

而**真正的购买决策点 `ShopScene.gd` 用的是 `equip_full`（全文 `effectDesc1`）**。

⇒ brief 的四个落点全是"空间最紧的一瞥"，`BRIEF_MAX = 60` 不是随手定的数，**是版面定的**。
⇒ 与 LoL 的分法完全对应：`desc` = 一瞥层、`tooltip` = 决策层。
⇒ **34 条不带数值的 brief 才是对的那批，62 条带数值的走反了。**

### 我在这一步自己绕了一圈，记下来

用户那句「而且你这全是简略啊，带数值的描述呢」是在说**我打印给他看的 LoL 语料全是 desc 层**
（当时我正在逐条打印 865 条），不是说我们的 brief 该带数值。我误读成后者，
于是把攻速档位和整个伤害式子塞进 brief，**94 字**，还拿
`codex_text_lint` 那句「长度只提示不算违规(完整性优先)」给自己背书 ——
而那句话说的是「**漏讲机制**才是硬线」，不是"数值越多越好"。
把 94 字塞进 44×44 图标的悬浮提示，是用一条通用原则压过了具体场景的硬约束。

最终 063 `effectBrief`（57 字，与韦鲁斯 W 的 desc 逐字同形）：

> 释放技能后获得攻击速度。普攻对敌人施加一层【气环】，可叠加 3 层；满层引爆，造成基于该敌人最大生命值的真实伤害。

完整数值（`15/30/50 + 0.8×攻击力 + 2.5/4/6% 该敌人最大生命值`）在 `effectDesc1` 里，
那一层才是"点开看全部"。

## 4. 把它焊进门禁 —— 我草拟四条，试跑之后只有一条站得住

在 195 段自家文案（装备 + 28 龟技能）上试跑：

| 规则 | 命中 | 判决 |
|---|---|---|
| ③ 同一伤害类型词在一句里重复且有 `+` | 2 | **全是误报**（022 那个 `+` 在括号里是攻击力系数）⇒ 判据宽一格造假 bug，不用 |
| ④ 裸写「%生命值」 | 1 | 那条（潮汐细剑「每损失 1%生命值」）是阈值语境，可接受 ⇒ 只值得做零新增基线 |
| ⑥ 说了「N 层」但没有【专名】 | 29 | **判据测错了东西** —— 那些效果（硬化/锻炼/吐息/灼烧/流血）名字都有，只是没加【】 |
| ⑤ 口语动词黑名单 | 10 | **站得住**（叠满/攒满/攒够/就炸开），且 LoL 侧的对照数已量出 |

⇒ 教训与 memory `fb-judge-must-fit-the-shape` 同形：**判据宽一格造假 bug、窄一格放过真 bug**。

## 6. 游戏内**渲染**层（2026-09-30 补 —— 用户直接截图给的，我原本拿不到）

前面 §1–5 全是**文本层**（Data Dragon 的 desc/tooltip 字符串）。用户 2026-09-30 截了
4 张 LoL 游戏内 tooltip（阿利斯塔 Q/E/R，含**按 Shift 前后各一张**），这一层才看得见。

### 6.1 ★★两层不是两段文案，是同一句话的展开

| | 默认 | 按 Shift |
|---|---|---|
| 正文 | `dealing 74 (🔮) magic damage` | `dealing 74 = (60 +80%🔮) magic damage` |
| 多出来 | — | **专名解释行**（斜体灰）+ **分档表**（Cooldown / Mana Cost / Damage 各 5 档，**当前档亮白、其余灰**） |

⇒ 我此前一直以为 `desc` 和 `tooltip` 是**两个界面的两段文案**，**错了**。游戏里是**同一个框，原地展开**：
简略给**结论**（74 = 我这一下打多少），详细给**推导**（74 怎么来的）。

⚠ 用户 2026-09-30 明确：「分档和切两层我们并不需要一模一样抄他们的，我们要的是思路」。
⇒ 思路是四条，形式我们自己定：
1. **默认给能直接决策的结论，推导按需展开**
2. **颜色编码语义**（伤害类型 / 控制），省阅读量
3. **高频概念用图标压缩**（`80%🔮` 而不是 `80% 法术强度`）
4. **术语不假设玩家懂**（详细版有专名解释行）

### 6.2 颜色（从那张干净 PNG 实测，不是肉眼描述）

| 元素 | 色值 | 实例 |
|---|---|---|
| 魔法伤害 | `#0acbe6` 青蓝 | `93`、`magic damage`、整个算式 `(80 +70%🔮)` |
| 控制效果 | `#ad76c4` 淡紫 | `Knocking Up`、`Disabling`、`Stuns` |
| 正文 | `#a09b8c` 灰白 | 其余全部 |
| 技能名 | `#e6ddc9` 米白 | `[E] Trample` |
| 底 / 边框 | `#080c10` / `#604b28` | 近黑底 + 金棕边 |

★**只有伤害数值上色，别的不上**：`takes 55% reduced damage for 7 seconds` 里
`55%` 和 `7` 都是**白的** —— 那不是伤害。我第一眼以为"数值都上色"，错了。

★**紫色只给控制效果**，不给所有关键词：`Stuns`/`Knocking Up`/`Disabling` 紫，
而 `Ghosted`（状态，不是控制）**是白的**。

### 6.3 属性图标

- 至少两类：**🔮 紫水滴 = 法术强度**；**⬆ 青箭头 = 随等级成长**（`20 = (20 - 275⬆)`）
- **嵌在算式里替掉文字**，不是放在行首当装饰

### 6.4 另一个游戏的做法（用户 2026-09-30 给的两张中文 ARPG 截图）

- **图标是单色**：橙色斜块（物理）、青色四角星（某属性），**且与它标注的数值同色**
  （`⚡102` 橙图标+橙数字；`✦132` 青图标+青数字）
- **专有名词统一上黄色**：「敏捷步伐」「阿斯特丽德的杰作」「攻击效果」「觉醒状态」全黄，
  普通叙述白色，伤害数值橙/青
  ⇒ 与 LoL 用紫色标控制效果是**同一个思路**：给专名一个固定颜色，让玩家一眼认出
    「这是个有定义的东西」。我们现在用【】方括号做这件事 —— 纯文本时代的办法。

### 6.5 ★★三方印证：属性图标应该是**纯白单色剪影 + 运行时染色**

| 来源 | 观察 |
|---|---|
| LoL tooltip | 🔮/⬆ 单色小图标，颜色跟随数值 |
| 中文 ARPG（用户截图） | 橙块 / 青星，**图标与数值同色** |
| Botworld 升级屏 | 属性网格里的 ♥/⚔/⏩ 是**纯白剪影** |

⇒ 结论：**图标只画形状，颜色交给代码**（Godot 一行 `icon.modulate = ...`）。
好处：一张图配任意颜色、统一性天然成立、改配色不用重画、缩到 8px 不糊
（没有渐变可糊）、同一形状能同时服务「属性行的大图标」和「嵌在文案里的小标记」。

**我们的现状**（实测 `assets/sprites/stats/` 14 张，全 32×32）：

| 图标 | 32×32 内的色数 |
|---|---|
| `dmg-amp` / `dmg-red` | **4~5 色**（真像素风） |
| `mr-icon` | **364 色** |
| `move-icon` / `def-icon` | **307 色** |
| 其余 | 86~258 色 |

⇒ **同一套图标里并存两种做法**：2 张 4 色像素图 + 12 张几百色渐变缩图。
另外还有三处不统一：**形状语言分裂**（写实物件 vs 抽象箭头混用）、
**带无关装饰**（生命那张红心旁挂三个绿球）、**靠渐变塑形**（缩小即糊）。

用户 2026-09-30：「属性图标我的建议是现在我们的所有属性图标全部重做，要像素风，
风格简洁统一，你看 lol 没这么花」「一定是要多色吗」⇒ **不必须，单色就够**。
