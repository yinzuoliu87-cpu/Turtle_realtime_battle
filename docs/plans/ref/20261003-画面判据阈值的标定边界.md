# 画面判据阈值的标定边界（2026-10-03 实测）

> 一句话：`tools/battle_scene_audit.py` 的「有效色数 ≥ 88 / 中间调 ≥ 24%」是拿**一张亮场**
> 截图标定的，**暗场景本来就达不到 —— 咩咩自己的暗地牢也达不到**。

## 0. 怎么量的

`sys.path.insert(0,'tools'); import battle_scene_audit as BSA`，直接调 `BSA.audit(path)`，
**复用仓库里那份实现而不是另抄一份**（口径一致才可比）。整图、无裁切、step=2。
样本是 `C:/tmp/cult/raw_*.jpg`（Steam 官方商店截图，1920×1080，无 HUD）。

## 1. 实测

## 2. 结论

- 门禁阈值「有效色数 ≥ 88」「中间调 ≥ 24%」：`raw_01`（79 / 16.5%）**两条都不过**。
- 阈值表里记的「CultOfTheLamb 174 / 59.7%」最接近 `raw_04`（175 / 56.9%）⇒ **标定用的是亮场那张**。
- ⇒ 这两条阈值**对亮场有效，对暗场无效**。拿它去卡一个暗主题，等于逼着把暗场改亮 —— 那正好是
  在消灭四版里「夜礁」「风暴」存在的理由。

## 3. 这条标定救了什么

2026-10-03 夜，我为了把 dusk 主题的色数从 76 推到 88，连试三招：
加大地面明暗起伏（±8%→±20%）、加抖动级数（6→12）、让浪尖泡沫映天色。
**三招全无效或更差**（76 / 76 / 78），而且每一招都在往"把画面改得不像我想要的样子"走。
量完参考才知道：**dusk 的 78~81 与咩咩自己的暗地牢（79）在同一档**。
三处实验已逐字节撤回。

（memory `fb-calibrate-the-ruler-before-trusting-it`：量尺要先标定再信。
 这次是标定**边界** —— 尺子本身没坏，是它的适用范围比我以为的窄。）

## 4. 未决点（要用户拍板，我不自己定）

🔲 **暗主题的画面判据怎么判。** 三条路：
  ① 阈值按场景整体明度分档（亮场沿用 88/24%，暗场用参考里暗场那几张的区间 79~129 / 16~37%）
  ② 只对默认主题跑这条判据，预览主题不跑（简单，但预览主题就没人守着了）
  ③ 四版最终只留一版上线，那版按它自己的明度定阈值
我的建议是 ①，因为它仍然卡得住"暗场里的真退化"，而不是把闸整个撤掉。
