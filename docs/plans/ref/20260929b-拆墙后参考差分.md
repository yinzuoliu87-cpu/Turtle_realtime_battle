## 3. 拆墙**只动了一格**，但动的是唯一一格 0 分项

### ✅ 有没有出口：**0 → 1，与中位持平**

这是 13 屏逐像素里我们**唯一一项拿 0** 的维度（`-100%` → `+0%`）。
屏幕上的落点：那一屏多了一颗「关闭」（159×81 = 44pt，与「发验证码」**并排在同一行**）。

★**它不是一个摆着看的按钮**：`verify_login_wall` ②b 真点了一次 —— 屏幕真的没了、
被藏起来的设置页原样交还、顶栏返回箭头也回来了。而 ⑧ 从第一屏走到战斗场景，
全程 `account_email` 是空的。

### ⚠ 一屏可点元件数：**4 → 5（+150%）—— 这是代价，不掩饰**

多出来的就是那颗「关闭」。参考中位是 2，我们本来 4 已经超了，现在 5。
**但这一格与「有没有出口」在参考里是一对反向指标**：13 屏里有出口的那些，出口自己就占一个元件。
中位 2 的那些屏是「一个输入框 + 一个主按钮」，它们的出口是**「跳过」那一类文字链**（不计入可点元件的量法见 `LIMITS`）。
⇒ 想把这一格压回去只有一条路：**把出口从按钮改成文字链**，那要重做这一屏的版式，单列一件。

### ⭕ 其余十项：**一个数没动**（55.3 → 55.2 是并排那一行让宽带来的舍入）

拆墙动的是「这一屏什么时候出现、关不关得掉」，**不是这一屏的版式**。
所以 v0.19.472 那一轮量出来的成果（44pt 靶子 / 21px 行隙 / 两步 / 预填名）**原样保留**。
