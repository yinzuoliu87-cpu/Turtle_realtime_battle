### 分批设计
- **6 批 × 10 个**，批与批串行（一批全部退出才起下一批）。理由：60 个 Godot 窗口同时开会卡死/蓝屏（memory `project-machine-bsod-during-tests`）。
- 每个窗口：独立 `APPDATA` = `C:/tmp/turtle-sim60/pNN`（**不碰上周的 `turtle-sim10`**）；游客匿名号（与上周同，墙已拆）；
  `QUIET=1` + `--audio-driver Dummy` 静音；1280×720 原生叠放在**右屏** (2000,80)（实测右屏 DISPLAY1 = x 1920..3627）；
  驱动给窗口挂 `FLAG_NO_FOCUS` 不抢焦点；**不清空 `TURTLE_BACKEND`**（真用户、打真后端）。
- 每个窗口打到**被拦**为止（配额 16 场打满 / 命用完），然后 `SIM_QUIT_WHEN_DONE=1` 自己退出。
- pid 靠命令行里的 `--sim-slot=NN` 认（`Win32_Process.CommandLine`），不靠「最新的 Godot」去猜；`stop` 只杀带这个标记的。
- 截图：`pNN/shots/latest.png`（每 5 秒自拍）+ `pNN/shots/<UTC时刻>_<名字>.jpg`（命名截图）。
- 事件：`pNN/Godot/app_userdata/斗龟场 实时版/sim_events.jsonl`（每件事一行：场景切换 / 对手是谁、是不是机器人、对手场次 / 结算 / 买了什么 / 装给谁 / 被拦的原话 / ANOMALY / STUCK）。
- **晋级存档留到周六**：`sim60.sh` 没有 reset 命令；周六对晋级的槽位再 `SLOTS="..." bash tools/sim60.sh start 1` 即可（驱动在主菜单走的是同一个 `_start_battle_flow()`，周六就是闯关赛）。

## 二、生产侧核对（只读，没改任何生产数据）

### 2.1 `purge_junk_anon_users`（每天 04:30 UTC）会不会在周六前删掉这些号？——**不会**
SQL（`server/supabase/schema.sql:973`）删除条件是**全部同时成立**：匿名 且 没邮箱 且 `coalesce(last_sign_in_at, created_at) < now() - 14 days`
且在 `ghosts / gauntlet_ghosts / saves / standings / matches / finals_entrants / finals_pending / finals_scout / accounts` 里**一行都没有**。
- 这批号 10-06 起建，到周六 10-10 最多 4 天，**14 天那一条就不成立**；最早 10-20 才可能满足。
- 而且打过一局就会上传快照（结算屏实测「阵容已上传 · 别人可能会打到你」）⇒ `ghosts` 里有行 ⇒ 之后也不会被删。
- ⚠ 这条结论读的是**仓库里的 SQL**，没有去生产库读 `cron.job` 与函数体核对（`~/.supabase` 在禁区）。如需双保险请主会话只读查一次。

### 2.2 匿名注册限流（上周记录 30 个/小时）吃不吃得下 60 个？——**分批就吃得下**
