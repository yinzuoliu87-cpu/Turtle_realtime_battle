  ★门禁: 断言「调用一次 _toast 之后、下一帧屏幕上仍有那行字」——

## A14 ★两个不同的号，匹配屏上「我的 ID」是**同一个号码**（#503911）
- 复现: p05 和 p06 是两个独立存档的全新账号。各自点「开始战斗」→ 匹配屏
  左边那张「你」的卡片上，两个号都写着 **ID #503911**（对手 Vito 也都是 #755428，但那是同一个 bot）。
- 证据: C:/tmp/keep_p5_same_id.png（p05）与前一屏 p06 同号；两张图逐位一致。
- 根因（源码）: `scripts/scenes/MatchmakingScene.gd:306`
  `return {"name": "你", "avatar": pid, "id": _display_id("me_%d" % int(GameState.season_id))}`
  —— 号码是 `hash("me_" + 赛季号) % 1000000`，**唯一的输入是赛季号**，
  而 `season_id` 是「第几大轮」（`autoload/GameState.gd:864`「一个自然周一轮」），**全服所有人相同**。
  ⇒ 同一个赛季里**每个玩家看到的「我的 ID」都是同一个数**。
- ★这一行的注释恰好说明了它想解决的问题:
  「自己的 ID 也别每场重摇 —— 原来是 randi(), 同一个玩家每场看到一个新号,
   而"ID"这个词在玩家眼里就是"我的号码"。按存档里的稳定量折算。」
  —— 稳定是稳定了，但挑的那个「稳定量」里**没有"是谁"这一维**，
  从「每场都变」修成了「所有人都一样」。
- 我的判断: **真 bug**。玩家报 bug、约战、认自己的号都靠它。
  ★修法: 折算的输入里必须带账号自己的东西（存档 uid / 邮箱 / 首次创建时的随机种子），
  不能只有赛季号。（正好对上 memory `fb-id-without-owner-dimension`。）
