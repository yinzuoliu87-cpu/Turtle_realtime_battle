## 2. 改了什么、为什么

| 改动 | 理由 |
|---|---|
| 第一句从「绑定只是把它锁到这个邮箱上」改成「绑上邮箱，换手机或重装都能接回来」 | 原话在解释**机制**（锁到邮箱上），新话直接说**玩家得到什么**。参考里第一句都是说得到什么。 |
| 新增「邮箱和名字以后随时能改」 | 13 屏逐像素参考里这句话到处都是（Pokémon HOME「you can change this later, too!」／Nier「This can be changed later.」／Octopath／Smash Legends／Sonic Rumble）。它干的事是**把这一步的心理成本压下去**。 |
| 「不绑，换了手机就接不回来」**保留并说得更直白** | 用户 2026-09-24：「没绑邮箱换设备就是丢档，**这一点要在 UI 上说清楚**」。事实不许删 —— 改的只是说法。 |
| 「或者换一个邮箱重发」→「或回上一步换个邮箱重发」 | 分两步之后，改邮箱的动作**就是**「回上一步」那颗钮。原话没告诉他怎么回去。 |
| 名字那行加「以后随时能改」、去掉「和对阵图」 | 同上：取名是这一屏心理成本最高的一步。去掉「和对阵图」是为了给新增的六个字腾出宽度，**仍然一行**。 |

## 3. 我**没**改的，以及为什么

- **标题「绑定邮箱才能开始」没动。** 它是陈述这道门的事实，不是恐吓；而且 `verify_ui_consistency`
  拿 `login_wall_head()` 当「墙那句话真的在屏幕上」的真分母。
- **设置页里玩家自己点开的那个绑定框的文案没动**（「⚠ 龟和装备是存在这台手机上的，换设备仍然会丢。」）。
  本轮任务点名的是 `login_wall_body()`；那一句在**玩家自己要求**绑定的语境里，是他需要知道的边界条件，
  不是拦路时的吓唬。要一起改的话建议单列一轮。
- **一个「游客 / 跳过」出口都没加**（方案书 §5 未决 1：与用户 2026-09-24「直接改为必须绑定账号吧」冲突，
  要翻也得他翻）。

## 4. 门禁钉在哪儿

`tests/verify_login_wall.gd` 第 ⑦B 节，六条：

- 第一句不含「丢」/「⚠」（**谓词自证**：拿旧版那两句跑一遍，必须都被判成恐吓，否则整节恒真）
- 必须出现「以后」+「改」
- 必须同时出现「不绑」与「换手机／换设备」（用户点名的事实）
- 不许出现「丢失存档／取回存档／找回存档」（与 `verify_account` ④ 同一条禁令）
- 至少两行，且**最后一行**必须是「收不到验证码」那句（第二步拿它当正文）
- 第一步要印的那几行里不许有「收不到」（还没发码）
