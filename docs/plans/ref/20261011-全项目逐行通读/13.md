- 问题：
  - 【疑点】20261007b_champion_cup.sql:179–196 —— 等待上限（20:00+3600s）一过，`finals_cup_seat` 只收**已收盘**组的冠军，未收盘组之后决出的冠军永远进不了杯（该组照样被 `finals_advance` 推完，但无人再看它）；幂等守卫 167 行使杯只建一次。原稿 §四「全部桶冠军」进签表。依据：读本函数 + `finals_advance`（schema.sql:1236）只推不建杯。影响：某组因宽限/补判拖过 21:00 时，该组冠军静默失格。是否接受需拍板。

### server/supabase/schema.sql（已读 1–1842 行，共 1842 行）
- 作用：Supabase 全量表结构 + 全部 RPC 的累积版（各迁移原样追加在尾部）。表：accounts、ghosts（PK account_id+season_week+battles）、gauntlet_ghosts（PK 含 gw/gl）、matches（+replay 列，决赛行只上传者可读）、standings（无写策略）、service_status、saves（`push_save` CAS）、finals_buckets/entrants/results/pending/scout、live_matches（触发器 `live_matches_stamp` 锁服务端时间戳）。函数：finals_round_sec(480)、finals_view、finals_week_view、finals_advance、finals_enter、finals_bucket_size/count/of、finals_seat、finals_report、finals_replay、finals_opponent、purge_junk_anon_users、week_leaderboard v1/v2/v3、冠军杯一组。
- 关键内容：同一函数被多次 `create or replace`（finals_view ×3、finals_week_view ×3、finals_advance ×2、finals_seat ×2、finals_bucket_size ×2、purge_old_matches ×3、week_leaderboard ×3），整份顺序执行时最终生效的是最后一份；中间旧版只是历史。
- 问题：
  - 【确认bug】schema.sql:781–815 `finals_report` —— 不校验 `p_match` 范围（只校验 round、桶成员、side∈{0,1}）。任意 match_no（如 99）都会写进 finals_results。`finals_advance`（:1251 `select count(*) into got … and round = b.round`）按**行数**判「本轮打完没」，越界行会被计入 `got` ⇒ 本轮在 480s 一到就翻面、真实未报的那场直接被 1291 行的无条件 insert 补判为 side 0。依据：读两个函数。影响：同组任何成员（或客户端算错 match_no 的 bug）可让真实对局被提前判负；与已承认的「同桶旁观者能替别人报」缺口叠加，但这一条连「替别人报」都不需要。修法：`p_match between 0 and slots/2^round - 1`。
  - 【疑点】schema.sql:667–695 `finals_enter` —— 不校验 `p_week` 是否本周、是否周六/周日，gw/gl 全由客户端报（注释已承认后者）。客户端每场周六结算后都 upsert（scripts/net/supabase.gd:2201 注释），入场依赖玩家周六在线打完；周日 08:00 `finals_seat` 一跑之后再报回 `already_seated`。原稿 §四「无签到、全员自动入场」——若晋级者周六第 4 胜那次上报失败且周日 08:00 前没再打开游戏，他就不在名单里。是否有补报单兜底见 backend.gd:1492（另一块负责），此处只记疑点。
  - 【注释或文档与代码不符】schema.sql:362–367、:586、:601–603、:1264、:1279–1281 —— 多处宣称「对阵/座次规则 SQL 里不写第二遍」，而 :1423–1425/:1504–1523 冠军杯段已写了 SQL 版座次表 `finals_seed_at_seat`（该段自己承认）。旧注释未同步。

  - 【注释或文档与代码不符】schema.sql:704–706（旧 finals_bucket_size 注释「2 个人分成两个 1 人桶……那不是比赛」）与 :1437–1438 新规则相反；旧函数体已被 :1443 覆盖，属历史段落残留。
  - 【注释或文档与代码不符】schema.sql:1080–1082 见 20261008 条。
  - 【小问题】schema.sql:973–988 `purge_junk_anon_users` 的「在任何数据表里都没有一行」清单不含 `live_matches`；但 live_matches.account_id 是 `on delete cascade`（:1158），删号不会失败，只是「没数据才删」的口径漏了一张表（只开过直播、没别的数据的匿名号会被删）。
