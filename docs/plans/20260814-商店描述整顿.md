## 3. 现状与需求的出入：「乱七八糟」逐条落到实测数字

| # | 毛病 | 实测证据 |
|---|---|---|
| **①** | **滚动提示压在正文最后一行上** | `_add_scroll_hint` 把提示画在 `desc.position.y + desc.size.y - 16` ——**框内**。截图里「▼ 下滑看完整描述」与「并使携带者获得20/25/30%」**像素级重叠**，糊成一团 |
| **②** | **14% 的装备描述根本放不下** | 探针量 95 件在 `372×264`、字号 20 下的 `get_content_height()`：**13 件溢出**；最长 `p2eq_084` 内容高 **420px = 框高的 1.6 倍**。代码注释还写着「现在只剩 1 件要滚」——那是 59 件时代的数，装备涨到 95 件后**没人回来改** |
| **③** | **标点全角半角混用** | 95 件 `effectDesc1`：半角逗号 **90 件**、半角括号 **74 件**、半角分号 **52 件**、半角冒号 **30 件**，而句号一律全角「。」。同一句里 `每次普攻时,小球会…射出一支藤蔓箭,造成…。` —— 中文排版里这就是最直接的「乱」 |
| **④** | **羁绊信息在同一屏说两遍** | 面板右上角 chip「🏹弓箭 ×0 · 未激活」 vs 描述区首行「羁绊·🏹弓箭 阈值 3/6/9 · 队伍现有 ×0(未激活)」——**同一份信息**，而且首行还被硬折成两行，「×0(未激活)」孤悬在第二行行首 |
| **⑤** | **非当前星档暗到读不出来** | `SkillText.highlight_star` 把另两档压成 `#5a6472`，面板底色 `#10202e` ⇒ **对比度 2.76:1**（WCAG 正文要 4.5:1）。截图里 `/30/45` 几乎只剩噪点 |

★②③是**数据/存量**问题，①④⑤是**渲染**问题。

## 3.5 方案

| 毛病 | 做法 |
|---|---|
| ① 提示压字 | 描述框高 264 → **246**，底部 18px **永久留给提示**；提示挪到框**外**下方 +2px |
| ② 放不下 | 新增 `_fit_desc_font`：**先缩字号再说滚动**（20→18→16→15），缩到底才挂提示 |
| ③ 标点 | 95 件 `effectDesc1/3` 的 `,;:()` 一律转全角，**数字一个不动**（改完逐件比对数字串） |
| ④ 说两遍 | 描述框里的三行羁绊 bbcode **删掉**（`_synergy_bbcode` 整个函数删掉，不留着不调），右上角小签扩成两行说完 |
| ⑤ 暗档 | `SkillText.highlight_star` 的压暗色 `#5a6472` → `#7d8ea0`（对比度 2.76 → **4.9**） |

## 4. 验收清单（子需求一次摊开）

- [x] **A** 滚动提示移出正文框 —— 框高 264→246，提示落在 `y+size.y+2`（框外）。**截图复核：不再压字**
- [x] **B** 「要滚才看得全」**19 → 2 件**（`_fit_desc_font` 缩字号后重测；两件只差 7px：打捞旋翼机/手半剑 253px vs 框 246）。
      ⚠**没到 0**：显式登记，不静默。门禁判据设成「≤3 件」，再多一件就红
- [x] **C** 95 件描述标点转全角，**改了 96 行**；改完逐件比对数字串 —— **0 件数字发生变化**
- [x] **D** 羁绊只说一遍：`_synergy_bbcode` **整个函数删掉**（不是留着不调），信息搬进右上角两行小签
- [x] **E** 暗档 `#5a6472 → #7d8ea0`。**从截图像素实测对比度 5.23:1**（背景实测 `(14,26,38)` 比我假设的还暗，
      所以实测比我算的 4.9 还好一点）—— R6 要求的「别信我的算术」已照办
- [x] **F** 门禁：⑥ 改成**复刻 `_fit_desc_font` 逐档缩字号**再判，并从 ShopScene 源码**回读框高与字号阶梯**对口径
      （手抄的副本必然落后）；⑫ 判据从 bbcode 搬到 `_synergy_two_lines` + 断言描述框里不再拼羁绊
- [x] **G** 改完重拍了两张：短描述（龟苓膏块）与**最长的一件**（手半剑，唯一会触发滚动提示的形态）

### 顺带修好的三处连带

- `verify_equip_nerf` 两条断言里写的是**半角括号**的文案 ⇒ 标点一改就红。已同步成全角（真红过，不是预防性改）
- `data_integrity` 的「装备评审表 ↔ json 一致」红了 ⇒ 跑 `tools/gen_equip_review_table.py` **按事实源重生成**，不手修
- `_fit_desc_font` 与 `_add_scroll_hint` 原本会**并发**（两个协程各等一帧）⇒ 提示会拿「还没缩完」的高度判，
  挂出多余的提示。改成**串行**（fit 完再挂）；`_center_middle` 也从等 1 帧改成等 6 帧（4 档字号各一帧）

## 5. 已知风险与未决点

| # | 风险 | 处理 |
|---|---|---|
| R1 | 改 `effectDesc1` 标点会不会打翻 `tooltip_number_audit`（它拿文案数值 ↔ 代码对账） | **它抓的是数字**，标点不参与。但**必须跑一遍确认**，不许推理 |
| R2 | 半角括号里可能有代码依赖的字面量（例如某处 `find("(")`） | 改前全仓扫一遍谁在解析 `effectDesc1` |
| R3 | `1,000` 这类**数字里的半角逗号**会被误改 | 替换规则只在**非数字上下文**动逗号；改完逐件 diff 看数字有没有变 |
| R4 | 描述框加高会不会挤到「购买」按钮 | 按钮是 `_center_middle` 收拢的，加高后要重新截图确认，不是算出来就算数 |
| R5 | 提亮暗档会不会让「哪档是我的」不明显 | 高亮档保持 `[b]` + `UIPalette.DEF`，只提暗档亮度；**截图对比**判定 |
| R6 | ⑤ 的对比度是我算的不是量的 | 改完从**截图像素**取色复算，别信我的算术 |

### 与方案的出入

- **B 没做到 0**：目标写的是「压到 0 件」，实际停在 **2 件**（差 7px）。
  继续压只剩两条路——字号降到 15 以下（用户骂过「这么小的字?」）或砍属性区（那是买之前要看的数值），
  两条都比「多滚一下」更差。**显式登记为缺口**，门禁判据设成 ≤3 件，超了就红。
- **全角标点让描述更宽了**：改完 ⑥ 从「19 件放不下」变成更差，是缩字号把它救回 2 件的。
  这条我改之前没预料到——标点统一是**排版对了但更占地方**。
