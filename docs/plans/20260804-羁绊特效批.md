## 0. 一句话结论

**数值全做完了，演出几乎全是空的。** 逐个核实 10 个系统文件，共 **34 条机制**：

| 现状 | 条数 | 说明 |
|---|---|---|
| **完全没有任何专属表现** | **21** | 只有伤害数字（甚至连数字都没有：属性/累积类） |
| **只有通用管线捎带的表现** | **9** | `_grant_shield` 的环 / `_heal` 的绿字 / `_freeze` 的环 —— 和别的护盾/治疗/冻结长得一模一样 |
| **有一点专属表现** | **4** | 处决与斩首的 `-999999` 大字、炮台与触手各一条 `_bolt_line` |

**最刺眼的三处**（不是主观，是"机制每几秒发生一次而画面上什么都没有"）：
1. **【怒气冲击波】叫冲击波，画面上只有一个黄色数字** —— `shield_synergy_system.gd:100-108` 只有 `_apply_damage_from` + `_grant_shield`。
2. **【三座炮台】和【触手】的"本体"完全不可见** —— 两个文件的注释都写着"做成逻辑实体，表现走现成特效函数，**玩家看到的东西一模一样**"（`gun_synergy_system.gd:16-22` / `spirit_synergy_system.gd:13-19`）。**这句话在没有本体演出的前提下不成立**：现在玩家看到的是"一条线凭空从场边射出来"。
3. **【腐蚀叠层】和【僵硬】是全场铺的 debuff，零显示** —— 敌人身上挂着 1~5 层腐蚀（增伤 +2~20%）、最多 20 层僵硬（攻击力 ×0.60），玩家**没有任何途径**知道。

**成本判断（先说结论，逐条见 §4）**：
- **零素材就能做完的：22 条**（程序化 3D + 现成 API + `VfxTex` 逐像素生成器）。
- **要新素材才好看的：12 条** —— 全部走"代码先合入 + `push_warning` 占位，素材后补"（§5 R8 有仓库既有先例）。

### 2.3 频率与刷屏（**这决定哪些能跳字、哪些只能做常驻显示**）

**仓库自己就写着这件事**：`battle_vfx.gd:555-559` 有一整节 `§VFX-DEMO` 的注释——
> 「GPUParticles3D 动态特效验证（**证明 2.5D 引擎能做"活"的粒子，非静态图滑动**）。两个 GPU 粒子函数：火焰爆发（球向上抛，重力回落，白热→橙→红→透）+ 能量冲击波（环向外扩散）。**全程 GPU 模拟**（每颗独立速度/重力/缩放/颜色随生命渐变），加色发光叠加，billboard 永远朝镜头。」

**最强的一个现成样板：`_tendril_draw`（`hookbomb_system.gd:722-817`）** —— 值得单独说，因为它证明了"零素材也能做出有体积的东西"：
- 纯 `ImmediateMesh`，**不用任何贴图**；
- 22 段脊线，**在 Y 轴拱起**（`TENT_ARCH=0.62` m），注释自陈「★这一条是"立体"与"贴纸"的分界。**平面弯曲救不了"贴图感"，立体拱起可以**」；
- 横截面 7 条，侧向偏移方向 = `切线 × 指向相机` ⇒ **无论触手朝哪个方向，看上去都一样粗**（不被 z 压扁）；
- 肌肉鼓包（正弦扰动）、出口收颈、沿脊一条细亮线当湿润反光；
- 建完挂 `_reg_tween` 0.22s 后 `queue_free`。

#### 四条技术路线的代价与适用面

| 路线 | 做法 | 素材成本 | 代码成本 | 适用面 | 不适用 |
|---|---|---|---|---|---|
| **① 贴片** | `Sprite3D` + 序列帧，走 `_burst_vfx` / `_fly_vfx` / `_play_anim_vfx` | **高**（每张都要新生成，PixelLab best-of-N 有交付风险） | **极低**（一行调用） | 有**具体形象**的东西：亡魂、金币、冻结外壳、符文印记、蛋的武装态 | ★**方向/长度是变量**的（每个方向要一套帧、公告板一转就歪、长度随距离变做不到） |
| **② 程序化 3D** | `ImmediateMesh` / `ArrayMesh`+`SurfaceTool` / `GPUParticles3D` / `QuadMesh`+加性材质 / `ShaderMaterial` / `VfxTex` 逐像素贴图 | **零** | 中（几十到一百多行，但有 `_tendril_draw`(hookbomb:722) / `_particle_burst`(RB:7466) / `_glow_bb`(RB:5034) / **新增的 `tentacle_vfx.gd`** 四个可照抄的样板） | **能量、光、冲击波、射线、粒子、连线、进度条、任意半径的环**，以及**方向与长度是变量**的东西（转 `Node3D`、拉伸顶点即可）—— 也就是本批的大多数 | 有精细具体形象的（画不出"一只亡魂"的脸） |
| **③ 混合** | 程序化打底 + 一张小贴片点睛 | 低（1 张） | 中 | 既要形象又要随参数变的：炮台本体（贴片）+ 炮口能量束（程序化） | — |
| **④ 导入 3D 模型** | `.glb` / `.gltf` + `Skeleton3D` + `AnimationPlayer` | 高（要建模，且不是 PixelLab 能出的） | ★**很高 —— 第一个模型要付整条管线的账** | 需要真实骨骼动画的复杂物体 | 本批**没有一条到这个量级** |

> **④ 的真实代价（实跑核实，不是估的）**：全仓库 **`.glb` / `.gltf` / `.fbx` = 0 个**；
> `scripts/` 里 `Skeleton3D` 与 `AnimationPlayer` **各只出现 1 次，且都在 `tentacle_vfx.gd` 的注释里**（即真实用例 **0**）。
> 而路线 ② 是**沿着仓库既有做法**走：`SurfaceTool` 现算网格已在 `battle_world_builder.gd:710` 用于地图几何，
> `ArrayMesh` 已在 `battle_aim.gd:137` 用于瞄准箭头，`BoxMesh` 在 `RB:1024` 用于地砖。
> ⇒ **④ 不是"做不到"，是"这一批用不上"**：本批 34 条里没有一条需要骨骼动画。
> 若日后确实要（比如给某只龟做真 3D 大招），那是**独立的一份方案书**，因为它要付导入/材质/像素风统一/包体/移动端性能一整套账。

#### ★★ 程序化 3D **不吃**"素材不复用"那条约束

**理由（不是我的推论，是仓库既有立场）**：
- 那条铁律管的是**产出可复用的图**（立绘 / 贴图 / 图标）。程序化 3D **不产出图**，它每次按参数现算几何与颜色。
- **项目已经这么用过并被接受**：`vfx_textures.gd:23-25` 面对同一条铁律时的解法就是「**逐像素画即可**」，而不是"去生成一张图"。35 个 `_make_*` 生成器被全项目各处共用（`_make_ring_texture` 同时供 `_skill_ring` 与 `_hit_spark`），**从未被当成"复用素材"**。
- 同理，`_glow_bb`（加性发光片）、`_bolt_line`、`_tendril_draw` 这些几何原语被多处共用，也从没被当成复用。

⇒ **这是本批性价比最高的一块**：§4 的 34 条里，**22 条可以完全走程序化 3D，零素材、不受铁律约束、不排 PixelLab 队**。

## 5. 已知风险与未决点

> 未决点写成**选择题**，每项给选项 + 代价，用户**一句话即可拍板**。
> ⚠ **素材复用不在未决点里** —— 用户 2026-08-04 已定：一律新生成（本文全文按此规划）。

### 未决点

**U1｜灵物触手与无头龟(27)「万千触须」的区分度怎么定？**（阻塞批 B）
两者同为触手、同一个战场。素材虽然各做各的，但**几何形态**若一样，观感上仍是"复用"。
- **A. 只换配色**（无头=紫黑肉感 → 灵物=青碧幽光），几何思路相同。代价：形态撞脸，可能被判成"偷偷复用"（2026-07-17 那次批评的正是这个）。
- **B. 换形态**：灵物做成**半透明的灵体触须**（无实体肉感，带残影与消散粒子），与无头的"实体肉触手"从根子上区分。代价：多约 40 行程序化代码。
- **C. 灵物不用触手形态**，改成"从地面升起的灵体巨手拍下"。代价：与机制名"触手拍击"对不上，要一并改文案（`phase2_types.gd` 的 `TIER_DESCS`）。
→ **建议 B**（区分度足够，且不用改任何文案）。

**U2｜怒气冲击波"一次连发 5 下"怎么演？**（阻塞批 B）
`shield_synergy_system.gd:84` 的 `while acc >= 400 and fired < 5` —— 挨一发靶向器大伤害会**连放 5 次**。
- **A. 放 5 次同样的演出**。代价：5 个环叠在同一帧同一点，糊成一团。
- **B. 同帧合并成一个更大的**（半径/强度按 `fired` 缩放）。代价：`_shockwave` 要改签名或在外面加一层合并 ⇒ **动到逻辑侧**，盾的门禁（`verify_shield_synergy`）要重跑确认数值一条没变。
- **C. 只演第一次**。代价：玩家看不出"打出了 5 倍伤害"。
→ **建议 B**。

**U3｜法器"法力条"要不要做可见 UI？**（阻塞批 C）
现状：每件法器各存 `eq_state[id].mana`（`staff_synergy_system.gd:92-94`），玩家**没有任何途径**看到进度。
- **A. 头顶徽章 + 百分比数字**（取身上最高的那条）。代价：带 3 件法器时只显示 1 条，信息不全；且**挤占已经满员的徽章行**（见 R6）。
- **B. 血条下方加一条细蓝条**（照龟能条做法）。代价：要动 `battle_render` 的血条布局，改动面比 A 大一档，且移动端竖屏空间紧张（本项目主跑手机）。
- **C. 只做"满条触发那一刻"的闪光**，进度不可见。代价：玩家知道"响了"但不知道"还差多少"。**成本最低**。
→ **建议先 C**，等玩家反馈"看不懂"再上 A/B。

**U4｜"静默滚雪球"四条（成长 / 远古之力 / 铸币 / 战利品）用什么节奏提示？**（阻塞批 C）
- **A. 跨阈值才放**（照抄魔法石三档，`docs/plans/20260730c`）。代价：要为每条各定 3 个阈值 = **4 组共 12 个数要拍**。
- **B. 每 5 跳（12.5 秒）跳一次累计值**。代价：数字与"这一跳加了多少"对不上，文案要写"累计 +N"。
- **C. 只做常驻表现**（脚下环随累计变浓），不跳字。代价：变化太慢，看不出。
→ **建议 A + C**（阈值放大招 + 常驻环）。若嫌 12 个数太多，退 B。

**U5｜头顶徽章行只有 4 格且已满，怎么办？**（阻塞批 A —— 不解决，后面加的徽章会被**静默截断**）
`HEAD_ROW_CAP = 4`（RB:5838），叠层行已被 electric / ink / cyber_ai / crystal 四种占满（RB:5843-5850）；`_layout_head_row` 直接 `mini(items.size(), CAP)` 丢掉多余的，**不报错不警告**。腐蚀 + 僵硬 + 法力再进来 = 7 项抢 4 格。
- **A. 扩容到 6**。代价：手机竖屏上一行 6 个 40px 图标 = 240px 宽，**可能超过角色间距**，多只龟的徽章行会互相重叠。
- **B. 定优先级**（羁绊类 > 龟技能类，或按"是否影响本次结算"排），超出的丢掉。代价：丢掉的那条就是白做。
- **C. 分第三行**（叠层行上再加一行）。代价：头顶越堆越高，遮挡场景。
- **D. 合并显示**：多个 debuff 只显示"最严重的那个 + 总数"。代价：要新写合并规则。
→ **建议 B + A（扩到 5）**，并把优先级写成常量表。

**U6｜"逻辑实体"要不要画本体？**（阻塞批 B）
- **A. 画**（炮台=场边常驻 Sprite3D，触手=从场边地面钻出）。代价：常驻节点要跟着 `clear()` / 换路撤干净（R7），且要新素材 1 张炮台。
- **B. 不画本体**，只把那条线做漂亮。代价：**"三座炮台"和"1~2 根触手"这两个设定玩家永远读不到**，两个文件里那句"玩家看到的东西一模一样"仍然不成立。
- **C. 只在顶档画**（3 件不画、9 件画三座）。代价：低档玩家看不到成长感。
→ **建议 A**。

**U7｜升版本号的粒度？**
特效是玩家可感知改动 ⇒ 按 CLAUDE.md §2.5 要 +1；但整批切成 4 个子批。
- **A. 每个子批各 +1 + 各打 tag**（4 次）。代价：4 轮四处同步 + 4 个 tag。
- **B. 整批做完一次 +1**。代价：中途出包给测试时**说不清是哪一批** —— 而版本号的全部价值就在这。
→ **建议 A**。

### 风险

- **R1｜★数值/参数门禁绝不能等 tween。** CLAUDE.md §3.5：`verify_pirate_hook` 连红三次（帧数→游戏时钟→墙钟），根因是**场景树 `create_tween()` 在无头 CI 下推进不稳**，判定埋在两层 tween 链末尾，等多久都是 0，**本地永远复现不出来**。⇒ 本批全部门禁按 §7 的八种同步断言形态写。
- **R2｜`_skill_ring` 不守 `_world == null`**（RB:4764-4776 直接 `_world.add_child`），而 `_buff_aura`(4981-4983) / `_body_glow`(4988-4990) / `_tendril_draw`(hookbomb:723-724) 都守。**新写的每一个演出函数都要守** —— 不守的话，在"只建单位不建世界"的数值测试里是 **SCRIPT ERROR 而不是 FAIL**，会被 `run-tests.sh` 的 `FATAL` 正则接住 ⇒ 整批红，且看着像别的问题。
- **R3｜★把 `_tendril_draw` 这类函数换文件会触发审计器误报。** CLAUDE.md §2 的 ★：`tooltip_number_audit` 等审计器读战斗源码找符号，函数外迁后找不到 = 误报；而 **`sweep.sh` 不跑审计器**。⇒ 本批只要动了函数位置，**push 前必须跑全套 `bash run-tests.sh`**，`sweep.sh` 全绿不算数。
- **R4｜单帧横向素材的尺寸陷阱**（§2.4② 末尾）：`宽%高==0 且 宽/高≥2` 会被 `_burst_vfx`/`_fly_vfx` 当横排帧切开、只显示左边一格。`tendril-ha.png`(128×64) 就踩中。**这个方向现有门禁不守**（`verify_vfx_frames.gd` 守的是反方向）。⇒ 新素材尺寸要过一遍这条判据。
- **R5｜圣光护盾现在就在刷屏，而且是"隐形"的。** `_grant_shield`(`battle_damage.gd:395`) **无条件**放 `_skill_ring`；圣光每 3 秒 55×件数 ≥ 8 ⇒ `got>=8` 门槛(:393)**一次都拦不住**。顶档 6 只都装 = 每 3 秒 **6 环 + 6 字**。更糟：9 档的 `_holy_convert`(:405-415) **递归调 `_grant_shield`** ⇒ 一次给盾放**两个**环。
  ⇒ 本批的选择：**要么承认它**（不动），**要么顺手治它**（改 `_grant_shield` 加节流）——后者会**波及全项目所有护盾来源**，属于跨批改动，不建议塞进本批。
- **R6｜头顶徽章会被静默截断**（见 U5）。不先解决就加徽章 = 加了可能看不见，**且没有任何报错**。
- **R7｜常驻节点必须跟着 `clear()` 撤干净。** 炮台/触手若画成常驻节点，换路 `_dl_clear_units()` 只 free 单位、`_reg_tween` 只 kill tween，**不会 free 你挂在 `_world` 上的常驻节点**。⇒ 照抄 `verify_ms_tier_vfx.gd:136-157` 的④"撤场干净"（含"装回来又建出来"的反向验证）。
- **R8｜素材缺失时的既有约定是"不画、不兜底、判定照走"。** 仓库四处先例：`trainer_system.gd:593,1052,1289,1494` 全是 `push_warning("… 缺素材 %s —— 不画(不复用别的贴图兜底)")`。⇒ 本批**每一张**新贴图都走这条：`ResourceLoader.exists()` + `push_warning` + 静默不画。这样**代码先合入、素材后补**，素材卡住不拖住代码（同 [20260802-装备扩充.md](20260802-装备扩充.md) R13）。
- **R9｜别把"效果半径"当"贴片尺寸"。** memory `[[fb-verify-must-run-the-real-path]]`：公式全对但算出 19.2 m 的贴片，比战场还长。冲击波/触手/炮台的贴片尺寸要**单独定**，门禁量**真实直径**（`tex.get_width() * pixel_size`，照抄 `verify_ms_tier_vfx.gd:104-106`）。
- **R10｜贴地环别再叠 `-90` 旋转。** memory `[[fb-axis-y-plus-rotation-cancels]]`：`Sprite3D.axis = AXIS_Y` **本身就是平铺**，再 `rotation.x = -90` 会掰成竖环（`|世界法线·上|` 从 1.000 变 0.000），当时"两圈贴地印记一直立着"整整一场。**照抄 `_skill_ring`(RB:4767-4768) / `_aura_vfx`(4963-4964) / `_beam_vfx`(5014-5015)：只设 `axis`、不加旋转**；`ice_system` 用 `-90` 是因为**它没设 axis**，"别抄一半"。门禁验 `|世界法线·上| > 0.99`。
- **R11｜3D 特效在无头 CI 下能不能建出来 —— 有间接证据，无直接门禁。**

## 7. 门禁怎么写（★本批最容易做错的一节）

### 7.1 铁律

> **一个测"特效对不对"的用例，不该等任何动画 tween 跑完。**

根因不是"等得不够久"。CLAUDE.md §3.5 记着：`verify_pirate_hook` 连红三次（帧数 → 游戏时钟 → 墙钟），
最后查出是**场景树 `create_tween()` 在无头 CI 下推进不稳** —— 判定埋在两层 tween 链（甩钩→拉回→callback）的最末尾，
CI 上那条链跑不完，**等多久都是 0，而本地永远复现不出来**。

⇒ 演出函数的结构要配合门禁：**建节点 / 设参数** 与 **tween 动它** 分开。
**节点和参数在调用返回时就已经是最终值**（`_skill_ring` 就是这么写的：`pixel_size` 先设成 `target_ps*0.4`，tween 只负责放大到 `target_ps`）——
所以门禁验的是"**节点在、参数对**"，不是"动画放完了"。

### 7.2 八种可行的断言形态（**全部同步，调完函数下一帧就能判**）

| # | 断言什么 | 怎么写 | 先例 |
|---|---|---|---|
| **A** | **节点真的建出来了** | 调**真入口** → `for c in s._world.get_children()` 按**贴图 `resource_path`** 计数 | `verify_ms_tier_vfx.gd:165-171`。★**按节点名数会数错**：程序生成的贴图 `resource_path` 是空串 —— 这类要按 `get_class()` + 自定义 `meta` 数 |
| **B** | **参数对** | 拿到那个节点，直接读 `hframes` / `pixel_size` / `axis` / `modulate` / `position` / `render_priority` | `verify_vfx_frames.gd`（`made.hframes == nf`） |
| **C** | **贴地的真的贴地** | `absf((spr.global_transform.basis * local_n).normalized().dot(Vector3.UP)) > 0.99` | `verify_ms_tier_vfx.gd:94-103`（R10） |
| **D** | **尺寸不离谱** | `tex.get_width() * spr.pixel_size` 落在 `[下限, 上限]` 米 | `verify_ms_tier_vfx.gd:104-106`（R9） |
| **E** | **只放一次 / 跨阈值才放** | 演出函数**入口**加一个同步计数器 `u["_xxx_n"] += 1`；喂多帧同状态 → 不涨；跨阈值 → 涨 1；**再跨下一档 → 再涨 1**（反向，证明上一条不是"永远不放"） | `verify_ms_tier_vfx.gd:108-134` |
| **F** | **撤场干净** | 触发条件消失 → 再调一次每帧函数 → 节点数回 0；**再装回来 → 又建出来** | `verify_ms_tier_vfx.gd:136-157`（R7） |
| **G** | **★分母：素材在位** | `ResourceLoader.exists(path)` 逐张断言，**放在所有别的断言之前** | `verify_ms_tier_vfx.gd:43-45` —— 缺图 → `push_warning` 不画 ⇒ **下面全是空检查** |
| **H** | **头顶徽章真排出来了** | 写完字段 → 调 `s._layout_head_badges(u)` → 数 `u["_hbrow_stack"]` 里 `visible == true` 的个数 + 读 `num` 子节点的文本 | `_layout_head_row`(RB:5863-5899) **是纯同步的，一行 tween 都没有** |

**3D 粒子专用（R11）**：只断言节点与参数 ——
`ps is GPUParticles3D` · `ps.amount == N` · `ps.one_shot == true` · `ps.emitting == true` · `ps.process_material is ParticleProcessMaterial` · `ps.draw_pass_1 != null`。
**绝不数粒子、不读画面**（无头 dummy renderer 下 GPU 模拟大概率不跑）。

### 7.3 **明确不许写的断言**（各自说明为什么，免得下一个人再写一遍）

| ❌ | 为什么 |
|---|---|
| `await get_tree().create_timer(x).timeout` 之后判 | 计时器走**未钳制** delta，战斗时钟走钳制后的 `minf(delta,0.1)`（CLAUDE.md §3.5.1）。慢机器上游戏时间落后 → 假 FAIL |
| **数帧**（`for i in range(N): await process_frame`） | CI 无头帧率极高、每帧只推进 1ms（CLAUDE.md §3.5）。同样的游戏时间要跑上千帧 → 循环没退出 → **"ALL PASS" 没打出来**（rc=0、致命报错=0，极像断言失败） |
| 拿 `_t` 当尺子 | `_kill` 之后战斗判定结束、`_t` **直接冻结**（实测「游戏时间 0.00 秒 / 94 帧」）。永远不会超时 |
| **"`_sim_tweens` 数量增加了"** | **假断言**：`_kill` 里别的死亡效果也建 tween，反向验证时不会红（CLAUDE.md §3.5 原文点名） |
| **"某个特效函数存在"** | memory `[[fb-verify-must-run-the-real-path]]`：**断言函数存在守不住"还有没有人调"**。钩锁那次死代码被门禁保护着，而 `VFXPREVIEW` 还指着它 ⇒ "目视确认新实现"看的是旧实现 = 无效验证 |
| 直接点演出函数 | 同上。**一律经真入口触发**：`_shockwave` / `_slap` / `_turret_one` / `_turret_two` / 各系统的 `tick()` / `on_hit()` / `on_death()` |

### 7.4 门禁落点与帧预算

- 新文件 `tests/verify_synergy_vfx.gd` + `.tscn`。测试**自动发现**（CLAUDE.md §2），**无需登记**。
- **按上面的形态写，绝大多数用例根本不用跑真实战斗** —— 建合成单位、直接调真入口、下一帧判。
  ⇒ 默认 500 帧预算够用。**若某条确实要跑战斗**，去 `run-tests.sh` 的 `frames_for()` 登记（帧数不够 = 跑到一半被掐断，表现为"没打 ALL PASS"而**不是**某条断言 FAIL，极易误判）。
- **用干净的合成单位，别用随机 spawn 的**（memory `[[fb-ci-vs-local-divergence]]`：队伍未播种 RNG / 敌带盾 / flat_dr 会让精确数值 CI 偶发红）。
  ⚠ 但 `_world` / `_cam` 必须真在（多数演出函数不守空，R2）⇒ **实例化真场景 + 往 `_units` 里塞合成单位**，这是 `verify_ms_tier_vfx` 的做法。
- **反向验证是硬要求**：报绿之前，把每条要验的那一行注释掉，确认它会 FAIL；并打印分母。
