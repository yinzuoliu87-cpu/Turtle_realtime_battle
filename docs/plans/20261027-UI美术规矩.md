## 3. 需求 ↔ 代码的出入

**3.1 出入**

1. 全游戏的页名 / 弹框标题 / 整屏大字都是正文字体放大，像素标题字只用在两处（§2）。
2. `UISkin.title_font()`（`ui_skin.gd:309-318`）**没挂回退链**：缺字（项目文案里 30 个汉字）在桌面偷偷走系统字体、在 iOS 上是豆腐块 + 每个字号一条 FreeType 报错（2026-10-13 内测那一类）。
3. 现有标题字号几乎都不是 12 的倍数（26 / 30 / 34 / 40 / 42 / 44 / 64 / 78）。`title_label` 向下取整 ⇒ 不显式给 12 的倍数就会**悄悄变小**（30 → 24、40 → 36）。主菜单模式卡赛制名若变成 24，会撞 `tests/verify_mainmenu_layout.gd:551`（要求 ≥ 26 号）。
4. 行高变成字号 × 4/3：卡在固定高框里的标题会溢出（模式卡赛制名框高 40、赛程卡标题框高 44，换 36 号后行高 48）。
5. 有三处**按旧字体、写死字号量宽**：`top_bar.gd:189`（26）、`MatchmakingScene.gd:501`（40，摆「匹配中」后面的点点）、`MatchmakingScene.gd:553`（26）。换字体不改这三处，量出来的宽是错的。（`week_close_card.gd:329` 已经按标题字体量。）
6. 入场用**非整数倍缩放**：结算大字 1.25 → 1（`settle_screen.gd:271-275`）、收盘卡 0.85 → 1（`week_close_card.gd:304-308`）、仪式冲击 1.18 / 光 1.25（`stage_ceremony.gd:162,239`）。像素字在非整数倍下笔画粗细不匀。
7. 描边 / 投影不在像素格上：仪式大字 72 号（1 个源像素 = 6 屏幕像素）用描边 14、投影 7；缎带字 36 号（1 源像素 = 3）用描边 7。
8. 三站颜色有两套：徽章（积分赛绿 #2c914c / 闯关赛深红 #7d1a30 / 决赛日金 #e8a83b / 休赛藏青 #11143a），而赛程卡抬头是 `PHASE_HEAD_COL`（`MainMenuScene.gd:1809-1814`：积分赛 #b0602c **橙**、闯关赛 #9c3328、决赛日 #a87a22、休赛 #7a6856）—— 同一张卡上抬头是橙、徽章是绿。全仓没有一个"三站色"常量。
9. 主视觉：三站徽章源图 34~41px（高 33~39），仪式里 ×7 ⇒ 屏高 32~38%，低于 40%，源图也小于 96px。
10. 用户以前拿掉过页名的屏：商店（`ShopScene.gd:513-516` 注释记了用户 2026-08-15 删牌子的决定）、背包（`InventoryScene.gd:330-333`，10-22 背包重做跟商店同一套）；匹配页是过场、也不放页名（`MatchmakingScene.gd:343`）。**规矩不许把页名加回去。**

## 4. 方案（规矩本身）

适用范围：`scripts/scenes/**` 的全部界面（菜单、枢纽页、弹框、结算、过场、战斗 HUD 上的大字）。战斗特效另有 `vfx_discipline` 管，不在这页。

### 4.1 字体：三种，各管一类

| 用途 | 字体 | 字号 | 怎么套 |
|---|---|---|---|
| **标题**：页名、弹框标题、整屏大字、缎带字、站名 / 模式名、过场标题 | 缝合像素 12px（`fusion-pixel-12px-zh_hans.otf`；2026-10-27 前是方舟像素，见 §8-4） | **只用 12 的倍数**，按层级取：<br>24 弹框标题<br>36 页名 · 卡片标题 · 缎带字<br>48 过场标题 · 小整屏大字<br>60~72 整屏主标题（首启、晋级仪式、加时）<br>84 结算胜负（全游戏最大，只此一处） | `UISkin.title_label(label, 字号)`，字号**显式写 12 的倍数**，不靠它向下取整 |
| **正文**：说明、按钮字、表格、名字 | NotoSansSC（主题默认链） | 现有各屏常量 / `UIPalette.F_*`，不动 | 不覆盖字体 |
| **数字与拉丁**：金币、等级、比分、倒计时、VS | m6x11（主题链第一位） | 现状 | 不覆盖字体 |

硬规矩：

1. 一屏最多两级标题字号（主标题 + 一级小标题），级差至少 12。
2. 标题字只给**固定文案**；玩家昵称等输入的字不用标题字，直到回退链挂上 NotoSansSC（§6）。
3. 标题框高按 **字号 × 4/3** 留（行高），不按旧字体的框套。
4. 量宽一律 `label.get_theme_font("font").get_string_size(text, …, label.get_theme_font_size("font_size"))` —— 量**标签自己**的字体与字号，不写死字体、不写死字号。
5. 描边 / 投影厚度落在**源像素格**上（一个源像素 = 字号 ÷ 12）。★2026-10-27 实拍改正：Godot 的 `outline_size` **每边只画约 1/4**（72 号 outline 14 实拍每边 4~5px、outline 24 每边 6px；36 号 outline 7 每边 2px、outline 12 每边 3px），所以**描边 `outline_size` 取「字号 ÷ 3」的整数倍**（24 号 → 8，36 号 → 12，48 号 → 16，60 号 → 20，72 号 → 24）= 每边一个源像素；**落影偏移**是真像素，取「字号 ÷ 12」的整数倍（72 号 → 6）。`verify_title_font` ④ 守着。
6. 标题里少用「·」（这套字里它是全宽，读着空）；能用空格就用空格。
7. 不新增第四种字体；不对标题字做粗体 FontVariation。

### 4.3 光

1. 光是**叠加发光**：`CanvasItemMaterial.BLEND_MODE_ADD`，素材**不带深色描边**（`stage_ceremony.gd:220-223`）。
2. **中心最亮**：主视觉背后是光，整屏底用中心亮四周暗的径向底（`stage_ceremony.gd:57-66`）。
3. 光**逐帧**动：几帧轮播（现成：4 帧、每帧 0.15 秒，`stage_ceremony.gd:36-38`），像素画**不自由旋转**、不做平滑缩放转圈。
4. 光效素材本身用像素台阶 + 抖点，不用平滑渐变（背景底色例外）。

### 4.4 主视觉

1. **一整屏只有一个主视觉**（徽章 / 宝箱 / 立绘），其余元素都比它暗、比它小。
2. 主视觉高 = **屏高 40~55%**（720 高 ⇒ 288~396px）。
3. 静止画面**只按整数倍放大**，`TEXTURE_FILTER_NEAREST`，尺寸 = 源图 × n。
4. 新画的主视觉**画布 ≥ 96px**（这样 ×3~×4 就落在 40~55%）。
5. 现状偏差：三站徽章源图 34~41px、仪式里 ×7 ⇒ 32~38%（§3.1-9），重画要花 PixelLab 额度 ⇒ 🔲。

### 4.5 动作节拍

时长只用 `UIPalette` 五档（`scripts/util/ui_palette.gd:84-88`，`tools/ui_tempo_audit.py` 只减不增）：

| 档 | 秒 | 用在 |
|---|---|---|
| `T_TAP` | 0.12 | 点击反馈、闪白起手、淡入起手 |
| `T_BASE` | 0.20 | **冲击落定**（过曝 → 原色原大）、标题滑入到位、错开间隔 |
| `T_TRANS` | 0.30 | 页面 / 面板转场、闪白退去 |
| `T_SLOW` | 0.55 | 强调、高光扫过 |
| `T_SET` | 1.00 | 一段演出的总长单位（落定后多久扫高光、多久给"点击继续"） |

固定动作（样板：`stage_ceremony.gd:144-176`）：

1. **冲击** = 主视觉先过曝（整枚发白、略大）→ `T_BASE` 内退到原色原大。这一下是**唯一允许的非整数倍缩放**，只在冲击那 0.2 秒里。
2. **标题滑入**：从一侧滑进来，`T_BASE`、BACK 缓出；**不用缩放弹入**（结算大字现在是缩放，要改）。
3. **高光扫过**：落定后约 `T_SET`，一道斜向高光扫过主视觉，`T_SLOW`；高光按源图像素格取整，不糊。
4. 提示字（"点击任意处继续"）最后出。
5. 卡片弹入可以 0.85 → 1（`T_TRANS`），但静止态必须回到 1。

### 4.6 弹框 / 整屏的结构

1. **一屏一件事**：一张卡只讲一件事；连着几件就排成几屏依次出。
2. **标题有底板**：缎带（`ribbon-gold.png` / `ribbon-slate.png`）或顶栏，标题字 + 描边；不让一行字飘在框里。
3. 一个主视觉（§4.4）；**数字单独放大**（m6x11），不混在句子里。
4. 奖励 = 格子（`reward-slot.png`），图标占满格、数量压在格子下沿。
5. 正文 0~1 句；规则说明不在这一屏讲。
6. **一颗主按钮**；卡片 / 弹框 / 操作条里的按钮一律 `UISkin.card_button`（用户 10-22 定），不用 `UISkin.button` 的铆钉木牌（`verify_card_buttons` 守着）。
7. 入场有层次：底板 → 主视觉 → 数字 / 奖励 → 按钮，间隔 `T_BASE`。
8. 整屏庆祝点任意处关；卡片用按钮关。

### 4.7 参考与出图流程

1. 参考必须是**同一种界面**（结算对结算、弹框对弹框），不拿别的界面凑。
2. 动态的东西看**不剪辑的实录**，逐帧记时间线；**先弄清它在原游戏里什么时候出现**，再设计我们的。
3. 参考记进 `docs/plans/ref/`，写清来源与逐帧记录。
4. **PixelLab 出图前**：先说用途和要出几次（额度），参考锁定、方向稿认可之后再出。
5. 出图后：挑一致的帧、锁色、去描边（光）、按整数倍用；跨屏借用素材在 `tools/asset_borrow_audit.py` 登记理由。

### 4.8 自查（每一屏交付前）

两个比例（16:9 与 4:3，必要时 19.5:9）实拍；标题是标题字、字号是 12 的倍数、描边在像素格上；主视觉整数倍、占比对；光无深色描边、中心最亮；按钮是 `card_button`；一屏一件事。
