# 装备「本局」统计逐件补齐

日期：2026-11-15　|　状态：**已完成**

## 1. 需求原文

用户 2026-11-15：

> 「然后还有这一费装备有个电压陶瓷片，那这个装备这装备统计现在啥都没有，但是你其实是不是知道应该是些人啊、呃，比如说已获得归能这样子的东西啊，你觉得呢？」

> 「然后呢，还有你像辣椒，辣椒你是不可以写以施加流血层数是多少多少层，是不是就够了？」

（「电压陶瓷片」= 085 压电陶瓷片，「归能」= 龟能，语音识别。）我答两条规矩（结果数 + 次数 / 层数），说了会逐件过一遍给对照表，用户没有反对。

## 2. 调查结论（现状）

- 装备「本局」统计 = `EquipTally`（`scripts/systems/equip/equip_tally.gd`）记在携带者 `u["_st_eq"][件]`，面板文字 `info_panel.gd` `eq_stats_text`。改前只有 7 个键：伤害三类 / 治疗 / 护盾 / 060 的减免伤害与闪避。
- 085 的转化量 `eq_gadget_batch.gd` `piezo_settle` 一直算得出来（`give`），只是没记账。
- 盘点探针 `tests/probes/_probe_eq_tally_sweep.gd`：95 件商店装备各 3★，两种场景（我方血 ×6 打 60 秒 / 原血量打 30 秒）取并集。**改前 10 件完全没数**：
  - 漏记（bug）：**043 海浪护符**（11-14 我把打中改成 `EquipTickSystem._tick_tide_hits` 逐步碰撞时没带记账上下文 —— 护盾 / 伤害 / 击飞全没记）、**037 蛋糕蜡烛**（光圈持续回血在 `_tick_unit` 里没有上下文，回血从没记过）。
  - 没有对应的键：085 / 065（龟能）、035（深海币）、066（免控）、059（时停）。
  - 纯属性：041 / 047 / 054 / 083。
  - 场景问题（不是 bug，换场景后有数）：033 / 094 要携带者阵亡、093 要活够久。

## 3. 需求 ↔ 代码的出入

| 用户要的 | 现在 |
|---|---|
| 085 显示获得了多少龟能 | 没有龟能这个键 |
| 辣椒显示施加了多少层流血 | 只有流血打出的伤害（DoT 份额记账），层数没记 |

## 4. 方案

**两条规矩**：每件装备的「本局」= ① 结果数（伤害 / 治疗 / 护盾 / 龟能 / 深海币 / 减免伤害…）+ ② 靠触发或叠层的效果再列次数 / 层数。在通用入口统一记，不逐件接：

| 新键 | 面板文字 | 记在哪 |
|---|---|---|
| energy | 获得龟能 N | `EquipSystem._eq_grant_energy` 末尾（唯一入口，认上下文） |
| dot_bleed / dot_burn / dot_poison | 施加流血 / 灼烧 / 中毒 N 层 | `EquipTally.on_dot_add` 归到装备的那一份 |
| stun | 眩晕 N 次（029 写「冰封」） | `BattleDamage._stun` 过了免疫、目标活着、之前没晕着 |
| knock | 击飞 N 次 | `_knockback` / 主场景 `_knock_up` 过了免疫 |
| cc_block | 免疫控制 N 次（017 写「免疫击飞」） | 上面三处的免疫分支；记给 066 / 017 |
| coins | 获得深海币 N 枚 | 035 产币处 |
| ts_sec | 时停 N 秒 | 059 释放处（瞬间龟能也切到这一件） |

**两处漏记修好**：043 放浪时记下 `[携带者, 这一件]`，逐步碰撞时切回；037 的光圈 HoT 记下来源 `candle_hot_by`，结算挪进 `EquipTickSystem.tick_hots` 开头（原来就紧挨着它调用，顺序不变）、按来源切上下文。076 偷来的龟能也切到这一件。

都是纯记账：不读不改结算字段 ⇒ 对局结果不变，跨平台确定性 15 个场景摘要一位没变；规则指纹因含统计行（`_st_eq|…`）重写，`RULES_VER` 不动。

## 5. 已知风险与未决点

- 控制次数按「上下文」归属：上下文串了会记错件。盘点里每条控制都对过装备文案（028 冰瓶确有小幅击飞、038 电磁波确有眩晕、056 每 5 下击飞），没有串的。
- 056 飞镖的「击飞」是击退 + 期间眩晕两步，面板只列击飞。
- 054 瞄准镜不加：必中时不掷闪避骰，要数「本该被闪几次」只能多掷骰，会改对局结果。
- 本次盘点顺带发现：029 冰封水母的冰道也是**出手那一刻**按位置排好谁挨打（`IceSystem` 用 `EquipTickSystem.schedule`），与 11-14 修的石头龟岩脊是同一类问题 —— 11-14 全仓扫只扫了 `_pending_shots`。11-15 用户「修」：`schedule` 全部 20 处逐个过，会走的扫荡只有 029 冰道 / 024 喷火龙两处，改成 `EquipTickSystem._tick_sweeps` 每步碰撞（门禁 `verify_ice_fissure` ⑦ / `verify_dragon_breath` ⑤，换回旧写法各红两条）；028 冰瓶的画面改成追着目标飞（判定本来锁定目标）。其余是纯演出或锁定目标的弹道。

## 7. 决策记录

- 11-15 用户提 085「已获得龟能」、辣椒「施加流血层数」；我提两条规矩并说逐件过，用户未反对，按此做。
