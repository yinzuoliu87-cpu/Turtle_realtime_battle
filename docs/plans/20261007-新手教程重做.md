用户「行」认可的方向（逐条钉住，实施时不许漂）：

1. 首次启动弹出选择：标题「新手教程」，两个按钮「开始教程」「跳过」。
2. 选「跳过」= 拿到与走完教程**完全相同**的东西（解锁项、币、标记一致），直接进主菜单。
3. 教程进行中，右上角常驻「跳过教程」按钮。

6. 文案不口语化。

## 4. 方案

### 4.1 新流程（逐步表）

原则：一步一句、祈使句、不带感叹/语气词；每步都有 `advanceOn`；**不渲染任何「下一步/知道了/完成」按钮**；事件可「越级」推进（玩家做了后面那步的动作，前面没做的步一并视为完成，防止卡死，例如没拖动就直接点开打）。

| 步 | 屏 | 高亮目标（锚点） | 文案（一句） | 前进事件（谁发） | 备注 |
|---|---|---|---|---|---|
| 0 | 主菜单首启 | 选择框 | 标题「新手教程」，按钮「开始教程」「跳过」 | 按钮 | 不是提示条，是模态选择框 |
| 1 | 选龟 | `roster` | 选择 3 只龟上阵 | `team_filled`（已有，`TeamSelectScene.gd:1238`） | |
| 2 | 选龟 | `confirm` | 点击出战 | 离开本屏（导演 `next_scene_after("team_select")`） | |
| 3 | 战斗·摆位 | `field` + 一只我方龟 | 拖动龟调整站位 | 新增 `unit_dragged`（`_dl_handle_place_input` 松开且位移 > 阈值时发） | 只在 `_dl_enter_place()` 后出现（修 B1） |
| 4 | 战斗·摆位 | `go_button` | 点击开打 | `fight_started`（已有） | 开打后全程无提示 |
| 5 | 结算 | 结算按钮 | 点击前往商店 | 离开本屏 | 新增结算按钮锚点 |
| 6 | 商店 | 买经验按钮 | 购买经验，升到 2 级 | 新增 `level_up`（`GameState.buy_season_xp()` 成功且等级变化） | **仅当 U3 选 A** |
| 7 | 商店 | `offer` | 购买 1 件装备 | 新增 `item_bought`（`ShopScene._on_buy` 扣币成功处） | 修 B2 |
| 8 | 商店 | 顶栏「背包」按钮（`TopBar.action_btns[0]`） | 点击背包 | 进入背包屏 | 删掉黄色「下一站」浮钮（修 B7） |
| 9 | 背包 | `backpack` 里第一件装备 | 点击一件装备 | 新增 `bench_selected`（`_on_bench_click`） | |
| 10 | 背包 | `lanes` 里一只统领 | 点击一只龟装上 | 新增 `item_equipped`（`_inv_ops._equip_to` / `_equip_minion` 成功） | |
| 11 | 背包 | 「完成教程」按钮（教程专用，替代返回箭头的位置） | 点击完成教程 | 按钮 ⇒ 导演 `end_tutorial("completed")` 回主菜单 | 主菜单飘一行「教程完成」 |

删除的站：第二把战斗、图鉴站、战斗内「观察 / 点龟看面板 / 双指缩放」三条说明（U2 已定）。

**教程期间没有任何返回入口**（用户 2026-10-07：「教程里就不应该有返回键啊，要一直跟着教程走啊」）：选龟/战斗/结算/商店/背包各屏的返回箭头、顶栏切屏按钮、结算「返回主菜单」、认输键、ESC/安卓返回键在 `tutorial_active` 下全部隐藏或吞掉；遮罩只放行当前步的高亮目标。唯一的出口是右上「跳过教程」（`end_tutorial("skipped")`）与第 11 步「完成教程」。

### 4.2 跳过 / 完成 / 放弃 —— 合成一个出口

新增 `TutorialDirector.end_tutorial(reason: String)`，`reason ∈ completed / skipped / abandoned`，**三种做同一件事**（这正是需求 2 的「相同」）：

1. 丢弃教程沙盒，把进教程前的**整份**账号状态原样换回（见下方「教程 = 完全隔离的沙盒」）
2. `GameState.dual_active = false`、`dual_ghost = {}`
3. `onboarded = true`、`tutorial_active = false`、`tutorial = false`、`tutorial_stage = "done"`、`tutorial_mandatory = false` —— **这是教程唯一带回账号的东西**
4. `GameState.save()`（此时内存里已是账号原状态 + 上面这几个标记）
6. 当前不在主菜单 ⇒ 切回主菜单
7. 记一行 `reason`（只用于日志/门禁区分，不影响状态）

调用点：
- 首启选择框「跳过」：`end_tutorial("skipped")`，留在主菜单并重建入口（商店锁状态立即刷新）。
- 教程中右上「跳过教程」：`end_tutorial("skipped")`。
- 第 11 步回到主菜单：`end_tutorial("completed")`。
- 看门狗（`_process` 认出「离开过主菜单又回来」，`tutorial_director.gd:64-80`）：原 `on_abandon()` 改为 `end_tutorial("abandoned")` ⇒ 顺手修 X3。
- 关窗 `NOTIFICATION_WM_CLOSE_REQUEST`（`:83-88`）：仍只还原经济并落盘，**不置 `onboarded`**（下次启动再问一次）。
- 进程被杀：`tutorial_active` 不进存档 + 残留文件兜底还原（现有 `restore_residue_if_any`）⇒ 下次启动 `onboarded=false` ⇒ 再弹选择框。

**幂等**：`end_tutorial` 连调两次，第二次只是重复写同样的标记；不发币、不加场次 ⇒ 结果不变。

**教程 = 完全隔离的沙盒**（用户 2026-10-07：「教程里的商店怎么能够和账号的商店互通呢，你懂什么叫教程吗，整个教程都不应该有当前存档的东西啊」）

- 推翻原做法「快照真存档的几个字段 → 教程里直接改真存档 → 结束还原」：那是在账号存档上做教程，漏一个字段就污染（X4 就是这么来的），方向本身错。
- 新做法：
  1. 进教程时把 `GameState` 的**整份**序列化状态存进内存（不挑字段），然后把 `GameState` 重置成一份**全新的教程专用状态**：固定 3 只教学龟、教程币、教程货架、1 级起步，和一个刚注册的新号一样，与账号存档无关。
  2. 教程期间 `GameState.save()` 一律不写盘（沙盒标记下直接 return），账号存档文件全程不被打开写入。
  3. 结束（完成 / 跳过 / 中途退出 / 看门狗）丢弃沙盒，把第 1 步存的整份状态原样换回，再只写上 `onboarded` 等教程标记。
  4. 进程被杀：账号存档从没被写过，重启自然是原样；只需 `onboarded=false` ⇒ 再弹选择框。
- 教程里的商店、背包、等级、装备全是沙盒里的，**与账号商店无关**；账号侧规则（本大轮首战后开商店）不因教程改变。⇒ 原 U1「教程后商店解不解锁」不再是问题，删除。
- 门禁：进教程前后对账号存档文件做逐字节比对（除 `onboarded`/`tutorial_stage` 等教程标记外完全相同），并在教程中途截一次「存档文件未被写入」。

### 与方案的偏差

- 沙盒用「新建 GameState 实例读默认值」实现全新状态，而不是手写一份字段表 —— 不挑字段，新增字段自动进沙盒。

- 第 3 步「拖动龟」的完成事件只在松手且位移 >20 战场像素时发（点一下不算）。

### 新发现的坑

- 提示条「矩形稳定」挡不住**淡入**型入场（结算屏「前往商店」淡入时洞挖在空地上）⇒ 加 `vis_rect`（透明度乘积）。
- 无头下 `Input.parse_input_event` 不往视口派发；门禁里用 `push_input`（拖动另用 parse 只为更新鼠标键状态）。
- 存档读回后整数变 float（2 → 2.0），所以「逐字节相同」的基线必须取「读档后再存」那一份 —— 与教程无关。
