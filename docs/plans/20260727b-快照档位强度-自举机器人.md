### 2.2 现状装备强度曲线（用门禁自带公式实算）

公式来自门禁自身 [verify_bracket_gear.gd:114-116](../../tests/verify_bracket_gear.gd#L114-L116)：
`强度 = cost × 1.8^(star−1) × k(cost)`，`k={1:0.85,2:0.90,3:1.00,4:1.15,5:1.30}`
**注意：这个公式只吃装备的费用与星级，本来就不含精英与等级** —— 与你「强度主要是装备强度」的判断一致。

| 档 | 装备/只 | 平均星 | 平均费 | **单件均强度** | **环比** | 队均总强度 |
|---|---|---|---|---|---|---|
| 0 | 0 | – | – | 0 | — | 0 |
| 1 | 1 | 1.00 | 1.11 | 0.96 | — | 2.9 |
| 2 | 2 | 1.29 | 1.92 | 1.97 | **+106%** | 11.8 |
| 3 | 3 | 1.69 | 2.39 | 3.18 | +61% | 28.6 |
| 4 | 4 | 1.90 | 2.70 | 4.26 | +34% | 51.1 |
| 5 | 4 | 2.07 | 3.14 | 5.75 | +35% | 69.0 |
| 6 | 4 | **1.82** | 3.85 | 7.01 | **+22%** | 84.1 |
| 7 | 4 | 2.41 | 3.84 | 9.73 | +39% | 116.7 |
| 8 | 4 | 2.60 | 4.32 | 13.22 | +36% | 158.6 |

**队均总强度**才是玩家的真实体感（件数 × 单件），它的跳变更陡：`2.9 → 11.8 → 28.6 → 51.1`，**档1→2 翻 4 倍、档2→3 再翻 2.4 倍**。前四档是断崖区。

## 3. 需求 ↔ 代码的出入（本节最值钱）

### ⛔ 出入1：「档0 无装备」在数据层成立，**在实际匹配层不成立**（我上一版说反了）
- 数据层：档0 的 12 支队，队长与小将确实 0 件，且有门禁守（[verify_bracket_gear.gd:81](../../tests/verify_bracket_gear.gd#L81)）

- → **"新玩家第一把遇到无装备对手" 目前并不成立。** 门禁只查 json、不查匹配窗口，所以一直绿着。
- 修法两条（待选）：档0 玩家不走窗口只抽本档；或把窗口下沿钳在"不低于也不高于自己"。**列入 §4 D。**

### ⛔ 出入2：「档8 = 纯3星5费」与你 2026-07-21 的决定相反
[verify_bracket_gear.gd:8](../../tests/verify_bracket_gear.gd#L8) 原文：*"旧档8 全 5费3星, 用户明确说 **5费3星『几乎不存在』**"* —— 档8 曾经就是纯3星5费，正因这句被改成现状 2.6星/4.32费。今天要改回去。可能是有意反转，但需你确认（U1）。

### ⛔ 出入3：「纯3星5费」与经济算术冲突
1 件 3星5费 = 9 件**同款**1星5费 = 45 币且商店要吐同一 id 九次；满配 12 件 ≈ **540 币** 跨 9 个 id 各 9 次。而档8 代表 45 场。**自举出的档8 长不成这个形态** → 自举上限 与 手工天花板 二选一（U1）。

### ⚠ 出入4：**30 把只能覆盖到档 6**
`bracket_for_battles`：≤30 → 档6，≤40 → 档7，>40 → 档8。
**打 30 把验不到档7/档8**，而档8 正是你给了锚点的那一档。建议：默认 30 把（你点的数），**另加一档可配 `N=45` 的长跑**把 7/8 也覆盖到。要不要跑长的，见 U3。

### ⚠ 出入5：「某档突然变难」实测位置与直觉不同
单件强度环比最陡在**档1→2（+106%）**、谷底在**档6（+22%）**；但队均总强度看，**档1→2 翻 4 倍**是全程最猛的一跳。若测试者说的是中后期变难，则与装备强度数据相反 —— 机器人跑完就能定论，不必现在争。

## 4. 方案

### 4.A 机器人本体（第一步交付，先做这个）

新文件 `tests/_autoplay.gd` + `.tscn`（**下划线前缀** —— `run-tests.sh` 只自动发现 `verify_*.gd`，工具不进门禁；与 `_tutorial_playthrough.gd` 同惯例）。走**数据层**，不走 UI、不建 3D 窗口、不等任何 tween（CLAUDE.md §3.5）。

**起跑状态**：全新存档（`reset_save()` + `start_new_season()`），`season_total_battles = 0`、背包空、零装备 —— 即真·第一把。

**单把循环**（重复 30 次）：

| 步 | 动作 | 用的 API |
|---|---|---|
| 1 | 选 3 龟（首把定，之后沿用） | `GameState.left_team` |
| 2 | 匹配对手 | `Backend.find_opponent(bracket, exclude, rng)` |
| 3 | **记赛前账**（见 4.B） | — |
| 4 | 开打（跳摆位） | `DL_AUTOFIGHT` + `dual_lane_flow` |
| 5 | 记胜负与比分 | `GameState.dual_lane_winner()` / `lane_results` |
| 6 | 收币 | **★未知口，必须先探，见 §5 P1** |
| 7 | 逛商店：出货 → 按策略买 | `Phase2Equip.roll_shop` |
| 8 | 回背包：三合一 → 装/换 | `auto_merge_all()` + `equip_to_turtle()` |
| 9 | 场次 +1 | `season_total_battles += 1` |

**买装策略**（可插拔，`AUTOPLAY_STRATEGY=`）：
- `merge_first`（默认·最像真人）：预算内优先补齐已有同款凑三合一，溢出才买更高费
- `greedy_cost`：永远买买得起的最高费（强度上限高、永远升不了星）
- `random`：随机买（对照组，探强度下界）

### 4.B 逐把记账（「每把情况记录好」）

每把一行，字段：

```
把次 / 赛季总战斗数 / 我的档位
我方: 3龟id+等级 + 每龟每件装备(id·名·费·星) + 队均总强度 + 背包余装 + 币余额
对手: ghost_id · is_bot · 它的档位 · 3龟id+等级 + 每龟每件装备(id·名·费·星) + 队均总强度
结果: 胜/负 · 上路/下路/终极 逐路比分
本把商店: 出货6件(id·费) / 实买了哪几件 / 花了多少币 / 触发了哪些三合一升星
```

产物两份：`tools/autoplay/run-<N>把.md`（人读）+ 同名 `.csv`（画曲线）。末尾汇总：**总胜率、按档胜率、我方与对手队均总强度逐把对比曲线**。

### 4.C 自举回路（第二步，等 30 把数据出来再定参数）

```
R0: 机器人打【现有 seed 池】→ 每把把自己当时阵容存回对应档 → 产出池 P1
R1: 打 P1 → 产出 P2 … 直到胜率进目标带且各档强度环比平稳 → 冻结导出 ghost_seed.json (SEED_VER+1)
```
每轮从固定初始存档起跑（防跨轮污染）、RNG 固定种子（`TURTLE_SEED`，[backend.gd:240](../../scripts/net/backend.gd#L240) 已支持）、保留 R0 基线对照。

### 4.D 匹配窗口修正（出入1）
让档0（或"第一把"）不吃 ±1 上沿，保证新玩家首战对手真的无装备。

### 4.E bot 兜底对齐（[backend.gd:83](../../scripts/net/backend.gd#L83)）
现在是"全 1 星 + 随机装备"，与自举池不同源；改成按目标档画像生成。

### 4.F 门禁补强（[verify_bracket_gear.gd](../../tests/verify_bracket_gear.gd)）
保留全部现有断言，新增：**环比涨幅带**（直接守"跳变"）+ **匹配窗口断言**（档0 玩家抽不到带装备的对手）。

## 6. 验收标准（含"怎么证明这个检查会 FAIL"）

| 验收项 | 通过判据 | **反向验证（先证明它会红）** |
|---|---|---|
| 机器人真在打 | 30 行记录齐全，打印总把数 N | **把对手装备全清空 → 胜率必须飙到 ~100%**；若仍 50%，说明对手压根没生效 |
| 机器人真在买 | 逐把打印出货/实买/花费/余额 | 把预算设 0 → 购买数必须恒 0 |
| 机器人真在装 | 逐把打印每龟装备位变化 | 关掉装备步 → 我方队均强度必须恒 0 |
| 三合一真在触发 | 打印升星事件 | 给 3 件同款 → 必须升星；给 2 件 → 必须不升 |
| 记录可信 | 我方/对手强度用**同一个** `_strength` 公式算 | 手改一件装备星级 → 强度数字必须跟着变 |
| 分母非空 | 打印 N；**N=0 判空检查，不判通过** | — |
