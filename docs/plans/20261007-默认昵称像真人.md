我给的方案（真人用户名的五类长相，中英约各半、有的带数字有的不带、长短不一；词放数据文件；屏蔽词；老号一次性迁移；机器人与真人同一个生成器），用户回：

逐条钉住（防漂）：

| # | 用户原话 / 已拍板的方案句 | 钉成什么 |
|---|---|---|
| ① | 「你得看现实玩家会用的名字」「用户名就行的」 | 默认名照真人用户名的长相：lyz0721 / kevin_99 / 豆豆 / 阿杰 / 不吃香菜 / 咸鱼本鱼 / 我要上王者 |
| ② | 「你这一看就是人机」 | 不许每个名字同一个形状；不许用游戏里的词（龟名 / 被动名 / 名头） |

## 2. 调查结论

- 旧生成器：`scripts/gamedata/phase2_config.gd` 原 1209~1304 行，定语 = `data/pets.json` 28 龟名去尾「龟」+ 28 被动名（56 个），名头 `NICK_HEADS` 6 个 ⇒ 336 个名字，全是「定语 + 名头」一个形状。
- 调用点：`nickname_fallback`（真人默认名，按账号 sha256 取两段 28 bit）、`backend.gd` `make_bot` 与 `seed_as_human`（机器人 / 内置陪练，`nickname_suggest_at(rng.randi(), rng.randi())`）、`SettingsScene.gd` 绑定屏与改名框的「换一个」（`nickname_suggest(avoid)`）。
- 默认名冻结：`autoload/GameState.gd` `default_nickname()` 第一次调用时生成并 `save()`，之后只读 `nickname_default`。所有上传 / 显示都经 `Backend.player_display_name()` → `default_nickname()`（快照 `build_ghost_snapshot` 的 `profile.name`、周日报到 `enter_finals_async`、排行榜、对阵图、回放 `viewer_name`、顶栏）。
- 旧池在 2026-09-29 ~ 2026-10-07 之间没变过：逐个提交核过 `data/pets.json` 的 56 个定语，各版本一致（脚本见实施回填）。
- 内置陪练：`_ensure_seeded` 只在 `SEED_VER` 升版或换赛季时重盖 ⇒ 不升版的话，老存档池里 396 条陪练还叫旧名字。

## 3. 需求 ↔ 代码的出入

- 「默认名 = 生成器结果」只对**新号**成立：老号的默认名已冻结进存档（10-04 拍板），换生成器不会自己生效 ⇒ 需要一次性迁移，否则约 120 个模拟选手和早期测试者永远叫「石头统领」。
- 「机器人也用同一个生成器」代码上已经成立，但内置陪练名字是**入池时**算的、存在本机池里 ⇒ 要靠 `SEED_VER` 升版让老池重盖。
- 绑定邮箱那屏把预填的默认名写进了 `GameState.nickname`（`SettingsScene.gd` 绑定确认处）⇒ 绑过邮箱的老号，旧默认名已经变成「自己起的」，按 ⑤ 不动（见 §5 R1）。

## 4. 方案

1. **词表** `data/nickname-words.json`（新文件，唯一出处）：模板表（15 种，带权重）+ 英文名 / 英文词 / 拼音名 / 拼音姓 / 首字母 / 单字名 / 姓 / 叠字 / 前后缀 / 整句名（随手一句、网络梗、游戏味）/ 装饰词 / 生日年份 / 短数字；屏蔽词 `block_sub`（小写子串）+ `block_core`（拉丁核心整串）+ `reserved`；兜底 `safe`；旧池 `legacy_v1`（冻结的 56 定语 × 6 名头，只用于认旧名）。
2. **生成器**（`phase2_config.gd` 「预填一个名字」节整段重写）：`nickname_suggest_at(si, hi)` 用两个整数播种一个本地 `RandomNumberGenerator`，按权重挑模板拼名字；拼出来不合法（超长）或撞屏蔽词就用同一个 rng 接着重抽（确定性），抽 24 次都不行落到 `safe` 表。`nickname_blocked` 判最终串：屏蔽词 + 与龟名 / 被动名 / 训龟大师相同 + 旧版名字。`nickname_suggest(avoid)` 重抽到不同为止，兜底从 `safe` 里挑一个不同的。`NICK_LAST_RESORT` 从「小龟主」换成「路人甲」。删掉 `NICK_HEADS` / `NICK_WORDS` / `NICK_STEM_FALLBACK` / `nickname_stems`。
3. **迁移**（`GameState.default_nickname()`；`nickname` 那一半在 `GameState._migrate_legacy_nickname()`，读档时调）：`nickname_default` 是旧版名字（`nickname_is_legacy_default`）且 `nickname == ""` ⇒ 按同一个种子（账号优先、没账号用安装号）用新生成器重算、落盘、打一行日志。新生成器永远不产出旧池名字 ⇒ 换过一次就不再触发，不另存标记。
4. **陪练**：`backend.gd` `SEED_VER` 15 → 16，老池里的陪练按新生成器重盖名字。
5. **门禁**：`verify_login_wall` ⑦A 整节重写（像真人 / 每个合法 / 长相杂 / 熵 / 换一个）、⑥e 谓词换成「像真人」；`verify_nickname` 去掉穷举池、⑥② 改成「词表改了」、新增 ⑧ 迁移一节；`verify_bot_card_honest` 改成机器人 vs 真人默认名的字形占比比较。

## 5. 已知风险与未决点

- **R1 已拍板（主会话 2026-10-07 代用户拍板，用户已说「行」）**：绑过邮箱的老号，绑定那一步把预填的旧默认名（如「石头统领」）写进了 `nickname`。决定：`nickname` 是旧池名字就当作没起过名 —— 读档时（`GameState._apply_save_dict` → `_migrate_legacy_nickname`）清空，默认名按同一个种子换新，只一次；旧池以外的名字一个字不碰。
- **R1b 已知**：迁移只在读档时做（开游戏 / 云存档落地），不在显示时做。代价：玩家此后**自己**改名改成旧池里的名字（如「石头统领」），下次开游戏会被清掉换成新默认名。旧池名字现在等同保留字，不另加改名拦截（未要求）。
- **R2 已知、不改**：服务端已存的旧名字不会自己变 —— 快照 / 排行榜要等这个号下一次上传；**本周已经报过到的决赛日 `finals_entrants`** 里存的是报到那一刻的名字（服务端没有改名接口，`SettingsScene.gd` 改名节也写着同一条），本周对阵图上仍显示旧名；本周已录好的回放 `viewer_name` 同理。
- **R3 已知**：模拟选手 p01..p120 的存档要等下一次开那个存档才迁移（迁移是启动后第一次取显示名时做的），没开过的那些在服务端还是旧名。
- **R4 撞名**：整句名（随手一句 / 梗 / 游戏味）约 170 条，抽中率约三分之一 ⇒ 120 人里会有几对同名；同名靠玩家 ID（`names_needing_tag`）分开，与旧版一样不做唯一性约束。2 万个样本去重约 8900 个。
- **R5 屏蔽词是黑名单**：只能挡列出来的；拼音首字母随机组合（如 sb / nmb / xjp）已逐个列入子串屏蔽，误伤只会让生成器重抽，不会放出名字。玩家**自己输入**的昵称仍然不过屏蔽词（本轮范围外，旧行为）。
- **R6 已堵**：迁移不能把新名字又认成旧名字（来回跳）—— `nickname_blocked` 拒绝旧池名字，门禁 ⑧① 断言新名字不是旧版。
- **R7 已堵**：`SEED_VER` 升版会把陪练整批清掉重并（桶序变化），这是历次升版的标准路径，`verify_ghost_seed` / `verify_pool_truth` / `verify_bot_snapshot_shape` 已跑过。

与方案的偏差：

- 迁移不另存版本标记（§7 已记）。
- 「换一个不避开」这条原来的随机抽查拿不掉（撞上的概率太小），补了一条把命名随机源倒回去的确定性断言。
- 词表调过三轮：看样本时删掉了几个读着别扭/有歧义的叠字（奶 咪 面 蛋 饭）和后缀（哥 姐），英文名后缀只留 酱 / 同学；随机两位数里的 64、38、69 和首字母组合 zf / sys / zz 等加进屏蔽词；整句名尾巴去掉单个数字。

新发现的坑：

- 绑定邮箱那屏会把预填的默认名写进 `nickname`（§5 R1，已按拍板迁移）。
- `default_nickname()` 里原来「`nickname` 为空才换默认名」的条件拿掉了：变异它没有任何门禁红，因为它只影响一个起过名的人看不见的字段 —— 留着就是一条没人守的分支。
- Git Bash 的 `sed -i` 把 CRLF 文件改成了 LF（memory `fb-grep-sed-lie-about-crlf`），当场用 python 恢复。
