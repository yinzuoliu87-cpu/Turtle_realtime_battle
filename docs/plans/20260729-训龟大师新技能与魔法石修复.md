## 2. 三个 bug 的根因（已查实，非推测）

### 2.1 局内右下圆盘图标显示的是钩锁而非魔法石

`scripts/scenes/battle/battle_hud.gd:130-133`：

```gdscript
var _act: String = GameState.trainer_active_skill()
var sid: String = battle._valid_active(_act) if _act != "" else ""
var ipath: String = str(battle.TRAINER_SKILLS.get(sid, {}).get("icon", battle.HOOK_ICON))
```

选魔法石（**被动**）时 `trainer_active_skill()` 返回 `""` → `sid = ""` →
`TRAINER_SKILLS.get("", {})` 取不到 → **回落到默认值 `HOOK_ICON`**。

★ 注意：`TRAINER_SKILLS` 里**根本没有 `magic_stone` 条目**（它只收主动技），
被动的图标在 `TrainerConfigScene.gd:10` 的 `SKILLS` 列表里（`magic-stone-icon.png`）。
两张表各存一半 —— 这本身也是个分歧源。

### 2.2 没有"循环绕圈"特效

**是已知待办，不是坏了。** 同一处注释自己写着：

> `# 单技能装配(2026-07-26): 装配的是被动(magic_stone)时无主动→ _act 为 ""(R2 再给圆盘加"被动生效中"循环特效)。`

当时标成 R2 推迟了。

### 2.3 石头命中只看到一个伤害数字

`trainer_system.gd:90-93`：

```gdscript
battle._ballistics._fire_trainer_rock(u, tgt)      # 物理: 归巢弹道, 【命中时】才结算
if str(u.get("_tr_passive", "")) == "magic_stone":
    _trainer_magicstone_onhit(u, tgt)               # 魔法: 【立即】结算, 不等弹道
```

**两段伤害在时间上错开**：魔法在扔出瞬间就跳字，物理要等石头飞到目标才跳。
所以看起来不是"一起出伤"。

### D. 魔法石被动加强（追加需求）

**现状实测值**（`battle_spawn.gd:242-248`）：训龟大师是**定值 500血 / 1攻 / 0双抗 / 移速0 / 射程2000**，
且**明确不吃等级缩放**（注释：「用户给的 500/1/0/0 是【定值】，缩放会让"伤害降为1"之外的血量随大轮涨，与"场外监视者"的设定不符」）。

| # | 子需求 | 现值 → 新值 | 备注 |
|---|---|---|---|
| D1 | 选魔法石时**训龟大师获得 10 倍攻击力** | ATK **1 → 10** | 只在选魔法石时生效（选主动技时仍是 1） |
| D2 | 普攻附带 **(2 + 0.1×大轮等级)% 目标最大生命**魔法伤害 | 固定 2% → **2.0%～3.0%** | 大轮等级 = `GameState.season_level`（1–10）：Lv1 = 2.1%、Lv10 = 3.0% |
| D3 | 原有的「每次攻击自身 +5% 攻速（可叠·本场重置）」 | **不变** | `trainer_system.gd:82` |

**换算**（石头本体伤害 = `1×ATK` 物理，见 `battle_spawn.gd:242` 注释「扔石头1物理」）：

| | 物理 | 魔法（打 1000 血目标） | 合计 |
|---|---|---|---|
| 现在 | 1 | 20 | **21** |
| 改后 Lv1 | **10** | 21 | **31** |
| 改后 Lv10 | **10** | 30 | **40** |

⚠ **注意 D1 的实际影响比看上去小**：训龟大师 ATK 从 1 变 10，
但它的伤害大头一直是**按目标最大生命百分比**的那段魔法（20–30 点），

## 4. 实施要点（已知的坑）

1. **新增 `aim: "target"` 模式** —— 现有 `battle_aim.gd` 只支持 `dir`(方向)/`point`(落点)/`none`。
   "指定敌方单位"是第三种，要新写选中判定（点/触到哪个敌人）+ 高亮反馈。
2. **受伤放大走唯一入口** —— `RealtimeBattle3DScene.gd:4353` 是全项目唯一的"受伤倍率"判定点，
   钩锁的 +25% 就在那。猎龟令的 +15% 必须加在同处，**不要在技能里自己乘**。
3. **归顺不要改写 `side`** —— 赛博侵入 2026-07-22 重做时踩过：
   改 `side` 会导致「赛博全队索敌跳过它 / 死亡不归队 / 跨路串阵营 / 单路瞬间判胜 / 召唤物串队」四类问题。
   现在的做法是只挂标记，敌我关系由 `_is_hostile` 统一裁决。**驯服必须沿用**。
4. **每秒 2% 掉血用 DoT 而不是自己写 tick** —— 项目有两条独立伤害路径
   （`_apply_damage` / `_apply_damage_from`），自己写 tick 容易漏掉减伤/护盾/统计。
5. **重生演出别让数值依赖 tween** —— CLAUDE.md §3.5：无头 CI 下 `create_tween()` 推进不稳，
   演出链跑不完。**"重生"这个事实必须即时置位**，2.5 秒回血过程才是演出。

## 5. 已知风险与未决点

### 5.1 驯服的"归顺"语义 —— ✅ **用户 2026-07-28 已拍板：「顺归算我方」**

赛博侵入是**临时倒戈 4 秒**，被侵入者是**孤军**（不算赛博方友军、不能被治疗/护盾、不算存活数、仍会被原队友攻击）。
驯服是**永久归顺、随我方战斗**，按用户拍板**算我方**，三条连带后果：

| | 处理 |
|---|---|
| 能被我方治疗/护盾 | **能**（`_is_ally` 要认它 → 会进入天使祝福、寒冰团队护盾等"全体友军"技能的作用范围） |
| 算我方存活数 | **算** —— 意味着我方统领全灭但被驯服单位还活着，**这一路不算输** |
| 击杀归属 | **归我方** |

⚠ 「算存活数」是三条里影响最大的：它直接改变**单路胜负判定**。已按用户拍板执行。

### 5.2 跨入终极战场 —— ✅ **难度不大**（★下面这段是对我先前说法的更正）

> **我先前写的「终极战场硬要求恰好3统领、插一个额外单位会牵动结构校验/UI/胜负判定」是错的。**
> `_dl_structure_ok`（`GameState.gd:658`）管的是**赛前布阵**，不是终极战场。查实后：
> **终极战场阵容 = `_dl_snapshot_survivors()` 拍的上下路幸存单位累加（含小将、带 30% 回血）**
> （`dual_lane_flow.gd:632`、注释 `459: 终极战场我方/敌方阵容 = 上下路累加的幸存(含小将+30%回血)`）。

幸存快照已有现成结构，被驯服单位跨入只需三步：

```gdscript
spec = {"hp_frac": …}                    # 回血后血量比例
spec["kind"] = "minion" / "leader"       # 小将还是统领
spec["role"]/["elite"]  或  spec["id"]   # 具体是什么
spec["equips"] = […]                     # 带装备进终极(2026-07-18 补的)
```

1. **快照时按 `_eff_side` 分组**（现在按 `u["side"]`，被驯服单位的 `side` 仍是原队 → 会被算进敌方）
2. **spec 加 `tamed: true`**
3. 终极战场 spawn 时看到该标记 → 重新挂驯服态（归我方 + 每秒 2% 掉血）

**不用碰结构校验、不用碰 UI 头像栏、不用碰胜负判定。**

⚠ **仍需实测的一点**：被驯服的可能是**敌方统领**（如敌方凤凰）。
重建时它以「我方阵营的凤凰」身份 spawn —— 若我方本来也有凤凰，**同 id 两只同场**是否冲突（头像栏/统计/技能绑定）**未验证**。

### 5.3 训龟大师技能表分成两张 —— 建议一并收口

- `RealtimeBattle3DScene.TRAINER_SKILLS`（战斗用：cd/range/aim/icon）
- `TrainerConfigScene.SKILLS`（配置页用：kind/name/icon/desc）

**图标在两张表里各写一份**，2.1 那个 bug 正是因为战斗侧表里没有被动条目。
建议合成一张（或加门禁校验两表一致），否则新增两个技能会让分歧变成三份。

### 5.4 猎龟令的嘲讽范围是"跟随目标"还是"施法时定住"？ —— **未决**

需求写"嘲讽 400 码的我方友军…圈圈内的我方友军会优先攻击该目标"。
若圈**跟着目标走**，目标可以主动逃离我方友军把圈带走；若**定在施法点**，则是个地面区域。
两种手感差别很大。

### 5.6 ★「10 倍攻击力」的实际收益远小于字面 —— **需你确认是否够**

见 D 节换算：大师普攻 = `1×ATK 物理` + `2% 目标最大生命 魔法`。
ATK ×10 只把**物理那 1 点变成 10 点**，而魔法那段（打 1000 血目标 = 20 点）**完全不吃 ATK**。
所以总输出从 21 → 31（Lv1）或 40（Lv10），**提升约 1.5~1.9 倍，不是 10 倍**。

如果你的意图是"魔法石流的大师要能真的打死人"，可选的额外杠杆：
石头物理系数（现 `1×ATK`）、攻击间隔（`TRAINER_ATK_INTERVAL`）、或让魔法那段也吃 ATK。
**这条未拍板前我按字面实现（ATK×10 + 百分比随大轮涨）。**

### 5.5 未量化的影响

- 猎龟令的 +15% 受伤与钩锁的 +25% **是否叠加**？（同一入口，默认会叠）
- 被驯服单位每秒掉 2% 最大生命 —— 对高血量单位（龟壳 1029）是每秒 20 点，
  对小将（750）是 15 点，**相对强度不同**，是否符合预期未验证。
