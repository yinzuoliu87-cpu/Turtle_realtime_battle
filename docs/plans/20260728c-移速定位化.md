# 移速定位化 —— 把「定位」提升为权威事实源 · 方案书

**日期** 2026-07-28 ｜ **状态** 已实施（用户逐条拍板）
**前置** [20260728b 龟技能加强削弱·第一轮](20260728b-龟技能加强削弱-第一轮.md)
**触发** 用户：「在第二次胜率测试前，还需要对所有龟的移速做一个整改」

---

## 1. 问题（实测，不是推测）

### 1.1 移速根本没设计过

28 只龟只有 **4 个移速值**：`145×11 只 / 105×11 只 / 74×1 只 / 70×5 只`。
11 只挤在 145、11 只挤在 105 —— 移速不承担任何角色区分功能。

### 1.2 移速与强弱**无关**

拿第一轮 3486 场全循环的按龟胜率去对：**相关系数 r = −0.087 ≈ 0**。
→ 移速目前不是平衡杠杆。改它不会直接改变强弱，它改变的是**战斗形态**（谁能贴到谁）。

### 1.3 ★真正的病：远程比近战跑得快，关系是反的

| | 只数 | 平均移速 |
|---|---|---|
| 近战（射程 70） | 15 | **104** |
| 远程（射程 400） | 13 | **125** |

- 145 档 11 只里 **8 只是远程**
- 70 档（最慢）5 只里 **4 只是近战**

**而远程确实会风筝** —— `RealtimeBattle3DScene._do_move`：

```gdscript
elif not u["melee"] and dist < rng * 0.7:
    intent = -to_t.normalized()      # 远程太近→风筝后撤
```

射程 400 → 280 码内就开始后退。所以**近战坦克（移速 70）结构性追不上远程（移速 145），被风筝到死**。
这不是数值问题，是结构问题。与实测吻合：水晶 26.1% / 缩头 39.4% / 钻石 49.4% 全在中下游，而它们坦度分位是全表最高的三只（91/95/80）。

### 1.4 定位早就存在，但只活在一行注释里

`turtle_stats.gd` 第 3 行（改造前）：

> `★攻速按定位压到 0.6-0.85 次/秒: 刺客0.85/近战斗士0.8/远程射手0.75/法师+辅助0.7/坦克0.6`

**没有任何字段承载它** —— `pets.json` 顶层没有 role 字段，代码里也没有表。
结果是 **攻速遵守了定位、移速完全没跟**。而且反推出来的定位还和 `melee` 标记**矛盾 6 只**，
「法师/辅助」一档塞了 **13 只 = 全表 46%**（均胜率最低 42.6%，内部极差 85.9pp）。

## 2. 方案：定位 = 距离 × 职能，二维网格，权威化

### 2.1 档位表（用户拍板：「多分点定位，如近战法师，远程坦克，远程刺客等」「移速分布在 120 到 60 之间」）

| 定位 | 移速 | 攻速(次/秒) | 只数 |
|---|---|---|---|
| 近战刺客 | **120** | 0.85 | 2 |
| 近战斗士 | **110** | 0.80 | 5 |
| 近战法师 | **100** | 0.70 | 3 |
| 近战辅助 | **100** | 0.70 | 2 |
| 近战坦克 | **95** | 0.60 | 5 |
| 远程刺客 | **90** | 0.85 | 1 |
| 远程射手 | **75** | 0.75 | 3 |
| 远程法师 | **70** | 0.70 | 4 |
| 远程辅助 | **68** | 0.70 | 1 |
| 远程坦克 | **60** | 0.65 | 2 |

**★结构保证：近战最慢档（近战坦克 95）> 远程最快档（远程刺客 90）**
→ 近战永远追得上远程。这是整改的核心目的，由门禁第 ⑤ 条守着。

（原提案里的「远程斗士 85」在双头改按近战处理后**无龟使用 → 已删**，不留空档死数据。）

### 2.2 归档依据：属性分位数，不拍脑袋

坦度 = `(HP 分位 + 双抗分位) / 2`，输出 = `ATK 分位`。

| 定位 | 龟（坦度%/输出%） |
|---|---|
| 近战刺客 | 忍者(9/86) 骰子(18/46) |
| 近战斗士 | 小龟(45/25) 无头(43/14) 海盗(61/46) 竹叶(7/25) 双头(12/96) |
| 近战法师 | 彩虹(66/25) 糖果(64/25) 熔岩(29/25) |
| 近战辅助 | 财神(84/14) 宝箱(52/25) |
| 近战坦克 | 缩头(95/4) 水晶(91/71) 龟壳(86/71) 钻石(80/11) 石头(75/0) |
| 远程刺客 | 幽灵(7/64) |
| 远程射手 | 赛博(25/86) 赌神(18/86) 猎人(34/64) |
| 远程法师 | 星际(48/79) 线条(21/82) 凤凰(32/57) 闪电(20/57) |
| 远程辅助 | 天使(48/4) |
| 远程坦克 | 寒冰(79/46) 泡泡(70/14) |

**用户逐条拍板的三处**：竹叶归斗士（不是法师）／双头按近战移速／熔岩两形态都按近战。

### 2.3 两只 melee 标记与定位**故意不一致**（白名单 `ROLE_MELEE_EXEMPT`）

| 龟 | 情况 | 处理 |
|---|---|---|
| **双头** | `melee=false` 远程起手，但技能会在两形态间切换（`two_head_system:309`） | 按**近战斗士** 110 |
| **熔岩** | 火山形态 `melee=true`/射程70/原移速175；小形态 `melee=false`/射程400/原移速145 | **两形态都按近战法师** 100；火山形态保留 ×1.2 冲脸相对提速 = **120** |

★ 熔岩原本就在两个形态里各自**硬写**移速（175/145），现在改成从 `ROLE` 派生。

## 3. 实施

### 3.1 代码

| 文件 | 改动 |
|---|---|
| `scripts/gamedata/turtle_stats.gd` | 新增 `ROLE_SPEC`（档位→移速/攻速）、`ROLE`（28 龟→定位）、`ROLE_MELEE_EXEMPT`；`STATS` 的移速/攻速改为**从 ROLE 生成的镜像** |
| `scripts/systems/skills/lava_system.gd` | 两形态移速从 `LAVA_SPD`（= `STATS["lava"][1]`）派生；`VOLCANO_SPD_MULT = 1.2` |
| `scripts/systems/equip/equip_system.gd` | 亡灵骷髅 130 → **110**（近战斗士档） |
| `scripts/systems/skills/cyber_system.gd` | 赛博机甲 130 → **95**（近战坦克档） |
| `scripts/scenes/battle/battle_spawn.gd` | 召唤物默认移速 120 → `SUMMON_DEFAULT_SPD = 100` |
| `scripts/scenes/codex/detail_views.gd` | 图鉴龟详情显示**定位**（用 2026-07-23 删 tag 腾出的位置） |

**★为什么 `STATS` 不做成运行时构建**：`RealtimeBattle3DScene.gd:98` 是
`const STATS := preload(...).STATS` —— const 表达式，不能引用 `static var`。
所以 `STATS` 必须保持字面 const，靠门禁焊死它与 `ROLE` 一致（见 3.2）。

**未动**（有明确设计出处，注释里写着）：水晶球 90、海盗船 40。

### 3.2 门禁 `tests/verify_turtle_roles.gd`

查 6 条：① 每只龟都有 ROLE ② 档名在 ROLE_SPEC 中 ③ STATS 移速/攻速 == ROLE 派生值
④ ROLE 的近战/远程前缀 == melee 标记（白名单除外）⑤ **近战最慢 > 远程最快** ⑥ 无空档。

**四条反向验证已实证会红**：
- 手改 STATS 移速 110→111 → `③ basic 移速 111.0 ≠ 档位值 110.0`
- 删掉 ninja 的 ROLE → `① ninja 没有 ROLE`
- 幽灵改成近战定位 → `③` + `④ ghost 定位是 近战刺客 但 melee=false`
- 近战坦克 95→85（低于远程刺客 90）→ 一片 `③` 红

另：`tests/verify_codex_stats.gd` 里硬编码的「小龟移速=105」改成**从 ROLE 派生期望值**，
否则以后每调一次定位就要改一次测试。

## 4. 已知风险与未决点

1. **全表整体变慢约 17%**（最快 145→120，最慢 70→60）。第一轮实测对局
   **中位 54.7 秒 / p90 67.9 秒 / 最长 105.2 秒**，降速会把这些数往上推，
   **更多对局会打进决胜**。这不一定是坏事，但第二轮的时长分布必须重新看。
2. **改动尚未实测验证**。第二轮胜率排行才是答案；预期近战坦克（水晶/缩头/钻石）会明显回升，
   远程法师（闪电/线条/星际）会下降 —— **但这是预期不是结论**。
3. **攻速只动了 3 只**（竹叶 0.70→0.80 归斗士、寒冰/泡泡 0.70→0.65 归远程坦克）。
   其余 25 只现有攻速与新定位本来就吻合 → 说明那行注释的分档基本是对的，只是没执行到移速上。
   ⚠ 寒冰刚在第一轮被加强（普攻 1.0ATK + 冰柱最多 +60% 攻速），基础攻速再压到 0.65
   意味着**满层后实际攻速 0.65×1.6 = 1.04，比改造前还快**，但**开局更慢**。用户已确认「寒冰没问题」。
4. **「近战法师/近战辅助」两档移速相同（100）** —— 目前靠职能名区分，数值上无差异。
   若将来要拉开，需要重新拍板。
5. **定位没有进 `pets.json`** —— 它只在 `turtle_stats.gd` 里。图鉴通过 `TurtleStats.ROLE` 读，
   HacknPlan 通过权威文档同步。若将来外部工具要读定位，需要再决定是否镜像进 json（**又一个镜像 = 又一个分歧源**，
   本轮刻意没做）。
6. **移速对「开局跑位到接敌」的影响未量化**。战场 `ARENA = 1596×728 px`；
   移速 60 横穿全场要 26.6 秒、120 要 13.3 秒。实际接敌距离约为宽度的一半，
   但**没有实测开局接敌耗时的变化** —— 第二轮跑完可从帧数分布反推。
