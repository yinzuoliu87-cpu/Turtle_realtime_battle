## 已知风险与未决点

**风险**
1. **热路径性能**：刀3-6 每帧调用穿过 RefCounted 边界（`battle._x_sys._fn()` 多一层）。GDScript 方法调用有开销，双路 STRESS 每秒数百单位×多效果 → 需压测确认帧时不劣化。
2. **确定性**：伤害/弹道/目标是逐字节可复现的根。搬动若改了求值顺序/RNG 取用次序 → determinism 门禁红。每刀后必跑 `verify_*_determinism`。
3. **§3.3 两条伤害路**：`_apply_damage` 与 `_apply_damage_from` 各自扣盾扣血，刀5 必须两条一起搬，只搬一条＝诡异 bug。
4. **§3.2 单位字典**：跨系统传单位字典正常（传引用），但**绝不能**在新系统里拿它当 dict key / 用 `==`。
5. **共享状态**：`_t` 全局时钟(§3.4)、`_units`、`_pending_shots` 等被多簇读写 → 留 battle、各系统走 `battle._t`/`battle._units`。
6. **`$NodePath`/`create_tween`/`await`**：RefCounted 不能用（坑11）→ 世界构建里大量 `$`/add_child/tween → 走 `battle.get_node`/`battle.create_tween`（extractor 已处理 add_child，$ 要手转或排除）。
7. **F5 覆盖不了的都靠压测**：determinism + STRESS + soak 是热路径的主网；F5 只验"看起来对"。

**未决点（要你拍板）**
- **U1 拆到哪一层？** ①仅刀1-2(安全·−1600·到~11000) ②刀1-4(+目标·−1900·到~10600) ③刀1-6(到~9200) ④一路到 3000(含生成+可能拆主循环·风险最高)。
- **U2 每刀都 F5 还是攒着一起 F5？** 视觉刀(1/2/3/5)建议逐刀 F5；纯逻辑刀(4/6)靠 determinism+stress 自动网。
- **U3 性能门槛**：是否要我在刀3前先加一个"双路 STRESS 帧时基线"探针，拆后对比不劣化才算过？（建议要——热路径拆分没有性能回归网＝盲拆）
