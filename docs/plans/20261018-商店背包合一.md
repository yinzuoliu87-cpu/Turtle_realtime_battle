**共同点（数了出现次数）**：
1. 商店和队伍同一屏：9 / 9 个有商店界面的游戏都是。我们是唯一分两页的。
2. 商店一次 3~5 件：没有一款一行摆 10 件。我们一行 10 件。
3. 刷新 / 锁定紧挨着商店行：7 款。
4. 装备页角色居中、槽围一圈：7 款，其中 3 款直接在角色下面标属性变化（绿箭头）。
5. 说明是选中后弹出的卡，不是常驻大面板：BagMaster、超级自动宠物、金铲铲、云顶、The Bazaar。
6. 「已装备 / 未装备」分开显示：Rumble Bag、Weapon Master。
7. （D 组）买和装是一步：5 款直接「买并装备」，其中 2 款（歧路旅人、火焰纹章）是买的时候选给谁。没有一款要求买完换一页再装。
8. （D 组）选商品时就看到装上去属性变多少：6 款。
9. （D 组）钱不够、装不了，在卡上 / 按钮上直接标，不等点了再报错：歧路旅人「Cannot Equip」、Void Tyrant「Unaffordable」、Card of Darkness「Can't Afford」。

## 出入

- 现状买一件再装上 6 下、跨两个界面；参考里有商店界面的游戏全部同一屏、买的那一下或下一下就装上。
- 初稿的「购买并装备」照搬 RPG 商店，与本作「买下自动三合一」冲突（买下的那件常常已经并进别处的星级），撤回。
- 本轮只改商店一屏的布局与操作，不改商品数量、价格、合成规则、装备上限与任何数值；背包页不动。

## 方案（已实现）

**商店一屏完成买 + 装，背包页保留不动**（背包页仍是完整管理入口；主菜单两个按钮不动）。

```
┌ ← 背包 │ 币 │ Lv ━━━ │ 买经验 ──────────────────────────────────────────┐
│ 货架 5×2（不变）                        │ 出战阵容            装备 1/4 │
│                                         │ 提示：此刻该做什么            │
│ 刷新 │ 锁定（不变）                     │ 上战场  龟/小将 ×3 + 3 槽     │
│ 羁绊条（不变）                          │ 下战场  龟/小将 ×3 + 3 槽     │
│ 背包 N 件  [格][格][格]…（可点）        │ [详情] [卖出] / [卸下 X]       │
│ 一句话提示                              │（选中货架卡时详情盖在这里，× 关） │
└──────────────────────────────────────────────────────────────────────────┘
```

1. 右侧原来空着的详情框 → **常驻出战阵容**（6 个单位 × 3 槽 + 「装备 N/M」）。选中货架卡时详情盖上来，右上「×」回到阵容。
2. 底部两颗只读弹层按钮 → **可点的背包条**（一行 8 格，放不下显示「+N」去背包页）。
3. **买下即待装**：买下的那件（没被合成掉、全队没满时）自动选中，能装的单位黄框高亮，点一只 → 装上。**买 + 装 = 2 下，不换页**。
4. 点背包条里任一件 = 待装，同样点龟装上；面板底部给「详情」「卖出 +N」。
5. 不在待装时点一个单位 = 选中它，面板底部给每件「卸下 X」。
6. 不能装时行变暗并写原因：「已满 3 件」「全队已满」「未选龟」。全队满时提示「全队已满 · 升级或先卸下一件」；平时提示「等级越高，全队可装越多」（解释 N/M）。
7. 装 / 卸 / 卖全部复用背包页的 `InvOps`（上限、自动合成、羁绊赠送件、存盘同一套）。
8. 教程不改（教程里仍走「商店 → 背包页装」，下一份方案书按新流程重写）。

代码：`scripts/scenes/shop/shop_lineup.gd`（新，RefCounted 拆分模板）；`ShopScene.gd` 删掉两个弹层及其 6 个函数（净 −358 行）。

## 第二刀：整页重做（2026-10-18 晚）

用户看了第一刀：「商店不够，你怎么参考的」「整个页面就应该重做啊，没有任何游戏搞的这种浏览器网页感」「做，然后继续迭代」。

第一刀的问题（对照参考逐条认）：只从参考里拿了「同一屏」，画面与操作都没照做 —— 把背包页的列表搬进了商店右侧，6 个单位挤在 54px 的行里，商品是方框卡片加名字，全是点了再点，字多。

| 参考的做法 | 第二刀 |
|---|---|
| 队伍是画面中心、画得大（超级自动宠物 / The Bazaar / Underlords） | 左半是两级木台，上战场站后排、下战场站前排，**龟本身的全身立绘 + 待机动画**，脚下 3 个装备格 |
| 商品是实物，价签贴在物品上（背包乱斗 / The Bazaar） | 右半是墙上两层货架，物品直接立在木板上，价签挂在板沿；价签框 = 费用 5 档框（7-29 用户要的「框框随费用变化」） |
| 拖到哪就买到 / 装到哪，能放的地方有提示（超级自动宠物） | 货架拖到龟 = 买下并装上；拖进背包 = 买下；背包拖回货架 = 卖出；拖动时能接的龟脚下亮金、不能接的变暗 |
| 主界面几乎只有数字和图标 | 名字直接写在场地上（描边字）；说明只在点开的卡里 |
| — | 点选流程全部保留（点卡 → 购买 → 点龟），拖拽是快捷方式 |

素材：背景 `assets/sprites/shop/shop-bg.png`（PixelLab Pro 新生成的货铺）。
门禁：`verify_ui_consistency` 商店「网页盒 / 圆角盒 = 0」照样卡着（光圈、影子用像素椭圆贴图，不用圆角盒）；`verify_prep_screen_one_step_equip` 加拖拽三条（变异验证：拆掉拖拽装备那一步即红 3 条）。

迭代 2（同晚）：详情卡挪到货架那一侧，左边场地整个露出来；卡上的物品图标就是拖动源，看着说明直接拖到龟身上即买即装。

## 手机优先重排（2026-10-21）

### 需求原文

- 用户 10-20：「商店页面搞了吗，背包呢」→「是的，但是如果你看ios上的商店页面，你会发现什么」。
- iPhone 6.1"（2622×1206）实拍 `img-20261020-AppStore/6.1in-2622x1206-04-商店.png`、`03-背包.png` 上看到的：
  1. 19.5:9 下构图被裁：左下宝箱只露上半截、「背包 22 件」压在被切的宝箱上；右侧货架伸出屏幕、镜像出半个「第三列」。
  2. 字太小：羁绊行、Lv / 经验、装备 9/10、背包 N 件、价签数字 14~16 号字，6.1" 屏上约 1~2 毫米。
  3. 左半屏被装饰商人占掉，可点的 10 件挤在右半，格子小。
  4. 左上返回 / 背包钮贴着刘海与圆角不安全区。
  5. 底部背包格 + 「+17」+ 刷新 / 锁定 / 买经验贴着底部横条。
  6. 背包：33 格大网格只用几格；羁绊两份两种写法（商店「灵物 2/5 ★☆☆☆」/ 背包「灵物 2 件 · 5 件升级」）；「统领 ×2 · 小将 ×1」「后排」无解释。
- 主会话（10-21）：保持第三版已认可的风格（店主场景、货架实物、暖铜圆钮、局内小卡说明）；羁绊写法与站位说明这类玩法文案按授权口径自定并注明。

### 方案（已实现）

**一、版式只认安全设计区**（商店 / 背包同一套口径）

- 设计框 1280×720 居中（`UIFrame`）。19.5:9（1560×720）两侧各空 142，刘海 / 圆角内缩按 iPhone 6.1" 横屏 62pt × (720 / 402) ≈ 111 算，主体不进；16:9 无内缩；4:3（1280×960）商店上下各空 120、背包顶对齐（`UIFrame` 新增宿主可选的 `ui_frame_top_align()`），多出的 240 给背包网格。
- 底部横条：iPhone 21pt ≈ 38 设计像素 ⇒ 商店底沿只用到 `SAFE_BOTTOM = 682`；背包底沿 `_bottom_limit()` = 视口底 − `SafeArea` 下内缩 − 6。
- 顶栏右侧补上安全区：`TopBar.add_right_action` 原来写死 18 边距 ⇒ 背包「站位」「?」伸进右侧圆角，改成跟 `safe_right` 走；页名框收到字宽（原来固定 520 宽，压着「商店」签）。
- 商店顶栏在 4:3 上贴视口顶（设计框下移 120 时顶栏和深海币跟着回到顶）。

**二、换算与下限**

- iPhone 横屏高 402pt = 720 设计像素 ⇒ 1pt ≈ 1.8 设计像素。最小字号 20（≈ 11pt）；触控 81（= 44pt，全项目原有口径）。

**三、商店**

- 背景：原图去掉货柜与左下半截宝箱、四边外扩成 `shop-backdrop.png`（宽屏两侧是同一场景的延伸，不再镜像出半个货架）；货柜单独抠成 `shop-shelf.png`（右边补一根镜像立柱），×3.8 摆在右侧（464..1262，底沿 682）。两张都由原 `shop-bg.png` 离线切出，不新生成、不复用别处素材。
- 商人 352 → 256，站在左栏靠货柜一侧；左栏（18..452）自上而下：羁绊（两列 × 至多 3 行，20 号字 + 32 图标，放不下折成「+N」）→ 提示条 → 商人 → 宝箱。
- 货架：10 件立在两层板上，物品 104×96、价签 86×40（22 号字）。
- 货柜底座一排：左段「Lv · 经验条 · 经验 N/M」整段 380×100 都是点开出货概率的热区，右段刷新 / 锁定 / 买经验三颗 128×100。
- 宝箱（背包）：左栏底部一排 5 格 81×81（第 5 格放不下时是「+N」去背包页）；标题行左「背包 N 件」右「已装备 N/M」（原在等级行最右）。
- 宝箱里点一件 = 弹说明小卡、卡底「卖出 +N」，与货架「点 → 说明卡 → 购买」同一手势（原来是这一排末尾的「详情 / 卖出」两颗，手机版一排铺满放不下）。
- 说明小卡（`InspectCard`）加 `min_px` 参数：商店传 20，正文 / 标签 / 属性行都不小于 20；局内信息面板不传，照旧。

**四、背包**

- 字号：全页最小 20（战场带标题、单位名、前排 / 后排、底栏、弹框正文、羁绊列）。
- 背包网格按实际件数：有几件画几格，空背包只写「背包为空」；「▼ 下面还有」只在真的有下面时出现。
- 格子里不再写装备名（12 号字放不下 20 号的 5 字名），只画 64×56 图标 + 星级；名字在选中后的底栏第一行。糖果罐格只写「N 档」。
- 单位卡上的 40px 装备格不再单独当靶子：点它 = 点这张卡（已选装备 ⇒ 装上；没选 ⇒ 选中这只、底栏列出「卸下」）。
- 前排 / 后排签从卡片右上 56×44 挪到头像下沿 96×38，热区 102×81（子节点 `TouchPad`）。
- 底栏 80 → 132 高、键 38 → 81 高；简述 3 行；「查看更多（N 行）」量行数时先去 bbcode 标签（原来连 `[color]` 一起量，一行的简述被算成 4 行）。
- 弹框（阵容说明 / 装备详情 / 羁绊详情）字号 20、键 81 高，底沿不过底部横条。
- 站位面板：场地比例 0.6 → 0.56（底下两颗键原来到 691，压进底部横条），字号 20。

**五、玩法文案（用户授权自定，10-21 方案书本节）**

- 羁绊统一一种写法：`Phase2Types.progress_text()` =「名 当前/下一档 ★☆☆」，满档「名 当前 ★★★」；名字用类型名本身（剑 / 法器 / 盾）。商店左栏、背包羁绊列、出战页 chip 三处都调它。背包原「剑系  3 件  6 件升级」与装备底栏「· 剑系」一并改成「剑」。
- 战场带右上的「统领 ×2 · 小将 ×1」（只是在数下面的卡）换成两条名词短句图例：上战场「统领：本大轮出战龟　小将：补位单位」，下战场「小将站位：前排近战　后排远程」。
- 阵容说明（「?」）两句跟着新行为改：「小将头像下方【前排 / 后排】：切换近战 / 远程」「点击单位：底部列出该单位装备，可卸下」。

### 已知风险与未决点（本节）

- 安全区数是按 iPhone 6.1" 横屏（62pt / 21pt）换算后喂进去的，**没在真机上看过**；更窄的刘海机型、Android 打孔屏的内缩会不同。版式按设计框 + `SafeArea` 运行时取值走，真机报的内缩更大时顶栏 / 背包会跟着让，商店主体在设计框内（两侧余量 142）。
- 4:3（iPad）商店上下各空 120，靠外扩的场景底图填（顶梁 + 沙地），没有为 iPad 单独放大货架。
- 背包格子不再写装备名，认装备只靠图标 + 选中后底栏；同名不同件（如「迷你水晶球A/B」）在格子上要靠图标区分。
- 宝箱一排只放 4 件 + 「+N」，背包多的玩家仍要去背包页。
- 背包页 4:3 下件数少时下半屏是空的（不画空格是有意的）。
- 教程流程未改；教程门禁（`verify_tutorial_flow_v3` / `verify_tutorial_anchors` / `verify_first_tips`）在新版式下全绿，但教程手势指针的观感没逐步实拍。
