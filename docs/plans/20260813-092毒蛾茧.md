# 092 毒蛾茧：航线实时跟随 + 三项数值加强

日期：2026-08-13　|　状态：**已完成**（v0.19.140 · 见 §8 回填）

---

## 1. 需求原文（用户逐字）

> 下一件有问题的装备是二费一个放毒的飞行物，为什么锁龟蛋和训龟大师，到底是怎么飞的，
> 飞行速度需要加快30%
>
> 飞行物有直接冲训龟大师和在屏障里的龟蛋吗
>
> 航线有实时变化吗
>
> 那这个其实有点问题啊，人家都往别的地方走了，飞行物却飞到别的地方
>
> 中毒层数加强为3/5/8，毒物停留时间加强为6秒，过冲改为160码
>
> 半径不用动

---

## 2. 调查结论（带行号证据 · 探针实测）

- **选靶**：`eq_venom_drone.gd:412` 走的就是 `_pick_enemies_of`（§PICK-TARGET 闸）。
  **探针实测**（`_probe_drone_target`，左边一只携带者 + 右边普通敌 / 训龟大师 / 围栏未破的蛋 / 围栏已破的蛋）：

  ```
  ★选靶闸给出的候选: ["小龟", "蛋(围栏已破)"]
     含训龟大师? false     含围栏未破的蛋? false     含围栏已破的蛋? true
  ```

  ⇒ **不会直接冲大师、也不会冲围栏里的蛋**。围栏破了之后的蛋被选是设计（破蛋窗口）。
- **毒雾**：`:307` 明确用 `_enemies_of`（注释「毒雾是范围扫到谁算谁」）⇒ AOE 波及大师是**规矩允许**的。
- **航线（真问题）**：`_new_leg` 只在**起段那一刻**快照 `t["pos"]` 算出过冲落点，
  之后整段只朝这个**固定点**转向；中途目标走开/死亡都不重瞄，只有「到点」或「超时 8 秒」才换段。
  ⇒ 用户看到的「人家都往别的地方走了，飞行物却飞到别的地方」就是它；
  也是「看起来在冲大师/蛋」的来源之一（过冲 260 码 ⇒ 航线常从他们头顶穿过）。

---

## 3. 需求 ↔ 代码的出入

用户问的三件事里，**只有一件是 bug**：

| 用户的观察 | 实际 |
|---|---|
| 「锁龟蛋和训龟大师」 | ❌ 不成立（探针证伪）——是毒雾 AOE 罩到 / 航线穿过 |
| 「到底是怎么飞的」 | 分段直飞 + 过冲，每段随机挑一个目标 |
| 「航线不跟着目标变」 | ✅ **是真问题**，起段快照一次就不再重瞄 |

---

## 4. 方案

1. **航线整段实时跟随**：`_new_leg` 存目标**单位引用** `d["tgt"]` 与起段位置 `d["leg_p0"]`；
   每帧若目标还活着 ⇒ `dest = overshoot_dest(leg_p0, tgt.pos)`。
   ★过冲相对**起段位置**算，不是相对当前位置——相对当前算的话落点会随飞行一直往后退，
   **永远飞不到、也永远不换段**。
   ★存的是单位字典引用；比较一律 `is_same`，绝不拿它当 key（CLAUDE.md §3.2）。
2. **数值**：飞行速度 110 → **143**（+30%）；中毒层数 2/3/5 → **3/5/8**；
   毒雾停留 4 → **6 秒**；过冲 260 → **160 码**。转弯半径**不动**（用户拍板）。

## 5. 已知风险与未决点

| # | 风险 | 状态 |
|---|---|---|
| R1 | 提速 30% ⇒ 转弯半径（= 速度 ÷ 转向率）变大、毒雾铺得更疏 | **用户拍板：不动转向率** |
| R2 | 实时跟随后，目标绕圈跑会让飞行物一直追不到、单段被 `LEG_TIMEOUT`(8 秒) 截断 | **已知**：超时换段本来就是兜底，不改 |
| R3 | 过冲从 260 收到 160 ⇒ 穿过目标后飞得更短，毒雾更集中在目标附近 | **这正是收短的目的**（少从旁人头顶穿过） |

## 8. 实施回填（2026-08-13）

### 实际改了哪些

| 文件 | 改动 |
|---|---|
| `eq_venom_drone.gd` | `_new_leg` 存 `tgt`/`leg_p0`；tick 里每帧按目标当前位置重算 `dest`；`POISON_STACKS [3,5,8]`、`FOG_LIFE 6.0`、`OVERSHOOT 160.0` |
| `venom_drone_vfx.gd` | `DRONE_SPEED 110 → 143`（+30%），并注明转弯半径会随之变大（用户拍板不动转向率） |
| `data/phase2-equipment.json` | 文案同步（3/5/8 层、6 秒） |
| `tests/verify_eq_venom_drone.gd` | 新增「目标挪走 ⇒ 落点跟着变」；**把所有写死的期望值改成从常量推导** |

### 与方案的偏差

无。三项数值与航线改动都按用户给的原样落地。

### 新发现的坑

1. **数值判据写死 = 调一次数值红一片。** 这次五条断言同时红（团数 16、层数 2/6、过冲 260），
   全是当初把数字抄进测试造成的。改成 `FOG_LIFE ÷ BEAT`、`POISON_STACKS[i]`、`OVERSHOOT`
   之后，下次调数值不必再动测试。
   ⚠ 但**不是所有数字都该改成常量**：⑤ 那条 `N == 16` 是"本用例自己采样了几次"，
   与 `FOG_LIFE` 无关，我一度错改成常量导致它红——**先看这个数字属于谁**。
2. **喂食时长也得跟着常量走**：期望值改成「寿命 ÷ 节拍」后，若喂食还写死 4 秒，
   寿命调到 6 秒就永远喂不满、团数自然不够。
3. 上一版（v0.19.139）漏了两处记账，门禁抓到：**路线图没写**（`docs_authority_lint` 报
   「路线图最新版本 ≠ project.godot」）、**装备评审表没重生成**（`data_integrity`）。
   改文案后这两件是固定动作。
