# 手机打字输入条（键盘正上方一条整宽输入条，四处统一）＋ 启动去掉 Godot 标

日期：2026-10-28　|　状态：**实施中**（代码与门禁已完成，随 0.22.4 上 TestFlight；真机验证清单 §6 第 2 部分待用户在手机上走）

## 1. 需求原文（逐字）

- 用户 10-27：「你知道玩家现在怎么在游戏里打字吗」「手机打字很难受」
- 用户 10-28 看完参考对照 + 方向稿（起名 / 反馈）+ 四处毛病 + 我自定的四条细节后：「行」
- 用户 10-28：「今天凌晨6点你安排出版吧」
- 用户 10-28：「然后现在开始游戏的时候，不是它会弹那个 g o d o t 引擎吗？把这个东西去掉，然后来做一个相当于只有我们工作室的一个，呃，开场动画，然后就调到那个小游戏的主界面，来想办法怎么做。」（本篇只做「去掉」那一半；工作室开场动画先出参考与方向稿，另立方案书）

「行」认可的内容是**我的提议**（用户没有逐条改）：键盘正上方整宽输入条、条里字放大约 2 倍、右边「清空 / 完成」、原界面不挪；四处统一换成这一种（绑邮箱也换）；验证码旁加「粘贴」；反馈按钮加高到 81；条上按钮新画。

## 2. 调查（现状）

完整走查与参考见会话 scratchpad `typing_1027/走查.md`、`参考对照.png`（6 款横屏手游 10 帧）。要点：

- **起名**（`scripts/scenes/FirstLaunchScene.gd` `open_naming`）：没有任何躲键盘处理；中文键盘 + 候选栏（52%）时「确认」被盖；回车只收键盘。
- **设置改名**（`scripts/scenes/SettingsScene.gd` `_open_rename_dialog`）：弹框不动，「取消」「确认」都在键盘底下。
- **绑定屏**（`SettingsScene.gd` `_wall_build_step1/2` + `_email_relayout`）：整框按键盘高往上挪，但键盘高要等弹出动画播完才拿得到（先被盖再跳）；验证码粘贴不了（godotengine/godot#60076）。
- **问题反馈**（`scripts/scenes/feedback_panel.gd`）：一聚焦就把整框挪到 y=-180，标题和类型钮被顶出屏幕；回车是换行，没有收键盘的键；按钮高 56，低于本仓 81 触摸线。
- **好友 ID**（`scripts/scenes/FriendsScene.gd`）：页面不动；点「查找」键盘不收，结果出在键盘底下；默认键盘在中文用户手上是拼音。
- **引擎事实**（Godot 4.6.3 源码）：iOS 用一个隐藏 `UITextView` 把文字差异转成按键发给获得焦点的框（`drivers/apple_embedded/godot_keyboard_input_view.mm`）；脚本写 `.text` 不会同步给它；点空白或点不可聚焦控件不会让输入框失焦（`scene/main/viewport.cpp`）；`LineEdit` 只有拿到焦点才弹键盘（`scene/gui/line_edit.cpp` `_edit`）。
- **启动标**：`project.godot` 只设了 `boot_splash/bg_color`，没关图 ⇒ 桌面启动显示 Godot 标；**iOS 启动屏（Launch Screen.storyboard）不看 `show_image`**：没设 storyboard 自定义图就用 `application/boot_splash/image`，那一项再空就用引擎自带 Godot 标（`platform/ios/export/export_plugin.cpp` 约 165-190 行）。

## 3. 需求 ↔ 现状的出入

- 走查里写「挪同一个 LineEdit 进条里（top_level）」。实施时改成**条里另起一个输入框、原框改成不拿焦点的显示框**：原框从不拿焦点 ⇒ 全程只有条里那一个框拿焦点 ⇒ 键盘只弹一次，同样避开「两个框交接焦点键盘闪一下」；而且不用动原框的父节点和层级（`top_level` 的绘制顺序在 CanvasLayer 之间不好控）。条里每打一字就写回原框，原界面的确认 / 提交逻辑一行不改。
- 「去掉 Godot 标」只关 `show_image` 在 iPhone 上去不掉（见 §2 最后一条），必须同时给 `boot_splash/image`。

## 4. 方案

**新组件** `scripts/util/keyboard_bar.gd`（`class_name KeyboardBar`，CanvasLayer 7000）：
- `attach(edit, opts)`：只在有虚拟键盘的手机上接管（`DisplayServer.has_feature(FEATURE_VIRTUAL_KEYBOARD)` 且移动平台；门禁用 `vkb_override_vp` 注入）。接管后原框 `focus_mode = NONE`，点它（松手）打开条。桌面 / 无头不接管，原框照旧。
- 条：整宽，底 = 键盘顶；键盘高没量到时按上次量到的、没量过按 52% 估，量到后每帧校正；系统收了键盘（iPad 收起键）连续 8 帧高为 0 ⇒ 条跟着收。左右按安全区（刘海）内缩。
- 单行 96 高：槽（字 32）+ 字数「n / max」+ 清空 ×（可点 81×81）+ 副键 + 主键（150×81）。多行：说明行（类型小签 + 「问题描述」+ 字数）+ 槽（字 28，1→3 行随行数涨，再多在槽里滚）。
- 点条外 = 收起（iPhone 键盘没有收起键）。回车 = 主键。
- 脚本改写条里的字（换一个 / 粘贴 / 清空 / 超 500 字截断）后调 `virtual_keyboard_show` 把新字交回系统键盘（`_resync`）。
- `attach_nickname(edit)`：三处昵称框共用一份选项（字数按 `nickname_clean` 数、上限 8、条里「换一个」、不设硬上限）。

**四处接线（穷举）**
1. `FirstLaunchScene.gd` `open_naming`：`attach_nickname`。
2. `SettingsScene.gd` `_open_rename_dialog`：`attach_nickname`。
3. `SettingsScene.gd` 绑定屏：`_nick_edit` → `attach_nickname`；`_email_edit` → `attach`；`_code_edit` → `attach` + 副键「粘贴」（`code_digits` 只取剪贴板里的数字）；`_vkb_height_vp` 在条开着时返回 0（原界面不挪）。
4. `feedback_panel.gd`：删掉写死的整框上移；描述框 `attach`（多行、标题「问题描述」、上限 500、小签 = 当前类型、副键「收起」、主键「提交」= 弹框自己的提交）；类型四选一 / 取消 / 提交加高到 81，框 440 → 520。
5. `FriendsScene.gd`：ID 框英文键盘（EMAIL_ADDRESS）+ `attach`，主键「查找」（收起后查）。

**新素材**（全新，`tools/build_keyboard_bar_ui.py` 确定性生成，0 次 PixelLab）：`assets/sprites/ui/keyboard_bar/` 底板 / 槽 / 聚焦槽 / 清空 × / 金键（常态 / 按下）/ 石板键（常态 / 按下）/ 类型小签，共 9 张，游戏里 ×3 最近邻。

**去掉 Godot 标**：`project.godot` 加 `boot_splash/show_image=false` 与 `boot_splash/image="res://assets/sprites/ui/boot/blank.png"`（16×16 纯底色 #0a0e18）。⇒ 桌面启动 = 一块底色；iPhone 启动屏 = 同一块底色。

## 5. 已知风险与未决点

- 【未验·真机】键盘高度出现的时机、换输入法时高度是否更新、iPad（兼容模式）上键盘与条的位置 —— 只能真机看，见 §6 第 2 部分。
- 【未决·引擎】拼音组字时字母先进框、首字母被自动大写（#108383）、第三方输入法（搜狗 / 微信）用不了（#110457）：这些是 Godot 在 iOS 上的已知问题，**这次没解决**，要写 iOS 原生插件改 `keyboardView` 的设置。
- 【未验】删 emoji 可能多删 1 个字（退格按 UTF-16 计）—— 引擎层问题，未处理。
- 【已堵】预填名字 + 硬上限 + 长拼音会吞字：昵称框接管时去掉硬上限（max_length=0），提交时 `nickname_error` 校验长度。
- 【已堵】脚本改字后系统键盘仍按旧字退格：`_resync`。
- 【未验·视觉】条在真机上的观感没有实拍（用户 10-27 起不同意不开窗口；本次没开）。门禁量的是几何（位置 / 尺寸 / 字号 / 是否在键盘下），观感待用户在 TestFlight 上看。
- 【未决】Android 启动屏：Godot 4.6.3 Android 用的是什么启动图未查（另一份调研在查），本次只保证桌面与 iOS。
- 【未决】验证码的 iOS 自动填充（oneTimeCode）要原生插件，未做。
