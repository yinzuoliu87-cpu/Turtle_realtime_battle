# 大陆玩家连通（F1 / F2）：自有域名中转 + 客户端多入口自动选路

### B. supabase.co 在我们这边长什么样（10-20 本机实测，只读请求）

`curl -sI https://cjefldecsfpnclhfwriw.supabase.co/rest/v1/` ⇒ `HTTP/1.1 401`、`Server: cloudflare`、`CF-RAY: …-LHR`、`sb-project-ref: cjefldecsfpnclhfwriw`；DNS 解析到 `104.18.38.10` / `172.64.149.246`（Cloudflare 任播段）。
⇒ **Supabase 的 API 前面是 Cloudflare**。玩家在大陆碰到的是「Cloudflare 普通网络在大陆的线路」，不一定是 supabase.co 被封。

## 出入

1. 问题总表 F1 写「连不上 `supabase.co`」——现象对，归因未定：调查 B 显示入口是 Cloudflare 任播，C 没找到 supabase.co 被封的证据 ⇒ 更可能是线路质量 / 运营商层面的干扰。**方案不依赖归因**：不管是哪种，换一条从大陆走得通的入口都有效。
2. F2「读系统代理」——Godot `HTTPRequest` 有 `set_http_proxy` / `set_https_proxy`，但没有「读系统代理设置」的接口；手机上（玩家大多数）拿不到系统代理配置。读了也只帮到「自己开了加速器但不是 TUN 模式」的那部分人。⇒ F2 不单独做，由中转覆盖（D4）。
3. 反馈文档写「客户端服务器地址指向它」——只改一个地址，中转机一挂全体玩家掉线。⇒ 改成**多入口自动选路**（直连 + 中转并存）。

## 方案

### 0. 总形状

```
                         ┌──────────── 直连（欧洲玩家默认） ─────────────┐
客户端 ──竞速选路──┬──→  cjefldecsfpnclhfwriw.supabase.co（Cloudflare → Supabase London）
                   │                         stream.turtlearena.xyz（Hetzner 纽伦堡）
                   └──→  cn.turtlearena.xyz（中转，大陆玩家自动选中）
                            /rest/v1/*  /auth/v1/*  ─反代→  supabase.co（Host 改写）
                            /streams/*              ─反代→  stream.turtlearena.xyz
```

- 中转只认一个名字 `cn.turtlearena.xyz`，它背后是哪台机器由 DNS 决定 ⇒ 换机器（Hetzner ↔ 香港）不用发新包。
- 中转是**纯转发**：不持有任何密钥，不改请求体，只改 `Host`；service key 永远不经过它。

### 1. 先量（不花钱）

1. 用公开的国内多节点测速网站（itdog.cn / boce.com / 17ce.com 一类，各省三网节点）对三个目标测 HTTPS：`https://cjefldecsfpnclhfwriw.supabase.co/rest/v1/`（期望 401）、`https://stream.turtlearena.xyz/healthz`（期望 200）、上线后的 `https://cn.turtlearena.xyz/healthz`；白天与晚高峰（北京时间 20~23 点）各一次；结果表（成功率 / 首包时间，按电信 / 联通 / 移动分）记进 `docs/plans/ref/大陆连通实测.md`。
2. 找一位大陆内测玩家（LP 或其他）装带「网络诊断」的包：设置页一行「网络诊断」⇒ 对每个入口测 `service_status` 三次，显示并随问题反馈上报（入口名、成功次数、中位耗时；不含 IP）。

### 2. 中转机：分两步

| 步 | 机器 | 费用 | 什么时候 |
|---|---|---|---|
| 2a | **现有 Hetzner**（裁判机）上加一个 Caddy 站点 `cn.turtlearena.xyz` | 0 | 先做，用来跑通整条链路 + 第 1 步实测 |
| 2b | **香港轻量服务器**（阿里云国际站或腾讯云国际站，选中国优化线路那一档；最便宜 1 核 / 0.5~1 GB 足够，Caddy 纯转发） | 约 ¥25~50/月（下单时以官网为准） | 第 1 步实测显示 Hetzner 晚高峰不可用就做；DNS 把 `cn` 改指过去 |

推荐：**两步都做，2b 在 11-09 前到位**（留一周给大陆玩家实测）。理由见 D2。

中转 Caddy 配置要点（进仓库 `server/relay/Caddyfile` + `README.md`）：
- 路径白名单：只放 `/rest/v1/*`、`/auth/v1/*`、`/streams/*`、`/healthz`；其余一律 404（不变成开放代理，也不暴露 `/storage`、`/functions`、`/pg` 等没用到的接口）。
- 方法白名单：GET / HEAD / POST / PATCH / PUT / DELETE / OPTIONS 以外 405。
- `reverse_proxy https://cjefldecsfpnclhfwriw.supabase.co { header_up Host {upstream_hostport} }`；`apikey`、`Authorization`、`X-Client-Version`、`X-Rules-Ver` 原样透传（版本闸照常在 Supabase 那边生效）。
- `/streams/*` 反代 `https://stream.turtlearena.xyz`（版本闸照常在 Hetzner 那边生效）；第一版不缓存（块是一次写成、长缓存头，以后需要再加磁盘缓存）。
- **不开访问日志**（Caddy 默认不记；即使开也默认隐去 `Authorization`）；错误日志只留 7 天。
- 证书：Let's Encrypt 自动签（与 `stream` 同法）。
- 上游超时 20 秒；单 IP 每秒请求数上限（防有人拿它刷 Supabase）。

### 3. 客户端多入口自动选路

1. 新设置项 `turtle/api_routes`（默认 `[直连, https://cn.turtlearena.xyz]`）与 `turtle/stream_routes`（默认 `[https://stream.turtlearena.xyz/streams, https://cn.turtlearena.xyz/streams]`）。`base_url()` 变成「当前选中的那条」；`TURTLE_SUPABASE` 环境变量仍然最优先（门禁 `" "` 停层不变）。内测服包（见 `20261020-内测服.md`）只有一条直连。
2. 启动竞速：并发对每条入口发 `GET /rest/v1/service_status`（版本闸白名单里的那张表，`server/supabase/schema.sql:2528-2533`），4 秒内**第一个回 2xx 的**胜出；结果与时刻存 `user://net_route.cfg`；下次启动先用上次那条，后台再竞速一次纠正。
3. 失败切换：**只认传输层失败**（HTTPRequest 结果不是 SUCCESS、或 code = 0）连续 2 次 ⇒ 标记这条坏、重新竞速。HTTP 4xx / 5xx / 426 是服务器真的回了话，不切。
4. **只有读请求会自动换路重发**（GET、`READ_RPCS` 里的 RPC，同 `scripts/net/supabase.gd` `is_write_request` 口径）；写请求失败照现有队列语义处理（`ghost_uploader` 落盘重试等），绝不在两条路上各发一次 —— 第一条可能其实已经写进去了。
5. 直播选路跟 API 走同一条（同一台中转），不另竞速。
6. 账号令牌与入口无关：JWT 由 Supabase 签发与校验，经哪条路都一样；切路不登出。
7. 「网络诊断」（第 1 步）读同一份选路状态，显示当前走哪条。

### 4. Supabase 侧要改的（用户本人在面板上点，费用 0）

- **匿名注册与 Auth 的按 IP 限流**：大陆玩家全都从中转机的一个 IP 进来，Supabase 看到的是同一个来源 ⇒ 匿名注册、发验证码会被按 IP 限流挡住。要在 Auth → Rate Limits 把相关项调高（具体默认值以面板为准，本次未核）。管理令牌写不了 `/config/auth`（memory `project-backend-supabase`：同值写回也 403）⇒ 只能面板点。
- 其余 RLS / 版本闸 / RPC 权限一律不动：中转对 Supabase 来说只是一个普通客户端。

### 5. 隐私政策与上架

- `docs/隐私政策.md` §1.7（服务商侧技术日志）补一句：部分地区的请求经由我们自己的中转服务器（香港 / 德国）转发，中转不记录访问日志、不保存请求内容。上架前更新（与 App Store 上架方案书 G13 同一批）。
- App Store 隐私问卷不受影响（不新增收集的数据类别）。

### 6. 不做的

- **不在大陆境内部署**（要 ICP 备案 + 境内主体）。
- **不用 Cloudflare Worker / Supabase 自定义域名**：入口仍是 Cloudflare 普通网络，对大陆线路无帮助，且后者要 Pro + $10/月。
- **F2 读系统代理不单独做**（出入 2）；TUN 类加速器照样可用。
- 离线上传 8 次就放弃（问题总表 B2）是另一件事，不在本篇。

## 已知风险与未决点

- **R1（未决·要花钱，待用户）**：香港中转机约 ¥25~50/月（≈ £3~6），要用户本人开阿里云 / 腾讯云国际站账号并付款。用户不批 ⇒ 只做 2a（Hetzner），大陆晚高峰体验按调查 C 预计较差。
- **R2（未验）**：Hetzner → 大陆的真实可达性，只有第 1 步实测能定。若 Hetzner 段被限速（Tor 报告的怀疑），2a 基本无效。
- **R3（未验）**：Supabase 前面的 Cloudflare 对「同一个 IP 大量请求」可能弹挑战或 429（中转机 IP 汇聚了全部大陆玩家）。上线后看中转错误日志里 403 / 429 + `cf-ray` 的比例；出现就把限流调高或多一台中转分摊。
- **R4（未验）**：按 IP 的 Auth 限流（§4）不调就会挡住大陆新号注册 —— 这是上线前必须做的那一步，漏掉的表现是「大陆新玩家进不来、老玩家正常」，极难从外面看出来 ⇒ 验收清单单列一条，用中转连续注册若干个测试号到内测服量。
- **R5（未验）**：香港 / 东京机房本身也可能遇到个别 IP 被干扰（调查 C Railway 个例）；对策是 DNS 换 IP，客户端不用动。
- **R6（已堵·设计）**：中转不持有任何密钥；即使中转机被入侵，拿到的只是 TLS 私钥与转发能力，拿不到 service key（它只在裁判机 `/etc/turtle-referee/env`，600 权限）。2a 方案里中转和裁判机同机 —— Caddy 以 `caddy` 用户运行，读不到该文件；但同机毕竟扩大了暴露面，这也是推荐 2b 的理由之一。
- **R7（已堵·设计）**：写请求不跨路重发（§3 第 4 条），防「第一条其实写进去了、第二条又写一次」。
- **R8（未决）**：「网络诊断」上报的内容要不要进隐私政策 §1.7b（问题反馈的附带信息）——只含入口名与耗时、不含 IP，我按「附带信息」处理，写进同一节。
- **R9（已知）**：老包（≤ 当前版本）只认直连，中转对它们无效；大陆玩家要装带选路的新包才行（iOS 走 TestFlight 更新）。
- **R10（未决·法规）**：不在国区分发、连海外服务器的游戏有无额外要求，未查到现行条文（调查 C）；内测期按「不面向国区商店」处理。
