## 2. 调查

### 2.1 「游客模式」这个词不准 —— 代码里本来就有账号

`account_email` 的注释自己写着：`"" = 匿名账号, 换设备会丢档`。
游戏**本来就给每个人发一个匿名账号**（`account_id` + token，`supabase.sign_in_anonymous()`）。

三道闸，代码注释里分得很清楚：

| 功能 | 闸 | 匿名号够不够 |
|---|---|---|
| 排位 / 报名 / 看桶 / 周赛事 / 传鬼魂 | 「服务端认得出你是谁」 | **够** |
| **云存档同步**（`push_save` / 拉档） | `sync_allowed()` = `id != "" and email != "" and token != ""` | **不够，这条才要邮箱** |

⇒ **邮箱唯一买到的是「换手机能接回来」。**
⇒ 拆墙**不是新增游客模式**，是**不再在第一屏拦人**。

### 2.2 那屏原来的标题是夸大的

「**绑定邮箱才能开始**」—— 不绑也能开始，只是没备份。这句话本身就不成立。

### 2.3 参考怎么说（数据在 [20260929 篇](20260929-登录屏参考重做.md) §2，别重抓）

- **224 款手机标题屏里强制凭据墙 0 款**，83% 连账号元件都没有。
- 逐像素 13 屏里「有没有出口」中位 = **1**，我们 = **0**。
- 我们那一屏剩下的五项差距（出口 0 / 两步 / 输入框 2 / 可点 4 / 第三方 0）**四项是同一件事的四个面** —— 都因为「必须当场打出一个邮箱」。拆墙之后这四项才压得下去。

## 4. 方案

**A · 墙不再拦人**：`login_wall_on()` 退役／改成不在启动时立。第一屏直接进游戏。
**B · 绑定入口留着、且找得到**：设置页那个入口保留；另给一处**非阻塞**的提示，告诉玩家「你的进度没备份」。
**C · 文案按新事实重写**：标题不许再说「才能开始」；正文说清楚**绑了买到什么**（换手机能接回来），而不是威胁。
**D · 门禁反向**：`verify_login_wall` ② 「墙上没有关闭」与 `verify_ios_ui` 的 `_wall_ok` 白名单，判据**掉个头**——现在要证明的是「拦不住人」。

## 5. 已知风险与未决点

**风险 1 · 拆墙会让一批人永远不绑，换手机就丢档。** 这是用户明确接受的取舍（他看过数才翻的）。
⇒ 缓解只能靠 B 那处非阻塞提示，**不许退回成拦路**。

**风险 2 · ★判据掉头最容易变成恒真式。**
「墙上没有关闭」翻成「墙拦不住人」，如果只断言「有一个叫关闭的按钮存在」，那是**数我自己插的标记**。
⇒ 判据必须走**真入口**：从第一屏开始，**不碰任何绑定控件**，一路走到能打一局。

**风险 3 · 老玩家已经绑过的，不许受影响。** 绑过邮箱的人行为一个字不许变。

**风险 4 · `sync_allowed` 这条闸不许动。** 拆的是**墙**，不是**云存档要邮箱**这条规则。
动它会让匿名号去写别人的档（[[fb-id-without-owner-dimension]]）。

**风险 5 · 我刚把两张素材写进 `asset_borrow` 白名单**（v0.19.472）。拆墙后那一屏如果不再存在，
白名单里那两条就成了**没有主体的理由**。⇒ 收尾要回去核对。

**不做什么**：不动 `sync_allowed`；不动匿名登录本身；不加第三方一键登录（那是另一件，参考中位 1 而我们 0，单列）。
