# 周日决赛：背包里调的阵容没进比赛（阵容提交修复）

日期：2026-11-15　|　状态：**实施中**

## 1. 需求原文

用户 2026-11-15 晚（周日决赛小组赛打完后）：

> 「发现个很严重的 bug 呀、啊！这个周日这里，这明明手明明在背包里面调了阵容，为什么在比赛里面的阵容不是这个备赛的呢？还说只有备赛时间段内，呃，调整阵容才算啊？这是怎么算的呀？」

我回复了原因与修法，并问「比赛阵容的规则改成『就是你背包里的阵容，每轮锁定前最后一次为准，什么时候改都算』，你同意吗？」，用户回「然后你就自己做事吧」—— 客户端部分照做；改正式服函数仍等明确点头（周末不动正式服）。

## 2. 调查结论

正式服只读核对（`tools/sb_ro.py prod`）：LouisT01（第 2 组 1 号）`finals_entrants.snapshot` = 统领 熔岩 / 赌神 / 石头，三只全在上路、下路空 —— 与 `gauntlet_ghosts` 里 **11-14 03:29:13 闯关第 4 胜**那一份逐项相同；之后背包里的调整一次都没进服务端。

| 环节 | 现状 | 证据 |
|---|---|---|
| 谁推阵容 | 只有对阵图界面每 15 秒推一次 | `scripts/scenes/BracketMapScene.gd:2869-2873`（`_on_poll`）→ `scripts/net/backend.gd` `finals_push_snapshot` |
| 服务端什么时候收 | 每轮 `round_at` 之后 180 秒内（备战窗），之外拒收 | `server/supabase/migrations/20261101b_finals_snapshot_guard.sql` `finals_update_snapshot` |
| 拒收会不会说 | 「开不了打」的阵容（`referee_lineup_ok`）静默拒收；客户端回包回调是 `func(_res): _bye()`，不看结果 | 同上 + `scripts/net/supabase.gd` `finals_update_snapshot` |
| 界面怎么说 | 「未调整阵容时沿用当前阵容」 | `scripts/ui/finals_day_model.gd:50` |

## 3. 需求 ↔ 代码的出入

- 用户理解（也是文案字面）：比赛用背包里现在那套。实际：周六晋级那一刻的那份，除非在某一轮备战的 3 分钟里人停在对阵图上让它推上去。
- 「只有备赛时间段内调整阵容才算」—— 准确说是「只有备赛 3 分钟里**并且停在对阵图上**，阵容才会被交上去」；在背包里改完、窗口关了还没回对阵图 = 白改。

## 4. 方案

**客户端（本次已做，随下一版）**

| 文件 | 改什么 |
|---|---|
| `scripts/net/finals_lineup_push.gd`（新） | `tick(group, cup, now)`：入座、这一组没收盘、备战窗开着 ⇒ 推；窗外改了阵容 ⇒ 提示「下一轮备战开始时，会按这套阵容提交」。`note_result`：服务端回 true / false / 网络失败各记一份回执，`tick` 据此返回一句提示（同一套只说一次） |
| `scripts/ui/finals_day_layer.gd` | 全局层（决赛日每个玩家屏都在，背包也在）每拍调 `tick`，回执在条下方弹 3 秒 |
| `scripts/net/backend.gd` | `finals_push_snapshot`：阵容没变 15 秒最多推一次；阵容一变（指纹不同）≥ 2 秒就推。抽出 `_finals_snap` / `snap_sig_of` / `finals_snap_sig` |
| `scripts/net/supabase.gd` | 回包交给 `note_result`（行数不变，2999 / 3000） |
| `scripts/ui/finals_day_model.gd` | 文案改成「以备战结束时背包里的阵容出战」 |

**服务端（未做，等用户点头）**：`finals_update_snapshot` 去掉「只在开打后 180 秒内收」，改成「入座后随时收、每轮锁定前最后一次为准」—— 提前在背包里调好、开打时人不在线也算。裁判任务建任务时拷贝快照，之后改 `finals_entrants.snapshot` 只影响下一轮。
