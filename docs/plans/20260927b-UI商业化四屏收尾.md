## 2. 调查结论(带行号)

### 2.1 尺子已经在仓库里,不用新造

## 3. 需求 ↔ 代码的出入(本篇最值钱的一节)

### 3.1 「UI 不够商业」在代码里不是一个整体,是 4 屏 26 个调用点

把它当整体重做 = 把已经达标的 3 屏也推倒重来,还会重新发现一遍已经焊成常量的教训。

### 3.2 ★★背包那 10 个网页盒里,有一批是**已拍板要保留的**,不是债

`verify_ui_consistency.gd:68-72` 逐字记着:

> · Inventory 的 10 个 = 单位卡上的 40x40 迷你装备格。2026-08-18 实拍对比后**退回过一次**:
>   换金属框会让**费用色从整块实心退化成一圈细边**,而那块实心色本身就是信息
>   (一眼分得出 2/3/4/5 费)。⇒ 贴图框有它的最小可用尺寸,小于它就该保持纯色块。

**代码里就写着别再试**(`InventoryScene.gd:467-469`,逐字):

> ⚠★2026-08-18 这里**试过换金属槽框, 实拍对比后退回了**, 原因记下免得再试:
>   格子只有约 26px, 而槽框原生 57×57 —— 四角铆钉在这个尺寸下**吃掉大半格子**

**我差点直接去修它。** 那正是 VFX 那次的形状:「060 和 065 的补丁都写好了,量完才发现不该改」。

### 3.2b ★★★而且它同时占着两栏 —— 背包的债比看着少一半

`:466` 那一句是 `csb.set_border_width_all(1); csb.set_corner_radius_all(3)`,
底色 `alpha 0.35/0.55`(< 0.95)⇒ 它**同时满足 `web` 和 `round` 两条判据**。

⇒ 背包那 `web 10` **一个都不是债**,而 `round 19` 里约 10 个是**同一批格子**。
真债只剩 **~9 个**,出自 `:279 / :329 / :403 / :595 / :624 / :754 / :926 / :966`。

同理 `tap 11` 里 8 个是这些迷你格、3 个是单位卡右上的前/后排小钮
(`verify_ui_consistency.gd:56-60` 记着:81×81 的靶子摆在 244×116 的卡上会盖住整卡三分之一)。

⇒ **这些是「算过账的取舍」,不是「还没做完」。**
★**债务排序因此整个翻过来了**:看基线数字是「背包最重(40)」,
按真债是 **选龟(~61) > 战绩(18) > 商店(11) > 背包(~9)**。
**先做背包的话,会把最多的力气花在最少的债上。**

### 3.3 结论:动手前必须先把 119 个盒子**逐个量出是什么控件**

现在门禁只**数个数**,不报是谁。拿个数当清单去改 = 改到豁免项上。
⇒ 第一步是把扫描器改成**能吐明细**(节点路径 + 真实尺寸 + 哪一类),
分成【真债 / 已拍板豁免 / 判据误报】三堆,再谈改哪些。

## 8. 回填：阶段 0（2026-09-27 · v0.19.452）

### 8.1 阶段 0 做了什么

① `verify_ui_consistency` 加明细开关 `UICONS_DUMP=1`（**判据一个字没动**，只加打印）——
命中时打 `[web]/[round] 类名 名字 真实尺寸 r= b= a=`。拿**个数**当整改清单一定会改到
已拍板保留的那批上（§3.2）。

② 新增**第 8 屏「登录墙」**：`SettingsScene.acct_override`（0 = 真实，1 = 强制
「后端开着且邮箱为空」）。与 v0.19.446 的 `clock_override_ts` 同一个模式，**默认 0 ⇒ 玩家路径一字不动**。

### 8.2 ★★★阶段 0 当场撞出一条阻断级 bug

**做法**很简单：我**拿真后端**跑了一次 `verify_ui_consistency`（门禁平时把后端置空）。
当场 4 条红，而那 4 条**任何门禁都没见过**——

门禁给每个测试 `TURTLE_BACKEND=" " TURTLE_SUPABASE=" "`（有意关后端）⇒
`_SB_ACC.enabled()` 恒假 ⇒ **登录墙与整块账号 UI 一次都没建出来**
（memory `fb-gate-subject-never-constructed`）。而那是**每个新玩家开游戏看到的第一屏**。

顺着这一屏往下查，探针 `tests/_probe_wall_escape.gd` 量出来：

```
成功之后 —— _email_layer 还在吗: true
成功之后 —— 返回箭头可见: false
成功之后 —— 状态文字: 邮箱绑好了
这一刻 login_wall_on = false    ← 墙本该已经不该开了
```

⇒ **绑完邮箱看着「邮箱绑好了」，一步也走不了**，唯一出路是杀进程重开
（重开能进，因为邮箱已写盘 ⇒ memory `fb-restart-is-a-separate-scenario`）。
下周 10 人测试**第一个动作**就会撞上。已修，见路线图 v0.19.452。

**这条对本方案书的意义**：阶段 0 的价值不只是「出清单」——
**换一个环境跑同一把尺子，就能照出一整类从没被量过的屏**。

### 8.3 ★★而「控件下限」挡不住这一屏的回归（反向验证当场证实）

给「登录墙」配了条真分母「墙自己那句话在不在屏幕上」。把墙改成永不弹之后：

| 判据 | 结果 |
|---|---|
| 控件下限 ≥10 | 实测 **37** ✅ 通过（墙不弹时控件反而**更多**） |
| 网页盒 ≤0 | 0 ✅ 通过 |
| 圆角盒 ≤1 | 0 ✅ 通过 |
| 热区 ≤2 | 1 ✅ 通过 |
| **墙那句话在屏幕上** | ❌ **只有它红了** |

⇒ **凡是「这一屏有没有量对」靠控件数判的，都要再问一句：量错屏时控件是变多还是变少。**
变多的那些，下限是摆设。

### 8.4 ★★★阶段 0 还查出一条比登录墙更大的

棘轮表里**根本没有 4 个屏**（`scenes/` 12 个，表里 7 个 + 新加的登录墙）：

| 缺的屏 | 玩家什么时候看 |
|---|---|
| **BracketMap** | 周日对阵图，整天都在看 |
| **Leaderboard** | 排行榜 |
| **Matchmaking** | **每一局对局之间都过** |
| TrainerConfig | 训龟大师配置 |

数据依赖已查（读源码）：排行榜／撮合／训龟大师**都有离线兜底**，不需要造数据；
只有 BracketMap 要注入一个桶（`set_bucket()`，`verify_bracket_map` 已有现成姿势）。

⚠ 全局断言（默认皮按钮／文字相撞／死点击／压扁／溢出）**没有分屏基线**，
