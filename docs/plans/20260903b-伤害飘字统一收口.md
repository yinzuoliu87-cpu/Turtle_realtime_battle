## 4. 方案

### 4.1 要做的（一处收口，不是 185 处）

把 `_apply_damage`（`battle_damage.gd:194`）的**颜色**也改成按类型统一取，与 `_apply_damage_from` 同一套：

```gdscript
var _fdt: String = {"tru":"true","mag":"magic","phy":"physical"}.get(bucket, "true")
var _fcol: Color = battle._VC.color_of(battle._VC.cls_for("damage", _fdt, false))
battle._vfx._float_text(pos, str(dmg), _fcol, false, "damage", _fdt)
```

★ 跳法与排行**已在 2026-09-03 改完**（这一条是当时用户点名的），只剩颜色。

### 4.2 影响面（动手前必须先量）

改了之后，**走 `_apply_damage` 且传主题色的调用点，颜色会当场变成三色之一**。要先穷举：

```
python - <<'PY'   # 扫 _apply_damage(非 _from) 且带显式 Color 的调用点，按 bucket 分组
PY
```

已知会变的（本次扫到的一部分）：
- `RealtimeBattle3DScene.gd:7301` `#c8b0ff` 紫 → 白
- `gremlin_gun.gd:76` `#a06cd5` 紫 → 白（古灵精怪枪自伤）
- `trainer_system.gd:1459` `#8b2e4a` 暗红 → 白
- DOT 累积那条（`_dot_accumulate`）已经走 `_dot_bucket_col`，不受影响

### 4.3 不要做的

- **不要**逐处商量「这一处要不要豁免」。用户 2026-08-29 在伤害类型上已经定过同样的调子：
  「没有例外，不逐件商量」（权威 §7.5）。颜色同理。
- **不要**据此写"颜色必须是 X"的静态门禁去扫调用点 —— 颜色由 `_float_text` 的取色逻辑决定，
  扫调用点是扫死参数。**门禁要落在取色函数的行为上**（见 §6）。

## 5. 已知风险与未决点

### 未决

有些技能的主题色可能是有意的美术选择（幽灵紫、糖果粉）。但它们**现在就已经不生效**了
（被 `_ncol` 覆盖），所以"统一"其实不改变现状，只是把死参数删掉。

## 6. 验收标准（以及怎么证明会 FAIL）

**判据要落在取色行为上，不是扫调用点**（扫调用点是扫死参数）：

| # | 判据 | 反向验证 |
|---|---|---|
| ① | 走 `_apply_damage` 打一发 `bucket="tru"`，读回飘字节点的 `font_color` == `#ffffff` | 把取色改回用 `col` → 传紫色时读回紫 → 红 |
| ② | 同上，`"phy"` → `#ff4444`、`"mag"` → `#4dabf7` | 同上 |
| ③ | 两条伤害路打同一种类型，**读回的颜色必须相同** | 只改一条 → 红（这条守的正是 §2.2 那个"只做一条"的坑） |
| ④ | `kind` 必须是 `"damage"`（抛物弹射），不是 `label` | 改回不传 kind → 读回的运动曲线是缓升 → 红 |
| ⑤ | **分母**：这一轮真的打出了 ≥1 发飘字（节点数 > 0） | 打 0 发 → 红（空检查不是通过） |
