## 1. 需求原文

用户 2026-09-25，按发生顺序逐字：

> ①「周日要打开」
> ②「那周五比如我的档是5场次的，我要和6场次的人打？这不合理啊」
> ③「不应该有这些东西啊粗格子:0 / 1-2 / 3-4 / 5-7 / 8-11 / 12-16 / 17-21 / 22-27 / 28+。你 5 场次在「5-7」」
> ④「要么你这快照旧从新做」→ 追一句「建议重跑」
> ⑤「每次机器人选的龟都只选了默认技能」→ 追一句「得修」

★这五句**不是五个需求，是同一个问题被逐层剥开**：② 是症状，③ 是根，④ 是根的根。
我第一轮只修了 ②（拉取窗口），用户当场指出粗格子才是真的尺子；修了 ③ 之后池子露出洞，
他又指出洞的成因在造池那一步。**每一层都是他比我先看到。**

⚠ 还有一句必须钉住，因为它约束了 ③ 的实现方式 —— 用户 **2026-07-27**：

> 「±1 这东西去掉」

那条当年废掉的是 ±1 **格子**窗口，理由是实测撞到明显更强的对手
（档0 全裸撞档1 带 3 件 / 强度 43.0 撞 99.0 / 45.8 撞 118.6）。
**它的意图是「绝不撞明显更强」，而不是「窗口必须为零」** —— 见 §3 出入。

## 3. 与现状最大的一处出入：2026-07-27 那条「±1 去掉」

用户 ③ 要求「不要粗格子」，而 2026-07-27 他要求「±1 去掉」。
**字面上这两条冲突** —— 去掉格子之后，唯一可用的尺子就是场次，而场次窗口只能是 0 或 ±N。

出入的解法不是选一条、也不是折中，而是**分清那条老约束的意图和它的表达式**：

- 表达式：「±1 **格子**」。当年只能这么写，因为没有更细的尺子。
- 意图：「绝不撞到明显更强的对手」（给的证据全是强度倍数，不是格子数）。

⇒ 用**场次**表达同一个意图，而且严格更紧：

| | 往上最多能碰到 |
|---|---|
| 旧「同档」（档7） | **+5 场**（22 碰 27） |
| 旧「±1 格子」 | 更多（跨一整档） |
| 新「±1 场次」 | **+1 场** |

**保护变强了，不是放松了。** 这一点必须写在这里 —— 否则下一个人看到「±1」两个字
会以为我把被否掉的东西加回来了。

## 6. 改了什么

### 6.1 尺子：粗格子 → 场次

`bracket_for_battles` 那九格从此**只是 `pool_add` 的索引**,不是"该碰谁"的判据。

```
① 场次完全相同
② ±MATCH_BATTLES_SPAN(对称)     ← 与拉取那侧同一个常量
③ 往【下】逐格找最近的(绝不往上)  ← 保住 2026-07-27 那条意图
④ bot
```

**③ 为什么只往下**:用户 2026-07-27「±1 这东西去掉」的意图是「绝不撞明显更强的对手」
(当时实测:档0 全裸撞档1 带 3 件、强度 43.0 撞 99.0、45.8 撞 118.6)。
那条约束当年**只能用格子表达**,因为没有更细的尺子。现在用场次表达同一个意图,
而且严格更紧:"同档"在档7 最多让人往上碰 +5 场,新规则最多 +1 场。

### 6.2 机器人技能

判据抽成 `scripts/gamedata/skill_choice.gd`。三个生产者(玩家上传 / 合成 bot / 队列模拟)
原本各写一份,2026-09-17 那次只补了第一个。

### 6.3 造池

主挑选 `每档 20 条` → `每场次 12 条`。输出仍按档建键(那是索引),
改的是"每个键里装哪几条":以前一档一个场次点,现在一档装齐它跨的所有场次。

### 7.3 我量错过的（记在这里免得下一个人照着信）

- 我先按"每场 +2 被动经验"算出 bot 等级比玩家高 **+5 级**,据此差点去改 bot 强度。
  拿**真数据**(184 条快照的 `season_level`)量完是 **±1** —— 真玩家会买经验,我的模型漏了。
  ⇒ **bot 强度一个字没动。**
- `verify_bracket_gear` 那条判据在我改参数含义之后**静默变成恒真式**(拿"格子"比"场次",
  0 例越线全绿)。抓到它的是我新加的「窗口往上真的开着吗」——
  而那条一开始红了(往上 0 次),根因是 `find_opponent` 里还在读 `GameState`,
  **入参根本没被用**。⇒ 改参数含义时,拿它当参数的判据全都要重读一遍。
