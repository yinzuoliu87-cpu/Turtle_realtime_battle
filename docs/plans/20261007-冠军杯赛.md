## 3. 需求 ↔ 代码的出入

1. **「服务端不写第二份座次表」（`schema.sql:362`）这条在冠军杯赛这里守不住。** 选组冠军要从 `finals_results` 顺着决赛往下追到第 1 轮的座位号，再换成种子号 —— 那就是座次表。⇒ 新增 `finals_seed_at_seat(slots, pos)`（与 `bracket.gd._seat_table` 同一个镜像展开构造）+ `finals_champion_seed(week, bucket)`。守法：`verify_champion_cup` 拿 SQL 原文里的构造与 `bracket.gd` 的 `seed_at_seat` 逐坑对账（n=2..64），并且把客户端 `champion_seed()` 与一份「照 SQL 逐行翻成 GDScript」的追溯在 n=1..40 × 随机结果上逐个比（SQL 本身没有本机 Postgres 可跑，这是能做到的最近的尺子；见风险 2）。
2. **组冠军现在拿的是「冠军」。** 原稿奖励是「冠军/亚军/四强/…/**桶冠军**」——冠军是**全服**一个。⇒ 组冠军改发新档「组冠军」，冠军 / 亚军 / 四强改从冠军杯赛派生。（初稿曾写「本周只有一个组 ⇒ 组里的亚军 / 四强照发」，10-07 主会话改为冠亚四强**只**从冠军杯赛来，见 §4.0。）
3. **「我那个组」的查法会被冠军杯赛撞上。** 组冠军在 `finals_entrants` 里有两行（组 + 杯），`finals_view(-1)` 的 `limit 1` 可能取到杯。⇒ 那条查询排除杯的组号。`finals_week_view` 也排除杯（老客户端会把它当成第 N 组画出来），杯另走回包顶层新键 `cup`（老客户端忽略未知键）。
4. **揭晓 / 去重没有组号。** 冠军杯第 1 轮第 0 场与组赛第 1 轮第 0 场坐标相同 ⇒ `_report_done` 会把杯那一场当成「报过了」而**不发**；`finals_pending_reveal` 会拿组的 `done` 去判杯那一场。⇒ 两处都带上组号。
5. **联网打开对阵图永远停在第一页。** `_view` 联网路径不按时刻选 ⇒ 晚上从主菜单进来看的是小组赛。⇒ 联网路径也走 `default_view()`（与 `set_data` 同一条），玩家点过页签后不再自动切。
6. 原稿「1 分钟押注截止窗口」—— 押注不在本篇范围（任务书明确排除），开播节奏沿用组赛（`finals_round_sec() = 480`）。

## 4. 方案

### 4.0 分组容量（用户 10-07 改规则，替换原来的自适应 32/16/8/4）

每组人数 s = {1, 2, 4, 8, 16, 32} 里**最小**的那一档、使组数 ⌈N/s⌉ ≤ 8；32 封顶（再多人组数超过 8，与原稿「桶数随人数线性伸缩」一致）。冠军杯赛人数 = 组数。蛇形切组照旧，各组人数差 ≤ 1（高种子在人少的那几组）。

| 晋级人数 N | 每组 | 组数 = 冠军杯赛人数 | 上午 |
|---|---|---|---|
| 1 | — | — | 不开赛（全周只有 1 人，沿用 `too_few`） |
| 2~8 | 1 | N | 没有对局，人人直接进冠军杯赛 |
| 9~16 | 2 | 5~8 | 每组一场（就是组决赛） |
| 17~32 | 4 | 5~8 | 两轮 |
| 33~64 | 8 | 5~8 | 三轮 |
| 65~128 | 16 | 5~8 | 四轮 |
| ≥129 | 32 | ⌈N/32⌉（200 → 7，1000 → 32） | 五轮 |

- **1 人组合法**：坐下即收盘（`finals_seat` 写 `closed = true`），他就是那组的冠军。原来「1 人一组 = 没有对手的冠军，不是比赛」那条作废——真正的冠军在冠军杯赛决出。
- 规格 `bracket.gd bucket_size_for` 与 SQL `finals_bucket_size` 同一条规则，`verify_champion_cup` ⑩ 在 N=1..1000 逐个对；上线后 `tools/probe_finals_server.py` ⑮ 在真库再对一遍。
- 「组冠军」**不设人数门槛**（用户「不用门槛」）：1 人组那一位也是组冠军。冠军 / 亚军 / 四强**只**从冠军杯赛来；冠军杯赛只有 1 人时他就是冠军，没有亚军 / 四强（原来「只有一个组 ⇒ 组里的亚军 / 四强照发」那条兜底删掉）。
- 客户端：1 人组页签「小组赛 · 直接晋级」，正文「第 N 组仅 1 人 · 直接晋级冠军杯赛 / 冠军杯赛 HH:MM 开赛」；2 人组只有决赛一格，摆在屏幕正中（原来被推到最右边，实拍抓到后修了 `bracket_layout.content_left`）。

### 4.2 服务端（`server/supabase/migrations/20261007b_champion_cup.sql`，同段带 BEGIN/END 标记追加进 `schema.sql`）

**为什么用哨兵组号而不是新表**：杯就是一张单败图，`finals_buckets/entrants/results` 的形状完全够用；`finals_report / finals_opponent / finals_advance / finals_replay / 开播 revealed_at` 全部按 `(周, 组号)` 工作 ⇒ 用一个保留组号 `1000000`（`finals_cup_no()`，任何人数下真组号都到不了：32 人一组也要 3200 万人）就**五件事零改动**。新表要把这五个函数各抄一份，就是同一套规则存两份。负数不行：`finals_view` 的 `p_bucket < 0` 已经表示「我那个组」。

新增 / 改动（★= 重新定义已有函数，正文逐字照抄 `schema.sql` 现行版只改标出的那几行；**生产库可能与 schema.sql 不一致，主会话上线前要拿生产的函数体对一遍**）：

| 对象 | 做什么 |
|---|---|
| `finals_cup_no()` | 1000000（客户端 `phase2_config.FINALS_CUP_BUCKET` 必须相等，门禁逐字对） |
| `finals_cup_hour()` | 20（= `FINALS_START_HOUR_UTC`，门禁逐字对） |
| `finals_cup_wait_sec()` | 3600：20:00 还有组没打完时最多再等多久 |
| `finals_seed_at_seat(slots, pos)` | 座次表（`bracket.gd._seat_table` 同一构造） |
| `finals_champion_seed(week, bucket)` | 收盘的组从决赛顺着 `finals_results` 追到第 1 轮座位 ⇒ 冠军种子号；没收盘 / 缺行 ⇒ null |
| `finals_cup_seat(week)` | 幂等。条件：杯还没建 且 现在 ≥ 周日 20:00 UTC 且 本周有组 且（全部组已收盘 或 已过等待上限）。取每个**已收盘**组的冠军，按周六战绩排种子（`gw desc, gl asc, account_id`，与 `finals_seat` 同一条排序 ⇒ 高种子轮空），快照用他组赛那一份（与「沿用上一轮阵容」一致）。1 人 ⇒ 建 n=1 且直接 `closed`（没有对局，他就是冠军） |
| ★`finals_view` | 「我那个组」的查询加 `and e.bucket_no <> finals_cup_no()`；其余逐字不变 |
| ★`finals_week_view` | 组列表排除杯；回包顶层加 `cup`（杯那一张，同形状含 round_at / revealed_at；没建 = null） |
| pg_cron `finals_cup_seat` | `*/5 20-23 * * 0`，先按名字 unschedule 再 schedule（可重复执行） |

不剧透 / 开播 / 回放：杯那一张走 `finals_view` 同一条 `b.closed or r.round < b.round`，开播窗口按杯的 `revealed_at`，回放 `finals_replay(week, 1000000, r, m)` —— 全部原样复用。

## 5. 已知风险与未决点

1. **已定（主会话 10-07）· 冠亚四强只从冠军杯赛来**：冠军杯赛 1 人 ⇒ 他是冠军，没有亚军 / 四强。原来「只有一个组 ⇒ 组里的亚军 / 四强照发」的兜底已删。新分组规则下 N≤8 人人直接进杯，「只有一个组」只会在全周 2 人以上而只收到一名组冠军（等待上限触发）时出现。
2. **未验 · SQL 没在真库跑过**。本机没有 Postgres；座次构造与追溯逻辑用 GDScript 逐行翻译版在 n=1..40 上与 `bracket.gd` 对账（`verify_champion_cup`），但 plpgsql 语法 / 权限只有主会话上线时才验得到。上线后建议在 staging 周跑一遍 `tools/probe_finals_server.py` 的同类探针。
