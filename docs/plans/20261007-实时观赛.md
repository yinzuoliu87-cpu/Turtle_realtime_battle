## 调查（2026-10-07 实施前读代码 + 探针）

- **录像 / 播放**：`ReplayRecorder` 录「种子 + 开局 16 个 GameState 变量 + 改结果的输入事件（fight 带站位 / present / surrender，按 sim 步号）+ 每 60 步一个校验点 + end」；播 = 从第 0 步重算，第 S+1 步开头放步号 S 的事件。推进入口只有一个：战斗场 `_process` → `_advance_sim_accum(rd × time_mult)`，每帧最多 8 步，步长恒为 SIM_DT。
- **周日翻面**：`finals_advance(p_week)` 由 pg_cron 每分钟叫（jobid 1）：本轮时间到（`round_at + finals_round_sec()`=480 秒）且该打的都有结果 ⇒ `round = round + 1, round_at = now()`；最后一轮 ⇒ 只 `closed = true`，**不动 round_at**。⇒ 没收盘时「上一轮的翻面时刻 = 本轮 round_at」，但**决赛那一轮翻面的时刻哪里都没记**。`finals_view` 下发 round_at，`finals_week_view`（观赛那几组）连 round_at 都不下发。⇒ 补列（见出入 4）。
- **周日录像**：选手那一份在揭晓前不上传（`replay_uploader.finals_upload_ready`），翻面后选手客户端在对阵图轮询时补传；服务端 `finals_replay()` 只给已揭晓的、按 `seed_used` 认出采纳那一份。⇒ 开播刚开始的几十秒里可能「暂无回放」（风险 8）。
- **SQL 惯例**：`server/supabase/migrations/YYYYMMDD[x]_<名>.sql`，同一段带 `-- >>> BEGIN … >>>` / `-- <<< END … <<<` 标记追加进 `schema.sql`（`verify_week_leaderboard` 逐字比两处）。周清 = `purge_old_matches()`（cron jobid 11，周二 00:00 UTC）。
- **★确定性缺陷（实施中查出，已修）**：031 迷你水晶球B 的扫射起始角用裸 `randf()`（引擎全局 RNG，没播种）⇒ 同一份录像重算时起始角不同。探针 `tests/_probe_lf_speed.gd`：同一配置重播 7 次分叉 4 次（对面 space 的生命在第 1751 步差 0.08，校验点 29 对不上；`_crystal_sweep_step` 一步之差的伤害/吸血）。改成 `battle._battle_rng.randf()` 后 8/8 + 3×6 档全部一致。不修的话，带 031 的对局观赛必「直播中断」、回放必「回放中断」。

## 出入（方案 ↔ 实际做法）

1. **SQL 路径**：方案写 `sql/20261007_live_matches.sql`；仓库惯例是 `server/supabase/migrations/` ⇒ 实际 `server/supabase/migrations/20261007_live_matches.sql`，同一段并入 `schema.sql`（验收清单 done-when 已改）。
2. **追帧目标**：方案写「开打至今真实时间 × 每秒步数 − 缓冲」。实际用「打的人最后上报的步号 horizon − 6 秒」：打的人的步数不等于墙钟（摆位思考、掉帧），而且观众**不许越过 horizon**——越过就可能漏掉打的人中途按的认输 / 点幕布 ⇒ 分叉。为此打的人除「每个事件追加一次」外**每 3 游戏秒心跳一次**（带 horizon；方案原文只写了事件）。跑到 horizon 就停、攒够 4 秒再放（不攒会每 3 秒卡一下）。
3. **开播窗口里的「该场时长」**：对阵图拿不到每场多长（录像点开才取）⇒ 没取过录像的场次按上限 240 秒（与服务端「4 分钟重放」同一个数）；取过录像后按真实时长 + 15 秒。
4. **翻面时刻**：新列 `finals_buckets.revealed_at`（`finals_advance` 两条 update 都写），`finals_view` / `finals_week_view` 下发；服务端没上线时客户端退回 `round_at`（没收盘的组照样有开播窗口；收盘的组没有 ⇒ 直接揭晓）。
5. **本人那一场**：开播窗口里下一轮的坑一律写「待定」（名字本身就剧透），**例外**是那一场有我（本轮备战与上一轮开播同时进行，我得知道对手才能打）。
6. **追帧暗幕**：方案只写「同步中」；实拍一帧 8 步快进时幕布与演出叠成一团 ⇒ 追帧期间整屏暗幕 + 正中「同步中」，追上了撤掉。
7. **已打完的直播行**：点「观赛」时那一场恰好打完 ⇒ 直接当回放放（带控件），不挂观赛会话。
8. **服务端没部署**：直播行 upsert 撞一次 404 ⇒ 本进程不再发（否则每 3 秒被拒一次、刷一行日志）。
9. **顺带修**：031 起始角的确定性缺陷（见调查最后一条）。

## 方案

### 周六·正在打的（真直播）
- 录像本来就是「种子 + 开局状态 + 改结果的输入事件（fight 站位 / present 点幕布 / surrender）」，播 = 本机重算。⇒ 打的人**边打边分段上传**：开打（seed+state+第一路 fight 事件）建一行，之后每出现一个事件追加一次，打完写 end。
- 观众端：取这一行 → 本机从第 0 步重算追到「当前该到的步」（= 开打至今的真实时间 × 每秒步数，减一个缓冲），再按 1 倍速跟播；追到最后一个已知事件仍未收到下一个（打的人还在摆下一路）⇒ 停在幕布上显示「下路准备中」，轮询到新事件再放。
- 打完：这一行转成正式回放（沿用现有上传队列与 `matches` 行），赛况板上该场从「直播」变成普通卡（写胜负 + 「观看」=回放）。
- 赛况板：战绩榜「在打」的人旁一颗红色直播标；右栏顶上「正在打」区，每场一张卡（双方名字 + 阵容 + VS + 「直播」小签，**不写胜负**）+ 「观赛」钮。
- 服务端：新表（暂名 `live_matches`），本人 insert/update 本人行，同周所有登录者可读；周清。SQL 写成文件审过再上生产（主会话执行，agent 不碰凭据）。

### 周日·逐轮开播
- 本轮结算封存 → 轮次翻面（=开播时刻）→ 这一轮的场次在「开播窗口」（翻面时刻起 + 该场时长 + 缓冲）内：对阵图格子**不显示胜负**、标「开播」；点格子弹卡**不写胜负**，按钮「观赛」，进去按「翻面时刻至今」的偏移同步跟播（迟到的人从当前进度看，不能倒回）。
- 开播窗口过了（或这位观众已经看完那场）⇒ 格子显示胜者 ✓，弹卡写「X 获胜」，按钮「观看」= 回放。
- 本人那一场同样遵守：揭晓随开播（已有 `finals_pending_reveal` 机制，不改）。
- 翻面时刻从服务端取（`finals_view` 已有轮次推进；没有时间戳就补一列，同样走审过的 SQL 文件）。

## 已知风险与未决点

1. **打的人中途断网/杀进程**：直播行停在某个事件上永不结束。处理：超过「最长一场 + 缓冲」未更新 ⇒ 赛况板不再列为直播；观众端显示「直播中断」并退出。正式结果仍走现有补报队列。
2. **流量**：观众每 2~3 秒轮询一次。内测规模（百人级）可接受；上量后应换 Supabase Realtime 推送。
3. **观众数 👁**：需要观众在线计数（额外写入），本轮不做，只做「直播」小签。
4. **周日双份战斗**：周日双方各在本机打对方快照，是两场不同战斗，服务端采纳先报的那一份。开播放的是**采纳那一份**；「正在打」期间不提供周日直播（结果封存，原稿要求同步开播）。
5. **剧透残留**：周六战绩榜本身公开几胜几负，观赛卡不写胜负，但榜上的数字在对局结束那一刻就会变 —— 原稿周六就是「实时战绩榜」，接受。
6. **版本不同**：观众与打的人客户端版本不同则不能重算（沿用 V6 拒播），显示「版本不同，无法观赛」。
7. **CPU**：观众端追帧要从第 0 步快速重算到当前步，一场 3 分钟约 5400 步，追帧期间显示「同步中」。

8. **周日开播开头几十秒「暂无回放」**：采纳那一份录像是选手客户端在**翻面之后**才补传的（揭晓前不传，防剧透）。选手不在对阵图上 ⇒ 要等他下次打开主菜单 / 对阵图。观众这段时间点「观赛」看到「暂无回放」，格子仍不揭晓（窗口按上限 240 秒）。根治要让服务端在翻面时自己出录像（选手提前把录像加密上传、翻面时解锁），本轮不做。
9. **开播是展示层遮挡**：周日结果在翻面那一刻已经下发（数据层的不剧透只管「当前轮」）。开播窗口靠客户端不画 —— 改不了「懂行的人抓包看得到」，与原稿「物理上是回放」一致，接受。
10. **追帧耗时**：一场打到第 3 分钟才进来 ⇒ 约 5400 步 ÷ 8 步/帧 ≈ 11 秒（60 帧机器）暗幕「同步中」。低端机更久。可接受；要更快得另开一条「一帧不限步数」的推进路径（确定性风险），本轮不做。
11. **直播行周清**：并进 `purge_old_matches`（同一个 cron、同一个周界）。直播行打完就没用了，最多留到下周二；行很小（≈2~3 KB），内测规模无压力。
