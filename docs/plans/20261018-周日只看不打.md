# 周日决赛：点开只能看，不在本地打；能看到所有组

2026-10-18 · 状态：草稿

- 用户 10-18 周日决赛进行中（看 LP 的号与自己的手机）：
  - 「我看到了有诸多问题，在框那里点开始对局有啥意义，就是本地的，又不是服务器的，而且还出现本地因为站位赢了，服务器的判输」

  - 我说明根因后：「对啊，得改的啊」
- 原稿 `docs/design/斗龟场大轮赛制方案v2-用户原稿.md`：第 85 行「3 分钟备战购物 → 系统瞬间结算 → 全桶观看 3 分钟战斗重放」；第 103 行「共享种子结算一次 → 双方各自观看同一份重放」。

## 调查

现状（v0.19.570，生产；服务端 `20261012d_finals_settle_once` 已上线，`finals_report` 带 `p_reporter_side`）：

| 环节 | 现在怎么做 | 代码 |
|---|---|---|
| 阵容锁定 | 购物窗（180 秒）内客户端每 15 秒推一次快照；窗外拒收 ⇒ 购物结束那一刻锁定 | `finals_update_snapshot` |
| 谁算这一场 | **上半区的客户端**在本地打「自己的**当前**阵容 × 下半区快照」；下半区等 300 秒宽限，上半区没报才由下半区替他打 | `Phase2Config.finals_fight_open`、`finals_report` |
| 打之前 | 进战斗场照常有**布阵阶段**，可以拖动重新摆站位，再按「开始战斗」 | `RealtimeBattle3DScene` 布阵 |
| 结果 | 服务端只收先到的那一份（`on conflict do nothing`） | `finals_report` |
| 看别的组 | 对阵图只拉自己那一组（+ 冠军杯赛） | `BracketMapScene`、`finals_view` |

**问题**（10-18 实战中用户看到）：
1. **站位不进快照**：上半区在布阵阶段重摆的站位只在他本地生效，快照里还是原站位。本地打赢 ≠ 服务端那份；下半区本地也能重摆、也能「赢」，但不会被采纳 ⇒ 用户看到「本地因为站位赢了，服务器判输」。
2. **「开始对局」大多是白打**：下半区点开、布阵、打完，几乎总是不算（上半区已经报了）；上半区虽然算数，但他能在看到对手快照之后再调站位，对下半区不公平。
3. **看不到其他组**：只能看自己组。

**10-18 冠军杯赛实测补充**：半决赛（萌新求带233 vs 圆圆）与决赛（单杀王 vs 萌新求带233）都没真打 —— `finals_results.seed_used = 0`，是服务端到点按「0 号位赢」代判的，没有录像。
根因：模拟号点开场次 → `fetch_opponent_async` 没拿到对手（时机不对）→ `BracketMapScene._try_start_match` 返回 false 但**不清 `_await_match`** → 自动驾驶 `_poke_bracket` 见「已在等」永不重试，挂了一个多小时（日志 `p92/logs/godot2026-10-18T20.59.02.log` 末行即「点开第 2 轮第 1 场」）。真人点一次没反应也是同一处。
另：用户 10-18 要求把第 4 组冠军从 bruce酱（模拟号）改判为单杀王（真人，他本地那局赢了而服务端采纳了对方的报告）——已在生产改 `finals_results` 一行（第 1 轮第 0 场 winner_side 1→0），用户逐字批准「改i」。

## 出入

- 原稿是「系统结算一次，所有人看同一份重放」；现状是「上半区本地打一场（还能临场改站位），其余人各打各的不算数的本地战」。
- 原稿里没有「决赛场里布阵」这一步；布阵只该在备战窗里做，并且进快照。

## 方案

1. **站位进快照、购物结束即锁定**：备战窗内在背包页 / 商店调整的站位随阵容一起推到 `finals_update_snapshot`（快照里已有站位字段的话直接用；没有就加）。购物窗关闭后双方快照都不再变。
2. **决赛场不布阵、不按「开始战斗」**：从对阵图点开自己那一场 = **观看**。战斗场按「双方锁定快照 + 服务端定的种子」直接开打，没有布阵阶段，没有可点的开战按钮。进场时机仍按现在的规则（购物结束 → 上半区算；宽限后下半区代算）。
3. **只有一份输入 ⇒ 谁算都一样**：两边看到的都是「快照 × 快照 × 同一种子」，战斗确定性已在跨设备回放里核对过（`docs/plans/20260926-A跨设备确定性.md`）。结果仍由上半区先报；下半区代报的结果与上半区按同一输入算出的必然相同。
4. **已经有结果的场次**：点开 = 看回放（现有 `open_replay`）；**正在打的** = 观赛（不知道结果、没有播放控件，10-07 用户定的「观赛≠回放」）。
5. **看所有组**：对阵图加组别切换（第 1 组 … 第 N 组 + 冠军杯赛），别的组只能看、能点开已揭晓的场次看回放。服务端 `finals_view` 按组号取，现有接口已带 `p_bucket`，确认匿名 / 非本组读权限是否放开。
6. 拿对手失败要清掉等待标记、到时再试（真人与模拟号同一处）。
7. 服务端到点代判不再一律判 0 号位：按双方锁定快照真打一场（与第 3 条同一件事），有结果有录像。
8. 门禁：
   - 决赛场进入时布阵阶段为空、开战按钮不出现（真入口：对阵图点开）。
   - 同一场「快照 × 快照 × 种子」在两个客户端（上 / 下半区视角）算出的胜方一致。
   - 对阵图能切到非本组并画出该组的对阵。

## 已知风险与未决点

- 快照里现在有没有站位字段、背包页调站位是否会写进推送的快照 —— 动手前先读 `finals_push_snapshot` 与快照格式确认；改快照格式要兼容旧快照（没有站位 ⇒ 用默认站位）。
- 上半区掉线、下半区代算：输入相同 ⇒ 结果相同，但要用门禁证实，不靠推理。
- 改服务端权限（看别组）要上生产 SQL，按规矩先给用户看语句再执行。
- 已发的 v0.19.570 客户端仍按旧方式打：新规则要么跟版本号门槛（旧客户端提示更新），要么服务端兼容旧报告；下一次内测前全平台对齐。
- 本次周日（10-18）不改，照现规则打完。
