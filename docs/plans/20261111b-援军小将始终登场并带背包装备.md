# 援军小将：始终在终极战场登场，并随机带一件背包装备

> 状态：实施中（2026-11-11）
> ★done-when：§6 验收 A1~A8 全部打勾，ship 进 main

## 2. 调查结论（行号）

- **现在只在名单为空时上**：`dual_lane_flow.gd:721` `_dl_survivor_specs(side)` —— 这一方 `GameState.dual_survivors[side]` 非空就原样返回，空了才返回一只 `{"kind":"minion","role":"reserve"}`。终极战场开场（`:565`）与对阵预览（`:141` / `:147`）都读它。
- **小将带装备的通路已有**：spec 上的 `equips` 数组（`_dl_spec_equips` `:474`，幸存者进终极战场就是靠拷 `equips` 带装备的 `:979`）。预览卡见到 `equips` 自动画装备小图标（`:394`）。
- **背包**：`GameState.persistent_bench`（未穿戴的装备，`{"id","star"}`）。穿着的在 `persistent_equipped`（统领）/ `dual_lineup` 小将格。
- **对手 / 服务器拿不到背包**：
  - 对手快照 `Backend.build_ghost_snapshot`（`backend.gd:1983~`）不带背包；
  - 服务器裁判局的左方状态由 `referee_job.gd:~300` 从 A 的快照拼出，也没有背包；
  - 录像 `ReplayRecorder.STATE_KEYS` 明确不录背包，`verify_replay_roundtrip` V3b 把 `persistent_bench` 列为「录像里绝不许出现」的敏感字段。
- **随机数**：战斗随机走 `_battle_rng`（`RealtimeBattle3DScene.gd:789`），种子在开局登记、录像记、裁判下发。探针实测 `RandomNumberGenerator.seed` 抽数前后不变（123456789 → 抽 50 次 → 仍是 123456789）。
- **机器人**：`Backend.make_bot`（`backend.gd:387`）用传入的 `rng` 顺序生成装备；后续机器人的序列依赖这条随机数流。

## 3. 需求 ↔ 代码的出入

| 需求 | 现状 |
|---|---|
| 援军小将始终登场 | 只在这一方没有任何幸存时登场 |
| 带背包里未穿戴的装备，随机一件 | 援军小将无装备（10-29 用户「没有装备，因为…背包是看不到我这个角色的」） |
| 对手的援军也要带对手背包里的 | 快照里没有背包 |

## 4. 方案

1. **始终登场**：`_dl_survivor_specs(side)` = 幸存者（照旧）+ 末尾追加一只援军小将。幸存为空时就只有它（与原来一致）。
2. **可抽装备 `reserve_pool`**：`GameState.reserve_candidates()` 从 `persistent_bench` 取有效装备 `{"id","star"}`，保持背包顺序，最多 60 件。
   - 左方在战斗里读 `GameState.reserve_pool`。
   - `ReplayRecorder.start()` 里在实打（录制 / 不录制）分支开头从背包刷新它；回放 / 观赛 / 服务器裁判 / 补打四条路在前面已经 return，各自用录像或任务带来的那份。
   - 进 `STATE_KEYS`，录像只录这份可抽清单，背包本体仍不进录像。
3. **对手**：快照新字段 `reserve_pool`（`build_ghost_snapshot` 写，`seed_as_human` 照拷）。右方读 `dual_ghost.reserve_pool`。服务器裁判的左方从 A 快照的 `reserve_pool` 填进 `GameState.reserve_pool`。三处都走 `Backend.reserve_pool_of`：有键用它（空数组 = 背包里没有没穿的，不带装备）；缺键（机器人 / 陪练种子文件）⇒ 按 ghost_id 派生 1~2 件 1 星商店装备。
4. **抽一件**：`ReserveConsts.pick_equip(pool, seed, side)` 是纯函数：独立 PCG，种子 = 对局种子异或阵营盐。
   - 不消耗 `_battle_rng`，预览卡、真打、回放、服务器裁判抽到同一件。
   - 抽到的写进援军 spec 的 `equips`（只这一场借用，不动背包）。
5. **机器人 / 陪练**：`make_bot` 写 `derived_reserve_pool(ghost_id)`（独立随机数，不消耗原 `rng`，已有机器人的其余内容逐位不变）；`seed_as_human` 写 `reserve_pool_of(g)`。缺键回落与它同一个函数 ⇒ 陪练「原样 vs 转换后」战斗强度逐字相同；陪练不会因为「全都没有可抽装备」被一眼认出（`verify_bot_snapshot_shape` 实测抓到过）。
6. **文案**：图鉴援军小将的被动「援军」说明、各处注释改成「始终登场 + 随机带一件背包装备」。

## 5. 已知风险与未决点（按我的判断定，用户说「自己自动做」）

- **双方都上**：需求说「始终在终极战场登场」，不分敌我 ⇒ 双方各一只。
- **候选范围**：背包里所有未穿戴的装备都算，含小木斧（抽到就召唤斧头，进度按这一方的）。星级按背包里那件的星级。背包空 ⇒ 不带。
- **站位**：援军排在幸存者之后，沿用 `_spawn_lane_side` 的纵向排开。
- **强度**：终极战场每方多一个单位、多一件装备，对局结果变 ⇒ RULES_VER 已在 0.23.1 之后升到 6（同一批），规则指纹金标刷新。
- **版本**：服务器裁判要随发版部署新版本（`tools/deploy.py`）才会按新规则判。旧快照不在新 RULES_VER 的池里，不会混打。
- 背包会出现在录像的 `reserve_pool` 里（只有装备 id 和星级）—— 这是机制本身需要的最小信息。

## 6. 验收标准（每条写明怎么证明会 FAIL）

- **A1** 走裁判真入口跑整局（`verify_reserve_minion`）：有幸存的一方也上援军，名单 = 幸存 + 1 只援军。变异：去掉追加 ⇒ 红。

- **A3** 同种子同一件；60 个种子能抽到池里 ≥ 3 种不同的件（不是恒取第一件）。变异：恒取第一件 ⇒ 红。

- **A5** `build_ghost_snapshot` 的 `reserve_pool` = 背包里的装备；穿在身上的不算。
- **A6** 录像 state 带 `reserve_pool`、仍不带 `persistent_bench`（`verify_replay_roundtrip` V3 / V3b 照过）。
