## 需求原文

用户 2026-09-11：

- 「继续接下来 10 件全部做完」
- 「**记住不一定每个特效都非要改，一定是有优化才改**」

⇒ 这一轮的交付物**不是「10 件都重做」**，而是**「10 件都体检过，并给出改/不改的凭据」**。
不改的那几件，必须说清「量到了什么、为什么它已经够好」；改的那几件，必须说清「量到的缺陷是什么」。

沿用 010/011 两轮定死的口径（用户 2026-09-10 原话）：

- 「**不应该有预警啊**」—— 文案没写的东西不许加。
- 「我实际的效果就是波在移动，碰到人造成伤害，你这样没有遵从装备效果啊」
  ⇒ **演出必须就是效果本身**，不是把效果换个说法重新编码一遍。
- 「不要拿图片贴图敷衍我，我要动画像素特效」；图标 **32×32**。
- 「为什么后续的斩击弧越来越小，**我不要这个东西**」—— 观感项以他实拍看到的为准。
- 素材不复用（2026-08-03 铁律）。

### ★★最大的那一条：这 10 件里 6 件在屏幕上的全部内容，是一个用户早就否掉的程序生成圆环

`battle_damage.gd:662` 的注释自己写着（不是我的推断）：

> ★★2026-08-09 用户看到 095 的画面：「**又是程序生成的环？哪个商业游戏是你这么做啊**」。
> 这一行就是那个环 —— `_skill_ring` 是**代码现画的一个圆**，而它封着全游戏 44 个给盾点，
> 于是任何来源给盾，脚下都糊同一个金圈。程序化圆环是占位素材的水平，这条不辩解。
> ⚠ 但它是**共享**的：直接删会波及所有装备/羁绊/技能 ⇒ 那是单独一轮的事（已记路线图）。

按 `vfx_textures.gd:154` 的公式逐字复算它的规格（96×96，`a = clamp(1-|d-0.82|/0.18)*0.6`）：

| 量 | 值 | 我给 010/011 素材定的线 |
|---|---|---|
| RGB 色数 | 1（纯白，全靠 `modulate` 上色） | ≤ 8 ✓ |
| **半透明像素** | **4184** | **0** ✗ |
| **全不透明像素** | **0** | — |
| alpha 档位 | **148 种连续斜坡** | 硬边 |
| 峰值 alpha | **153/255**（公式里那个 `×0.6` 封的顶） | 满亮 |

⇒ 它同时踩了**「不是像素画」**与**「淡出病」**两条，
而 012 / 013 / 016 / 018 / 019 / 021 六件的可见反馈**就是它**（经 `_grant_shield` → `_skill_ring`）。

**调用点 187 处、44 个文件** —— 所以它不能靠"每件各画各的"解决，只能在**那一个函数**里换。

## 方案

### 第 1 步（共享层，一处修好 187 处）：把程序生成环换成烤好的像素环

- 新 `tools/gen_skillring.py` → `assets/sprites/vfx/skill-ring.png`：
  **白→浅灰的明度阶梯（≤4 色）+ 硬 alpha（0/255）+ Bayer 抖动按最终像素算**，
  依旧**纯灰度**，颜色仍由各调用点的 `modulate` 决定（187 处一个都不用改）。
- `VfxTex._make_ring_texture` 改成 `load()` 这张图；程序生成那段删掉。
- **感知亮度保持不变**：现状峰值 alpha 是贴图自带的 0.6，换成硬 alpha 后
  由 `RING_PEAK_A` 承接（1.0 → 0.62），**这一轮不顺手把全游戏调亮** —— 那是另一个决定。
- 曲线、`set_meta("ring_target_ps")`、tween 一律不动 ⇒ 现有曲线门禁原样通过。

### 第 2 步（本批 10 件）：图标改成 32×32 像素画

沿用 010/011 的两步流水（`gen_*.py` 渲大图 → `pixelize_sheet.py` 锁板下采样）。
判据：色数 ≤ 8、半透 = 0、32×32。做一件从 `pixel_art_debt.json` 里销一件。

### 第 3 步（本批 10 件）：逐件实拍 100 帧，只改量到缺陷的

每件配 VFXLAB 案例 → 拍 100 帧 → **每一帧都看** → 写进 `docs/studies/`（`frame_study_audit` 焊死帧号连续）。
**看完没缺陷的，就写「不改」并给出量到的数** —— 这是本轮交付物的一部分，不是省事。

## 已知风险与未决点

1. **换环的波及面是全游戏 187 处**。风险不在"会不会崩"（API 与几何一字不动），
   而在**观感会整体变一次**：软边 → 硬边像素环。这正是用户要的方向，但**是全局的**，
   所以第 1 步做完**先开窗给用户看**再往下走。
2. **`RING_PEAK_A` 1.0 → 0.62 是为了"不顺手改亮度"**。如果实拍发现像素环在硬边下比软边更闷，
   要调的是这个数，**不是**回头去加半透（那等于把反锯齿又请回来）。
3. **012 的图标不在债务台账里**（63 色 / 0 半透）—— **查清了，台账判据确实有洞**：
   `tools/pixel_art_audit.py` 的 `MAX_COLORS = 64`，而 012 是 **63 色**，差一点点溜过去。
   台账的线（≤64 色）比我给新素材定的线（**≤8 色**）宽了 8 倍。
   ⇒ **本轮不动那个阈值**：收紧会让台账里剩下的 33 件当场全红，那是范围决定，要用户拍板。
   ⇒ 但结论要记住：**「不在债务台账里」≠「这张图没问题」**，下一轮别拿它当免检。
4. 本批全是防御/辅助件，**很可能有几件查完确实不用改**。那是预期结果，不是偷懒。
5. 十件的 VFXLAB 案例大多**还不存在**，要现配（`vfxlab_cases.gd`），配错台子会把"我没配对环境"报成"效果有问题"。

## 决策记录

| 决策 | 谁定的 | 理由 |
|---|---|---|
| 本轮先动共享的环，再动单件 | 本方案 | 10 件里 6 件的可见反馈**就是**那个环；不换它，单件怎么改都还是"脚下糊同一个金圈" |
| 换环只换贴图，不动曲线/不动 API | 本方案 | 187 处调用；把爆炸半径压到"一张图" |
| 亮度维持现状（`RING_PEAK_A` 承接 0.6） | 本方案 | 用户要的是"别用程序生成的环"，没说要更亮；顺手调亮是夹带 |
| 不改的件也要写结论 | 用户「不一定每个特效都非要改，一定是有优化才改」 | 「不用改」也是交付物，但必须带量到的数 |

### 踩的坑（记账，不是自责）

换 `_make_ring_texture` 时我按「从 func 切到下一个 func」删范围，
**把夹在两个函数之间的 `static var _star_tex_cache` 一起吃了** ——
四个门禁一起红、9 条 `Parse Error`。memory `fb-block-delete-eats-functions` 早写过这一条
（「删函数逐个按函数名定位别按范围切，切完立刻 `git diff | grep '^-func '`」），我没执行那一步。
⇒ 之后每次块替换都紧跟一次 `git diff` 核对「净删除里有没有我不想删的声明」，本轮后面两次都照做了。

### 另一个发现：像素画债务台账的判据有洞

`tools/pixel_art_audit.py` 的 `MAX_COLORS = 64`，而 012 的旧图标是 **63 色** —— 差一点点溜过去，
所以它**不在**债务台账里，却同样不达标。台账的线比本轮给新素材定的线（≤8 色）宽 8 倍。
本轮**不动那个阈值**（收紧会让剩下 33 件当场全红，是范围决定，要用户拍板），
但结论要记住：**「不在债务台账里」≠「这张图没问题」**。
