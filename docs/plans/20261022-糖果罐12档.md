# 糖果罐改 12 档（赢 +2 / 输 +3 / 封顶 60 / 每档 2~4 个奖励）

日期：2026-10-22　|　状态：实施中

## 1. 需求原文

- 用户 2026-10-22：「以及记得糖果罐需要调整强度」→「糖果罐强度晚点弄」→ 我列现状（6 档、赢 +1 输 +4 封顶 30、四个问题）→
- 「改为赢+2，输+3，封顶60，分为12档」
- 「每档制定2-4个奖励」

## 2. 调查（改之前的现状，代码实查）

- `autoload/GameState.gd` `_CANDY_JAR_TIERS`：6 档，每档 = 深海币区间 + 1 件装备（费档 / 星级）+ 临时等级器**概率**（档 4/5/6 = 25% / 50% / 100%）。
- 计数：赢 +1 / 输 +4 / 封顶 30；积分赛（`RealtimeBattle3DScene` 结算）、周六闯关（`gauntlet_settle`）、周日决赛（`finals_reveal`）三处加。
- 档位：0-5 / 6-11 / 12-17 / 18-23 / 24-29 / 30。

## 3. 需求 ↔ 代码的出入

- 用户只定了结构（赢 +2 / 输 +3 / 封顶 60 / 12 档 / 每档 2~4 项），每档具体发什么没定 ⇒ §5 的表是我拟的。
- 原来的临时等级器是**概率**给（档 4/5/6 = 25% / 50% / 100%），「每档 2~4 个奖励」按确定项数算 ⇒ 改成到档必给。
- 原来领奖框固定 300 高、最多 3 行，4 项奖励放不下 ⇒ 框高跟行数走。

## 4. 方案

- 计数常量化：`CANDY_JAR_WIN = 2`、`CANDY_JAR_LOSS = 3`、`CANDY_JAR_CAP = 60`、`CANDY_JAR_TIER_SPAN = 5`；三处加计数都改读常量。
- 档位 = 计数 ÷ 5 + 1，上限 12（第 12 档 = 55~60）。
- 每档 2~4 套奖励，打碎时随机给其中一套（各套等概率）；一套 = 深海币 / 装备 / 大轮经验 / 临时等级器的组合。表见 §5（我拟）。
- 领奖框按奖励行数自适应高度（原来固定 300 高、最多 3 行）。
- 背包罐子的说明改成顿号分隔（原来「｜」「×1」不合文案规矩）。
