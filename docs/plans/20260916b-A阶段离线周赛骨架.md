## 1. 需求原文

母方案书 §7 的拍板，与 A 阶段直接相关的部分：

- 赛程：周一休赛 / **周二~周五积分赛（8 命 + 24 场配额）** / 周六闯关赛 / 周日决赛日。

- 时区默认英国、**可配置**。
- 头衔四档：冠军 / 四强 / 进决赛日 / **积分赛满配额**（只有最后一档落在 A 阶段）。

A 阶段**不碰**：后端、周六周日的同步赛事、观赛、重放、训龟大师改造（那些在 D~F 与 §4.4）。

## 3. 与现状的出入

1. **配额这个概念现在完全不存在**。现在只有 `season_total_battles`（只增不减、跨大轮由 `start_new_season` 归零），
   没有「本周期可打几场」。A2 要新增的字段是真·新增，不是改语义。
2. **「按已打场数分 9 档」与「双方总场次必须相同」不是一回事**。现在 `pool_add` 按 9 档装桶，
   桶内随机取。A6 是在桶内再加一层精确过滤 —— **桶结构不用动、旧池不用迁移**（快照里本来就带原始场数，`backend.gd:482`）。
3. **排行榜现在按「碎蛋数」排**（`backend.gd:207` 的注释明写"信任本地 `season_eggs_killed`，不复算"），
   A8 要换成「胜场 → 余命 → 横扫」，而**快照里现在没有"横扫数"这个字段**，要新加。
4. **横扫（2-0）现在没人记**。判定所需的东西都在：`GameState.lane_results` 在结算这一刻还活着
   （写入点 `dual_lane_flow.gd:750`），`phase2_duallane.gd:39-47` 有「要不要打终极」的判定函数。
   但没有任何地方把"这局是不是 2-0"存下来。
5. **赛季面板现在恰好四行**，而且这个数字被门禁焊死（`verify_mainmenu_layout.gd:209`）。
   A5 加「剩余场次」那一行 ⇒ **这是要改的账**（把分母改成五并写清为什么），不是放松判据。
6. **时区现在没有任何概念**。`SEASON_DURATION_SEC = 432000`（5 天）是"每台设备各自滚动"，
   不是自然周、更没有收盘时刻。A1 要把赛程从"时长"改成"带时区的周历"，这是**语义变更**不是加常量。

## 4. 方案

### A1　常量落位　`scripts/gamedata/phase2_config.gd`

在「V2 赛季」区（`:14` 那一段）后面加一组：积分赛配额、补发地板（币 / 经验）、
晋级线、闯关线、赛程各阶段起止、**时区偏移（默认英国、可配置）**。全部集中在这一个文件。

⚠ 门禁**不要**断言「常量等于某个数」—— 那是把参数抄两份。常量的正确性由 A3~A7 的行为门禁间接守。

### A2　存档字段　`autoload/GameState.gd`

新增：积分赛已用场次 / 横扫数 / 补发已发场次（幂等用）/ 赛程阶段 / 自然周锚点 /
闯关战绩（胜、负）/ 是否已晋级。**每个都走 §2.4 的五处。**

门禁 `verify_week_season.gd`（A 阶段新建，现在还不存在）：
① 存档往返保值 ② `start_new_season()` 后全部归零。
反向验证：注释掉载入那一行 ⇒ ① 红；注释掉 `start_new_season` 那一行 ⇒ ② 红。

### A3　结算接线　`RealtimeBattle3DScene.gd:7531 _settle_season`

- `:7551` 旁边记积分赛配额消耗；**闯关赛 / 决赛日的场次不吃积分赛配额**，按赛程阶段分流。
- 横扫：在 `:7556` 附近判「两路都打完 + 不需要终极」⇒ 横扫数 +1，并写进 `record_match`（`:7581`）。
- 补发要用到的按场数成长在同一段：096 砍伐经验 `:7553`、糖果罐 `:7554`（**按拍板不补**，见 A7）。

门禁③直接调 `_settle_season(true/false)`（照抄 `verify_combat_sanity.gd:61-65` 的调法），量配额计数与横扫计数。
反向验证：把横扫条件改成恒真 ⇒ 打到终极的那局也被记成横扫 ⇒ ③ 红。
⚠ 门禁里的场数、命数**一律写死**，不要用常量算期望值。

### A4　开局拦截　`scripts/scenes/MainMenuScene.gd`

现在只有「0 命淘汰」一个闸（`:212` / `:235` / `:716-718`）。拆成三种原因各自一条提示：
命尽（文案改成「等周六观赛」）/ 配额已打满 / 当前不是能打的阶段。

门禁④照抄 `verify_season_elim.gd:24-45`（实例化主菜单 → 数 toast → 断言 `dual_active` 没被置 true）。
反向验证：去掉配额那一条 ⇒ 配额打满还能开打 ⇒ ④ 红。

⚠ **商店锁（`:235`）要不要也吃配额，必须显式决定**。现在它的条件是
`season_total_battles <= 0 or eliminated`，而 §2.2 有 5 个门禁靠"设 `season_total_battles = 3` 让商店开门"过日子。
改这一行就要同时复核那 5 个。

### A5　读数（界面）

主菜单 `:524-529` 赛季面板加「剩余场次」；结算屏 `battle_hud.gd:1395-1412` 数据块加同一读数；
副标题在配额打满 / 出局时各说各的。
⚠ `verify_mainmenu_layout.gd:209-210` 断言恰好四行 —— **改成五行并写清为什么**。

### A6　匹配　`scripts/net/backend.gd`

`pool_find` 加参数（**必须带默认值**，见 §2.3），在桶内按「场数完全相同」过滤；
按 D10，同场次的多份快照**按上传时刻倒序取最新的**（新鲜度是排序不是过滤）。
回落顺序：精确同场次 → 同桶其它人 → 机器人，**每一场都记账**（这一场是精确 / 同桶 / 机器人），
让「有多少场是真同场次」变成可量的数。

门禁⑤：池里放场数不同的三份快照，我打过 N 场 ⇒ 必须选中场数 N 的那份；
再放两份同为 N 场但上传时刻不同的 ⇒ 必须选中较新的那份。
反向验证：去掉精确过滤 ⇒ 选中别人 ⇒ ⑤ 红；去掉倒序 ⇒ 选中旧的 ⇒ ⑤ 红。

### A7　配额补发　新函数放 `GameState`

触发：积分赛阶段结束且该玩家晋级；补发场数 = 配额 − 实打场数；每场补币与经验（地板值见 A1）。
**按 U6 拍板：不补 096 砍伐经验、不补糖果罐。**
幂等靠「补发已发场次」字段：只补差额，重复调用不再给。

门禁⑥：合成一份存档（打了 K 场、晋级），补发后币 / 经验等于「打满配额的最低供给」——**量真实字段，不套公式**。
门禁⑦：连调两次，第二次一分不加。反向验证：去掉幂等字段 ⇒ ⑦ 红。
门禁⑧：补发后 096 砍伐经验与糖果罐进度**没变**（把「不补」这条拍板焊死，否则将来顺手补上没人拦）。

### A8　终榜　`backend.gd:207-217` + `LeaderboardScene.gd:37/58/80`

排序键换成字典序「胜场 → 余命 → 横扫」；快照补这三个数（`:474-483`），旧快照缺字段当 0（不作废旧池）。
标题与表头文案一起改（现在写「本赛季击杀龟蛋数」）。

门禁⑨：构造同胜同命、横扫不同的三份快照，断言顺序。反向验证：比较器改回只比碎蛋数 ⇒ ⑨ 红。
