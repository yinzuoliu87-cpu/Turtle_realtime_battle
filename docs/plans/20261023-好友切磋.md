# 好友系统 · 切磋

日期：2026-10-23　|　状态：**草稿**

## 1. 需求原文

- 用户 2026-10-23「接下来新任务，好友系统，主要实现切磋，但切记不会去叠比如香火石，宝箱龟被动的层数，因为是不在常规赛里的，切磋是当前的背包阵容vs好友的最新背包阵容。」

拆成三句可验的话：
1. 有好友系统，主打**切磋**。
2. 切磋 = **我当前的背包阵容 vs 好友最新的背包阵容**。
3. 切磋**不在常规赛里** ⇒ 不叠香火石、宝箱龟被动层数等**一切常规赛累积**（用户举的是两个例子，范围按「一切」穷举，见 §2.3）。

## 2. 调查结论（代码实查，2026-10-23）

### 2.1 身份与社交：好友相关的东西现在一样都没有

- 账号 = Supabase Auth uid（`autoload/GameState.gd:50`），首启匿名注册（`scripts/net/supabase.gd:1377-1389`），可补绑邮箱。
- 玩家 ID「#XXXXXX」**不存库，现算**：sha256(`turtle-id:`+account_id) 取 48 位编 6 位（`scripts/gamedata/phase2_config.gd:1298-1315`）；**不唯一**，1 万人约 0.1 对撞号（`:1291-1294`）。服务端有同算法 `player_tag_of`（`server/supabase/schema.sql:3646-3661`）但对客户端 revoke 了。**没有按 ID 查人的接口。**
- 好友 / 关注 / 邀请码：全仓 0 处。拉黑只在本机 `user://blocklist.json`（`scripts/util/blocklist.gd:1-14`）。
- 玩家菜单 `scripts/scenes/social/player_menu.gd:29-33, 120-122` 只有「举报 / 拉黑」，排行榜、周六赛况、周日对阵图、对局顶栏点人都弹它 —— **「加好友」放这里最顺**。
- 昵称只活在各份快照的 `profile.name` 里，服务端 `accounts` 表客户端从来不写（基本是空表，`schema.sql:19-38`）。

### 2.2 阵容快照：链路现成，但「最新背包阵容」服务端上没有

- 快照由 `Backend.build_ghost_snapshot`（`scripts/net/backend.gd:1871-2015`）拼：统领、分路、小将（含装备与站位）、统领站位、统领装备与星级、等级、技能、训龟大师技能、赛季等级、宝箱 / 香火 / 小木斧进度、profile。
- **只在积分赛结算时上传**（`scripts/scenes/RealtimeBattle3DScene.gd:7514-7535`）进 `ghosts` 表（主键 account_id + season_week + battles，`schema.sql:48-79`）；每周二清上周（`migrations/20261008_purge_ghosts.sql`）。打完之后在背包里改阵容**不会再传** ⇒ 服务端只有「最近一场结算那一刻的阵容」，没有「最新背包阵容」。
- 「打指定某人的快照」有现成先例：周日对阵图 `finals_opponent` RPC（`schema.sql:5071-5123`，security definer，先验资格再回快照）→ 写 `GameState.dual_ghost`（`scripts/scenes/BracketMapScene.gd:2300`）→ 进战斗；右方由 `_dual_foe_lane` 读快照建队（`RealtimeBattle3DScene.gd:1460-1520`，全只读）。教程的 `TutorialDirector.arm_battle_sandbox()`（`autoload/tutorial_director.gd:384-388`）直接塞 `dual_ghost` 进战斗，切磋照它最省事。
- 云存档 `saves` 表只有绑邮箱的号才推、RLS 只许读自己（`schema.sql:289-357`, `:301`）⇒ **不能**拿它当好友阵容来源。

### 2.3 一场普通对局会改哪些持久状态（切磋要全部隔离）

**局内实时写（结算时挡来不及）：**

| 状态 | 位置 | 现有闸 |
|---|---|---|
| 香火石 `incense_charge` / `incense_marks` / 装备上的 `chg` | `scripts/systems/equip/incense_stone_system.gd:212-214, 219-222, 376-403` | **无**（只判左方） |
| 宝箱龟 `chest_treasure_value` / `chest_treasures_won`（开箱当场还 `save()`） | `scripts/systems/skills/chest_system.gd:99, 136, 146-147` | `_is_scored_match()`（`scripts/scenes/battle/battle_world_builder.gd:1588`） |
| 赌神龟 `gambler_wheel_stacks` | `scripts/systems/skills/gambler_system.gd:265-267` | **无** |
| 小木斧击杀 / 助攻经验 `axe_exp_*`、`axe_evo_pending` | `scripts/systems/equip/axe_system.gd:455-471` → `GameState.gd:2054-2070` | 只挡对手的斧头 |
| 中途退出待结算单 `user://pending_match.bin` | `scripts/systems/replay/replay_recorder.gd:211-213, 590` | `AbandonedMatch.wanted()` |
| 录像 / 周六直播 | `replay_recorder.gd:192-213`、`live_upload.gd:54-57` | `should_record()`（`replay_recorder.gd:272-279`，按 `week_phase` 判 ⇒ **周六切磋会被直播**） |

**结算时写（`_settle_season`，`RealtimeBattle3DScene.gd:7401-7563`）：** 生命 `hearts`、`season_total_battles`（还决定商店刷新 / 匹配场次 / 装备槽）、`ranked_used` + 头衔、赛季经验 / 等级、小木斧 +15、糖果罐、`season_wins` / 碎蛋 / 横扫、周六闯关战绩与快照、周日决赛上报、**快照上传**（匹配池 + 周榜）、深海币、`battles_total` / `battles_won`、战绩 `match_history`、录像文件 + 服务端 `matches` 行、`ensure_season()`、`save()` 标脏 → 云推送。

**选龟页「出战」时写：** `week_phase` + `save()`、`season_leaders`、`sync_synergy_grants`、`user://lastLineup.json`（`scripts/scenes/TeamSelectScene.gd:1447-1468, 1520-1532`）⇒ 切磋**不走选龟页**。

**云推送推的是内存值**（`GameState.gd:1557-1561` 定时、`:1573-1575` 切后台）⇒ 局内改过的香火 / 宝箱 / 赌神值切后台就会被推上云，除非 `test_mode` 或还原。

### 2.4 现有「这局不算」的机制，没有一个够用

- `test_mode`：`save()` / 云推送 / 待结算单全空转（`GameState.gd:1851, 1558, 1574`）。回放与裁判用「`ReplayRecorder.capture_all()` 整份备份 → `test_mode=true` → 离场还原」（`replay_recorder.gd:943-964`，`RealtimeBattle3DScene.gd:3205`）。
- 教程沙盒：快照账号 → 换全新 → 结束还原（`tutorial_director.gd:287-316`）。
- `_is_scored_match()` / `_is_dev_tool_battle()`：只有宝箱、待结算单等少数地方读。
- **表演赛（0 命打积分赛）不能当切磋用**：照写 `battles_total` / 战绩 / `save` / 录像上传，局内香火 / 赌神 / 斧头也照写。
- `scripts/scenes/RecordScene.gd:27` 已有一个现成标签 `"custom": "切磋"`（没人用）。

## 3. 需求 ↔ 代码的出入

1. 「好友的**最新背包阵容**」：服务端上**不存在**这个东西（只有积分赛结算那一刻的快照，赛季初是空的，淘汰后也不再传）⇒ 要新加「最新阵容」上传：离开背包时传一次。
2. 「不叠香火石、宝箱龟」：这两样（以及赌神、斧头击杀经验）是**局内实时写**的，只在结算时挡**挡不住** ⇒ 必须整局隔离。
3. 好友要能「加」：玩家 ID 不唯一、服务端查不到 ⇒ 要服务端给 ID 建索引，撞号时提示「请让对方告诉你昵称」二次确认。

## 4. 方案

### 4.1 服务端（一份迁移 `20261024_friends`，内测服先上，正式服按周一节奏、上之前跟用户说）

| 新增 | 说明 |
|---|---|
| `accounts.tag` 列 + `me_touch()` RPC | 启动时 upsert 自己那行；tag 由服务端 `player_tag_of` 算，**不信客户端** |
| `friendships(a, b, requester, status, created_at)` | a<b，账号删除级联；RLS 开但无策略，只能走 RPC |
| `friend_request(p_tag)` / `friend_respond(p_other, p_accept)` / `friend_remove(p_other)` / `friend_list()` | 限流（照 `report_nickname` 的 advisory lock + 每日上限）、好友上限、对方已申请过我就直接互加 |
| `lineups(account_id 主键, snapshot, rules_ver, client_version, updated_at)` + `put_lineup(p_snapshot)` | 限大小、带版本检查；客户端用同一个 `build_ghost_snapshot` |
| `friend_lineup(p_account)` | **先验双方是好友**，再回快照 + rules_ver + 名字；没有 lineups 行时退回对方最新一行 ghosts |
| 删号 / 匿名号清理 / 昵称举报处理三处补新表 | 否则有好友的匿名号会被 14 天清理误删 |

### 4.2 客户端 · 好友页

- 入口：主菜单左栏加「好友」键（与背包 / 商店 / 图鉴 / 排行榜并排）＋ 玩家菜单（点别人名字）加「加好友」。
- 好友页：顶部「我的 ID #XXXXXX」+ 复制；「添加好友」输入 ID；「好友申请」列表（接受 / 拒绝）；好友列表每行：头像（对方第一只统领）、昵称、ID、阵容更新时间、**「切磋」**、删除。
- 背包：离开背包时 `put_lineup`（只在阵容有变化时传）。

### 4.3 客户端 · 切磋对局

1. 点「切磋」→ `friend_lineup` → 规则版本不一致就提示「对方版本较旧，等对方更新后再切磋」并停下。
2. 设切磋标志 → `GameState.dual_ghost = 对方快照` → **直接进战斗**（不走选龟页 / 匹配页，照 `arm_battle_sandbox`）。左方 = 我当前背包阵容，起点值（等级、香火充能、宝箱进度等）读我当前的真实进度，**只读不写**。
3. **两层隔离**：
   - 第一层（切磋标志）：`_settle_season` 提前返回（在 `RealtimeBattle3DScene.gd:7432` 决赛上报之前）；`should_record()`、`_is_scored_match()`、`AbandonedMatch.wanted()` 遇切磋一律 false ⇒ 不录像、不直播、不上传、无待结算单、宝箱不写、首场提示不出。
   - 第二层（兜底）：开局 `ReplayRecorder.capture_all()` 备份 + `test_mode=true`，离场（`_exit_tree`）还原 ⇒ 香火 / 赌神 / 斧头击杀这些**没有闸**的局内写入、以及**以后新加的**写入点，都不会落盘、不会上云、离场后内存也回到原样。
4. 结算屏：「切磋 · 不计入赛季进度」，不出奖励格；按钮「再来一局」「返回好友」。
