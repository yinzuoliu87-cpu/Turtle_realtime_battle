## 2. 调查

### 2.1 ★根因是实测的，不是推理的：反汇编 iOS 版引擎

`ios.zip` 里的 `libgodot.ios.release.xcframework/ios-arm64/libgodot.a`（Godot 4.6.3 官方模板）带符号，
逐函数用 capstone 反汇编数 `fmadd/fmsub/fmla`（融合乘加，**只舍入一次**；x86-64 基线没有 FMA，两次舍入）：

| 引擎函数（iOS 版） | 融合指令 | sim 上用到吗 |
|---|---|---|
| `Vector2::length / length_squared / distance_to / distance_squared_to / normalized / dot / cross` | 各 1 | **大量**（索敌、移动、射程） |
| `Vector2::rotated`(2) `angle_to`(2) `limit_length` `move_toward` `lerp`(fmla) `slerp` | 有 | 有 |
| 全局 `lerpf / lerp / smoothstep / lerp_angle / move_toward / wrapf / remap / cubic_* / bezier_*` | 有 | lerpf 55 处 |
| `RandomPCG::random(float,float)` = **`randf_range`**、`randfn` | 有 | `_battle_rng.randf_range` 11 处 + 演出 |
| `Geometry2D::get_closest_point_to_segment` | 有 | 1 处（096 炽天使） |
| **补间缓动** `Quad/Sine/Cubic/…::in/out`、`Animation::interpolate_variant`（非 float 补间） | 有 | 写 sim 状态的补间 10 处 |
| **寻路** `NavMeshGenerator2D::bake…`(6)、`NavMeshQueries2D::_query_task_search_polygon_connections` | 有 | 每个移动单位每 0.4 秒一次 |
| `Linear::in`、`Tween::run_equation`、`MethodTweener::step`、`gdscript_vm`、`variant_op` 的标量 `+ - * /` | **0** | —— 安全 |
| `String::to_float`（脚本/JSON 字面量解析） | 1（`1e9*frac1 + frac2`） | 积是精确值 ⇒ 融不融合结果相同（见 §2.3） |

另一类是 libm：`sin/cos/tan/atan/atan2/asin/acos/pow/exp/log` 由各平台 libm 自己近似（Apple ≠ MSVC/UCRT ≠ glibc），
IEEE-754 不要求逐位一致。

### 2.3 其它平台相关项（逐条核过）

| 项 | 结论 |
|---|---|
| RNG | PCG32 整数；`randf()` = `ldexpf(整数, -32)` 精确；`randi_range` 整数 ⇒ 安全。只有 `randf_range/randfn` 融合 → 已改 |
| Dictionary 遍历 | 插入序，与哈希无关 ⇒ 安全 |
| `Time.*` | sim 路径上没有（sim_driver/live_* 在 SKIP 范围；主场景 1 处只写战绩时间戳） |
| 物理查询 | 没有；**寻路**是唯一的引擎查询 → DetNav |
| 浮点字面量解析 | `built_in_strtod` 同一份算法；那条 fmadd 是 `1e9×(≤9 位整数)+…`，积 < 2^53 精确 ⇒ 结果与不融合相同（反汇编核过常量 0x41CDCD6500000000）。**但它 16 位以上不正确舍入**：DetMath 的 fdlibm 常量因此一律写成「整数 ÷ 2 的幂」（修前 sin(98765) 误差 1.4e-11，修后 1.3e-16） |
| Vector2 运算符 `+ - * /`（VM 里一次一条） | 单次运算，不融合 ⇒ 安全；Vector2 是 float32，DetMath 按 double 算完再存回 float32，两步都确定 |
| `Transform2D * Vector2`、Quaternion 乘法 | 融合，但 sim 上没用 |

## 3. 需求 ↔ 代码的出入

| # | 出入 | 正确的事实 |
|---|---|---|
| 1 | 09-26 方案书 §2.3 说「真正喂进 sim 的只有 7 处 sin/cos」 | 那张表只数了超越函数。**FMA 才是大头**：`distance_to/normalized/length` 每步几百次，iOS 上逐个融合；还有补间缓动和寻路 |
| 2 | 09-26 §9 「Windows↔Linux 13 个场景逐位相同」 | 成立，但两边都是 x86 无 FMA ⇒ 它证明不了 ARM。本方案用扰动在 x86 上模拟 ARM |

## 4. 方案（已实施）

1. **`scripts/util/det_math.gd`（class_name DetMath）**：上表所有函数的确定性版，只用 `+ - * / sqrt floor` 与比较。
   超越函数移植 fdlibm（sin/cos 三段 π/2 归约 + 多项式；atan/atan2；exp；log；pow 整数指数走逐位平方、±0.5 走 sqrt）。
   **门禁开关**（一处）：`raw=true` 退回引擎原版（= 加固前，数值逐位相同 —— 实测 raw 模式 15 个场景终局指纹与改前逐个相同）；
   `perturb=N` 每 N 次平台相关调用给结果 ±1 ulp（double 结果按 double ulp、Vector2 / float32 结果按 float32 ulp）。
2. **改写工具 `tools/det_math_rewrite.py`**（幂等、保留混合行尾、跳过注释/字符串/`"""` 着色器块）：
   方法调用按后缀表达式回溯接收者 → `DetMath.fn(接收者, …)`；接收者类型用 `det_math_scope.recv_kind` 判
   （声明类型 / 3D 标记 / 字符串标记 / 首个实参 / 行内写 `.position=` 的纯演出；**本行写 sim 状态的一律当 Vector2**）。
3. **补间**：写 sim 状态的 `tween_method` 一律 float 0→1、线性；缓动在回调里 `DetMath.tween_ease(q, TRANS, EASE)`（Quad/Cubic/Quart/Sine，in/out/in_out/out_in）。
4. **寻路 `scripts/util/det_nav.gd`（DetNav）**：3 个椭圆障碍的 14 边形（含 OBSTACLE_MARGIN + 烘焙的 agent_radius 10）上做可见图最短路
   （只保留切线边；Cyrus–Beck 判线段穿不穿洞；Dijkstra 平手按下标）。起止点在洞里 / 出界时推到最近的边上（与引擎「取最近的图上点」同义）。
   `battle_world_builder._build_navmesh` 同时建 DetNav；主场景 `_nav_dir` 那一行改走 `det_nav.path`（行数不变）。
5. **门禁**：`tests/verify_determinism_ulp.gd`（新）+ `tools/det_math_lint.py`（新，进 run-tests 审计器）+ 金标 `tests/golden/determinism_cross.json` 重生成。

### 选型理由（逐类）

| 类别 | 选 | 为什么不选别的 |
|---|---|---|
| 超越函数 | (a) 自己实现 | (b) 量化到网格：边界上照样翻（每局几万次调用，翻一次就分叉）；(c) 向量化：sin/cos 大多是在**造**方向（环绕、扇形），没有现成向量 |
| Vector2 长度/归一/点积… | (a) GDScript 逐条算 | 引擎版无法关融合；单次调用多 0.15~0.2 µs，整局不可测（见 §6 性能） |
| 补间缓动 | 线性补间 + 自算缓动 | Linear 方程 `c*t/d+b` 先除后加，反汇编确认不融合；其余方程都融合 |
| 寻路 | (a) 自己实现 | 引擎寻路是 C++ 内部（烘焙+查询都融合），GDScript 管不到；量化路点：查询每局几千次 × 每次几个点，边界翻转概率不可忽略，而且 A* 的平手选择也可能翻 |

## 5. 已知风险与未决点

| # | 风险 | 状态 |
|---|---|---|
| R1 | **真机没验**：结论来自 x86 上的扰动模型 + iOS 引擎反汇编。扰动模型覆盖「走 DetMath 的每一处」，覆盖不了「引擎里我没发现的融合」 | **未验**。需要在 iPad 上录一局、PC 上放（或反过来）。建议主会话出包后第一件事做 |
| R2 | 判 Vector3/Color/String 放行的 125 处是启发式 | 已人工过一遍；`--list-other` 可复查。判错的方向若是「Vector2 被当成 3D」⇒ 这一处仍裸调，lint 看不见 —— 为此加了「本行写 sim 状态 ⇒ 强制按 Vector2」 |
| R3 | 演出文件按「函数碰 sim 标记」判，标记表（SIM_MARK）可能不全 | 未决：一个演出函数若通过间接调用改 sim（不出现标记字样）就漏 |
| R4 | DetNav 的路径与引擎路径**不完全一样**：引擎的拉直路径不是最短路，DetNav 是 | 探针 `_probe_det_nav`：2000 对随机起止、685 对需绕障；路径长平均差 0.68%，>2% 的 188 对（几乎都是 DetNav 更短）；单位绕礁石会更贴、更短。**玩家可感知的玩法变化**（轻微） |
| R5 | 数值改了 ⇒ 老录像必然对不上 | **发版必须升版本号**（回放入口按 client_version 拒放旧录像，正是要它） |
| R6 | 引擎内部还有融合但 sim 没用到的（Transform2D、Quaternion、Animation 轨道、AnimationMixer） | 现在 sim 没用；lint 只盯「已知会用到的入口」。新代码若把它们拉进 sim，lint 看不见 |
| R7 | `int(NaN)` / 超范围 float→int：x86 得 INT64_MIN，ARM 饱和/得 0 | 未处理（sim 正常不该出 NaN）；记账 |
| R8 | 字符串格式化 `"%.2f"` 若进 sim 判断（当键 / 比较） | .5 舍入方向随平台；目前只在指纹里出现过，已改位模式 |
| R9 | 性能：DetMath 单次调用 0.4~1.3 µs（引擎 0.1~0.2 µs）；DetNav 每次查询 ~60 µs（引擎 5 µs） | 整局实测不可分辨（见 §6）；手机慢 3~5 倍也在预算内 |

**实际改了**：

- 新增 `tests/verify_determinism_ulp.gd`（U1/U2/U4·frames 40000·实测 20788 帧 ≈2.5 分）、`tests/verify_determinism_ulp_replay.gd`（U3·frames 60000·实测 28956 帧 ≈3.4 分）；
  探针 `tests/_probe_det_perf.gd`、`tests/_probe_det_nav.gd`
- `tests/_det_scenarios.gd` 抽出 `run()`（cross 与 ulp 共用建场）；`tests/golden/determinism_cross.json` 重生成（15 条里 11 条变了 —— 数值改了，本意）
- 66 个 sim 文件机器改写 ≈1035 处；手工：`axe_final_forms`（Geometry2D）、10 个写 sim 的补间（hookbomb×2 / elite×2 / headless / lava×3 / pirate / shell）、
  `battle_world_builder._build_navmesh`（同时建 DetNav）、主场景 `_nav_dir` 一行。`RealtimeBattle3DScene.gd` 行数不变（8643）

**性能**（编辑器无头、确定性场景表 15 个 14900 步、三遍取最小，同一时段背靠背）：
加固前（raw）1117.2 µs/步 · 加固后 1110.3 µs/步 —— 差在噪声里。单次调用：sin 111→525 ns、atan2 145→635、distance_to 134→276、normalized 157→328、rotated 213→1272；
DetNav 每次查询 ~60 µs（引擎 5 µs），每个移动单位 0.4 秒查一次 ⇒ 每步摊 ~0.04 ms。

**与方案的偏差 / 新发现的坑**：
- 原以为主嫌疑是 libm；反汇编后发现**引擎 FMA**覆盖面大得多（每次 distance_to 都中），而且补间缓动和寻路也在里面 —— 只修超越函数修不好
- Godot 的浮点字面量解析 16 位以上不正确舍入（同一算法、跨平台一致，但会让 fdlibm 常量偏 1 ulp）⇒ 常量改「整数 ÷ 2 的幂」
- 场景表 `run()` 会把静态 `DEBUG_EDIT` 置真，之后再建双路对局就卡在 `_dl_state=""` 永远打不完（实测 727 个校验点）⇒ U3 拆文件 + 显式还原
- 着色器源码在 `"""` 多行字符串里，第一版改写工具把里面的 `smoothstep(` 也改了（运行时报 SHADER ERROR）⇒ 改写与 lint 都跳过 `"""` 块
- 引擎寻路烘焙会按 `agent_radius`（默认 10）再外扩障碍 —— DetNav 第一版没算，绕障点差 10 px
- 本 worktree 基于 c3ec315f（比 main 落后 2 个提交，其中一个改了命运之轮/海盗船/水晶球）⇒ 合并时这几个文件可能冲突；改写工具幂等，冲突后对合并结果重跑一次 `python tools/det_math_rewrite.py` 再跑 `det_math_lint` 即可
