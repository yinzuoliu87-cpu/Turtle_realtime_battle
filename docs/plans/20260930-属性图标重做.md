另有三处不统一（看图确认，不是推测）：

1. **形状语言分裂** —— 写实物件（剑 / 弓 / 鞋 / 盾）与抽象符号（上下箭头）混用

3. **靠渐变塑形** —— 盾与魔抗用高光渐变做体积，缩小即糊

## 3. 出入（需求与现状对不上的地方）

1. **需求说「像素风」，而 12/14 张根本不是像素风** —— 是高清图缩到 32×32，靠抗锯齿出形。
2. **需求说「统一」，而现在是两套做法并存** —— 不是"某几张画得差"，是**标准本身不存在**。
3. **需求说「不要这么花」，而"花"的根源不止是色数** —— 还有装饰元素和渐变塑形。
   只限色不去装饰，仍然花。
4. ★**我们缺一整类图标**：LoL/ARPG 那种**嵌在文案里的小尺寸类型标记**（`⚡102` 里的 ⚡）。
   我们现在的 14 张全是"属性行前面的图标"，文案里一个图标都没有。

---

## 4. 方案

### 4.1 规格（全部 14 张统一）

| 项 | 定死的值 |
|---|---|
| 画布 | **32×32**（不变，消费点不用改尺寸） |
| 有效作画格 | **16×16 概念格**，每格 2×2 像素 —— 保证放大后是干净的像素块 |
| 颜色 | **纯白 `#FFFFFF` 一色** |
| alpha | **只有 0 和 255**，不许有半透明边（染色后会出灰边） |
| 描边 | **不画描边** —— 描边会被 `modulate` 一起染色。需要描边时由 Godot 侧统一加 |
| 装饰 | **禁止** —— 一张图一个物件，不挂小球/粒子/反光 |
| 形状语言 | **全部写实剪影**，不混抽象符号（增伤/减伤那两张改成实体物件） |

### 4.2 染色接线

- `scripts/util/ui_palette.gd`（已存在）新增 `STAT_<KEY>` 一组颜色常量
- 7 个消费点在 `load(...)` 之后加一行 `icon.modulate = UIPalette.stat_color(key)`
- ⇒ **改配色不用重画**，改一处常量全局生效

### 4.3 14 个形状清单（★这一节要用户过目再动手画）

| key | 属性 | 形状提案 | 现状问题 |
|---|---|---|---|
| `atk` | 攻击 | 单剑（剑尖朝右上） | 现有 225 色带高光 |
| `aspd` | 攻速 | 双箭头（>>） | 现有 211 色 |
| `crit` | 暴击 | 四角星芒 | 现有 263 色，放射线太密 |
| `crit-dmg` | 暴击伤害 | 星芒 + 裂纹 | 现有 258 色 |
| `def` | 护甲 | 盾（平顶尖底） | 现有 307 色，靠高光塑形 |
| `mr` | 魔抗 | 盾 + 漩涡 | 现有 **364 色**（全表最花） |
| `hp` | 生命 | 心 | 现有 171 色，**旁边挂三个绿球要删** |
| `shield` | 护盾 | 盾（与 def 需明显区分） | 现有 206 色，与 def 形状太像 |
| `move` | 移速 | 带翼靴 | 现有 307 色 |
| `range` | 射程 | 弓 | 现有 174 色 |
| `lifesteal` | 吸血 | 血滴 + 牙 | 现有 195 色，**现在画的是辣椒**，与语义不符 |
| `dodge` | 闪避 | 残影/双身位 | 现有 86 色 |
| `dmg-amp` | 增伤 | 上升箭头 → **改成实体物件** | 现有 5 色，但**形状语言与其余不一致** |
| `dmg-red` | 减伤 | 下降箭头 → **改成实体物件** | 同上 |

### 4.4 新增：文案内嵌标记（小尺寸）

（物理 / 魔法 / 真实），颜色与数值一致。⇒ 这一套在**文案渲染改造**做完之前不接线。

## 8. 实施回填（2026-10-01）

### 做了什么

- **22 张属性图标全部用 PixelLab 重新生成**（`create_image_pixflux`，64×64 → NEAREST 缩 32×32）。
  原来 14 张，补齐了 8 个一直没有图标的属性：护甲穿透 / 法术穿透 / 龟能上限 / 龟能充能 /
  治疗与护盾 / 治疗强度 / 护盾强度 / 反伤。
- 新增门禁 `tools/stat_icon_audit.py`，接进 `run-tests.sh`。
- 实测色数：旧素材 14 张合计 **2776 色**（`mr-icon` 一张 364），新 22 张最高 **43 色**。

### 反向验证（人工做的，机器不记账，所以写在这里）

| 变异 | 结果 |
|---|---|
| 藏掉 `armorpen-icon.png` | 审计器点名 `armorPen 应有 armorpen-icon.png, 不在盘上` ✅红 |
| 把 `hp-icon` 改成 554 个随机色 | 审计器点名 `hp-icon.png 554 色(上限 80)` ✅红 |
| 还原后 | sha256 与定稿版逐字节一致 ✅ |

### 走过的弯路（都是实测推翻的，不是事后总结）

1. **我先用 PIL 画几何图元**（`arc` + `polygon` 拼形状），画了四版还在调坐标。
   用户：「你是有毛病吗，为什么要骗我，说了用pixel啊」——有 PixelLab 不用是硬错。
2. **白剪影方案作废**（§7）。两种转法都试了：按 alpha 填实丢内部结构，按亮度二值化丢形状。
3. **16px 是真正的硬约束**。属性图标实际显示只有 16×16 = 256 个像素格
   （`detail_panel.gd:220` 的 `_sp(16)`；文案内联是字号 ×1.15 = 15~20px）。
   弓 / 翅膀 / 跑步的人在这个尺寸下**物理上画不出来**，不管提示词怎么写。
   ⇒ `aspd` 最终用沙漏、`dodge` 用龙卷风——只有**紧凑实心**的主体活得下来。
   这也解释了为什么 LoL 和 Botworld 的图标都那么简单：不是审美，是小尺寸逼的。
4. **缺 8 个图标是用户问出来的**，不是我查出来的。用户问「治疗强度和护盾强度呢」，
   我才去扫 `equip_stats.gd` 的属性全集。⇒ 这条已焊进审计器 ①。

### 没做的

- 染色接线（`UIPalette.STAT_*` + `modulate`）—— 白剪影作废后不需要了。
- 新增那 8 张图标**暂时没有消费点**（现有代码只读 14 张）。它们是给
  [说明文案两层渲染](20260930b-说明文案两层渲染.md) 的 P3 期用的，素材先行。
