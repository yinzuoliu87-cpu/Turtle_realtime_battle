1. **形状语言分裂** —— 写实物件（剑 / 弓 / 鞋 / 盾）与抽象符号（上下箭头）混用

3. **靠渐变塑形** —— 盾与魔抗用高光渐变做体积，缩小即糊

## 3. 出入（需求与现状对不上的地方）

1. **需求说「像素风」，而 12/14 张根本不是像素风** —— 是高清图缩到 32×32，靠抗锯齿出形。
2. **需求说「统一」，而现在是两套做法并存** —— 不是"某几张画得差"，是**标准本身不存在**。
3. **需求说「不要这么花」，而"花"的根源不止是色数** —— 还有装饰元素和渐变塑形。
   只限色不去装饰，仍然花。
4. ★**我们缺一整类图标**：LoL/ARPG 那种**嵌在文案里的小尺寸类型标记**（`⚡102` 里的 ⚡）。
   我们现在的 14 张全是"属性行前面的图标"，文案里一个图标都没有。

## 4. 方案

### 4.1 规格（全部 14 张统一）

| 项 | 定死的值 |
|---|---|
| 画布 | **32×32**（不变，消费点不用改尺寸） |
| 有效作画格 | **16×16 概念格**，每格 2×2 像素 —— 保证放大后是干净的像素块 |
| 颜色 | **纯白 `#FFFFFF` 一色** |
| alpha | **只有 0 和 255**，不许有半透明边（染色后会出灰边） |
| 描边 | **不画描边** —— 描边会被 `modulate` 一起染色。需要描边时由 Godot 侧统一加 |
| 装饰 | **禁止** —— 一张图一个物件，不挂小球/粒子/反光 |
| 形状语言 | **全部写实剪影**，不混抽象符号（增伤/减伤那两张改成实体物件） |

### 4.2 染色接线

- `scripts/util/ui_palette.gd`（已存在）新增 `STAT_<KEY>` 一组颜色常量
- 7 个消费点在 `load(...)` 之后加一行 `icon.modulate = UIPalette.stat_color(key)`
- ⇒ **改配色不用重画**，改一处常量全局生效

### 4.3 14 个形状清单（★这一节要用户过目再动手画）

| key | 属性 | 形状提案 | 现状问题 |
|---|---|---|---|
| `atk` | 攻击 | 单剑（剑尖朝右上） | 现有 225 色带高光 |
| `aspd` | 攻速 | 双箭头（>>） | 现有 211 色 |
| `crit` | 暴击 | 四角星芒 | 现有 263 色，放射线太密 |
| `crit-dmg` | 暴击伤害 | 星芒 + 裂纹 | 现有 258 色 |
| `def` | 护甲 | 盾（平顶尖底） | 现有 307 色，靠高光塑形 |
| `mr` | 魔抗 | 盾 + 漩涡 | 现有 **364 色**（全表最花） |
| `hp` | 生命 | 心 | 现有 171 色，**旁边挂三个绿球要删** |
| `shield` | 护盾 | 盾（与 def 需明显区分） | 现有 206 色，与 def 形状太像 |

## 9. 染色接线（v0.19.483 · 2026-10-01）

§4 的方案是「纯白模板 + 运行时染色」两步。v0.19.480 做完了第一步就报了完成——
**而只做第一步的画面效果是 22 个一模一样的白方块**，在暗底上看着像「图标设计成白的」，不像 bug。

### 做法

`SkillText.stat_icon_color_of(key | 路径) -> Color`，两段来源都是现成的：

| 来源 | 覆盖 | 为什么 |
|---|---|---|
| `KEYWORD_RULES` 第 3 项（图标 key）→ 第 2 项（色类） | 12 个 | 规则里本来就有这张对应表；以后谁改了规则的颜色，图标**自动跟着走** |
| `ICON_CLASS_EXTRA` | 10 个 | 这些 key 在文案里没有内联图标，没法反查。**但它映到的是已有的 val 色类，不是新的十六进制** ⇒ UIPalette 仍是颜色唯一出处 |

没登记的 key **故意返回洋红**而不是兜底成白——兜底成白＝以后加属性忘登记又会静默变白，
正是这次要治的毛病。

### 为什么不染成「这一行文字的颜色」

那是我最初的方案，当场被实测推翻：同一个「攻击」在三个界面的文字色是

| 界面 | 攻击的文字色 |
|---|---|
| 战斗信息面板 `info_panel.gd` | `#ff9d8a` |
| 图鉴属性牌 `detail_views.gd` | `#ff9f43` |
| 备战席 `detail_panel.gd` | `UIPalette.PHYS` = `#ff4444` |

跟着文字走 = 图标也跟着漂。图标要做成属性的**固定身份**：全项目一个属性一个色。

### 六个消费点

`info_panel`（属性格 + chip 两处）／`detail_panel`／`detail_views`／
`dmg_stats_panel`（Button 图标不吃 `modulate`，走 `icon_*_color`，**五个状态都要盖**，
只盖 normal 会让按下时跳回白）／`LeaderboardScene`（**只染 `stats/` 那张**，
奖杯与横扫是成品彩图，一视同仁地染会把它们毁掉）／`battle_vfx`（暴击飘字）。

文案内联图标从短式 `[img=W]` 换成长式 `[img width=W color=#rrggbb]`——短式没有 color 参数。

### 门禁 `verify_stat_icon_color`（4 条反向验证全红过）

★done-when: `gate:verify_stat_icon_color`

| 条 | 守什么 | 反向验证 |
|---|---|---|
| ① | 每张图标都能解析出染色，没落到洋红兜底 | 删掉 `ICON_CLASS_EXTRA` 里的 `reflect` ⇒ 红 |
| ② | 染出的颜色 ≥ 6 种（全同色 = 等于没染，却照样能过 ①） | — |
| ④ | **素材在不透明处只有 1 种 RGB 且接近纯白** | 把一张图标涂 20 个橙像素 + `--import` ⇒ 红 |
| ⑤ | `render_bbcode` 的**真实输出**里每处 `[img` 都带 `color=` | 把长式改回 `[img=%d]` ⇒ 红 |
| ⑥ | 引用了 `sprites/stats/` 的 `.gd` 必须调过 `stat_icon_color_of` | 把 `LeaderboardScene` 那行换成 `Color.WHITE` ⇒ 红 |

⑤ 一开始写的是「`color=#` 出现次数 ≥ `[img` 次数」——**那是恒真的**：文字色
`[color=#xxxxxx]` 里也含这串（2 枚图标时它数出 5）。改成数 `[img width=<px> color=#` 这一整段。

④ 是这套做法最容易静默坏掉的地方：`modulate` 是**乘法**，哪天有人塞一张彩图进来，
画面上不报错，只是颜色变脏。

### ⑦ 同色的两张图标，形状不许也撞（v0.19.484 补）
