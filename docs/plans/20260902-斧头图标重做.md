## 调查

### §1 参考素材是什么（量出来的，不是"看着像"）

| 量 | 实测 |
|---|---|
| 文件尺寸 | **353 × 317** |
| 背景 | **白色不透明**（`#FEFEFE` 占 15.7%），**不是透明背景** |
| 颜色数 | **11503 种** |
| 非白内容包围盒 | x 9~343（宽 335）· y 5~315（高 311） |
| 像素格 | 跳变间距众数 **16 px** |
| ⇒ 底层分辨率 | **约 21 × 19 格** |

**★结论：这是一张像素画被放大 16 倍 + 抗锯齿后的截图，不是干净的像素素材。**
11503 种颜色与 1px 的最小游程都是重采样的产物 —— **不能直接当素材用，也不能直接喂进游戏**。
（memory `fb-pixel-1to1-video-reference`：量之前先对齐口径；`fb-my-thresholds-degrade-good-assets`：
别拿我拍的阈值去"清理"它。）

**形态特征**（照图描述，供生成时对齐）：单手木斧、**斧头朝右上**、长木柄自左下斜向右上，
斧刃为浅色（近白/米色）楔形、斧身棕色、外缘深棕描边，木柄有逐格明暗的木纹。

### §2 现在盘上有什么（这一节解释了"为什么要统统换"）

**斧头装备图标 9 张**（`assets/sprites/equip/axe-*.png`）：
`wood / stone / iron / gold / diamond` + 四个最终造物 `undead / seraph / holo / ember`

| 量 | 实测 | 说明 |
|---|---|---|
| 尺寸 | 全部 **32 × 32** | 而仓库主流是 **64×64（69 件）**，32×32 只有 30 件 |
| 内容包围盒 | 全部 **24 × 25** | 九张一模一样 |
| 颜色数 | 全部 **26** | 九张一模一样 |
| **透明蒙版** | **8/8 与第一张逐字节相同** | ⇒ **九张是同一个形状换配色** |
| 两两像素差异 | `diamond` vs `ember` 只有 **140/1024（13%）** 不同 | 只有颜色不同 |

**★这就是"统统要换"的真问题**：九档进化在图标上**几乎看不出区别** —— 玩家从木斧升到钻石斧，
图标只是变了个色，形状一模一样。这不是"美术不够精致"，是**九个档位没有各自的形态**。

### §3 图标是怎么被消费的（决定新图必须满足什么）

- 唯一出口 `EquipIcon.stage_img()`（2026-09-01 收口，六处消费方共用）
- 路径由 `AxeEvolution.icon_path()` 给出：`equip/axe-<key>.png`，key 来自 `display()`
- **9 个 key 一个都不能少**，少一个 → `EquipIcon.make` 走 emoji 兜底分支（表现成"图标变成 📦"）
- 门禁 `tests/verify_axe_evolution.gd` 断言「九档九张图标都在盘上」
- 门禁 `tests/verify_axe_shop_codex.gd` 断言「六种形态给出**六张不同的图**」+ 背包屏幕像素比对

## 方案

### §4 生成路线

**PixelLab**，与仓库既有做法一致（055 病毒箭头、096 现有图标、斧头小将都是这么来的）。

**关键：九档要有九个【形态】，不是九个配色。**

| 档 | key | 形态方向（在参考的木斧基础上演进） |
|---|---|---|
| 1 | `wood` | **照参考做**：单手木斧，浅色楔形刃 + 棕色斧身 + 木纹柄 |
| 2 | `stone` | 石制斧刃：更厚重、带缺口，柄上缠绳 |
| 3 | `iron` | 铁刃：金属高光、双面刃形 |
| 4 | `gold` | 金刃：华丽、刃背带纹饰 |
| 5 | `diamond` | 水晶刃：半透感、棱面 |
| 终1 | `undead` | 亡灵：骨质柄、绿焰、破损刃 |
| 终2 | `seraph` | 炽天使：光翼、金白配色 |
| 终3 | `holo` | 全息：蓝青半透、扫描线 |
| 终4 | `ember` | 余烬：暗红熔纹、余火 |

★这九条只是**方向**，不是最终提示词 —— 提示词要短（memory `fb-pixellab-sprite-tuning`：
用户「简单点的提示词就好啊」，堆形容词会做出"刻意搞主题"的东西）。

### §5 验收怎么量（判据落在像素上，不落在"我看着像"）

| 判据 | 怎么量 |
|---|---|
| **九张形状各不相同** | 两两比**透明蒙版**：任意两张的蒙版不许逐字节相同（现状 8/8 相同 ⇒ 这条现在就是红的） |
| 九张都在盘上 | 既有门禁 `verify_axe_evolution.gd` |
| 六处消费方都换了 | 既有门禁 `verify_axe_shop_codex.gd`（真建背包场读屏幕像素） |
| 与参考的形态一致（仅第 1 张） | 并排渲出来看 + 量刃/柄的长度比 |
| 尺寸与仓库主流一致 | 见未决点② |
| **不许糊** | 采样必须 NEAREST；内容不铺满整张（memory `fb-vfx-defect-families`） |
