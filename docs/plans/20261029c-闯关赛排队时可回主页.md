### 2.2 A · 服务端排队语义（不改服务端也够用的部分）

- **重复进队不重新计时**：`gauntlet_queue_join` 在已有 waiting 时 `on conflict … do update` 刷新快照与 `last_seen`，`joined_at` 不变（`server/supabase/schema.sql:6880`、`:6946`）。
- **心跳断开 15 秒算离开**：`gauntlet_queue_ttl_sec` = 15（`schema.sql:6634-6635`）。
  - poll 看到自己 waiting 且心跳过期 ⇒ expired（`:6972-6975`）。
  - 过期后重新 join = 新的一行，**重新计时**（`:6940-6945`）。
- **兜底等待线**：最后一份 `gauntlet_queue_fallback_sec` = 180（`schema.sql:7724-7725`）。
  - 前 60 秒只配在线真人：迁移 `server/supabase/migrations/20261029c_gauntlet_human_first_minute.sql`（提交 ecd53f6d，内测服 / 正式服已上），只改「找同格子在线对手」那一段，最后一份 `gauntlet_queue_advance` 在 `schema.sql:7858` 起。
  - 迁移编号恰好也叫 20261029c，与本方案书无关；客户端不依赖它。
- **配上时的回包**：带 `job_id` / `match_id` / `side` / `job_status` / 对手卡（`gauntlet_queue_view`，`schema.sql:6752-6780`）。
  - 客户端 `_paired_of` 把 `job_status` 丢了（`referee_net.gd:217-224`）。
- **取消**：已配上 ⇒ 回 `{ok:false, reason:paired}`，那一局照算（`schema.sql:6992-7015`）。
- ⇒ **「离开匹配屏后继续心跳」只要客户端那个会话活着就成立，服务端不用改。**

### 2.10 B · 裁判机推流

- **发布顺序**：
  - 块 N+1 出现才把块 N 挪到对外目录（`server/referee/referee_poller.py:172-182`）；
  - Godot 进程退出后才挪 `end.json`（`:184-198`、`:269-272`）；
  - 之后才 `referee_complete`（`:292`）。
  - ⇒ **流录完时任务还是 claimed 的窗口真实存在**（R11）。
- **算失败**：已发布的半截整个删掉（`referee_poller.py:195-197`），重领时从第 0 块重录。
  - 已有 `end.json` 就不再录（`:159-162`）；注释说两次录的「特效随机不同」（R10）。
- **算的速度**：比 1 倍快 1.75~2.5 倍（`docs/plans/20261019-服务器逐帧直播.md:967`、`:970`、`:897`；`server/referee/README.md:27`）。
  - 旧机型 CX33 最重的局 0.8 倍，追不上（`逐帧直播.md:888`）。
  - ⇒ 按 1 倍跟播，正常只会越来越落后于服务器，不会卡在「同步中」。

**共同做法**
1. **长等待的游戏都放人离开匹配页，短等待的手游整屏接管。**
   - PC 客户端放人离开：英雄联盟、Dota 2、Valorant、守望先锋 2。
   - 整屏接管：荒野乱斗、皇室战争。
   - 我们最多等 3 分钟，更接近前者。这一句是判断，不是查到的结论。
2. **排队状态是随页面不消失的一块，取消贴在旁边。** 原来的开战键会变灰或变形：英雄联盟 FIND MATCH → IN QUEUE + 左侧 X；Apex PLAY → 灰 + 下方红 CANCEL。
3. **锁的是「会改这次排队内容」的东西。** 英雄联盟锁换模式；**没查到任何一款排队时锁商店。** 我们锁背包、商店，是因为阵容就是这次排队的内容（用户点名）。
4. **配上时不管玩家在哪个页面，都弹全屏居中的框盖住当前页。** 有接受键的一派是英雄联盟 / Dota 2，没有接受键的一派是 Valorant。
5. **「排队时去玩别的模式」最容易出事。** Valorant 靶场上线三周就下线；「取消和配上同时发生」几家都出过 bug（[荒野乱斗 2021](https://brawlstars.fandom.com/wiki/Version_History/2021)、[皇室战争 2022](https://clashroyale.fandom.com/wiki/Version_History/2022)、[Dota 2 报告](https://github.com/ValveSoftware/Dota2-Gameplay/issues/36637)）。

**没核实的**：
- 英雄联盟手游、云顶手机版、王者荣耀、宝可梦大集结排队时能不能离开；
- Dota 2 搜索中状态的样子；
- 守望先锋 2 配上时怎么从练习场转出来；
- 任何一款有没有任务栏闪烁。

需求 B「像英雄联盟观战」的延迟时长**本轮没有查证**：方案只用「画面跟在服务器后面、结果最后揭晓」这一层意思，缓冲按现有 3 秒。

## 4. 方案

### 4.0 顺序（memory「参考和走查在动手前」）

1. **方向稿**（不出新图，不写代码）。拼四张给用户看：
   - 主菜单排队态：主按钮 + 取消键；
   - 背包 / 商店锁着的样子与弹出的说明卡；
   - 排队屏加回「←」与说明行；
   - 「匹配成功 · 即将进入对局」遮罩。
2. 用户认方向后出**全新素材风格稿**：取消键、主按钮排队态的面、遮罩、音效。哪些可以借现有的走 `asset_borrow_audit` CROSS_OK 写理由，见 U1。
3. 再实现 A，然后 B（U14）。

### 4.1 A · 玩家看到的（建议，待拍板项见 §5）

1. **排队屏（匹配屏周六那一支）**
   - 左上「←」回来，含义 = 回主页、继续匹配。
   - 「已等待」下面加一行说明「可返回主页，匹配成功后自动进入对局」。
   - 「取消匹配」不变。
2. **回到主页后，主按钮变成排队态**
   - 面换成非亮黄的「进行中」样子，不挂呼吸光晕。
   - 两行字：「匹配中」/「已等待 1 分 04 秒」，每 0.25 秒刷新。
   - 点它回排队屏，不经过选龟。
3. **取消键在主按钮左侧**
   - 同高的红色方键带 ✕，主按钮相应变窄；触摸区 ≥ 81 视口像素。
   - 放左侧的理由：右手拇指落在主按钮右半，误触取消的代价是重排；英雄联盟的 X 也在 IN QUEUE 左边。
   - 按下后变灰显示「正在退出」，回话后主按钮恢复「开始战斗」。
   - 取消那一刻刚好配上 ⇒ 照配上处理。
4. **背包、商店锁住**
   - 与现有商店锁同一种样子：压灰 + 像素锁角标 + 常驻短签「匹配中」。
   - 点了弹现有的被拦卡（`block_card`），文案：「正在匹配闯关赛对手，阵容已锁定。取消匹配后可使用背包。」商店那一句同样写法。
   - 是否同时锁训龟大师、「?」教程、好友切磋、设置里的删号 / 换号：见 U4。
5. **配上时**
   - 不管玩家在哪个页面（主页、图鉴、排行榜、好友、战绩页回放、赛况板观战……），都盖一层全屏遮罩「匹配成功 · 即将进入对局」，约 1.5 秒后自动进匹配屏的 VS 卡（Valorant 式，没有接受键：配上那一刻服务端已经建好任务，拒绝不了）。
   - 正在看回放或观战 ⇒ 直接打断（U5、U6）。
6. **出队提示**
   - 收盘、心跳断开、连不上服务器而出队 ⇒ 主按钮恢复，主菜单飘对应那句（「当前不在闯关赛时段」/「已退出排队」/「连接中断，已退出排队」，都是现有文案）。
   - 人在别的页面 ⇒ 回到主菜单时飘（`RefereeWatch.notice` 那条现成的路）。

### 4.2 A · 架构：让「这一局的会话」活过换场景

- **不新建 autoload**（理由同 `remote_pool.gd:212-214`：会进每个测试进程）。
  - 沿用仓库已有的「挂到 root 上」做法（`remote_pool.gd:222`、`net_route.gd:244`、`stream_watch.gd` 的 Guard）。
- **离开时**：排队中按「←」，把匹配屏下面那个 `referee_run` 节点 `reparent` 到 root。
  - 名字 `GauntletSession`，`process_mode = ALWAYS`；静态 `RefereeRun.active` 指向它。
  - 然后才 `SceneNav.go`，必须在 `SceneNav` 把旧场景停用之前搬走。
  - 心跳 Timer 是它的子节点，跟着走，不中断。
- **回来时**：匹配屏 `_server_pick`（`sat_only`，可以改）先看 `RefereeRun.active`。
  - 有 ⇒ 认领它：连 `changed` 信号，画排队屏或 VS 卡，不再 `start_queue`。
  - 没有 ⇒ 与今天一样。
- **会话在 root 上收到 paired**：
  - **不当场** `_on_submit`（那会在回放沙盒里写任务单，R2）。
  - 先把配对回包存起来，盖「匹配成功」遮罩，然后 `SceneNav.go(Matchmaking)`。
  - 匹配屏 `_ready` 时，旧场景（回放 / 观战）早已离树、`end_play` 已还原，这时再 `resume_paired()` 走原来的 `_on_submit`。
- **离开排队态时**：会话在 root 上进 left / later / error ⇒ 写 `RefereeWatch.notice`、发 `changed`（主菜单据此恢复主按钮），然后自己释放。
- **唯一判据**：`RefereeWatch.queue_locked()`（新增，纯函数）= 有活会话且状态 ∈ {submit, queue, cancel}。
  - 主菜单画锁、门、主按钮排队态，以及切磋 / 教程 / 设置的拦截，都只读它。
  - 吸取商店锁「锁画在那儿门却是开的」那次的教训（`MainMenuScene.gd:541-546`）。

   - 万一收尾时服务器的结果还没到（R11），收尾处停住显示「正在确认结果」，到了再出。
4. **中途退出或杀进程**
   - 账照记，回主菜单飘「上一场闯关：胜利 / 失败」（现成文案）。
   - 不再把人拉回这一局（U12）。
5. **我是 B（右边）**：左边写对手名、右边写我，「我方 / 对方」按我翻（现成的 `viewer_side`）。
6. **算完前就已经 done**（裁判很快，或玩家刚配上就切走又回来）⇒ 走今天这条路：先记账，再从头播录像。

### 4.5 B · 流程与记账

- **会话活到看完**：配上后匹配屏会换成战斗场，所以会话也要活过换场景（与 A 同一个 `detach`）。
  - 它在跟播期间继续每 2 秒问 `referee_job_status`：
    - 拿结果；
    - 抓 failed / no_job ⇒ 结束播放回主菜单，提示「结算失败，请重新开战」并销单，与 `referee_run.gd:262-266`、`:293-296` 同一句。
    - 这是因为流被撤回后 `finished=false` 会永远等（R9）。
- **种子（不改服务端）**：任务 claimed 后，问现成的 `RN.live_gauntlet_async`（`referee_net.gd:378-388`），按 `match_id` 找自己那一行拿 `seed`。
  - 找不到就下一拍再问；先等到 done 就走旧路。
  - 也可以加一份小迁移让 `referee_job_status` 直接回 seed（U9）。
- **新入口** `StreamWatch.enter_own_live(tree, {id, seed, ver}, names, sess)`：
  - 与 `enter_live` 共用拉流和沙盒；
  - 会话 `kind = KIND_REFEREE`，走结算屏那条，`result` 先是空字典；
  - 开局状态多给 `dual_ghost` = 对手卡，右边名字就有了；
  - `return_scene = MAIN_MENU`。
  - 名字：A 方给 {左: 我, 右: 对手}；B 方用 `watch_names`，配上时就用 `side` 和 `opp.profile.name` 拼好。
- **结果到达（done）时，在沙盒里「预演」记账**：
  - `RefereeWatch.settle(gs, job_id, st, preview=true)`：与真记账**同一个函数**，跳过所有不会被还原的写入——销单、`record_match`、`replay_pending_id`、上传快照、`report_finals_entry`；`save()` 在沙盒里本来就空转。
  - 沙盒里的战绩、深海币因此变成「打完之后」的样子，结算屏、晋级仪式不用改读法就能显示对的数字。
  - 返回的 `view` **原地**写进 `SW.current.result`：守卫拿的是同一个字典引用（`stream_watch.gd:261`）。
- **离场时真记账**：`StreamWatch._left`（`:267-275`）在 `end_play()` 之后（这时沙盒已还原）。
  - 对「自己那一局」的会话：结果已到 ⇒ `settle(..., preview=false)` 真落盘、真上传；结果没到 ⇒ 什么都不做，单子留着，交给主菜单补记（现成）。
  - 没看到结算屏就退出的 ⇒ 写 `notice` = 「上一场闯关：胜利 / 失败」。
  - `_left` 挂在战斗场 `tree_exiting` 上（`stream_watch.gd:312`），早于下一个场景的 `_ready` ⇒ 结算屏点「前往商店」时，商店读到的已经是记完账的钱。
- **不会记两次**：`settle` 只认单子上那个任务号，记完单子就清（`referee_watch.gd:184-186`、`:216`）。主菜单补记与离场记账谁先到谁记。
- **收尾等结果**：`battle_hud.show_stream_end`（`battle_hud.gd:2465-2481`）对「自己那一局」会话且 `result` 为空时，停在收尾显示「正在确认结果」，等会话填好结果再出结算屏。
- **陪练号**：`RefereeWatch.skip_play` 为真时**不进跟播**，一字不变走 done → settle → `ST_SKIPPED`（`referee_run.gd:302-304`）。
- **开关**：只在 `StreamWatch.wanted()`（stream_on 与版本）成立时走跟播；否则走旧路。
