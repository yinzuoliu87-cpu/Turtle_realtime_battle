## 2. 调查结论（带 `文件:行号` 证据）

### 2.1 现在**一行联网代码都没有**

全仓扫 `HTTPRequest|HTTPClient|WebSocket|request(`，唯一命中是
[`autoload/preload_cache.gd:70`](../../autoload/preload_cache.gd#L70) 的
`ResourceLoader.load_threaded_request()` —— **那是本地资源预载，不是网络**。

⇒ 「开始做后端」在代码层面是**从 0 到 1**，不是改造。

### 2.2 但后端的**接口已经按"可替换"设计好了**

[`scripts/net/backend.gd:3-9`](../../scripts/net/backend.gd#L3) 自己写着：

> Backend — V2 异步 ghost 匹配 / bot 兜底 / 排行榜 的**本地实现**（阶段4/5 MVP）。
> MVP 全本地: ghost 池存 `user://ghost_pool.json`（按进度档分桶）。**接口稳定，
> 以后换 RemoteBackend(Supabase) 不动调用方**。

- 池路径 `user://ghost_pool.json`（[backend.gd:18](../../scripts/net/backend.gd#L18)）
- 冷启动种子 `res://data/ghost_seed.json`（[backend.gd:19](../../scripts/net/backend.gd#L19)）
- 快照结构版本 `SCHEMA_VER := 2`，**不做向后兼容**（用户 2026-08-14 拍板：老快照全删）
- 进度档 0~8 的分档函数 `bracket_for_battles()` 已实装（[backend.gd:44](../../scripts/net/backend.gd#L44)）
- 每档桶封顶 `BUCKET_CAP := 50`

⇒ 真正缺的是**远端存储 + 身份**，不是重写匹配逻辑。这是本项目一块**已经打好的地基**。

### 2.3 玩法设计早已定稿（不需要重新设计）

[`docs/design/V2模式策划-异步PvP生命赛季.md` §十三](../design/V2模式策划-异步PvP生命赛季.md)：

- 打的是**快照(ghost)**，不是实时对局；结果**单向**只影响挑战者
- 需要的是「**存档案 + 抽档案**」的轻量后端，**不是帧同步/服务器权威战斗**
- **bot 是永久安全网**，不只是冷启动：任何档凑不到真人就用 bot，保证永远匹配得到
- 排行榜若要防作弊，**需要后端复算**（§十五#3）—— 那一档就不轻量了

### 2.4 存档是**单机单文件**，且赛季/生命这层**没实装**

- [`autoload/GameState.gd:5`](../../autoload/GameState.gd#L5) `SAVE_PATH := "user://savegame.json"`
- 已有 `recent_ghost_ids`（[GameState.gd:22](../../autoload/GameState.gd#L22)）—— 匹配去重用
- **搜不到 `lives` / `hearts` / `season` 字段** ⇒ V2 设计里的
  「8 颗心 · 赛季 5 天重置 · 深海币局外商店」**这一整层 meta 还没做**

⇒ 这条是本篇最重要的调查结论，见 §3。

## 3. 需求 ↔ 代码的出入

**这一节是本篇最值钱的部分。**

### 出入①：「怎么上线」目前**缺的不是打包，是可留存的内容**

直觉会以为上线 = 搞定证书和商店审核。但按 §2.4，**赛季/生命/局外商店这层 meta 还没实装** ——
现在的游戏是「进去打一场、出来什么都不留」。

⇒ **先上线再补 meta 是错的顺序**：没有留存循环，商店页面的下载量只会变成一次性流失，
而且第一版的差评会永久留在页面上。**meta 先于上线**。

### 出入②：「开始做后端」**不是从零起步，但也不是接一根线就完**

接口是现成的（§2.2），可真要联网，**三件事同时到期**，缺一件都跑不起来：

| 缺的 | 为什么非它不可 |
|---|---|
| **身份** | ghost 要能去重（`ghost_id`）、要能排除自己、要能记「近期打过谁」。现在这些全在**本机存档**里，换台设备就作废 |
| **存储** | 池子现在在 `user://`，别人根本看不到你的快照 —— 也就没有"异步 PvP"可言 |
| **信任** | 快照是客户端上传的。**不复算就等于让客户端自报战绩**，排行榜必然被刷（设计 §十五#3 已点명） |

### 出入③：iOS 这条路**有一个不可绕过的前置条件，而它不在代码里**

Sideloadly + 免费证书 = **7 天过期**，只能给自己和少数测试者用。
要真正"上线"，**必须有 Apple Developer Program（99 USD/年）**：
TestFlight 要它、App Store 要它、连"证书不过期"都要它。

⇒ 这是**未决点，不是技术问题**（见 §5-U1）。

## 4. 方案（分阶段，每阶段可独立交付、可独立回滚）

> 排序原则：**先把"值得上线的东西"做出来，再上线**；后端按"最小可用"切，
> 不一次性做账号体系。

### 阶段 A｜把留存循环补上（无需任何后端 · 纯本地）

做 V2 设计里已定稿、但没实装的那层：**8 颗心 · 赛季 5 天重置 · 战后结算深海币 · 局外商店**。

- 数据：`GameState` 加 `lives / season_id / season_started_at / meta_coins`，进存档
- 结算：战后按设计 §三 公式给币（`25 + 2×现有心 + 5×已失心 +（赢则 +15）`）
- 赛季重置：过期即清心/币/局内等级（**统领等级不清**，设计 §五已明确区分）
- 商店：主菜单入口（设计 §五「商店入口在主菜单」）

**为什么放第一**：它 100% 本地可做、可完整测试，且**它才是"上线"要卖的东西**。
做完这一阶段，游戏就已经是个能玩一周的完整循环 —— 哪怕后端一行没写。

### 阶段 B｜最小远端 ghost（只做两个接口）

保持 `Backend` 的调用方一字不改，新增 `RemoteBackend`：

| 接口 | 语义 | 失败时 |
|---|---|---|
| `upload_ghost(snapshot)` | 上传我的阵容快照到「进度档」桶 | 静默失败，不阻塞游戏 |
| `pick_ghost(bracket, exclude_ids)` | 从该档随机抽一个别人的快照 | **回退到现有 bot**（安全网已实装） |

- **选型建议：Supabase**（backend.gd 注释里本来就写的它）。理由：免费档够用、
  自带 Postgres + 行级权限、有匿名登录，不用自己运维。
  ⚠ **这是建议不是决定**，见 §5-U2。
- **身份用匿名 id 就够**：阶段 B 不做账号、不做登录界面 —— 首次启动生成 UUID 存本地，
  作为 `ghost_id` 前缀。丢了就丢了（快照本来就是可再生的）。
- **离线必须能玩**：网络不可用时行为与今天**完全一致**（打 bot）。这是硬要求，不是降级。

### 阶段 C｜信任与榜（只有真的要做排行榜时才做）

- 后端复算：把快照 + 战斗种子送回服务端跑同一套 sim，比对结果
- 前置条件：**战斗必须确定性可复现**。本项目已有 `rng_discipline` 门禁在守这条，
  但"同种子同结果"**从没被端到端验证过** ⇒ 见 §5-U4
- 若不做榜，阶段 C 可以永远不做 —— 异步 PvP 本身不需要它

### 阶段 D｜商店分发

1. **先 TestFlight**（要 §5-U1 的账号）：把 7 天证书的痛点直接消灭，测试者装一次能用 90 天
2. Google Play 内部测试轨（25 USD 一次性，比 Apple 便宜且审核宽松）→ 可作为**先行验证渠道**
3. Web 版本可作为"零门槛试玩"入口，但**不作为主发行**（触控/性能未验）

## 6. 验收标准（每条都要能证明它**会 FAIL**）

### 阶段 A
- 新增 `verify_meta_season.gd`：造一个存档 → 打一场 → 断言心/币按公式变化；
  **反向验证**：把公式里的系数改掉 ⇒ 必须红
- 赛季过期：把 `season_started_at` 推到 6 天前 ⇒ 断言心/币被清、统领等级**没被清**；
  反向验证：让重置也清统领等级 ⇒ 必须红

### 阶段 B
- 断网（把远端地址指到不可达）⇒ 断言**行为与今天完全一致**（打 bot、不卡、不报错）；
  反向验证：移除回退分支 ⇒ 必须红
- 上传后从**另一个本地存档**能抽到该快照；反向验证：抽取时不排除自己 ⇒ 必须红
  （现有 `_is_self_ghost` 已实装，这条是回归守卫）

### 阶段 C
- 同一快照 + 同一种子，客户端与服务端跑出**逐帧一致**的结果；
  反向验证：给服务端注入一次裸随机 ⇒ 必须红

### 阶段 D
- 产物验真身（本项目已有做法）：拆 IPA 读 `Info.plist` 版本号 + pck 内容探针，
  **不看 CI 那步绿**（memory: 产物才是判据）
