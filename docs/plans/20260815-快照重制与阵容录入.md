## 2. 调查：快照到底是什么、从哪来

### 2.1 敌方是谁

`Backend.find_opponent(bracket, exclude, rng)` —— 同档 ghost → 就近低档 → 全空才 `make_bot`。
ghost 池存 `user://ghost_pool.json`，按进度档（bracket）分桶。

两个来源：

| 来源 | 谁产的 | 存哪 |
|---|---|---|
| **内置种子池** | `tests/_cohort.gd` 跑 N 队机器人真实爬梯 → `tools/cohort_to_seed.py --write` | `data/ghost_seed.json`（进包，只读） |
| **真人快照** | 玩家打完一场，`RealtimeBattle3DScene.gd:7769` 调 `Backend.upload_ghost(build_ghost_snapshot(...))` | `user://ghost_pool.json` |

冷启动/老档无种子时 `_ensure_seeded()` 把内置种子并进池子（幂等）。

### 2.2 老快照错在哪（这是要重制的原因）

`build_ghost_snapshot()` 原来带：`leaders` / `lane_assign` / `minions`（含装备）/ `equipped` /
`pet_levels` / `bracket` / `season_total_battles` / `season_eggs_killed`。

★**唯独宝箱进度一件不带** —— `backend.gd` 全文只出现过 1 次 "chest"，还在无关注释里。
于是敌方宝箱龟走一套**单场旧制**阈值 `[80,130,240,360,590]`，比我方低 **12~50 倍**，
一场就能开满 5 件传说。那不是真人打出来的进度，是代码凭空编的对手。

## 5. 逐步操作（详细到命令）

### 线 A｜重制内置种子池

> ⚠ 本机 CPU 有确诊硬件故障（WHEA 20 条 / 两次无转储关机），队列模拟是重负载。
> **小批次 + 批间留间隔 + 断点续跑**，别一次 blast 全套。

```bash
# A1. 先确认没有别的重活在跑(agent/门禁都停了)
#     然后跑队列模拟 —— N 队机器人互相打, 输光 8 命出局, 每场后存当时的真实家当
#     产出: tools/autoplay/cohort-snapshots.json
COHORT_N=32 timeout 3600 "/c/Users/Louis/Desktop/Godot_v4.6.3-stable_win64.exe" \
  --headless --path . tests/_cohort.tscn > /tmp/cohort.log 2>&1
#     （真实开关名以 tests/_cohort.gd 顶部注释为准，跑之前先 grep 一遍 OS.get_environment）

# A2. dry-run 看对照表, 不写盘
python tools/cohort_to_seed.py

# A3. 自检过关才写(脚本自己会拒写不合格的数据)
python tools/cohort_to_seed.py --write

# A4. 验：档位装备单调 / 档0 全裸 / schema=2
"/c/Users/Louis/Desktop/Godot_v4.6.3-stable_win64.exe" --headless --path . \
  tests/verify_bracket_gear.tscn --quit-after 600
"/c/Users/Louis/Desktop/Godot_v4.6.3-stable_win64.exe" --headless --path . \
  tests/verify_ghost_seed.tscn --quit-after 600
"/c/Users/Louis/Desktop/Godot_v4.6.3-stable_win64.exe" --headless --path . \
  tests/verify_ghost_chest.tscn --quit-after 600
```

★ **A3 之后必须回头确认新种子带了 `schema_ver: 2` 和两个 chest 字段** ——
`cohort_to_seed.py` 是我改字段【之前】写的，它很可能原样吐出旧结构。
不确认的话：新种子一进 `load_pool` 就被 `_drop_stale_schema` 全部丢掉，
**表现是"池子永远空、永远打 bot"，而没有任何报错**。
（这一条已加进 `verify_ghost_chest` 的第 ③ 组断言，会红。）

### 线 B｜录入你自己的阵容

**先清掉本机老池**（老快照进不了新 schema，留着也是被丢，但清掉能看清效果）：

```bash
# B1. 备份再删 —— 别直接删
cd "C:/Users/Louis/AppData/Roaming/Godot/app_userdata/斗龟场 实时版"
cp ghost_pool.json "ghost_pool.backup-$(date +%Y%m%d).json"
rm ghost_pool.json
```

**然后每配一套阵容打一场**，快照自动上传：

1. 主菜单 → 选龟 → 配装 → 开打
2. 打完（不管输赢）游戏自动调 `upload_ghost` 落盘
3. 想让某套阵容进**指定档位**，就把 `season_total_battles` 推到那一档
   （档位由 `Backend.bracket_for_battles()` 算）

**验证录进去了**（不靠感觉，直接读文件）：

```bash
python - <<'EOF'
import json, io, collections
p = "C:/Users/Louis/AppData/Roaming/Godot/app_userdata/斗龟场 实时版/ghost_pool.json"
d = json.load(io.open(p, encoding="utf-8"))
c = collections.Counter()
for b, arr in d.get("brackets", {}).items():
    for g in arr:
        c[(b, g.get("schema_ver"), bool(g.get("is_bot")))] += 1
for k, v in sorted(c.items()):
    print("档%s  schema=%s  bot=%s  →  %d 支" % (k[0], k[1], k[2], v))
EOF
```

看三件事：① `schema=2` ② 你那几支 `bot=False` ③ 落在你要的档位。
