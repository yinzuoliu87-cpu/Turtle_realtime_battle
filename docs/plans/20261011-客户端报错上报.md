2026-10-11 · 状态：已完成（v0.19.567）

## 需求原文

- 「然后下周2开始应该有二十多个真实玩家来打，你有后台能够收集任何问题和反馈吗」

## 调查

- `tools/beta_daily.py` 只看服务端：注册 / 对局 / 进度 / 直播 / 三项异常。
- 客户端脚本报错、引擎报错、闪退只写在玩家本机日志里，**一条都不上传**
  （全仓 grep `add_logger` / `Logger` 零命中）。服务端只能看到「直播 10 分钟没更新」这种结果，看不到原因。
- 游戏内没有文字反馈入口。
- Godot 4.6.3 有引擎接口 `Logger`（4.5 起），实测虚函数
  `_log_error(function, file, line, code, rationale, editor_notify, error_type, script_backtraces)`。
- 导出包默认 `debug/settings/gdscript/always_track_call_stacks = false` ⇒ 发布包里拿不到脚本调用栈。

## 出入

- 用户问的是「问题和反馈」；本轮只做**报错与闪退**的自动上报，**文字反馈入口不做**
  （20 来个朋友，直接找用户最快；反馈带版本号和时间即可对上服务端数据与录像）。
- 方案初稿签名用「文件:行:错误原文」；门禁实测 `push_error` 报上来的出处一律是引擎内的
  `core/variant/variant_utility.cpp:1024`，消息又常带数值 ⇒ 一处 bug 会刷出几十个签名。
  改成**栈顶脚本帧「文件:行」**（没有调用栈才退回初稿做法）。

## 方案

### 客户端 `scripts/net/error_reporter.gd`

- `ErrorReporter extends Logger`，GameState._ready 里 `install()` ⇒ `OS.add_logger()`。
- 只收 ERROR / SCRIPT / SHADER，不收警告，不收 print。
- 同一进程同一签名只报一次；每进程最多 30 个签名。
- 回调可能来自任意线程 ⇒ 只往带锁的队列里塞；主线程每 10 秒清一次队列再发。回调里不 print / push_error。
- 闪退：开局写 `user://running.flag`；正常退出 / 切后台删掉，回前台再写。
  下次启动还在 ⇒ 报一条 `unclean_exit`，附上一次进程记下的最近报错（`user://last_errors.txt`，只在出新签名时写）。
- 网络走 `SupabaseNet.report_client_errors_async`（复用 `_await_token` / `_http`）；没配后端什么都不做；时间穿越中按写请求拦下。
- `project.godot` 开 `always_track_call_stacks`，发布包也带脚本调用栈。

### 服务端 `server/supabase/migrations/20261011b_client_errors.sql`

- 表 `client_errors`，主键 (account_id, day, sig)，`count` 累加。
- 只能经 RPC `report_client_error` 写（security definer，主人 = `auth.uid()`）；表上 anon / authenticated 无任何直接权限。
- 每人每天最多 200 行；消息 1000 字、详情 4000 字服务端截断。

### 看数据：`tools/beta_daily.py` ⑥「当天报错」

按签名汇总：次数（= 碰到过的进程数）/ 人数 / 其他人数 / 版本 / 平台 / 界面 / 消息 / 栈顶。

## 已知风险与未决点

- **前台时被系统因内存杀掉**会报成 `unclean_exit` —— 那本来也要知道。切后台后被杀不误报（切后台时已删标记）。
- `count` 是「多少个进程碰到过」，不是总次数（进程内只报首次）。
- 退出那一刻的报错发不出去（如 resources still in use at exit）。
- 引擎原生崩溃拿不到堆栈，只有 `unclean_exit` + 之前记下的最近报错。
- 发不出去就丢，不重试不落盘 —— 报错不是玩家数据，丢几条只少一个线索。
- `always_track_call_stacks` 有少量运行开销（每次脚本调用记一帧），未单独量。
- 隐私：上传内容是代码文件名 / 行号 / 报错原文 / 版本 / 平台 / 界面名，不含存档内容；隐私政策已补 1.7a。
  ⚠ 隐私政策 1.5「对局记录与重放（尚未上线）」已过时（重放早已上线），本轮未改，另记。
