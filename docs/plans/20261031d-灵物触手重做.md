## 2. 调查结论

### 2.1 现在长什么样（实拍）

- 特效台 `VFXLAB_CASE=syn_spirit`（`VFXLAB_REALMAP=1 VFXLAB_GLOW=1` 真实地图 + 桌面泛光），录像 `C:\tmp\tentacle_review\real.mp4`：触手是一根**半透明、发青光的「水柱」**，比场地还高、从龟身上穿过，没有实心轮廓、没有由粗到细的收尖，读不出「一根触手拍下来」。
- 设计表里灵物配色是紫 `#b388ff`（`synergy_vfx.gd:475`），实际是青蓝（`tentacle_vfx.gd` 头注：照 LoL 俄洛伊**实机**「淡青绿半透明能量体」做的）。

### 2.2 抽搐与闪光（逐帧量出来的，不是目测）

量法：`scratchpad/tent_motion.py`，60fps 录像里取待机那根触手的区域，逐帧算触手像素的平均亮度、面积、重心。

| 版本 | 亮度每秒变向次数（闪） | 面积每秒变向次数 | 重心二阶差分 p95（抖） |
|---|---|---|---|
| 8 月 22 日 v0.19.268（同一台子、同参数） | 25.4 | 12.9 | 2.54 px |
| 现在 | **29.9** | **14.7** | **3.19 px** |

~~⇒ 60fps 下亮度几乎每隔一帧来回翻一次 = 「一直闪光」~~ —— **更正（同日，参考调研反证）**：同一脚本量 LoL 俄洛伊待机（30fps 有损网络视频）也有每秒 7~11 次变向、整体亮度帧差 0.28%（我们 0.31%），**这把尺子在有损录像上分不出好坏**，上表只能说明「两版差不多、现在略重」，不能当「闪」的证明；用户亲眼看到的抽搐与闪光仍是需求本身（静态截图两版几乎一样，`C:\tmp\tentacle_review\old_vs_now.png`）。

嫌疑（没逐项坐实 —— 用户已定大重做，换掉整套做法后这些一起消失，不再花时间逐项排除）：
- 流纹贴图 `TEXTURE_FILTER_NEAREST` + 每帧滚 `uv1_offset` + 网格每帧变形（`tentacle_vfx.gd:666-683, 884`）—— 最近邻取样在变形的网格上滚动 = 逐帧跳像素；
- 双面半透明（`CULL_DISABLED` + `BLEND_MIX`）同一网格自身叠层，三角形绘制先后随形状变 = 亮度跳；
- 粗细逐帧起伏 `r *= 1 + 0.055 sin(…) + 0.032 sin(…)`（`:2003`）；
- 链式模拟（08-21/22 引入）本身的抖动。

### 2.3 回放掉帧

- 触手是**每帧整根重建的程序化 ArrayMesh**（`tentacle_vfx.gd` 2222 行；`RealtimeBattle3DScene.gd:2198` `_tentacle_vfx.tick(dt)`「每帧重算网格」）。
- 逐帧直播 / 回放（S3，`stream_recorder.gd:813-823`）：触手网格每步换一代，录成「生成参数」发给手机，手机端**每次收到都重算整根网格**（待机 / 预警 / 收回 15 Hz，拍击 30 Hz）。⇒ 手机上掉帧的直接原因。

## 3. 需求 ↔ 代码的出入

- 8 月验收时用户认可过这一版（memory `fb-3d-quality-bar-tentacle`），但那时地图和单位还不是现在的像素画风（10-03 地图翻新、像素画风决定）；现在是平滑半透明 3D 网格叠在像素画上。
- 用户 8 月定的「3D 水准线 = 触手那版」指的是**方法**（逐帧量参考 → 表驱动 → 物理模型 → 连续性门禁），不是这一版的外观；重做沿用这套方法。

### 4.2 逐帧直播录法（第二路，2026-10-31）

两路之间的约定：新触手每根 = 一个 `MeshInstance3D` + 一份 `ShaderMaterial`，节点 meta `stream_shader_params`（`PackedStringArray`，每步会变的 uniform 名；现为 `TentacleMeshVfx.STREAM_PARAMS`，`tentacle_mesh_vfx.gd:50`，`:178` 设到节点上）；网格开局建一次、之后不换。做成**通用能力**（不认触手，认 meta）：

- **录制端**（`stream_recorder.gd`）
  - 带 meta 的节点建镜像前登记它身上所有着色器材质（覆盖 / 叠加 / 面材质 / next_pass 链）：`_sp_reg`（`:1499`，调用 `:564` 及换网格 / 换材质两处）。
  - 材质定义时把列出的 uniform 从通用 30 Hz 跟踪表里拿出来单独比（`_res_param_vals` `:1389`）：`_sp_check`（`:1538`，`_samp` 末尾 `:1011` 每步调）—— float / int / bool **逐步**比（命中白闪只亮 1 步也录得到），其余（点数组 / 颜色 / 向量）按变换同频 30 Hz 比，变了才发，走原有的 `OP_RES_SET`。
  - 没列出的 uniform 照旧按 30 Hz 比（不丢），但每变一次记元数据 `sp_unlisted`（`:1477`）—— 门禁要求为 0 = 「不滚纹理、不逐帧改粗细」的纪律。
  - 顺带补两处通用缺口：着色器材质的 `next_pass` / `render_priority` 原来只进报警基线、不发（`:1382`；`_collect_mats` 也收 next_pass 链 `:1186`）；带热参数的存盘材质按参数型发（`:1239`，路径型手机直接 load、参数不比）。
- **格式 v4**（`stream_format.gd:21`，v3→v4）：值标签加 `T_V3Q` / `T_V3QD`（`:103-104`）—— 点数组按 1/1024 米量化（`Q_PTS` `:110`）；整份发「第 0 点绝对 + 相邻差」，差分发**逐点「已解出的前一点 + 段向量线性外推」的残差**，录流器带 1 个单位的死区（`PTS_DZ` `:123`，`pts_encode` / `pts_decode` `:165` / `:183`）。为什么这样（实测，`tests/verify_stream_tentacle.gd` 场景，三根触手一待机就拍）：

  | 编码 | 热参数压缩后 B/(根·秒) |
  |---|---|
  | 只量化、与上一份做一阶差 | 1617 |
  | 绝对坐标二阶外推 | 1451 |
  | 绝对坐标二阶外推 + 死区 | 1851（梢端加速度一采样 2~3 毫米，死区盖不住） |
  | **段向量外推 + 逐点死区（采用）** | **1420**；误差 ≤ 1 毫米、不沿点序累积（★11-01 控制点改 1/128 米后误差 ≤ 7.8 毫米，见下） |

  整局对照（探针 `tests/_probe_stream_chunk_mix.gd`：跑最重那局、把热参数单独抽出来按块压）：最重那局（`tests/golden/stream_heavy_pair.json`，三路打满）触手热参数合计 **297 KB**；旧触手同一局本体 366 KB + 外发光壳 29 KB = **395 KB** ⇒ 换做法后直播体积没涨反降。
  ★11-01 第一路恢复 8 月动作（链式模拟，32 个控制点 + 每点半径 `ctrl_r[32]` + 弧长 `arc_len`）后重量：同一版本号内再加 `T_F1Q` / `T_F1QD`（`stream_format.gd:106-107`；`f1_encode` / `f1_decode` `:214` / `:226`；录制端 `stream_recorder.gd:1583`；播放端 `_arr_of` `stream_mirror.gd:456`，插值也插浮点数组）—— 浮点数组同样 1/1024 量化 + 逐元素线性外推 + 死区，`ctrl_r` 142 KB → 31 KB（25 秒场景）。但 `ctrl_pts` 本身压不下去：同一场景 207 KB，死区 1 → 4 毫米只省 2%（残差大 = 链式模拟每步的加速度噪声大，和「抽搐」是同一件事）；量化 1/1024 → 1/256 省 22%、→ 1/128 省 31%。最重那局（第三路已换成种子 2000029，比原来长 11%）触手热参数 **878 KB**（旧触手 395 KB），整局 **3.44 MB > 预算 3.32 MB**（最大一块 66 KB 未超）—— 见 U9 / U12。
  ★★11-01 协调（训龟大师那一路实测：两路改动合起来整局 3,446,455 B > 预算 3,320,000 B，只有训龟大师改动时同种子 3,116,002 B ⇒ 多出的约 33 万字节来自触手新录法；**不许放宽预算**）⇒ 控制点量化 1/1024 → **1/128 米**（`stream_format.gd:117` `Q_PTS`，与流里所有节点位置 `Q_POS` 同一档，死区 1 格 ⇒ 与本机差 ≤ 7.8 毫米 ≈ 0.35 像素；1/1024 是我当初拍的「≤ 1 毫米」，比其它节点位置细 8 倍、没有画面上的理由）；每点半径另立 `Q_F1` = 1/1024（`:119`，半径小、梢端 3.5 厘米，1/128 会差两成；随姿态慢变，几乎不占体积）。重量（种子 2000032，含第一路新加的接触阴影子节点 —— 它再带一份 `ctrl_pts` / `ctrl_r`，逐字节相同、ZSTD 基本吃掉）：最重那局整局 **3,215,992 B ≤ 3,320,000 B**、最大一块 64,428 B；触手比旧录法多出的部分从约 33 万字节降到约 10 万字节。门禁容差同步写死 1/128（`tests/verify_stream_tentacle.gd` `TOL_PTS`；半径 `TOL_F1` 1/1024），M1（死区改 3）在新档位下照样红。
- **播放端**：`StreamMirror._apply_props`（`stream_mirror.gd:420`）按 rid + 参数名记最近两份绝对整数串（`:46`），`_pts_of`（`:441`）还原；30 Hz 采样之间控制点线性插值（`res_lerp_to` `:513`，`StreamPlayer._interp` `stream_player.gd:679`；`restore` `:454` 先回真值）—— 手机 60 帧不顿；标量到步就换。网格本身走原来的出处键（`gen_tentacle_tube`，整局按 keyframe 段发几次，手机建一份复用），材质与着色器走原来的参数型 / 路径型资源。
- **旧客户端（0.22.6）兼容结论**：**不崩，也播不到新流**。流绑版本（R7）：每个入口先比「录像版本 == 本机版本」才去拉块（`stream_watch.gd:174` → `ReplayRecorder.play_check` `replay_recorder.gd:975`；观赛 `stream_watch.gd:234` / 跟播 `:269`）⇒ 0.22.6 看 0.22.7 的局直接是「版本不同，无法观赛」/「回放版本…不兼容」，一块都不解。就算拿到了（例如补流），0.22.6 的解码器（`tests/golden/stream_format_v0226.gd.txt`，v0.22.6 标签原文）在头里版本号那一步报 `version 4 != 3`，播放器停在「画面无法播放」（`stream_player.gd:259` → `:186`）；把版本号硬改成 3 再喂，它在新标签那一步报 `tag 20` 返回 —— 两条都由 `tests/verify_stream_tentacle.gd` 现编译 0.22.6 解码器实测。⇒ 版本号必须提（不提的话 0.22.6 会一路解到新标签才报错，改坏验证 M4 实测红）。
- **零生产者清理**（新触手切默认后，旧触手每步重建网格那套没有别的用户了）：`VfxTex.tag` 的第 5 个参数 `every`（`vfx_textures.gd:17`）、录流器按 meta 第 4 项降频（现 `stream_recorder.gd:820` 固定 30 Hz）、出处键「参数别名」方式 0、差分里的 `T_BXOR` / `T_IDIFF`（编码 + 解码 + 播放端还原，编号 0 / 18 / 19 留空不复用，`stream_format.gd:102`）。`GEN_DELTA` + `T_SAME` 仍有 090 水带等每步重建的网格在用，保留。v4 解码器不需要读 v3 的块（版本闸），所以解码侧一起删。

## 6. 验收标准

1. 不闪 / 不抖 —— **做法层面的硬判据**（门禁直接量代码与运行时，不量有损视频）：触手显示用固定素材帧（或不逐帧重建的固定网格），不滚纹理坐标、不逐帧改粗细；待机阶段只按动画表步进（同一帧号 ⇒ 画面逐像素相同）。
2. 量画面用**无损**录像（Movie Maker 输出 PNG 序列、固定镜头），待机段逐像素时间差与同场静止物体同级（阈值用同一录像里一块静止礁石标定，memory fb-calibrate-the-ruler-before-trusting-it）。
3. 回放不掉帧：手机端播放带触手的局，触手相关的每帧耗时有上限（判据待定），直播录像体积不因触手暴涨。
   - 第二路已守（`tests/verify_stream_tentacle.gd`）：手机端每步只把几个 uniform 写回材质、网格整场一份不换代（不再按出处键每步重算整根网格）；采样步控制点与本机差 ≤ 1/128 米（与节点位置同一档；每点半径 ≤ 1/1024 米）、采样中间 = 两次采样的中点（插值不顿）、标量（露出 / 白闪 / 拍痕 / 地洞）每步与本机相同、白闪次数相同、从中途 keyframe 跳进来照样对得上；热参数体积只量不判（第一版表驱动动作 1420 B/(根·秒)、最重局 297 KB < 旧触手 395 KB；11-01 恢复版 3924 B/(根·秒)、最重局 878 KB，见 U9 / U12）。
   - 旧客户端（0.22.6）：入口版本闸先挡；拿到 v4 的块也只是报错返回、不崩（同一门禁现编译 0.22.6 解码器实测）。
4. 玩法不变：现有拍击 / 命中 / 预警 / 层数门禁全过。（第二路：玩法类 8 条对新显示层不改照跑，见 §4.3。）
6. 做法纪律的硬判据（第二路，§4.3）：固定网格（同一份网格对象贯穿全程）、没列进热参数名单的 uniform 一次都没变（直播 `sp_unlisted` = 0 + `tests/verify_tentacle_rhythm.gd` 逐帧核）、名单里没有粗细 / 贴图坐标一类、状态切换处控制点不跳、白闪与伤害同帧、直播往返控制点一致。动作好不好（抽搐）的阈值见 U11；按参考定的尺寸 / 帧数尺子已撤（10-31 协调）。
5. 两比例实拍 + 视频交付。

## 8. 实施回填

**实际改了什么**（`scripts/systems/equip/tentacle_vfx.gd` / `tentacle_mesh_vfx.gd` / `assets/shaders/tentacle.gdshader`）：

1. 渲染：固定网格 + 顶点着色器沿控制点弯曲（不再逐帧重建网格）；`blend_mix` + `depth_draw_never` 半透明灵体，中间 alpha 0.30、轮廓亮；与棱鳍同节距的淡螺旋棱纹；拍痕改淡亮紫 alpha 0.2；去深色描边。
2. 动作：链式模拟（抽搐来源，探针 [jflip] 出手四段速度方向反转 33 次 vs 目标姿势 12 次）换成「临界阻尼跟随目标姿势 + 段长约束」；整套拍下直接贴目标姿势（撞地那帧速度最大、下一帧停死）。
3. 姿态：待机拉直（ANG_IDLE [84, 45]、卷曲 160/136）；抬起三次缓出 `LIFT_TOP` 0.62；等曲率后弯 `LEAN_DEG` 85 / `LEAN_P` 1.6（最高点各段离竖直 18→70 度）；拍下「拖尾」（`SLAM_TRAIL` 0.10 / `SLAM_LAND_SPREAD` 0.06 / `SLAM_EASE` 2.6，根→梢依次第 18~21 帧贴地）；收回 smoothstep 两头缓。
4. 直播：格式 v4 录着色器热参数（第二路，见 §4.2 / U2）。
5. 门禁：`verify_tentacle_vfx` ⑤ 端点倍数 1.6 → 1.25（待机拉直后的必然结果，注释里引了用户原话）；探针 `tests/_probe_tentacle_jitter_src.gd` 加 [peak] / [land] / [hgt] / [spd] 四组读数；新调试场 `tests/demo_tentacle_side.tscn`。

**与方案的偏差**：方案写「不透明 + 像素化着色 + 深色描边」，用户先后否掉（「这是3d吗」「太实体了」）⇒ 半透明灵体；方案写「沿用 8 月姿态表」，最后抬起 / 拍下 / 收回的时间曲线与后弯都换了，只剩状态机与时长不动（玩法不变）。
