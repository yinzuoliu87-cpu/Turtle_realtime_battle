## 2. 调查结论

参考研究：`docs/studies/20261120b-地图生动参考-咩咩启示录实机逐帧.md`（总览 38 张 + 逐帧 60 帧 + 静止镜头运动热图）。配图 `docs/plans/img-20261120c-地图优化/`。

**① 「很假」量得出来：我们的场景一动不动**
- 探针 `tests/probes/_probe_world_movers.gd`：四张正式地图开场 1.5 秒里，背景层（远景 `FarBackdrop`、边草 `EdgeTufts` 171 个、装饰 `LayoutProps` 57 / `TileDecor` 72、灯 `FieldLamps` 10、边缘光 `RimLights` 43）**0 个节点在动**（建场在 `scripts/scenes/battle/battle_world_builder.gd:496 / 579 / 774 / 799 / 995`）。
- 同一把尺子量参考（只取镜头静止段）：画面中央经常在动的面积 4 ~ 15%（草整丛摆、所有火光闪、前景落叶飘、光柱呼吸）；我们暗林 1.4%，且全是龟和特效，场景本身 0。
- 静态画质：`tools/battle_scene_check.py` 删旧图后第一次量四张正式图，**14 项低于标定目标**（中间调 8 ~ 23%，目标 ≥ 24；有效色数 42 ~ 57，目标 ≥ 88；中带噪声 16.9 ~ 20.3%，目标 ≤ 5.2），台账 `tests/golden/battle_scene_maps.json` 只减不增。
- 参考的结构（研究记录第一节）：场地是一块**有厚度的浮空岛**、四周压到近黑；**超大前景物件**框住画面；暗处散红灯 / 发光眼撑纵深；地面有大块设计（路、水）；物件成组摆、每组一个光源。

**② 龟蛋 / 训龟大师被挡：挡住它们的是场边那一圈装饰**
- 站位：龟蛋 `ARENA.x + 70`、中线（`scripts/scenes/battle/dual_lane_flow.gd:412-413`）；训龟大师 `ARENA.x + 40`、中线上 150（`scripts/scenes/battle/battle_spawn.gd:595-598`）—— 正好落在场边装饰圈里。
- 实拍（`img-20261120c-地图优化/现状-龟蛋与训龟大师被挡.png`，真对局 1560×720 暗林）：左边训龟大师只露出一点头顶，身子被边草丛 + 一根横木挡住；右边训龟大师完全看不见；左边蛋罩被暗林的大树干切掉一块，蛋罩前面压着草丛。

**③ 镜头往左推不够：蛋推到头还压在队伍卡片底下**
- 平移上限 `min(22 − 当前半视野宽, 9 米)`：`scripts/scenes/RealtimeBattle3DScene.gd:771`（`PAN_LIMIT = 9`）、`scripts/scenes/battle/arena_outer.gd:18-42`。
- 探针 `tests/probes/_probe_egg_reach.gd`（镜头推到最左，手机 1560×720）：

  | 缩放 | 推到最左 | 龟蛋屏幕 x | 蛋血条中心 x |
  |---|---|---|---|
  | 1.0（默认） | 3.0 米 | 372（24%） | 377 |
  | 1.5 | 3.5 米 | 191（12%） | 200 |
  | 2.0 | 8.1 米 | 254（16%） | 266 |

  左侧队伍卡片占屏幕 x 0 ~ 170 ⇒ 拉近后蛋和血条贴着卡片边、蛋罩被盖住一块；iPad（4:3）同样是 12 ~ 16%。

**④ 场地现在是 2.2 : 1 的椭圆**
- `ARENA = Rect2(70, 110, 1596, 728)`（`scripts/scenes/RealtimeBattle3DScene.gd:56`），形状 `ArenaShape.N = 2`（`scripts/util/arena_shape.gd`，矩形内切椭圆；22 个文件都经它夹取）。画出来的岛由 `tools/assetgen/gen_arena_map.py` 的 `ISLE` 生成，`tests/verify_island_boundary.gd` 守「看得见的 = 走得到的」。
- 站位：阵容格子存的是相对本方队形中心的偏移 `off`（队形中心 = 场地中心 ∓ 420，`scripts/gamedata/lineup_pos.gd` `FORMATION_DX`），可摆范围 dx −300 ~ 280、dy ±290；背包站位编辑 `scripts/scenes/inventory/formation_editor.gd` 按同一套几何画。

## 3. 需求 ↔ 代码的出入

- 「物理上是圆形」：用户听完代价（改玩法、规则版本、两蛋距离缩三成）后改口「还是椭圆」⇒ **场地不动**，本方案书不碰对局结果。
- 「龟蛋…被一个东西遮住」：默认机位下挡住它们的不是界面，是场边的草 / 树 / 木头；只有把镜头推到边上时才是被队伍卡片盖住（②③ 两件事）。
- 「做四版」：四张正式地图（暗林 / 深礁 / 紫墟 / 赤林）都按参考的做法重做；对局仍按种子从四张里随机。
- 「武器的甩动 / 丢出去的特效」：这是龟的普攻 / 弹道，不在地图代码里；研究记录第三、四节已逐帧拆出做法，**建议另开一份方案书逐只改**（未决点 U5）。
- 场地保持椭圆后，P2 ~ P4 全是画面改动；训龟大师**不挪位置**（他扔石头的飞行时间跟站位有关，挪了就改对局结果），改成让装饰给他让开。

## 4. 方案

分四步，每步单独交付；美术部分用户看视频点头前不进预检 / CI。

**P1 场地改正圆 —— 已取消**（用户 11-20「那还是不要正圆了吧？那还是椭圆喽」）。

**P2 镜头**
1. 平移上限改按「内容」算：任何缩放下都能把两端龟蛋（含血条、蛋罩）和训龟大师推到队伍卡片内侧（屏幕 x ≥ 25%）；手机 / iPad 两种比例都量。

**P3 龟蛋 / 训龟大师不被挡**
1. 场边装饰在龟蛋、训龟大师周围留空（高物件不许放在它们前方 / 身上）；大师站位不动（站位进对局结果）。
2. 门禁：真对局里把四张图的装饰精灵投到屏幕上，与龟蛋 / 大师 / 蛋血条的包围框重叠面积 = 0。

**P4 四张图「生动」重做（先做暗林一张给用户看，认了再做另外三张）**
1. 场景会动：所有草丛按风摆（同一阵风有先后）、所有灯 / 火 / 蜡烛闪、每张图一种前景飘浮粒子（暗林落叶 / 萤火、深礁气泡 / 光尘、紫墟灰烬、赤林火星）、每张图一两处会自己动的布景。全部纯画面，不进 sim、不进直播数据。
2. 场地做成有厚度的岛（形状仍是现在的椭圆）：边缘露侧面，外面压暗；大尺度前景 / 远景剪影框住画面，远处散光点撑纵深。
3. 地面重画：大块明暗与路径设计，物件成组、每组一个光源；仍是像素硬边画风（地图规矩不变）。
4. 门禁：探针 `_probe_world_movers` 改成门禁 —— 每张图背景层在动的节点数有下限；时停门禁 `verify_timestop_freeze` 已改量「携带者 3 米以外的整个世界」，新加的会动的布景自动受它管（时停时必须冻住）。`battle_scene_check` 台账逐张往标定目标收。

## 5. 已知风险与未决点

- **U1【已定·用户 11-20】场地保持椭圆**，不改正圆。
- **U2【待用户定】顺序**：我建议 P2 镜头 + P3 遮挡先做（纯画面，随时可推）；P4 美术迭代时间长，暗林先出视频给你看，认了再铺另外三张。
- **U4【我定】训龟大师站位不动**，装饰给他让开，保证默认机位整只露出来。
- **U5【待用户定】武器挥动 / 投掷**：研究记录第三、四节已逐帧拆出（出手前身体闪白 2 帧、刀光是一整块实心形状、身高的 2 ~ 5 倍、约 0.27 秒；投射物走抛物线、拖等宽实心色带、落点留 0.4 秒光池）。建议另开一份方案书，先挑 3 ~ 5 只普攻最没劲的龟改，不并进地图这份。
- **U6【待用户定】训龟大师的锁链技能**：要改动作 / 特效 / 机制里的哪一块？（11-08 改过一轮机制：30/15/眩晕 2.5/随机敌人）
- R1【未验】手机性能：每丛草摆动、每盏灯闪、粒子 —— 用着色器顶点摆动与少量 GPU 粒子，进门禁前在手机（iPhone / 安卓模拟器）量帧率。
- R2【已堵】画面动效不能改对局结果：全部只挂在画面节点上，不读写单位、不进 `_sim_step`；`verify_rules_fingerprint` 前后对比。
- R3【未验】直播 / 录像：布景动效是本地画面，不进直播数据；直播回放里也要动（本地照样跑）—— `verify_stream_parity_wide` 要能区分。
