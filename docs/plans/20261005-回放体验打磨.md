## 3. 需求 ↔ 代码的出入

1. 「倍速不能破坏确定性」—— 事实：sim 一步的长度 `SIM_DT` 固定，协程等待走 `_wait_sim`（按 sim 步号，`RealtimeBattle3DScene.gd:1691`），摆位期本来就 8 倍快进。⇒ 倍速只改「一帧跑几步」，零结构改动；门禁照样逐个比校验点。
2. 「对阵图看回放时谁是谁」—— 对阵图只知道这一场的两个人，不知道哪一方上传了录像。录像里对手快照的名字 = 录像方的对手 ⇒ 对得上就认出两侧；对不上（快照名与对阵图名不同源）就按对阵图顺序写「A 对 B」，不冒充左右。
3. 「主菜单加战绩入口」—— 左栏竖向一分都涨不了（4×81 落到 623，赛程条 636）⇒ 第 5 行放不下。

我替用户定的默认（不等拍板，可回头改）：

- 倍速档位 **1 / 2 / 4**，一颗钮轮换（皇室战争/荒野乱斗同款），**沿用上次选的**；暂停不沿用。空格键 = 暂停。
- 不做拖动进度条/跳转：回放是本机重算，往回跳 = 从头重算到那一步，手机上要卡几秒；先不做。
- 收尾卡在最后一击落地后 **1.2 秒**出，免得把最后一击盖住。
- 看自己的录像标题写「胜利 / 失败」（与结算屏同词）；看别人的写「X 获胜」。
- 积分赛 / 表演赛（淘汰后的积分赛）都录；教学、调试场不录。
- 战绩入口与排行榜同一行对半分（都是「看成绩」）；状态块那一行照旧可点。

## 8. 实施回填

**反向验证**（脚本逐个变异 → 跑 `verify_replay_controls` → 还原并逐字节比对；每个变异先打印命中数当分母，都是 1）：

| 变异 | 打红的那条 | 还原逐字节相同 |
|---|---|---|
| M1 `time_mult()` 不看 `paused` | ② ★暂停: 喂 60 帧 sim 一步都没走（389→749） | ✓ |
| M2 倍速不生效（恒返回 1） | ③ 分母: 倍速真的生效（4× 用帧 2319 > 1× 的 1/3） | ✓ |
| M3 单位栏不滤蛋 | ⑥ ★两侧单位栏里没有龟蛋那一格（蛋格 4） | ✓ |
| M4 `should_record` 去掉积分赛 | ① ★积分赛要录 等 9 条 | ✓ |
| M5 `end_play` 不重挂「再看一遍」 | ④ ★「再看一遍」⇒ 同一份录像从头开始 | ✓ |
| M6 主菜单不建战绩入口 | ⑤ ★左栏有「战绩」入口 | ✓ |

**新发现的坑**

- 新加 `class_name` 后不 `--import`，引用它的脚本整片编译失败、战斗场起不来（memory `fb-import-ok-is-not-runnable` 同族）。
- 回放 UI 第一次读了 `GameState.nickname`（看自己录像写「我」的名字），`verify_replay_roundtrip` V3c 当场红：回放那一遍读到的变量必须 ⊆ 录像键 ∪ 白名单 ⇒ 改成进场前取好（`ReplayRecorder.viewer_name`）。
- 多倍速时结算那一帧剩下的几步照样跑 ⇒ 播完那一刻的 `_sim_step_n` 比 1 倍多几步；比终局要比 `on_settle` 那一刻（产品自己已比过），不比播完后的步号。
