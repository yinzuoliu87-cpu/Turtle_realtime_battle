## 一、主文件现在是什么

`scripts/scenes/RealtimeBattle3DScene.gd`（12585 行）= **纯核心战斗引擎**：
spawn / tick / `_apply_damage*` / `_fire_*` 弹道 / 移动分离 / `_st_*` 状态机 / 目标选取 / 主循环
（`_sim_step` 定步长 60Hz + `_render_step` 渲染插值）+ 与核心 spawn 交织的 `_review_demo()` 评审分支。
**这些相互咬合，不该再拆**——拆了碎化引擎、反伤可维护性。这是自然底。

## 二、拆出去的系统（都是 `class_name` + `RefCounted` + 构造注入 `battle`）

**模式**：`var _xxx_sys := XxxSystem.new(self)` 成员；类内函数名不变；外部引用加 `battle.`；
状态（`_units`/各种 `_xxx` 成员）留主场景，系统经 `battle.` 读写。RefCounted 不能自己
`create_tween()`/`await get_tree()` → 走 `battle.create_tween()`/`battle.get_tree()`。

## 三、「我要改 X」去哪

- **某龟技能数值/演出** → `systems/skills/<龟>_system.gd`（别读 `scripts/engine/` 回合制旧引擎）
- **装备效果** → `systems/equip/`（真事实源 `P2RT.STATS` 仍在 `engine/phase2_equip_runtime.gd`）
- **伤害公式/击飞/状态/移动/spawn/弹道/主循环** → 主文件（核心引擎，没拆）
- **双路流程/放置阶段** → `dual_lane_flow.gd`；**点龟面板** → `info_panel.gd`
- **跨文件调用**：系统调主场景函数 = `battle._xxx()`；主场景/别的系统调某系统 = `battle._xxx_sys._fn()`
