## 0. 一句话结论

**7 技的数值本身全部与文案一致，没有发现算错的地方。** 但审出**两类基础设施问题**，都已修（值不变）：

1. **一个"看起来是事实源"的常量其实是死的** —— `HOOK_VULN_MULT` 在游戏代码里零读者，
   真实行为来自 `_mitigate_incoming` 里硬编码的 `1.25`。而门禁 `verify_trainer_desc`
   **拿这个死常量去推文案该写什么**。→ 改常量能让门禁要求一个错的文案，并判它正确。
2. **三个技能的实质数值门禁一个都不查** —— 怒火药水 / 口哨 / 冰川只查了射程和 CD，
   因为它们的数值是散在 `trainer_system.gd` 里的裸字面量（那个文件原来**一个 `const` 都没有**），
   没有常量可以推期望值。

另有 **6 条「代码里有但文案没写」**，都不是错，是要不要告诉玩家的问题（见 §3，需你定）。

#### 逐技目视（2026-07-30 补·`VFXPREVIEW=tr_tame` 走真入口 `_cast_active`）

一开始的现象是「施放成功，但画面上什么都没有」。查下来是**四个独立问题**，其中两个是数值 bug。

**① 两圈"贴地印记"其实一直立着**（同时修了猎龟令）

`Sprite3D.axis` 的语义是「面**垂直于**该轴」，所以 `axis = AXIS_Y` **本身就已经是平铺**（法线 +Y）。
代码却又写了 `rotation_degrees = Vector3(-90,0,0)`，把局部 Y 掰到全局 -Z → **法线 (0,0,-1) = 竖立**，两者相互抵消。

| | 改前 | 改后 |
|---|---|---|
| `\|世界法线·上\|` | **0.000**（竖立） | **1.000**（平铺） |

一条根因解释了两个此前想不通的现象：驯服环「看不见」= 竖环被龟立绘挡掉大半只剩几道弧；
猎龟令环「横穿龟腿」= 竖环当然跟立绘重叠。
★**别照抄 `ice_system` 那两处的 `-90`**：它们**没有设 `axis`**（默认 `AXIS_Z`，面在 XY 平面竖着），所以那个 `-90` 才对。抄一半正好抄反。

**② 归顺掉血从来不是 2%/秒 —— 最狠偏 ×50**

原来是每帧 `int(ceilf(maxHp * 0.02 * delta))`。`ceilf` 让**每帧至少扣 1 点** → 真实速率 = `max(2%/秒, 帧率 ÷ maxHp)`：

| maxHp | 30fps | 60fps | 600fps |
|---|---|---|---|
| 200 | 15%/秒（×7.5） | **30%/秒（×15）** | **100%/秒（×50）** |
| 600 | — | 10%/秒（×5） | 100%/秒（×50） |
| 2000 | 3%/秒（×1.5） | 3%/秒（×1.5） | 30%/秒（×15） |
| 6000 | — | 2%/秒 ✅ | 10%/秒（×5） |

两层错：ⓐ小血量单位几秒融化（200 血 3.3 秒死，而非 50 秒）；ⓑ**跟帧率绑死** —— 同一技能在 30fps 手机 / 60fps / 高刷屏上速度完全不同。
改成**每秒跳一次**（用户 2026-07-30 定）+ 掉帧后补跳（上限 10）。现在 3 帧率 × 4 血量 = 12 组全部精确 **2.00%/秒**。

★**门禁 ⑧ 当时是绿的**：它调 `_tick_tame_decay(1.0)`（一次·delta=1 秒）—— 那正好是取整误差**唯一消失**的调用方式，
它模拟的是游戏里**永不发生**的情形。教训：**逐帧机制的门禁必须按逐帧喂，并至少验两种帧率**。

**③ 这份掉血不是真实伤害**（用户 2026-07-30 指出）

原来 `bucket = "dot"`，而 `_apply_damage` 里 `_raw = (bucket == "tru")` → 会过完整减伤链：
钻石 ×0.82 / 石头岩石之躯 ×最多 0.7 / 石头嘲讽期减免 / 铁壁盾016 `flat_dr` 固定减。
实测带 `flat_dr=30` 的 2000 血单位每秒只掉 **0.5%（×0.25）**。
文案写的是「每秒损失 2% 最大生命」= 归顺的固定代价，不该被对方护甲天赋抵掉。改 `"tru"`。
（护盾照吸 —— 本项目真伤的既有语义，不改。`is_self=true` 保留：自损不吃靶向器那类增伤。）

**④ 重生时符文环叠成两个、且从不"转青"**

施放落地建 1 个，`_tame_revive_dramatize` 又建 1 个 → **2 个**。旧环自毁条件是 `alive == false`，
而 `_kill` 在驯服钩之前**根本没置 `alive=false`** 就 `return` 了 → 旧环永远等不到。
两环创建时间不同 → `rotate_y` 相位不同 → 糊成一团。
而那个函数的头注一直写着「符文环转青」—— **转青也从来没实现过**。
现在：已有环就染青碧（`#7de8c8`，与「归顺!」飘字同色），没有才新建。

★真修复是「转青而不是重建」；`_tame_rune` 里新增的「建前清旧」只是第二道闸（反向验证证过：
只去掉那三行、保留转青，环数仍是 1）。

**门禁**：`verify_trainer_hunt_tame` ⑦b 组 3 条（环数 / 转青）+ ⑧ 组 8 条（3 帧率 × 2 血量 + 真伤桶 + 不许回退 ceilf）+ ⑨ 组加 2 条平铺断言。
反向验证：ceilf → FAIL x5；`"dot"` 桶 → FAIL x5；原始双环写法 → FAIL x3；`-90` 加回 → FAIL x1。

## 2. 审出的问题（已修 · 值一律不变）

### 2-1 ★`HOOK_VULN_MULT` 是死常量，而门禁拿它当事实源

**修前**：

```gdscript
# RealtimeBattle3DScene.gd  const 区
const HOOK_VULN_MULT := 1.25          # ← 游戏代码【零读者】

# _mitigate_incoming 里
d *= 1.25                              # ← 真实行为在这, 硬编码
```

而 [verify_trainer_desc.gd:45](../tests/verify_trainer_desc.gd#L45) 是：

```gdscript
["受伤加成", "+%d%%" % int(round((K["HOOK_VULN_MULT"] - 1.0) * 100.0))]
```

**两个 1.25 只是碰巧相等。** 把常量改成 1.5 会发生：门禁要求文案写 +50% → 改了文案门禁绿 →
**游戏里仍然是 +25%**，也就是门禁**把错误的文案判成了正确的**。
冰川那条更彻底：`d *= 1.2` 连常量都没有。

**已修**：两处改成读 `HOOK_VULN_MULT` / 新增的 `GLACIER_VULN_MULT`（值不变）。
**反向验证**：把 `HOOK_VULN_MULT` 改成 1.60 → `verify_hook` 的「被钩→受伤×1.25(100→125)」
报 `160.0` 并 FAIL。修之前改这个常量**什么都不会发生**。

### 2-2 三个技能的实质数值门禁一个都不查

`trainer_system.gd` 原来**一个 `const` 都没有**，数值全是函数里的裸字面量。后果两条：
① `pet_effect_dump` 抽不到（它靠展开具名常量）② `verify_trainer_desc` 没常量可推期望值，
于是 `want` 表里怒火药水/口哨/冰川**只有射程和 CD**。

**已修**：提出 15 个常量（`FURY_*` / `WHISTLE_*` / `GLACIER_SLOW_MAG` / `MS_HASTE_PER_STACK` / `WHISTLE_SHRED_MULT`），
门禁覆盖的数字 **20 → 32 个**。
**反向验证**：`FURY_HASTE 1.3→1.5` → 报「描述里找不到 +50%攻速」；
`GLACIER_VULN_MULT 1.2→1.35` → 报「描述里找不到 +35%」。

### 2-3 `pet_effect_dump --trainer` 第一版七技全是"效果 0 条"

看着像"大师没有任何效果"。**探针**（不是推理）打出 `_hook_grab` 的函数体，看到
`battle._damage._stun(target, battle.HOOK_STUN, "hook")` —— 数值是**跨文件常量**，
而 `expand_consts` 只展开同文件的。已加 `expand_cross()` 处理 `battle.CONST` 形式。

另外六个主动里有三个的入口是主文件里的**薄包装**（`_cast_glacier` 只往 `_glacier_zones`
塞个字典就返回，效果全在 `_tick_glaciers`），而 `func_scope` 只跟同文件子函数 →
`TRAINER_SKILLS` 改成**每技一条函数链**（13 环），并加了「链上函数失踪」检查
（它当场抓到我把 `_tick_hunt_taunt` 写成了 `_hunt_taunt_tick`）。

现在：**7 技 / 13 环全在位 / 12 条效果 / 文案未提 0 条**。

### 2-4 附带发现（**没改**，超出本次审核范围）：装备域有同一个反模式

给新门禁写"硬编码倍率不许回来"这条断言时，我第一版写成「全文件不许出现 `d *= 1.2`」，
结果抓到的不是冰川，而是 **装备·靶向器055** 那行：

去核文案的，所以目前不会出错；但它和钩锁那条是同一个形态，哪天有人给它加个"事实源常量"
就会重演 §2-1。**本次没动它** —— 装备不在需求 3 的范围内，而且改它要连 59 件装备的口径一起看。

## 4.5 ★逐技目视补完后审出的最大问题：钩锁根本不是 skillshot（已修）

§4 那张"7 技全有演出函数 + 13 素材在位"的表是**静态检查**，它给的是绿灯。
用户 2026-07-30 让我「一个个仔细看」，逐技目视之后审出的最重的一条**和美术无关，是逻辑**：

**`_cast_hook` 在出手那一刻就判定命中。** `_hook_first_target` 沿方向选定目标 → 算好 `arrive`
→ `_pending_shots` 定时到点**必钩**（唯一条件只是"还活着"）。飞行期间目标走出路径 / 跑出射程 /
绕到背后**全部无效**。代码注释自己写着「返回是否**将**命中」。

**决定性证据**：`HOOK_MISSILE_SPD` 那行的注释是
「用户2026-07-26 再−40%: 950→570·**更像可躲skillshot**」——
用户当时降速 40% 的意图就是让它可躲，而判定在出手瞬间，**那次降速根本没让它变可躲**，
只是把"假可躲窗口"从 0.6 秒拉长到 1.05 秒。用户 2026-07-30：「lol锤石的Q哪有这么锁的？」

**成因**：注释写「结算逻辑从演出里抽出可测（照海盗钩索 / CLAUDE.md §3.5）」——
§3.5 的目标是**别让数值结算依赖演出 tween**（海盗钩索那次连红三次的教训），这是对的；
但实现时把**命中判定**也一起挪到了出手瞬间，**过头了**。两者本可兼得。

**已修**：钩头按 delta 逐帧推进（挂 `_tick_hooks`，它本来就在 sim tick 里 → 不依赖 tween、无头可测），
每帧做 `HOOK_HIT_R = 70` 碰撞检测。返回值语义从"是否将命中"改成"是否成功放出"
（游戏内三处调用都不看返回值，只有门禁在断言）。CD 出手即进 20，飞满射程未命中才返还成 10。

**门禁** `verify_hook` ③ 组重写成 6 小组，核心是**「飞行中走开躲得掉」**。
反向验证：把碰撞检测改回"无视距离"（复现旧的锁定行为）→ 这条立刻红。

★**这会让钩锁变弱**（原来必中）。要不要调 CD / 眩晕时长补偿，**待用户拍板**。

★另一个遗留问题（这次没改）：`_hook_chain` 每帧都在调，但**屏幕上看不到从大师连到钩头的铁链**。
旧的 tween 版本也一样。
