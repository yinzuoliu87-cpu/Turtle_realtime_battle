# 10 人模拟 —— 怎么起 10 个窗口、怎么绑 10 个账号

> 用户 2026-09-26：「你试着创建10个简单邮箱，然后准备10个窗口，下一周我们模拟跑一遍看有什么问题」

工具：[tools/sim10.sh](../tools/sim10.sh)

---

## 一、一句话

```bash
bash tools/sim10.sh start 10      # 起 10 个窗口（各自独立存档 = 10 个独立账号）
bash tools/sim10.sh mails         # 看槽位 ↔ 邮箱 ↔ 昵称对照表
bash tools/sim10.sh focus 3       # 把 p03 提到最前（十个窗口标题一模一样，靠它认）
bash tools/sim10.sh status        # 每个槽位：进程活着吗 / 账号 / 邮箱 / 场次
bash tools/sim10.sh stop          # 只关它自己起的那些
```

## 三、为什么必须绑邮箱（不是可选）

`phase2_config.login_wall_on(后端已配, account_email)` —— **后端配着而邮箱为空就挡住**，
一局都开不了。所以 10 个槽位各要一个邮箱。

---

## 四、10 个邮箱哪来的

**不用真去注册 10 个。** 用 Gmail 的 `+` 别名：

| 槽位 | 邮箱 | 昵称（登录墙第一格） |
|---|---|---|
| p01 | `turtlesupport32+t01@gmail.com` | 测试01 |
| p02 | `turtlesupport32+t02@gmail.com` | 测试02 |
| … | … | … |
| p10 | `turtlesupport32+t10@gmail.com` | 测试10 |

- Gmail 把 `+` 后缀的信**全投到 `turtlesupport32@gmail.com` 同一个收件箱** ⇒ 10 个码在一个地方读
- Supabase 把每个别名当**全新地址** ⇒ 不撞 `email_exists`
  （查过库：`+test@` 与 `+e2e…@` 在 `auth.users` 里是两个独立行，**没有被归一化**）

★昵称是**排行榜和对阵图上真会显示的字**，所以建议用「测试01…10」这种一眼能对上槽位的。

## 五、绑定的正确节奏（线上限流是查出来的真值）

从 Management API 读的（2026-09-26）：

| | 值 | 意味着 |
|---|---|---|
| `smtp_max_frequency` | **60** | 两封验证码之间**至少隔 60 秒** |
| `mailer_otp_exp` | **3600** | 码 **1 小时内**有效 |
| `rate_limit_email_sent` | 30 / 小时 | 10 封够用 |
| `rate_limit_anonymous_users` | 30 / 小时 | 10 个号够用 |

⇒ **推荐流程（约 15 分钟）**

1. `bash tools/sim10.sh start 10`
2. **先把 10 封码全发出去**：p01 填昵称 + 邮箱 → 点「发送验证码」→ **等 ≥60 秒** → p02 → …
   （`focus <n>` 可以把指定窗口提到最前）
3. 全发完后去 `turtlesupport32@gmail.com`，一次性读出 10 个码
   —— 码有一小时有效期，**不用发一个读一个**
4. 逐个窗口回填验证码 → 点「确认」
5. `bash tools/sim10.sh status` 核对：10 行的「邮箱」列都不再是 `<未绑定>`

★绑定是**一次性**的。存档在 `C:/tmp/turtle-sim10/pNN/`，下周直接 `start 10` 就是已登录状态。

## 六、注意事项

| | |
|---|---|
| **别删存档** | `reset` 会把账号连同邮箱绑定一起清掉，而那些别名**不能再绑第二次**（撞 `email_exists`），重来要换 `+t11…+t20` |
| **别用 `taskkill /IM`** | 那会连你自己开的 Godot 编辑器一起杀。用 `sim10.sh stop`（它只关自己记下的 pid） |
| 十个窗口**标题一模一样** | 位置就是身份：左上角起，从左到右、从上到下 = p01…p10；认不准就 `focus <n>` |
| 窗口是 **656×399**，不是我要的 460×258 | Godot 有最小窗口尺寸，`--resolution` 给小了会被顶上去（GetWindowRect 量的）。1920×1080 上**最多排得下 4 个不重叠**，所以 10 个是错开摆的 |
| 全部**静音** | `--audio-driver Dummy`，十个窗口同时出声没法用 |
| 带 `SHIP=1` | 关掉 demo 劫持 —— 不带的话假人永不死、战斗永不结束（CLAUDE.md §4） |

## 七、下周跑的时候，已知会碰到的问题

这几条是**已经查实**的，跑之前先知道，省得当成新 bug：

| 什么时候 | 会看到什么 | 状态 |
|---|---|---|
| 周日决赛日 | **两边都可能显示自己赢** —— 双方各在本机打对方的快照，服务端先报的算，后报的那个已经发过奖了 | 根因已定位，修法要改周日架构（A→B→C），A 阶段在做 |
| 周日 | 晋级 ≤1 人时整天开不起来（10 人规模下概率 **9.2%**） | 已登记，晋级线是玩法手感，没动 |
| 周日晚上 | 没有「冠军签表」那一场 —— 跨桶冠军赛一行没做 | 10 人只有一个桶，本来也用不上 |
| 周六 | 对手大概率是真人（v0.19.449 之前是 93% 机器人） | 已修 |
| 全周 | 匹配只会碰到**总场次完全相同**的人 | v0.19.447 起 |
