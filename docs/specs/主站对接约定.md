# 主站 × 小游戏 对接约定

版本：2026-11-06　|　状态：**已被取代**（主站 11-07 发来《龟战主站整体方案》，以 [它](龟战主站整体方案.md) 为准）

本文给主站开发者，写清楚两边各做什么、接口怎么约定。接口路径和字段是我方建议，主站有现成规范的可以提出修改。

## 1. 分工

两个产品只互通三样东西：**账号、玩家持有的龟、龟的等级**。

| 事项 | 主站 | 小游戏 |
|---|---|---|
| 账号 | 账号主体，提供登录 | 一一对应地存一个账号 |
| 龟与等级 | 唯一账本：拥有、抽取、升级、经验 | 只读，打周赛时上报经验事件 |
| 擂台赛开轮、停轮 | 决定并通知小游戏 | 按通知执行 |
| 撮合、对战、裁判 | 不参与 | 负责 |
| 战果 | 接收、查询、自己的业务处理 | 保存并发给主站 |
| 看录像 | 内嵌小游戏提供的网页播放器 | 提供播放器 |

小游戏**不显示也不接收**主站的积分、余额或任何结算信息。

玩家想打擂台赛必须安装小游戏（iOS 或安卓 APK），因为阵容在小游戏里配置。

**小游戏的术语：**

- **大轮：** 一个自然周（UTC）。周一休赛，周二到周五积分赛，周六闯关赛，周日决赛日。
- **周赛：** 积分赛、闯关赛、决赛日的统称，是有成长的正式比赛。
- **总场次：** 玩家本大轮打过的周赛场数，擂台局不算。
- **擂台局：** 玩家之间的切磋，不改变任何进度。

## 2. 账号

### 2.1 建号互相同步

| 触发 | 动作 |
|---|---|
| 玩家在主站注册 | 主站调 `POST 小游戏/mainsite/account`，小游戏建好对应账号（玩家没装 App 也建） |
| 玩家在小游戏打完第一场 | 小游戏调 `POST 主站/game/account`，主站建号并赠送一只小龟 |

- **幂等：** 同一个对方账号 ID 重复调用，返回同一个结果。
- **不回调：** 谁发起建号，对方就不再反向通知，否则会循环。
- **时机：** 小游戏不在打开 App 时建主站号。这样已有主站号的玩家先登录（2.2）时不会多出一个空号，只装不玩的安装也不会产生主站账号。
- **失败：** 请求带昵称和头像；失败时小游戏重试，玩家在此期间可以正常玩。
- **存量：** 上线时小游戏已有的老账号，由小游戏批量调用一次建号接口。

### 2.2 已有主站号的玩家登录小游戏

做法与电视、桌面软件登录账号相同，玩家不需要手动输入任何码：

1. 玩家在小游戏点「用主站账号登录」。
2. 小游戏生成一次性登录码（5 分钟有效），用**系统浏览器**打开 `主站/game/link?code=XXXXXX`。
3. 玩家在主站用现有的用户名和密码登录（已登录就跳过），点「确认登录小游戏」。
4. 主站调 `POST 小游戏/mainsite/link/confirm`，传登录码和主站用户 ID。
5. 小游戏一直在轮询，收到确认后切换到这个账号。玩家回到 App 就是登录状态。

- **防误确认：** 确认页要写明正在登录的设备型号，登录码只能用一次，避免玩家替别人点了确认。
- **切换账号：** 小游戏本机原来的账号进度不合并到主站账号，切换前在 App 里提示玩家。
- **页面内容：** 这个页面由 App 打开，只放登录和确认，不放充值、活动等其他入口。

用系统浏览器的原因：小游戏全程不经手主站密码，主站以后增加登录方式也不用改小游戏。换手机找回账号走同一个流程。

**主站要做：** 一个确认页，一次回调。

### 2.3 小游戏建的号怎么登录主站

主站账号靠用户名和密码登录，而玩家在小游戏里建的号没有密码，**直接上主站登录不了**。做法：

1. 玩家在小游戏设置页看到一个「主站绑定码」（5 分钟有效，一次性）。
2. 玩家自己打开主站，在注册 / 登录页选「已有小游戏账号」，输入绑定码。
3. 主站调 `POST 小游戏/mainsite/link/verify` 校验绑定码，拿到对应的主站用户 ID。
4. 玩家在主站设置用户名和密码，之后正常登录。

App 里只显示这个码，不放跳转主站的按钮或链接。还没有主站账号的玩家（没打完第一场）看不到这个码。

### 2.4 删号

苹果要求 App 内必须能删除账号（审核指南 5.1.1(v)），小游戏已有这个功能，不能去掉。

| 触发 | 动作 |
|---|---|
| 玩家在小游戏删号 | 只删小游戏数据并解绑，调 `POST 主站/game/account/unlinked` 通知主站。**主站账号和龟保留**，之后用 2.2 重新登录即可 |
| 玩家在主站删号 | 主站调 `POST 小游戏/mainsite/account/deleted`，小游戏删除对应账号 |

## 3. 龟与等级

- **编号：** 两边统一用主站的 `petKey`（如 `basic`、`lava`），本文写作 `pet_key`。主站现有 11 只的 `petKey` 与小游戏的龟 ID 完全一致；数字 ID 和主站的 `pet_id`（如 `"8"`）两边不通用。
- **查询：** `GET 主站/game/users/{user_id}/pets`，返回 `[{pet_key, level}]`。
- **数量：** 主站目前 11 只，以后同步到 28 只，新增的龟按附录 B 命名。按 `pet_key` 对应，不写死数量。
- **等级范围：** 1～10。
- **等级生效：** 周赛每局开打时取最新等级；擂台赛取点「准备」时的等级，这一轮内不变。
- **主站不可用时：** 小游戏用上次查到的结果，周赛不中断；擂台赛暂停撮合新对局，恢复后继续。
- **周限免：** 每个号每周 7 只 1 级限免龟，由小游戏计算，自己拥有的不在其中。
- **经验：** 周赛每局裁判算完，小游戏调 `POST 主站/game/exp`，上报 `{match_id, user_id, pet_key, won, mode}`。`mode` 取 `ranked`（积分赛）、`gauntlet`（闯关赛）、`finals`（决赛日）。主站按自己的规则换算并设上限。幂等键为 `match_id + pet_key`。

以下情况**不上报经验**：
- 限免龟。
- 擂台赛的所有对局（擂台局等同切磋，没有任何成长）。

## 4. 擂台赛

### 4.1 流程

1. 主站调 `POST 小游戏/mainsite/arena/open`，传 `{run_id, user_id}`，表示这个号可以开始一轮。小游戏回复 `{ok: true}` 或拒绝原因：`closed`（周一休赛）、`no_first_match`（还没打完第一场）、`run_active`（这个号已有进行中的轮）。
2. 玩家打开小游戏，点「准备」确认阵容。阵容在此刻锁定。一直没点准备的，到换周时按 `not_ready` 结束这一轮。
3. 小游戏把玩家放进队列，后台等待，玩家可以离线。
4. 配到对手后由裁判机算出结果。
5. 小游戏调 `POST 主站/game/arena/result` 发送战果。
6. 主站在回复里说明这一轮继续还是停止（见 4.3）。继续就自动排下一场，阵容不变。**小游戏收到回复才排下一场**；主站暂时不可用时这一轮暂停，不会多打。

### 4.2 规则

| 项目 | 规则 |
|---|---|
| 开放时间 | 周二 00:00 到周日结束（UTC）；周一休赛 |
| 参加条件 | 玩家已选龟并打完本大轮第一场 |
| 对局性质 | 等同切磋：按锁定时的阵容和进度打，打完没有任何成长 |
| 配对 | 只配本大轮总场次相同的玩家，先到先配，等多久都不放宽 |
| 不配对 | 同一设备的两个号；陪练号 |
| 同一对手 | 有其他人在等时不连续配同一对手 |
| 换周 | 周一 00:00 UTC 所有进行中的轮结束；已经开打的那一场打完，照常发战果 |

### 4.3 接口

**战果（小游戏 → 主站）** `POST 主站/game/arena/result`

```json
{
  "match_id": "uuid",
  "run_a": "主站的 run_id", "user_a": "主站用户 ID",
  "run_b": "主站的 run_id", "user_b": "主站用户 ID",
  "winner": "a",
  "replay_url": "https://…",
  "finished_at": 1794000000
}
```

- `winner` 为 `a` 或 `b`。对局没有平局。
- 裁判开算后出错，或开算超过 30 分钟没有结果时，`winner` 为 `null`，这一场作废，由主站决定如何处理。排队等裁判的时间不算在内。
- 幂等键为 `match_id`，同一场重复发送只处理一次。
- 发送失败时小游戏按退避重试，直到主站回复。

**主站的回复**

```json
{ "run_a": "continue", "run_b": "stop" }
```

小游戏据此决定是否继续排下一场，所以**不会多打一场**。

**停轮（主站 → 小游戏）** `POST 小游戏/mainsite/arena/stop`，传 `{run_id, reason}`。还在排队就直接出队，正在进行的这一场打完才停。

**一轮结束（小游戏 → 主站）** `POST 主站/game/arena/run-ended`，传 `{run_id, reason}`。**每一轮不管怎么结束都发一次**，主站收到它才算这一轮彻底结束，在此之前可能还有战果要到。`reason` 包括 `stopped`（主站要求停止，含回复 `stop`）、`week_end`（换周）、`not_ready`（一直没点准备）、`lineup_invalid`（阵容不再合法，例如版本更新删了装备）、`pet_lost`（玩家不再持有这只龟）。

**查询（主站 → 小游戏）** `GET 小游戏/mainsite/arena/runs/{run_id}/matches`，用于对账。

### 4.4 录像

小游戏提供轻量网页对局播放器，主站用 iframe 内嵌 `https://…/player?match={match_id}`，加 `allow="autoplay; fullscreen"`。地址随内测接口一起提供。

- **只支持电脑浏览器：** 手机上不打开播放器。主站在手机上点「看录像」时显示「请在小游戏内观看」，玩家在 App 的战绩页看。
- **加载：** 第一次打开要下载游戏资源，需要等待，之后走浏览器缓存。
- **保留期：** 擂台录像保留 30 天。过期后播放器显示「录像已过期」，战果记录不受影响。
- **版本：** 录像绑定当时的游戏版本。小游戏负责让播放器能播保留期内各版本的录像，主站不用处理。

## 5. 陪练号

小游戏有一批陪练号（目前约 286 个）用于周赛撮合。

- 小游戏批量调用建号接口时带 `bot: true`。
- 主站为它们建**空账号**：不送龟、不发通知、不进排行榜和运营统计。
- 陪练号在主站没有任何行为，也不参与擂台赛。
- 陪练号的龟和等级由小游戏自己管理，不查主站，也不上报经验。

## 6. 接口通用约定

- **鉴权：** 服务器之间互相调用，用共享密钥做 HMAC-SHA256 签名，带时间戳，时差超过 5 分钟拒绝。
- **密钥：** 内测和正式各一套，不进代码仓库。
- **格式：** JSON，时间一律 UTC 秒。
- **幂等：** 所有写接口都要幂等，收到重复请求返回与第一次相同的结果。
- **回包：** 成功 `{ok: true, …}`，失败 `{ok: false, reason: "…"}`；网络错误和 5xx 重试，`ok: false` 不重试。
- **环境：** 两边都要提供内测环境地址，联调和测试全部在内测环境做。

## 附录 A：接口总表

路径前缀以两边实际为准，「主站」「小游戏」分别代表各自的接口地址。

**主站提供，小游戏调用**

| 接口 | 用途 | 请求 | 回复 |
|---|---|---|---|
| `POST /game/account` | 建号（2.1、5） | `{game_id, nickname, avatar, bot}`，`avatar` 可空 | `{user_id}` |
| `POST /game/account/unlinked` | 小游戏删号（2.4） | `{user_id}` | `{ok}` |
| `GET /game/users/{user_id}/pets` | 查龟和等级（3） | 无 | `[{pet_key, level}]` |
| `POST /game/exp` | 上报经验（3） | `{match_id, user_id, pet_key, won, mode}` | `{ok}` |
| `POST /game/arena/result` | 战果（4.3） | 见 4.3 | `{run_a, run_b}` |
| `POST /game/arena/run-ended` | 一轮结束（4.3） | `{run_id, reason}` | `{ok}` |
| 页面 `/game/link?code=` | 确认登录（2.2） | 网址带登录码 | 确认后调 `link/confirm` |

**小游戏提供，主站调用**

| 接口 | 用途 | 请求 | 回复 |
|---|---|---|---|
| `POST /mainsite/account` | 建号（2.1） | `{user_id, nickname, avatar}`，`avatar` 可空 | `{game_id}` |
| `POST /mainsite/account/deleted` | 主站删号（2.4） | `{user_id}` | `{ok}` |
| `POST /mainsite/link/confirm` | 确认登录（2.2） | `{code, user_id}` | `{ok}` |
| `POST /mainsite/link/verify` | 校验绑定码（2.3） | `{code}` | `{user_id}` |
| `POST /mainsite/arena/open` | 开轮（4.1） | `{run_id, user_id}` | `{ok}` 或拒绝原因 |
| `POST /mainsite/arena/stop` | 停轮（4.3） | `{run_id, reason}` | `{ok}` |
| `GET /mainsite/arena/runs/{run_id}/matches` | 对账（4.3） | 无 | 这一轮的战果列表，字段同 4.3 |
| 页面 `/player?match=` | 看录像（4.4） | 网址带对局 ID | 播放器 |

`user_id` 是主站用户 ID，`game_id` 是小游戏账号 ID，都按字符串传。
